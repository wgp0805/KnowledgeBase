# 通用代码Bug检查 (generic-bug-check)

## 触发条件

**任何时候用户出现以下任一情况，你必须使用本Skill：**
1. 说"检查bug" + 一个URL或文件路径
2. 说"代码审查" + 一个功能描述
3. 说"检查代码质量" + 一个模块名称
4. 直接粘贴一个前端页面URL或后端Controller路径

---

## 工作流程

### 阶段一：项目结构分析

1. **识别项目类型**
   - 根据文件路径或URL判断项目类型（Vue+Java、纯Java、纯前端等）
   - 确定项目根目录和主要模块结构

2. **定位入口点**
   - 前端：根据URL找到对应的Vue页面文件
   - 后端：根据URL或类名找到对应的Controller

### 阶段二：全链路追踪

根据入口点，逐层深入：

1. **前端层**（如果适用）
   - Vue页面文件（`src/views/`）
   - API JS文件（`src/api/`）
   - 路由配置（`src/router/`）

2. **后端层**
   - Controller层（`@RequestMapping`）
   - Service层（业务逻辑）
   - Mapper/DAO层（数据访问）
   - Entity/DTO层（数据模型）

### 阶段三：Bug检查维度

对**每一层代码**，依次检查以下维度：

#### 1. 数据流/逻辑错误
- 前端传参是否与后端接收参数一致
- 请求方法（GET/POST）是否前后端匹配
- 响应数据的结构是否被前端正确处理
- 条件分支逻辑是否有遗漏
- 状态流转是否完整

#### 2. 空指针/异常处理
- 链式调用是否存在中间对象可能为null
- 集合操作前是否判空
- 参数校验是否完整
- 异常处理是否合理

#### 3. 安全漏洞
- SQL注入风险
- 越权风险
- XSS风险
- 参数校验
- 敏感信息泄露

#### 4. 性能问题
- N+1查询
- 大对象传输
- 不必要的数据库操作
- SQL性能问题

#### 5. 事务问题
- 多表操作是否有事务注解
- 事务注解是否被绕过
- 异常处理是否影响事务

#### 6. 接口兼容性
- 接口定义与实际是否匹配
- 字段增删是否兼容
- 请求/响应结构变更

#### 7. 代码规范
- 统一返回类型
- 异常处理规范
- 代码分层规范

## 检查结果输出

检查完成后，**生成Markdown报告文件**，同时**在终端输出摘要**。

### 输出规则

1. **生成报告文件**：使用 `Write` 工具将完整报告写入当前工作目录下的 `代码检查报告/{功能名}-bug-report.md`
2. **终端输出**：检查完成后在终端显示报告路径 + Bug数量统计 + 最严重的3个问题
3. **每个Bug必须附带修复建议**，给出修改后的代码片段
4. **修复建议要具体**：直接给出修改后的代码，标明需要修改的文件和行号

### 报告模板

````markdown
# 代码Bug检查报告：{功能名称}

> 检查时间：{时间}
> 检查范围：{前端页面} → {API文件} → {Controller} → {Service} → {Mapper}
````

## 重要注意事项

1. **找不到文件时的处理**：
   - 如果URL对应的路由不存在 → 搜索相关目录找匹配的文件
   - 如果Controller找不到 → 搜索所有Controller目录，用路径段模糊匹配
   - 每一步找不到都要向上报告，不要自己假设

2. **多层调用**：注意跨模块、跨服务的调用关系

3. **动态参数**：注意路径参数和查询参数的处理

4. **配置文件**：检查相关配置文件是否正确
