- 这事你会 反复做

## 找个 Skill 的 底子

那就第二步，先找个 Skill 的底子。

**2.1 搜索现成的 Skill**

我们通常可以先让 Agent 搜一搜有没有现成的“去 AI 味的”，如果有成熟的，就在它基础上改；

如果没有，那官方的 skill-creator 就是你的底子，两条路都通，后面的步骤是一样的。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/6319a6a03259468ac30818e0799afb07_MD5.png)

不过下载来的现成 Skill 得留个心眼，看看它的更新时间，很多是给老模型写的。模型一升级换代，一些写死的规矩，反而会把新模型束缚住。

所以如果你换了新模型，记得先关掉 Skill 裸跑一次，发现不如不用 Skill 的，就可以直接删掉了～

那我们让 Agent 一搜就会发现，去 AI 味最火的现成 Skill，是国外** blader 做的 Humanizer**，已经 7 万星了，而且几天前还在更新。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/5c910873513590b3e65c24024b1928a0_MD5.png)

## 从样本里提炼个人标准

其实，不管是一句话让 AI 写的 Skill，还是网上下载的，都没法直接拿来就用。

SkillsBench 的研究就测试过，

> 只让 AI 凭空自己写的 Skill，用了会比不用还差 8 到 12 个点；网上的热门 Skill，也有大半装了跟没装一样；但是人结合自己真实任务磨出来的，平均能涨 16.6 个点。

![图为研究结果示意。AI 自编 Skill 的下降对应三组特定配置；不能视为所有 Skill 的固定效果。](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/4c1968a21f6bf96eab7697f6e2884db0_MD5.png)

原因就是 AI 不懂你的目标和细节标准，那我们的目标是**让 AI 写的东西像你自己写的**，

而每个人说话、写字都有自己的习惯，比如喜欢短句、爱用什么标点、有什么口头禅，这些就是你跟 AI 平均值不一样的地方，这些独有标准，其实也都能统计、总结出来。

### 3.1 准备自己的语料

所以，我们需要先准备语料：找 **10 篇以上**你自己写的东西，最好是没用 AI 之前写的，聊天记录、朋友圈、微博也算。

我挑了 10 篇我之前的视频文稿放在了项目里。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/92f3a596e3a1daf946092f91026a48d1_MD5.jpg)

### 3.2 提炼个人风格清单

接下来，要把这些原料提炼成味道清单，可以把这段提示词发给 Agent，

- ●●

```
帮我分析这些视频文稿的句子长短，标点，口头禅和表达习惯，不好数出来的特征，比如怎么开头和怎么转折，总结成规律并且附上原文当证据
```

那这是我们的结果，需要自己仔细地过一遍，分成**要留的、要改的、和想加的**。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/4508d6eed4cac78a3ebf21ff6ab2261e_MD5.png)

比如我就发现，我一期稿子六十段，有十段是“那”开头的，虽然是我的味道，但这不好，这是要改的味儿～

![图片](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/1b06e2ee3161c085ca7f4b075bc819dd_MD5.webp)

## 边改边教，让 AI 写得像你

那有了底子和自己的风格清单，你可以拿一件真要做的事，带它先做一遍。

### 4.1 结合风格清单改一篇

比如还是之前那篇 AI 写的稿，让 Agent 使用 Humanizer 并且结合我们的风格清单，改成像我写的。

![这一轮加入了固定开头、转折和结尾，并缩短句子。](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/6824bac051d7e94c770d5f054cb50bac_MD5.png)

### 4.2 逐句评论，反复打磨

结果出来了，我们就读着，哪句不像你就给它标出来，**打上评论**，最好还可以告诉它，如果是你的话可能会怎么写。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/9c9ff7ef2cc2a07c783704439757b1d3_MD5.gif)

它这个评论也很方便，然后如此反复几轮，直到最终读起来终于像你了。

这个打磨的过程，我们就**又有了一些细节的标准**～

![图片](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/d230d827c3e5550d212f56037cf39ded_MD5.webp)

## 把有效做法整理成 Skill

### 5.1 生成新的 Skill

文章打磨好后，就把风格清单和刚才总结出的改稿做法，存成新的 Skill，我们调用 skill-creator，告诉它：

- ●●

```
在 Humanizer 的基础上，把我们的风格清单，和刚才这套做法改进去，存成一个新的 Skill，并且起一个自己的名字，把原作者署名和 MIT 协议留在文件里。
```

这样，它就会帮我们**创建一个属于自己文字风格的**** Skill**。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/0b797ceb77b57163ddf00b1a28ae0b54_MD5.png)

新 Skill 存好以后还得做两件事：砍掉多余内容，再拆分文件。

### 5.2 砍掉多余内容

AI 很容易在原本底子的基础上，只增不删，但 Skill 文件是越短越精简，效果越好的。

所以我们可以手动地把 AI 本来就会的统统删掉、把原作者那些跟我们目标关系不大的，我们很少出现的情况删掉，比如它的英文习惯。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/05dd21fec8ca65461ffaa0ae11aeeabe_MD5.png)

这个过程你可以让 Agent 自检去删删，也建议一边自己看文件一边给出具体的评论。

### 5.3 拆分文件

SKILL.md 里尽量只留主流程和目录，

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/7686d6a7fcdaea2af7c79594a415adb2_MD5.jpg)

我们增加的习惯清单、样文、统计放进旁边的 reference 文件夹，检测脚本放进 scripts 文件夹。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/94e86d678921bf2a40820e9bf5dcb5a3_MD5.jpg)

## 在使用中迭代 Skill

那改好之后，也不代表完美了，Skill 的真正生命是在使用中不断迭代变好的。在迭代过程中也有几个注意点：

### 7.1 用规律替代禁令

第一个容易踩的雷，就是不停往 Skill 里加“不要这样”“不要那样”。比如我们一直往里加“不要写不是、而是，不要写与其、不如”，会导致禁令越攒越多，AI 反而不知道正确的该怎么样。

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/2b6061cc318b7bd495f058411b285204_MD5.png)

所以抓到错了，先问它为什么，跟它一起找到背后的**规律和模式**，以及该怎么样。这样一条规律，就能拦住同类的问题。

### 7.2 把复盘规则写进 Skill

另外，大家可以对 SKILL.md 进行编辑，

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/11ace2b8553728db3e2c322ca42e60dc_MD5.png)

可以加上这一句，这样 Agent 就可以主动复盘，再由你决定哪些经验值得写进 Skill～

![](assets/2026-11-24%20-%20%E5%83%8F%E9%AB%98%E6%89%8B%E4%B8%80%E6%A0%B7%E5%81%9A%E8%87%AA%E5%B7%B1%E7%9A%84%20Skill%EF%BC%81%E3%80%90%E5%B0%8F%E7%99%BD%E6%95%99%E7%A8%8B%E3%80%91/534dc48e871d493a8c26f4c20f29b17c_MD5.png)

### 7.3 更新参考，再裸跑一次

reference 当中的参考也记得常常更新，每隔一阵就把你新的满意的参考换进去，模型更新了，也记得关掉 Skill 裸跑一次，你会发现有些规矩可以删掉了。
