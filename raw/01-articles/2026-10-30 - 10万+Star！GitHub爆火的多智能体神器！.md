# 10万+Star！GitHub爆火的多智能体神器！

```
上方蓝色“程序员追风”，选择“设为星标”

来源：github.com/paperclipai/paperclip
```

现在很多开发者的桌面是这样的：Claude Code开一个窗口，Cursor开一个标签页，Codex CLI在另一个终端里跑着。

三个代理各忙各的，互不认识。想让它们配合做一件事，只能自己当中间人，在几个窗口之间来回传话。

Paperclip想解决的就是这个问题。它不做代理，它做“公司”——给这些各自为战的AI安排岗位、划定汇报线、分配预算、跟踪进度。

01

它扮演的角色：不是员工，是公司

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/a5yW0MNUS2B35YuvvOcHKH4Nyc8qkXE92WGR1H2T2y4EV3SSq0OuwIKTOw0akzKow9ibibGyLJmw5fywKWgrwYRg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=2)

项目是Node.js服务端加React前端，MIT协议，今年三月开源，目前十万多Star。

开发者自己的比喻很到位：OpenClaw是员工，Paperclip是公司。

具体怎么理解？Claude Code可以当CTO，Codex当工程师，Cursor当设计师。Paperclip负责给它们定目标、派任务、设预算、盯进度。上级往下布置，下级完成后往上交。心跳机制定时唤醒每个代理，该干活干活，该汇报汇报。

![图片](https://mmbiz.qpic.cn/mmbiz_png/wzfB4YnnqWrSsg5UII4Sr5aPW0pvBNB4CFT5iabwqh80aygib5iboNQb6wJcfGcnaoicjUIEBcRSYicXtQgInicgECMfm0JUicY3mMxeaqYC28eDicw/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=3)

它不关心代理写的代码好不好，只保证每件事都有人负责。

![图片](https://mmecoa.qpic.cn/mmecoa_png/NYQt9rr8A02C3T5QEAYDkicr7qUALPHCSStuKSuobXBHeoLkiaRVbicicYUibISUmZrzuuQXwVGBJc3W2zZOOo6iaECg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=4)

02

接入方式：填空就能“入职”

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/a5yW0MNUS2B35YuvvOcHKH4Nyc8qkXE92WGR1H2T2y4EV3SSq0OuwIKTOw0akzKow9ibibGyLJmw5fywKWgrwYRg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=5)

支持接入的类型不少：Claude Code、Codex、Cursor、Gemini CLI、bash脚本、OpenClaw，甚至自己写的HTTP机器人。

每个代理需要配置角色、职称、汇报关系、预算。官方把适配器都写好了，把接入点填进去即可。

接入本身已经简化成填空题，真正需要动脑的是：你希望这堆代理协同完成什么。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/Lgu1K9Ehrgdg03vhsFuCooliabwT2VLwDoLdb1YyuTC6rM4zY4w76KZdR22uszLbCLEL25nlicrbNUfuQiciaSJksw/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=6)

开发者有句话说得朴实但准确：只要能接收心跳，就能入职。

任务跟公司目标、项目目标、具体工单绑定。代理清楚自己为什么做这件事，而不是只看到一个任务标题。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/wzfB4YnnqWr3J0uTHIoiaBssGG8rsAOGXU3siabuQSarXQicWPnBQxYuzgRvVz6lEw5ToYPKp8KmAnuejdAhbXtWIagCrLgJr8ibMy5uDd3tzTI/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=7)

心跳按时间表唤醒代理，检查状态，把结果往上汇报。一个目标拆到哪一层、谁负责哪一段，面板上都能追溯。

![图片](https://mmecoa.qpic.cn/mmecoa_png/NYQt9rr8A02C3T5QEAYDkicr7qUALPHCSStuKSuobXBHeoLkiaRVbicicYUibISUmZrzuuQXwVGBJc3W2zZOOo6iaECg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=8)

03

刹车机制：预算和审批

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/a5yW0MNUS2B35YuvvOcHKH4Nyc8qkXE92WGR1H2T2y4EV3SSq0OuwIKTOw0akzKow9ibibGyLJmw5fywKWgrwYRg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=9)

每个代理有月度预算，花到上限自动停止。不会出现某个代理陷入循环、把额度烧光的情况。

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/wzfB4YnnqWrIrtWvNAJyXjrbW77LJick1bRm1QKic4lIGlyA4R6w3eDRVCkEnMhs6jhOUOPIOeDAxFG721jQsGNDpwLFpVeaSPFCVwJ7hg2Ns/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=10)

雇佣、暂停、终止代理，都需要审批。

所有操作留审计日志，配置变更带版本控制，改错了能回滚。

这条设计的分量比看起来重。代理跑起来之后，人很难逐条盯着它做了什么。“能查、能回滚”这两件事必须由系统兜底。

组织架构也是完整的一套。代理有老板、有头衔、有职位描述。工单系统记录每次对话和每次工具调用。任务之间有依赖关系，阻塞项没解决，下游不会启动。

上下文从任务往上流到项目和公司目标，代理始终清楚自己在做什么。

一个实例可以跑多个公司，数据互相隔离，手机上也能监控。同时折腾几个side project的人，这一条能省不少切换成本。

![图片](https://mmecoa.qpic.cn/mmecoa_png/NYQt9rr8A02C3T5QEAYDkicr7qUALPHCSStuKSuobXBHeoLkiaRVbicicYUibISUmZrzuuQXwVGBJc3W2zZOOo6iaECg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=11)

04

安装：一行命令起一个实例

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/a5yW0MNUS2B35YuvvOcHKH4Nyc8qkXE92WGR1H2T2y4EV3SSq0OuwIKTOw0akzKow9ibibGyLJmw5fywKWgrwYRg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=12)

开源、自托管、不需要注册账号。默认走本地回环，第一次跑最快：

```nginx
npx paperclipai onboard --yes
```

想配成局域网或Tailscale，加一个参数：

```nginx
npx paperclipai onboard --yes--bind lan
# 或者走tailnetnpx
paperclipai onboard --yes--bind tailnet
```

npx报错多半是私有npm registry的问题，强制走公共源：

```nginx
npx --registry https://registry.npmjs.org paperclipai onboard --yes
```

也可以手动拉源码：

```bash
git clone https://github.com/paperclipai/paperclip.gitcd paperclippnpminstallpnpm dev
```

API服务跑在3100端口，嵌入式PostgreSQL自动创建，不用手动配。前置要求是Node.js 20以上、pnpm 9.15以上。

![图片](https://mmbiz.qpic.cn/mmbiz_png/wzfB4YnnqWpU16CPzXvMv6MgBGyBb1WY3jl3BY521e5h1e4Wme0vmOUYO6aFcvcokotCRNiamt6jZXoMNe9IllwVDx6CVdQicHtY89qzicJrL0/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=13)

整个流程没有账号体系要打通，也没有云端控制台要点，链路全在本机。

![图片](https://mmecoa.qpic.cn/mmecoa_png/NYQt9rr8A02C3T5QEAYDkicr7qUALPHCSStuKSuobXBHeoLkiaRVbicicYUibISUmZrzuuQXwVGBJc3W2zZOOo6iaECg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=14)

首次使用：先建一家公司

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/a5yW0MNUS2B35YuvvOcHKH4Nyc8qkXE92WGR1H2T2y4EV3SSq0OuwIKTOw0akzKow9ibibGyLJmw5fywKWgrwYRg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=15)

06

现状：方向对，但仍需打磨

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/a5yW0MNUS2B35YuvvOcHKH4Nyc8qkXE92WGR1H2T2y4EV3SSq0OuwIKTOw0akzKow9ibibGyLJmw5fywKWgrwYRg/640?from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=24)

同时开多个代理干不同的事，管理成本只会越来越高。Paperclip把自己定位成公司而不是员工，这个区分很有价值。眼下流行的“一人公司”模式，前提就是得有人把这些Agent调度起来。

生态还在生长，社区在推插件，Star也还在涨。

一年前，让几个不同的AI代理围绕同一个目标协作，还得自己写调度脚本。现在这件事被收进了一个界面里。

但它离成熟还有距离。开源才半年多，issue区还堆着六千多个未关闭的问题，说明坑不少。

现阶段它更适合爱折腾、能接受边用边修的人。想找一个装上就零维护的团队工具，还得再等等。
