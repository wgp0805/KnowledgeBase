## 一、先搞懂：为什么你的灰度发布总是“灰飞烟灭”？

在动手指之前，咱们得先明白一个道理： **单服务灰度好搞，全链路灰度难上天** 。

为啥？因为全链路灰度就像 **机场的“特殊旅客通道”** ——

从你进航站楼（网关）、过安检（服务A）、登机（服务B），全程都得有人认出你是“VIP”，给你特殊待遇。

要是某个环节掉了链子，比如安检员没认出来，把你赶到普通队伍，那VIP通道不就白开了吗？

技术人踩的坑，其实就这四个：

**（1）只给网关“打了招呼”，下游服务一脸懵**

很多人觉得在网关层把灰度流量切到灰度服务就万事大吉。

结果网关是切了，但服务A调用服务B时，负载均衡一看：“哟，服务B有两个节点，轮着来吧！”

于是灰度流量跑到了生产节点，数据错乱得一塌糊涂。

**（2）Nacos配置搞成“大杂烩”，灰度生产不分家**

Nacos是个好同志，但配置不对就是定时炸弹。

我上次把灰度服务的命名空间和生产混在一起，结果灰度服务一注册，生产服务直接拉取到了“双倍节点”，流量分配当场爆炸。

**（3）负载均衡“傻白甜”，灰度流量被乱点鸳鸯谱**

默认的负载均衡（比如轮询）才不管什么灰度不灰度，它只认服务名。

你要是不告诉它“带Gray标签的请求必须走灰度节点”，它就会把灰度流量均匀分给所有节点，包括生产节点。

**（4）灰度标识传递断了线，下游服务不认账**

灰度流量得有个“身份证”，比如请求头里加个 `X-Gray: true` 。

但很多人只在网关加了头，服务A调用服务B时忘了传，服务B一看没身份证，直接发配到生产节点。

这就跟你过了VIP安检，但登机口不认你的VIP牌一样，白折腾。

搞懂这四个坑，咱们再动手，就能避开90%的翻车现场。

### 2.1 Nacos安装：三步搞定，别整花活

Nacos官网下载2.2.3的zip包，解压后三步走：

**（1）改端口** ：默认8848，如果被占用了就改 `conf/             application.properties           ` 里的 `              server.port            ` 。

**（2）改数据库** ：默认是Derby内存库，重启就丢数据，必须改MySQL。在 `              application.properties            ` 里加：

```
spring.datasource.platform=mysql

db.num=1

db.url.0=jdbc:mysql://localhost:3306/nacos?characterEncoding=utf8&connectTimeout=1000&useSSL=false&serverTimezone=UTC

db.user.0=root

db.password.0=123456
```

然后在MySQL里建个 `nacos` 库，执行 `conf/             nacos-mysql.sql           ` 脚本。

**（3）启动** ：Windows双击 `bin/             startup.cmd           ` ，Linux/Mac执行 `sh bin/             startup.sh            -m standalone` 。

启动后访问 `http://localhost:8848/nacos` ，账号密码都是 `nacos` ，能登录就成功了。

## 三、核心实战：手把手搭起全链路灰度

咱们这次要搭的架构是： **用户请求 → Gateway网关 → 服务A → 服务B** 。

灰度规则很简单：带 `X-Gray: true` 头的请求，全程走灰度节点；不带头的，走生产节点。

全程分四步：① Nacos隔离 → ② 网关灰度过滤 → ③ 服务搭建与标识传递 → ④ 自定义负载均衡。

#### 3.2.3 写网关灰度过滤器

这个过滤器的作用：如果请求头里有 `X-Gray: 1` ，就在请求头里加 `X-Gray: true` ，否则加 `X-Gray: false` 。

```
package 
            com.example.gateway.filter;
          

import 
            lombok.extern.slf4j.Slf4j;
          
import 
            org.springframework.cloud.gateway.filter.GatewayFilter;
          
import 
            org.springframework.cloud.gateway.filter.factory.AbstractGatewayFilterFactory;
          
import 
            org.springframework.http.server.reactive.ServerHttpRequest;
          
import 
            org.springframework.stereotype.Component;
          

@Slf4j
@Component
publicclass GrayGatewayFilter extends AbstractGatewayFilterFactory<GrayGatewayFilter.Config> {

    public GrayGatewayFilter() {
        super(Config.class);
    }

    @Override
    public GatewayFilter apply(Config config) {
        return (exchange, chain) -> {
            String grayTag = 
            exchange.getRequest().getHeaders().getFirst(
          "X-Gray");
            boolean isGray = "1".equals(grayTag);
            
            log.info(
          "网关识别到灰度标记: {}, 是否灰度: {}", grayTag, isGray);

            ServerHttpRequest mutatedRequest = 
            exchange.getRequest().mutate()
          
                    .header("X-Gray", 
            String.valueOf(isGray))
          
                    .build();

            return 
            chain.filter(exchange.mutate().request(mutatedRequest).build());
          
        };
    }

    publicstaticclass Config {}
}
```

启动类加上 `@EnableDiscoveryClient` ：

```
@SpringBootApplication
@EnableDiscoveryClient
public class GrayGatewayApplication {
    public static void main(String[] args) {
        
            SpringApplication.run(GrayGatewayApplication
          .class, args);
    }
}
```

#### 3.3.3 在服务间传递灰度标记

服务A需要调用服务B，必须把灰度请求头 `X-Gray` 传递过去。这里我们用Feign，通过自定义 `RequestInterceptor` 实现。

            feign.RequestInterceptor;

### 3.4 第四步：自定义负载均衡——让流量“精准投递”

现在服务和网关都有了，但负载均衡还是默认的轮询，需要告诉它：“灰度请求只能走灰度节点，生产请求只能走生产节点”。 我们通过实现Spring Cloud LoadBalancer的 `ReactiveLoadBalancer` 来定制策略。

#### 3.4.1 灰度负载均衡器

```
package 
            com.example.servicea.loadbalancer;
          

import 
            org.springframework.beans.factory.ObjectProvider;
          
import 
            org.springframework.cloud.client.ServiceInstance;
          
import 
            org.springframework.cloud.client.loadbalancer.DefaultResponse;
          
import 
            org.springframework.cloud.client.loadbalancer.EmptyResponse;
          
import 
            org.springframework.cloud.client.loadbalancer.Request;
          
import 
            org.springframework.cloud.client.loadbalancer.Response;
          
import 
            org.springframework.cloud.loadbalancer.core.ReactiveLoadBalancer;
          
import 
            org.springframework.cloud.loadbalancer.core.ServiceInstanceListSupplier;
          
import 
            org.springframework.web.context.request.RequestContextHolder;
          
import 
            org.springframework.web.context.request.ServletRequestAttributes;
          
import 
            reactor.core.publisher.Mono;
          

import 
            javax.servlet.http.HttpServletRequest;
          

publicclass GrayLoadBalancer implements ReactiveLoadBalancer<ServiceInstance> {

    privatefinal String serviceId;
    privatefinal ObjectProvider<ServiceInstanceListSupplier> supplierProvider;

    public GrayLoadBalancer(String serviceId, ObjectProvider<ServiceInstanceListSupplier> supplierProvider) {
        this.serviceId = serviceId;
        this.supplierProvider = supplierProvider;
    }

    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        // 获取当前请求的灰度标记
        ServletRequestAttributes attributes = (ServletRequestAttributes) 
            RequestContextHolder.getRequestAttributes();
          
        boolean isGrayRequest = false;
        if (attributes != null) {
            HttpServletRequest httpRequest = 
            attributes.getRequest();
          
            String grayHeader = 
            httpRequest.getHeader(
          "X-Gray");
            isGrayRequest = "true".equals(grayHeader);
        }

        ServiceInstanceListSupplier supplier = 
            supplierProvider.getIfAvailable();
          
        if (supplier == null) {
            return 
            Mono.just(
          new EmptyResponse());
        }

        return 
            supplier.get().next().map(instances
           -> {
            ServiceInstance selected = filterInstances(instances, isGrayRequest);
            return selected != null ? new DefaultResponse(selected) : new EmptyResponse();
        });
    }

    private ServiceInstance filterInstances(Iterable<ServiceInstance> instances, boolean isGrayRequest) {
        for (ServiceInstance instance : instances) {
            String grayTag = 
            instance.getMetadata().get(
          "
            service.gray.tag"
          );
            boolean isGrayInstance = "true".equals(grayTag);
            if (isGrayRequest == isGrayInstance) {
                
            System.out.println(
          "负载均衡选中: " + 
            instance.getHost()
           + ":" + 
            instance.getPort()
           + " 灰度:" + isGrayInstance);
                return instance;
            }
        }
        // 如果没有匹配的，返回第一个（兜底）
        return 
            instances.iterator().next();
          
    }
}
```

#### 3.4.2 注册负载均衡器

在服务A和服务B里都要注册这个自定义负载均衡器，通过配置类实现。

```
package 
            com.example.servicea.config;
          

import 
            com.example.servicea.loadbalancer.GrayLoadBalancer;
          
import 
            org.springframework.cloud.client.ServiceInstance;
          
import 
            org.springframework.cloud.loadbalancer.core.ReactiveLoadBalancer;
          
import 
            org.springframework.cloud.loadbalancer.core.ServiceInstanceListSupplier;
          
import 
            org.springframework.cloud.loadbalancer.support.LoadBalancerClientFactory;
          
import 
            org.springframework.context.annotation.Bean;
          
import 
            org.springframework.context.annotation.Configuration;
          
import 
            org.springframework.core.env.Environment;
          

@Configuration
publicclass LoadBalancerConfig {

    @Bean
    public ReactiveLoadBalancer<ServiceInstance> grayLoadBalancer(Environment environment,
                                                                   LoadBalancerClientFactory clientFactory) {
        String serviceId = 
            environment.getProperty(LoadBalancerClientFactory.PROPERTY_NAME);
          
        returnnew GrayLoadBalancer(serviceId, 
            clientFactory.getLazyProvider(serviceId,
           ServiceInstanceListSupplier.class));
    }
}
```

然后在启动类上加上 `@LoadBalancerClient` 注解，指定服务名和配置类：

```
@SpringBootApplication
@EnableDiscoveryClient
@EnableFeignClients
@LoadBalancerClient(name = "user-service-b", configuration = LoadBalancerConfig.class)
public class UserServiceAApplication {
    public static void main(String[] args) {
        
            SpringApplication.run(UserServiceAApplication
          .class, args);
    }
}
```

服务B也需要类似配置，但服务B不调用别人，所以可以不加。

## 四、测试验证：看它到底灰不灰

### 4.1 启动所有服务

按顺序启动：

- Nacos
- 网关（gray-gateway，8090）
- 服务A生产版（8080）
- 服务A灰度版（8081）
- 服务B生产版（8082）
- 服务B灰度版（8083）

在Nacos控制台查看服务列表：

- `prod-namespace` 下应有：gray-gateway、user-service-a(8080)、user-service-b(8082)
- `gray-namespace` 下应有：user-service-a(8081)、user-service-b(8083)

### 4.2 用Postman测试

**1\. 普通生产流量（不带X-Gray头）**

请求： `GET http://localhost:8090/api/a/hello`

返回结果应为：

```
服务A(端口:8080,灰度:false) -> 服务B(端口:8082,灰度:false) 处理成功
```

日志里应看到负载均衡只选中了生产节点。

**2\. 灰度流量（带X-Gray:1头）**

请求： `GET http://localhost:8090/api/a/hello` ，Headers里加 `X-Gray:1`

返回结果应为：

```
服务A(端口:8081,灰度:true) -> 服务B(端口:8083,灰度:true) 处理成功
```

日志里应看到灰度标记被正确传递，负载均衡选中了灰度节点。

### 4.3 常见问题速查

- **服务没注册到Nacos** ：检查bootstrap里的命名空间ID对不对，有没有加 `@EnableDiscoveryClient` 。
- **灰度标记没传递** ：看网关日志有没有“网关识别到灰度标记”，Feign日志有没有“Feign传递灰度标记”。
- **负载均衡没生效** ：检查 `@LoadBalancerClient` 注解的配置类是否正确，服务元数据里有没有 `              service.gray.tag            ` 。

## 五、进阶玩法：让灰度更稳更可控

### 5.1 监控灰度流量

用Prometheus + Grafana监控灰度服务的QPS、响应时间、错误率。

在服务里加 `spring-boot-starter-actuator` 和 `micrometer-registry-prometheus` ，然后配置Grafana导入Spring Boot仪表盘（模板ID 12856）。

重点看灰度服务是否比生产服务慢，错误率是否升高。

### 5.2 一键回滚

如果灰度服务出问题，快速回滚步骤：

1. 修改网关配置，把 `GrayGatewayFilter` 注释掉，重启网关（灰度流量就进不来了）。
2. 在Nacos控制台把灰度命名空间里的服务全部下线。
3. 排查灰度服务的bug，修复后重新上线。

### 5.3 灰度比例控制

在网关过滤器里加个随机数，比如只放行10%的流量：

```
int grayPercent = 10; // 10%
Random random = new Random();
boolean isGray = 
            random.nextInt(
          100) < grayPercent;
if (isGray) {
    mutatedRequest = 
            exchange.getRequest().mutate().header(
          "X-Gray", "true").build();
} else {
    mutatedRequest = 
            exchange.getRequest().mutate().header(
          "X-Gray", "false").build();
}
```

这样就能小流量验证，避免一下子把生产流量切过去。
