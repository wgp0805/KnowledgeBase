# 又一个神级 Skill，让 AI 少写字、多画图！

最近给 AI 编程助手装了一个开源Skill，叫 show-me，作用是让它解释问题的时候少写字，多画图。

现在这些工具的回答越来越长，问一个函数的调用关系，能给你写三屏，从背景到取舍到风险全来一遍。这些内容写得都没错，就是读起来太慢，大部分时候我直接拉到最底下看代码，中间的解释都跳过了。

这个 Skill 近期非常火，有必要跟大家分享一下。

# 先说 show-me 是个什么东西

![](https://mmbiz.qpic.cn/sz_mmbiz_png/38IO1Mnhnawd67IwZOocTia6jlomUaspPjSGlyibBxiaxAibf7MK9iaR7PjkgicRNib5Upm6PVxf8996MvzHlYurZkq6sNMUic4ibUrZqsK3JYIeDTxY/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=0)

它不是一个单独的工具，没有自己的界面。说白了就是一份技能文件，装在你已经在用的 AI 编程助手里生效。国内的 WorkBuddy、Trae、CodeBuddy 这类支持技能机制的工具都能装，Claude Code、Codex 也一样。

这个技能有个地方和想象的不太一样：它不教 AI 任何新本事。整个技能就是一个一百多行的 Markdown 文件，里面写的全是输出规范，比如解释问题的时候不要写铺垫，能用图说清楚的就不要用字。

项目放在  `humanlayer/skills`  这个仓库里，MIT 协议，目前有4k Star。仓库里一共五个技能，show-me 是讨论度最高的一个，B 站上也有人做了实测视频。

作者 Dex Horthy 在发布博客里说，模型在榜单上越来越聪明，但用起来有个明显退步的地方，就是表达，他自己一天要看好几次那种全是术语的长回复。Reddit 的前 CEO 也公开吐槽过 Claude 的说话风格，说怎么纠正都纠正不过来，所以打磨出这个 Skill。

# 它都能画出什么

我把技能文件完整读了一遍，里面给 AI 规定了七八种表达形式，每种对应一类问题，挑几个我觉得最实用的说。

**讲逻辑用伪代码。** 比如一个保存操作，内容没变就返回缓存，变了就写入新内容。这种东西用文字讲得两三句话，伪代码四行就完了，扫一眼就懂。

**调用关系画成一棵树。** 谁调用了谁，一层一层往下缩进排列。这种写法是另一位工程师 Dillon Mulroy 先玩起来的，他说自己写的计划现在基本都是伪代码加调用栈，不光自己看，给 AI 实现的时候也直接拿它对齐。

![](https://mmbiz.qpic.cn/mmbiz_png/38IO1MnhnawrTy3luBib7Dc8384xsZLrkQe6ZbLWpMu6elIquicKakX8I9XQTqoaCnTb17j4BDjia1YXglWo5H9yzjagp3nd2IShibjBAxRpk3o/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=1)

Dillon Mulroy 分享的调用栈写法**前端结构用组件树。** 只保留重要的状态 hooks 和模块边界，其他全部省略，还会把文件路径标在旁边。哪个组件在哪个文件里，谁套着谁，看得很清楚。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/38IO1MnhnaxMT4XzhvbA2wZTaMNiby3gicJ4rF7WE4hshicdoibzzI1T3ocT7UgUJ760pLCYrxUBt970TiaKGkNR1dfXYqOPGZw8GTBecU8lpRnQ/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=2)

show-me 输出的组件树示例**多方参与的交互过程，用 Mermaid 时序图。** 比如用户点了按钮，前端把请求发给后台，后台再把结果流式返回，谁先谁后、谁在等谁，画出来比写出来清楚。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/38IO1MnhnaxicDkwZ9pwbibJxQcrvzMh2lF8kQ8URgtiaedv35f9PO790ULpohPoYkeTLlbWavX1FaYCRDk7annRdAxia2XjIXQV8uKmJGxMnB8/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=3)

### 有个小提醒，图能不能直接在对话界面里显示，取决于你用的工具支不支持 Mermaid 渲染，不支持的话，把它给的代码复制到飞书文档或者随便一个在线 Mermaid 编辑器里，照样能看。

**讲改动的时候用 diff，这个是我个人用得最多的。** 两个方案摆在面前，AI 各写一大段优缺点，读完还是不知道差在哪。让它把改前改后用加号减号标出来就清楚了，哪个方案动了三个文件，哪个方案要重构半个项目，对比着看几秒钟就有数。

![](https://mmbiz.qpic.cn/mmbiz_png/38IO1MnhnazaryTunibkeqBugNhxtYGxeuLEpqC8Ps7IiahkW3Fdyxhtex0fYffZg36C0ziam1U801hs5dLGE2JjicP5J6FlP4LowwMaKKq70uo/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=4)

用 diff 形式展示文件结构的变化**图也讲不清的，它会直接做一个网页。** 比如要讲一个复杂概念，文字和简单图表都吃力，它会让 AI 生成一个独立的 HTML 文件，把内容拆成几块，配上图，双击用浏览器打开，就是一份能照着讲的材料。HumanLayer 团队自己说，他们内部做原型的时候，HTML 页面已经很大程度上替代了 Figma。

![](https://mmbiz.qpic.cn/mmbiz_png/38IO1MnhnayGwXrHibwu4jTicibR61nNFBcnZ5JLmo4tI6dTh3xLVBsTt7460RefcG1ZgcbmylGBPd2Q1skwSwm0cdlAvNaAjFn79TckclrRWQ/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=5)

show-me 生成的 HTML 讲解页，浏览器直接打开技能文件最后还有一条总的约束：**挑最小的那个视图，把关键点说清楚就行，大多数时候只用得上其中一两种，别堆砌。** 我觉得这条挺重要的，真把七八种图一次全甩出来，那比看文字还累。

顺便提一句，TypeScript 社区的 Matt Pocock 之前做过一个叫 /teach 的技能，专门生成 HTML 讲解页，作者在博客里专门致谢了他，说 show-me 的网页讲解功能就是受这个启发。

# 安装使用

一行命令安装：

```
npx skills add humanlayer/skills --skill show-me
```

装完不用记什么复杂用法，在对话里输 /show-me，或者直接跟 AI 说"内容太多了，给我看"，它就会把刚才那堆字换成图。也可以指着具体的东西让它讲，一个路由、一个服务、一个 PR 都行。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/38IO1MnhnayB2VlhazM5hgHR7PV3sicc165YzOE47ANNRMe81IdxB0UpIVV0q64LFFxIccOtm03icml52LWfmQtbOkR3xwtREggX5bxxn0wic4/640?wx_fmt=png&from=appmsg&watermark=1#imgIndex=6)

在对话里调用 show-me 技能想让它出网页版的讲解，就在后面补一句 as an html explainer。

# 两个要注意的地方

说完好用的部分，再说几个我觉得要注意的。

**第一，图是 AI 画的，有可能会画错。** 尤其是面对它不熟的小众框架，组件树可能漏掉关键模块，调用树可能编出不存在的调用。我一般是先看图了解大概结构，具体细节再回到代码里核实。

**第二，它管的只是表达形式。** 方案本身靠不住的话，画成图也靠不住，而且图看着比文字更可信，反而容易把人带偏，这一点心里要有数。

# 最后说两句

show-me 这类项目的好处是简单，一百多行 Markdown，谁都能读，谁都能改，完全可以改成自己团队顺手的版本。

用下来我有个感觉，很多时候 AI 的回答不好用，未必是能力问题，可能就是我们没提前说清楚想要什么形式。

这半年类似的 Skill 出来不少，管代码评审的，管需求追问的，管文档风格的，做的事都差不多，把人的工作习惯写成文件，让 AI 照着来，反正我觉得这个方向挺好。
