昨天晚上，我的技术群被一条消息刷屏了—— **DeepSeek多模态模型正式上线API了**。

说实话，这个消息我等了很久。

但一直有一个硬伤：**它看不见东西**。

一张截图、一份图表、一个UI界面——你只能靠文字描述给DeepSeek听，它再根据你的描述去理解。

**2026年8月21日，这个短板终于被正式补齐了**。

全新的多模态视觉理解模型**DeepSeek-V4-Flash-Vision-Exp**正式上线DeepSeek API平台。

开发者可以通过设置 `model='deepseek-v4-flash-vision-exp'` 访问该模型。

## 一、这是一次“加法”

在聊具体能力之前，我先说一个很多人可能没注意到的点。

这次上线的模型名字里带了一个“**Exp**”（Experimental，实验性）。

官方明确表示这是一个**实验性质的模型**。

但“实验性”不代表“不成熟”。

最关键的一点是：**在纯文本能力上，DeepSeek-V4-Flash-Vision-Exp与DeepSeek-V4-Flash正式版完全持平**。

Agent能力、推理能力、世界知识——这些V4-Flash已经验证过的核心能力，Vision版本一个都没丢。

这意味着你可以放心地把现有的V4-Flash业务切换到这个新模型上，文本相关的功能不会受到影响，同时还白捡了一个看图能力。

## 二、DeepSeek多模态模型长什么样？

在深入技术细节之前，我们先建立一个整体认知。

![](assets/2026-08-22%20-%20%E9%87%8D%E7%A3%85%EF%BC%8CDeepSeek%E5%A4%9A%E6%A8%A1%E6%80%81%E6%A8%A1%E5%9E%8B%E4%B8%8A%E7%BA%BF%E4%BA%86%EF%BC%81/3250563e9cf9c31b5cc650123d4baca3_MD5.jpg)

这张图展示的是DeepSeek多模态模型的完整架构。

和主流多模态模型最大的不同在于—— **DeepSeek不是简单地把图片切成碎片丢给模型，而是先把图片“压缩提炼”成一套“视觉原语”再融合进推理过程**。

**架构层面的核心设计**：

- DeepSeek-ViT ：负责将图像转换为视觉特征
- 文本分词器 ：负责处理用户的语言指令
- 基座模型 ：DeepSeek-V4-Flash进行推理融合
- 去分词器 ：输出自然语言与视觉原语（如坐标框、区域标记）的联合响应

这种设计的核心价值在于—— **模型既能理解文本，又能原生地定位视觉对象**，而不需要在两种能力之间做牺牲。

## 三、底层原理

这是这次发布最让我意外的一个数字。

官方公布：**一张图片最多只占384个tokens**。

做个对比——GPT和Claude处理同等分辨率的图片，通常消耗**800到1100个token**。同一张图，DeepSeek的token开销不到竞品的一半。

**他们是怎么做到的？**

答案藏在DeepSeek今年4月30日发布的技术报告里——《**Thinking with Visual Primitives（以视觉原语思考）** 》。

传统多模态模型的做法是把图片切成无数个小块（patch），每张图动辄几百上千个patch。DeepSeek的做法截然不同—— **它把视觉元素压缩成空间坐标式的原语，而不是把整张图拆成密密麻麻的图像patch**。

**具体的压缩路径是这样的**：

![](assets/2026-08-22%20-%20%E9%87%8D%E7%A3%85%EF%BC%8CDeepSeek%E5%A4%9A%E6%A8%A1%E6%80%81%E6%A8%A1%E5%9E%8B%E4%B8%8A%E7%BA%BF%E4%BA%86%EF%BC%81/a8197f2142bd238548e81c93cb24e14b_MD5.jpg)

**这个压缩机制有多惊人？**

DeepSeek实现了**7056倍的视觉压缩**。

一张756×756的图片经DeepSeek-ViT处理后生成2916个图像块token，经3×3空间压缩合并为324个token，再通过CSA（压缩稀疏注意力）机制将KV缓存进一步压缩4倍，最终仅剩81个视觉KV条目。

值得注意的是，这份技术报告发布于今年4月30日。

当时DeepSeek灰度上线了识图模式，技术报告就是解释那套能力背后的实现原理。

今天正式上线的API版本，在架构上沿用了这套“视觉原语”框架。

**384个token意味着什么？**

意味着**一张图的token成本，跟一段200-300字的文字差不多**。

你做RAG的时候，把一张图塞进去的成本，跟塞一段话差不多。

这个成本结构，让多模态能力从“奢侈品”变成了“日用品”。

## 五、一场“被社区逼出来的”发布

有一个很有意思的背景故事值得讲讲。

8月13日，DeepSeek开源了Harness——一套高度可组合的Agent运行框架。

Harness能调用终端、文件、代码和外部工具，Agent几乎什么都能做。

**但有一个致命问题：DeepSeek自己的模型没有视觉能力**。

过去一周，在DeepSeek Harness的GitHub讨论区里，“怎么让DeepSeek看图”已经成为一个高频问题。

有开发者上传图片时，Harness直接返回：**MODEL_DOES_NOT_SUPPORT_IMAGES**。

于是社区开始自己给DeepSeek“装眼睛”。

一种方案是在DeepSeek前面再接一个Qwen-VL等视觉模型，先把图片转换成文字描述。

另一种方案则尝试修改Harness，让图片先保存到工作区。

过去几天，GitHub上已经出现多个类似的vision bridge插件，开发者甚至专门做出了 `dsh-deepseek-vision` 。

**这形成了一个略显尴尬的局面**。

DeepSeek刚刚发布了一套高度插件化的Agent框架，但面对最常见的截图、网页图片和报错界面时，仍需要借用其他公司的模型。

然后，8月21日，Vision-Exp上线了。

回头看，DeepSeek对视觉能力的准备其实已经提前写进了Harness。

Harness最新rc.8版本的Release Notes明确增加了一项功能：“**增强多模态支持度，DeepSeek模型适配器支持配置启用原生图片请求**”。

与此同时， `/goal` 、 `/plan` 等命令开始支持图文输入。

**视觉模型上线当天，Harness同时发布了v0.1.1-rc.1版本，原生支持新模型**。

这种“工具链+模型”的协同节奏，说明DeepSeek在多模态上的布局是体系化的，不是临时起意。

## 六、API怎么调？

> 有些小伙伴可能会说：“DeepSeek的API文档里都是Python示例，Java怎么调？”

别担心，DeepSeek的API兼容OpenAI格式，Java调用非常简单。

下面我直接用OkHttp + Jackson给你写一个完整的示例。

### 6.1 基础调用

只需要把 `model` 参数改成 `deepseek-v4-flash-vision-exp` ：

```
import okhttp3.*;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;

public class DeepSeekVisionExample {
    private static final String API_URL = "https://api.deepseek.com/chat/completions";
    private static final String API_KEY = "你的API Key";

    public static void main(String[] args) throws IOException {
        OkHttpClient client = new OkHttpClient();
        ObjectMapper mapper = new ObjectMapper();

        // 构建多模态请求体
        String json = """
            {
                "model": "deepseek-v4-flash-vision-exp",
                "messages": [
                    {
                        "role": "user",
                        "content": [
                            {"type": "text", "text": "这张图片里有什么？"},
                            {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}}
                        ]
                    }
                ]
            }
            """;

        Request request = new Request.Builder()
            .url(API_URL)
            .header("Authorization", "Bearer " + API_KEY)
            .header("Content-Type", "application/json")
            .post(RequestBody.create(json, MediaType.parse("application/json")))
            .build();

        try (Response response = client.newCall(request).execute()) {
            String responseBody = response.body().string();
            JsonNode root = mapper.readTree(responseBody);
            String content = root.path("choices")
                .path(0)
                .path("message")
                .path("content")
                .asText();
            System.out.println("AI回复：\n" + content);
        }
    }
}
```

**这段代码的核心要点**：

- API地址和格式与OpenAI完全一致，Java开发者用OkHttp/RestTemplate都能调
-  `messages[].content`  是一个数组，可以混合传入  `text`  和  `image_url`  两种类型
- 响应解析路径是  `choices[0].message.content`

### 6.2 三种图片传入方式

多模态API支持**三种图片传入方式**：

| 方式 | 适用场景 | 特点 |
| --- | --- | --- |
| ** base64内联 ** | 本地图片、小文件 | 直接把图片编码后传入 |
| ** 外部URL ** | 网络图片、CDN图片 | 传URL即可，最简单 |
| ** Files API ** | 重复使用的图片 | 上传一次，多次引用 |

**方式一：base64内联**

```
import java.nio.file.Files;
import java.nio.file.Paths;
import java.util.Base64;

// 读取本地图片并转base64
byte[] imageBytes = Files.readAllBytes(Paths.get("/path/to/image.jpg"));
String base64Image = Base64.getEncoder().encodeToString(imageBytes);

String json = """
    {
        "model": "deepseek-v4-flash-vision-exp",
        "messages": [
            {
                "role": "user",
                "content": [
                    {"type": "text", "text": "识别这张图片"},
                    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,%s"}}
                ]
            }
        ]
    }
    """.formatted(base64Image);
```

**方式二：外部URL**

```
// 传URL即可，最简单
String json = """
    {
        "model": "deepseek-v4-flash-vision-exp",
        "messages": [
            {
                "role": "user",
                "content": [
                    {"type": "text", "text": "这张图里有什么？"},
                    {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}}
                ]
            }
        ]
    }
    """;
```

### 6.3 Files API：免费且实用

这次同步上线的**Files API**是一个值得关注的功能。

用法很简单：先把图片上传到DeepSeek平台，拿到一个 `file_id` ，后续所有请求都通过这个 `file_id` 引用图片。

**上传文件获取file_id**：

```
public class FileUploadExample {
    public static void main(String[] args) throws IOException {
        OkHttpClient client = new OkHttpClient();

        // 使用multipart/form-data上传文件
        RequestBody fileBody = RequestBody.create(
            new File("/path/to/image.jpg"),
            MediaType.parse("image/jpeg")
        );

        MultipartBody requestBody = new MultipartBody.Builder()
            .setType(MultipartBody.FORM)
            .addFormDataPart("file", "image.jpg", fileBody)
            .build();

        Request request = new Request.Builder()
            .url("https://api.deepseek.com/files")
            .header("Authorization", "Bearer " + API_KEY)
            .post(requestBody)
            .build();

        try (Response response = client.newCall(request).execute()) {
            String result = response.body().string();
            // 解析出file_id，例如 "file-abc123"
        }
    }
}
```

**通过file_id引用图片**：

```
String json = """
    {
        "model": "deepseek-v4-flash-vision-exp",
        "messages": [
            {
                "role": "user",
                "content": [
                    {"type": "text", "text": "分析这张图片"},
                    {"type": "image_file", "image_file": {"file_id": "file-abc123"}}
                ]
            }
        ]
    }
    """;
```

**Files API的核心价值**：同一张图要反复用的时候，不用每次都重新传一遍。最关键的是—— **这个API本身不收费**，只收存储费用。

### 6.4 用Spring Boot RestTemplate简化调用

如果你的项目已经是Spring Boot，用 `RestTemplate` 更简洁：

```
@RestController
public class VisionController {

    private static final String API_URL = "https://api.deepseek.com/chat/completions";
    private static final String API_KEY = "你的API Key";

    @PostMapping("/vision")
    public String analyzeImage(@RequestParam String imageUrl) {
        RestTemplate restTemplate = new RestTemplate();

        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        headers.setBearerAuth(API_KEY);

        String json = """
            {
                "model": "deepseek-v4-flash-vision-exp",
                "messages": [
                    {
                        "role": "user",
                        "content": [
                            {"type": "text", "text": "描述这张图片的细节"},
                            {"type": "image_url", "image_url": {"url": "%s"}}
                        ]
                    }
                ],
                "max_tokens": 1024
            }
            """.formatted(imageUrl);

        HttpEntity<String> entity = new HttpEntity<>(json, headers);
        ResponseEntity<String> response = restTemplate.exchange(
            API_URL, HttpMethod.POST, entity, String.class
        );

        return extractContent(response.getBody());
    }

    private String extractContent(String responseBody) {
        try {
            ObjectMapper mapper = new ObjectMapper();
            JsonNode root = mapper.readTree(responseBody);
            return root.path("choices").path(0).path("message").path("content").asText();
        } catch (Exception e) {
            return "解析失败：" + e.getMessage();
        }
    }
}
```

## 七、应用场景

DeepSeek官方在发布时同步展示了三个应用场景：

### 场景一：商业定制PPT生成

在Agent框架下生成商业定制PPT，用户可以直接提出要求：

> “帮我做个西藏攻略的ppt，藏南+藏北，一个月，自驾游，我是高端定制游，只做私人服务，和别的旅行团不一样，核心调性：野性、原始、探索感——不是常规打卡路线，是深入无人区级别的体验。视觉风格要大气、粗粝、有力量感，拒绝小清新和网红风。ppt要发送给高净值客户，要足够大气、野性、高端美观且最后给到三种真实定价方案，所有配图使用真实摄影图片风格（实拍质感）。”

模型会理解“野性、原始、探索感”这种抽象的风格要求，输出包含真实配图、三种定价方案的高端定制方案。

### 场景二：网站二次创作

对DeepSeek Harness官网进行未来主义风格重构，运用“**黑蓝深海、玻璃UI、ASCII原子像素**”等视觉要素，经过长多轮交互完成创意设计。

### 场景三：前端动态特效

基于“一群可爱的3D黏土小怪物加入跃动复古舞池派对”的创意提示，直接制作黏土怪物风格动态特效的前端Mini Demo。

**这些场景的共同特征是：模型不仅要“看懂”图，还要“理解”风格、“执行”任务、“输出”成品**。这正是DeepSeek多模态模型的核心价值所在—— **它不是给你一个“看图说话”的玩具，而是给Agent装上了一双能理解世界的眼睛**。

## 八、定价

DeepSeek这次在定价上也延续了一贯的风格—— **高性价比**。

图片会先转换为token再计入用量，**单张图片最多按384个tokens计算**。

计价与V4-Flash**完全一致**。

根据官方公布的定价表：

| 计费场景 | 价格（元/百万tokens） |
| --- | --- |
| 输入（缓存命中，空闲时段） | 0.05元 |
| 输入（缓存命中，高峰时段） | 0.10元 |
| 输入（缓存未命中，空闲时段） | 1.5元 |
| 输入（缓存未命中，高峰时段） | 3.0元 |
| 输出（空闲时段） | 4.5元 |
| 输出（高峰时段） | 9.0元 |

**据此计算，高峰时段用该模型理解一张图片的最高价格为0.001152元**。

一张图一分钱，按高峰时段满打满算也才**1厘钱**。有开发者实测整个任务只消耗了**384个token**，**成本可以忽略不计**。

## 九、优缺点

### 优点

**1. 纯文本能力零妥协**在Agent、推理、世界知识等纯文本基准上，Vision-Exp与V4-Flash正式版完全持平。换模型不降文本能力。

**2. 多模态Agent能力接近Opus-4.8**在4项多模态Agent评测中与Opus-4.8打成2胜2负。ApexBench从26.2提升到36.5，提升幅度接近40%。

**3. Token效率极高**一张图最多384个token。DeepSeek实现了**7056倍的视觉压缩**，不到竞品的一半。

**4. 价格极低**一张图最高0.001元，实测35秒任务几乎零成本。

**5. 调用方式灵活**支持Chat Completions、Messages、Responses三种格式，支持base64、URL、Files API三种图片传入方式。

**6. 1M超长上下文 + 思考模式**延续100万token超长上下文窗口，最大输出384K，支持思考和非思考两种模式。

### 缺点

**1. 实验性质，不建议生产环境直接使用**官方明确标注为“Exp”实验版本。正式版上线时间暂未公布。

**2. 部分任务与Opus-4.8仍有差距**在NL2Repo（57.7 vs 69.7）等基准上差距依然明显。

**3. 目前只有Flash版本**多模态能力目前只开放给V4-Flash，Pro版尚未跟进。

**4. 多模态生态刚刚起步**工具链的完善需要时间。
