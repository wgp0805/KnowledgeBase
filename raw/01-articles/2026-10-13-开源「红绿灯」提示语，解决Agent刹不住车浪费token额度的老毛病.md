# 开源「红绿灯」提示语，解决Agent刹不住车浪费token额度的老毛病

> **来源**: 人人都是产品经理  
> **链接**: https://www.woshipm.com/ai/6477460.html  
> **抓取日期**: 2026-10-13  
> **相关性评分**: 1.0

> Agent 从不会主动说做完了，每轮都抛来一批新的优化清单，一个半小时的需求拖成一下午。作者手搓了不到三百字的进度提示语，用绿黄红三色收尾：绿灯只记搁置项，黄灯给带证据的后续计划，红灯存档结束，额度也省下来了。

![](https://image.woshipm.com/2024/09/30/d9fb349a-7f18-11ef-bb45-00163e142b65.png)

我给Agent每次对话结尾加了三个emoji，把额度省下来了，也终于可以不需要被模型暗示把任务无限往下跑了。

现在是凌晨两点，我盯着屏幕上的Claude Code和Codex窗口发呆。本来我是想做一个逆向做一个vibe coding小工具合集，本来是不缺额度的，但是每次对话都刹不住车。

我发现自己已经坐了三个小时。最开始的那个需求，第一个小时就做完了。后面两小时在干嘛呢。在处理 Agent 给我列的优化清单。每改完一批，它又给新的一批。

![Image](https://image.woshipm.com/wp-files/sha256/85/52/8552878c9b7d9ce2e0c61d027de77f5ebc79f2d6d53682de7348a32c69cc1cfc.png)

这个建议虽然也不是新的东西，但是开了多任务的情况下非常非常容易被拉着盲目走。

而且类似这种二选一的选项有的时候还是错的，我是明确知道数据的错误是发生在飞书日报里的，但是更多时候是不清楚的，模型说啥我点啥。咋一看Agent给的建议，每条都挺有道理的。代码确实可以再重构一下，测试确实可以再补几个，文档确实可以再更新一版。于是就顺手说「行，搞吧」。然后它又做完了，又给你列一批新的。

**如此反复，一个本来半小时能搞定的需求，不知不觉变成了一个下午。**

**前两天跟一个朋友吃饭聊到这个，他放下筷子说了一句，Agent推荐下一步做什么，这个功能本身就是认知陷阱，它会让你永远觉得任务没完。**

对，就是这个感觉。这个感觉在凌晨3点的时候在我脑子里炸开了。

想要在每个Agent每个AI每个对话都可以自动生效，那就不依靠skill，手搓一个提示语再加一个hook这样我们就可以脱离认知陷阱。Agent是永远不会主动告诉你「做完了」。

我有一段时间就不停在发一句，**这个对话时可以归档还是下一步了**

我花了一个小时迭代优化出来了不到三百字的提示语。毕竟每次对话生效的话要省额度，还不能增加查看的难度。

> ## 进度提示语
> 
>  
> 
> 开工第一轮用一行钉住原始需求：
> 
> 目标：A、B、C。
> 
> 此后每轮只对照这份清单干活，清单只在我追加需求时才变。
> 
> 每轮回复最后一行是进度条，三种状态：
> 
> ![🟢](https://s.w.org/images/core/emoji/16.0.1/72x72/1f7e2.png) 还差：B、C｜搁置：X —— 原始需求有未达项，任务继续。顺手发现的改进只记进搁置，一行以内，先放着。
> 
> ![🟡](https://s.w.org/images/core/emoji/16.0.1/72x72/1f7e1.png) 原始需求已全部达成。以下可做成下一轮 Plan —— 每项都附了证据。超出项能构成有明确目标和验收标准的后续计划，落盘成 plan/handoff 文件给路径，等我决定是否启动。
> 
> ![🔴](https://s.w.org/images/core/emoji/16.0.1/72x72/1f534.png) 原始需求已全部达成，以下仅供存档 —— 每项都附了证据。超出项零散、不构成可执行计划，压成三行以内存档清单，结束。
> 
> 黄灯与红灯的判定：超出项能否串成一个有清晰目标的 Plan？
> 
> 能 → ![🟡](https://s.w.org/images/core/emoji/16.0.1/72x72/1f7e1.png)，
> 
> 不能 → ![🔴](https://s.w.org/images/core/emoji/16.0.1/72x72/1f534.png)。
> 
> 转黄/转红之后都停手，等我下指令。
> 
> 我追加需求：更新目标清单，进度条回到 ![🟢](https://s.w.org/images/core/emoji/16.0.1/72x72/1f7e2.png)。

这是我用了最初的两态版本之后踩出来的坑。一开始只有绿灯和红灯，红灯下面的「超出范围」区会列一堆东西。

来看一个真实场景。

![Image](https://image.woshipm.com/wp-files/sha256/6f/24/6f24092d085595e185bb6c1053b0ef3b43cf0dec51027b82ec12f372a649d23b.jpg)

看到那个红灯了吗，![🔴](https://s.w.org/images/core/emoji/16.0.1/72x72/1f534.png) 下面列了三件事：PR 合并等我确认、远端分支未删、生产迁移的后续步骤。

我看完之后当时就懵，这些东西有做过吗？

新开了一个Agent对话查了一圈才告诉我，三件一件都没做。

在只有红灯的世界里，列出来的这些待办，就跟模型输出的千字长文一大堆无关紧要的建议混在一起。我们自己还要离开对话再分一遍，这不就又回到老路上了吗。

所以我加了黄灯。

**黄灯就是，你要的活我做完了，但剩下这些模型给的建议能构成一个完整的下一步计划。这个提示语会自动帮你做出一个完整计划，我们可以快速浏览决定要不要启动。**

**红灯变成了，你要的活我做完了，剩下的零零碎碎，不值得专门开一轮，存个档就行。**

来看一个真实的黄灯场景。

![Image](https://image.woshipm.com/wp-files/sha256/a8/3e/a83e6b8f18dab8c90b5c6e08910426166ef3856cfc8e5e59c304960608787fde.jpg)

老粉应该都知道，GoodCase .ai是我做的一个AI提示语案例库，里面有1700多条案例，我一条条手工打过分，再用 Claude、Codex和DeepSeek三个模型做自动评估来校准，所以我们可以比较准确地测评AI视频生成的质量。

我直接把最后的结论发出来给大家看看，如果要做AI视频质量评估的话可以参考用这三个模型对应的档位。

![Image](https://image.woshipm.com/wp-files/sha256/a7/fe/a7fec297e57907c9a81699be318854fdec1c5810e5d0fbac278d33a8ba632585.jpg)

这个对话的结尾就亮了黄灯。

这个对话没停在一个「超出范围」的清单上，直接帮我写了一份 37 行的后续计划。我可以跟模型那一大堆没啥用的输出完全区分开，就集中在判断下一步要跑还是不要跑就行了。

子代理也一样。我的 Sonnet 子代理跑完一个数据库迁移的验证之后，回复末尾一行绿灯。

![Image](https://image.woshipm.com/wp-files/sha256/72/31/7231557f2b0798b1bc803c77ce49d2e6e307b4bb2b3e5c02132b408818dc1f1f.jpg)

以前子代理给我的回复是什么呢，「已完成数据库迁移验证，建议后续可以 1) 优化索引策略 2) 添加回滚测试 3) 更新文档……」

**你根本分不清哪些是你要它做的、哪些是它自己额外加的。**

现在只看绿灯的最后一行就够了。

这个机制不止写代码能用。

我有一次整理积压的旧会话，让 Agent 把十几个过期对话里的残留事项归类处理。做完之后它亮了黄灯，列了三个需要我拍板的决定，附了一份 63 行的剩余事项解决计划。

![Image](https://image.woshipm.com/wp-files/sha256/17/e9/17e9c5590ff49a853bd6b1b81e53e56e16baa644a8fc4ddaaf8e30c67c7c9c67.jpg)

写代码、整理会话、配运维，什么类型的任务都是同一套规则，同一行 emoji。

用了两天之后，还是有几个很明显的变化。

心理上的。每个任务开始有「完成的时刻」了。

以前像一条河，你不知道对岸在哪，只能一直往前淌。现在有终点线。绿灯是还在跑，黄灯红灯都是停下来处理一下。你一天跟 Agent 协作十几个任务的时候，这种确定感特重要。

效率上的。黄灯帮你整理「接下来做什么」。

以前得从Agent的一堆建议里自己挑，或者模型说啥我点啥，现在它直接做了整合和去重，而且因为区分了黄灯和红灯，出来的计划质量比以前好得多。

你想想，现在所有人都在卷怎么让 Agent 更强。

更大的上下文，更多的工具，更长的自主运行时间。

也没解决怎么让它停下来啊。

人类造了汽车，花了几十年才发明安全带。

每一种强大的能力背后，都跟着一个制动装置。

Agent现在一口气做100个小时的任务都不算啥稀奇了，700多篇数学论文写出来了，把1/3紫外线没观察到的天空也都还原了，能力在疯涨，但我们依旧可以把判断的权利留给自己，装个红绿灯就挺形象的。
