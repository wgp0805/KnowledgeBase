# 国产开源 Pi Agent 桌面端神器来了：项目、会话、Diff、多 Agent，一个窗口全管住！！

**大家好，我是冰河~~**

先说个真实的场景。我平时写代码会同时开着 Claude Code 和 Codex，一个负责改前端，一个跑后端测试。两个窗口并排，中间还得夹一个编辑器看 Diff。

如果哪个任务需要交叉验证，我就得在两边之间复制粘贴，或者干脆自己手动串一遍。一天下来，真正写代码的时间可能不到一半，剩下的都花在“找窗口”和“搬信息”上。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/fb2058f55ddd202ab745245279bdc36d_MD5.png)

PI-Desktop 是我最近试的一个桌面端，国产开源，Windows、macOS、Linux 都能装。

它没有发明什么新技术，也没有自带模型，做的事情说白了就是：**把原来散在几个窗口里的东西，塞进一个窗口里**。听起来不惊艳，但用过之后，我确实把终端数量从三个减到了一个。

## 它不聪明，但它有秩序

很多人第一次打开 PI-Desktop 会有点失望，因为它本身不提供任何模型能力。你得自己接 API，云端、本地、自建网关都行，它只负责把接口对上。

它的 Agent 运行时来自开源 Pi 项目，桌面这一层做的是会话管理、权限、插件和多 Agent 调度。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/2bf7f9bd8193d35c2d31e179d34f9d98_MD5.png)

换句话说，它不负责“让 AI 变聪明”，只负责“让 AI 干活的时候，你别到处找东西”。这个定位反而让我觉得踏实，因为模型能力是别人的事，工作区秩序是自己的事。

## 会话不再是一次性的

以前用命令行 Agent，最大的问题是会话没有归属。一个任务做完，关掉终端，下次再想接着聊，得从头讲背景。

PI-Desktop 把会话挂到项目下面，左边一栏能看到每个项目最近干了什么，常用的置顶，暂时不用的归档，还能从旧会话开分支。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/734f9679bf388a18713600dcd14f1b07_MD5.png)

我现在的习惯是：一个仓库对应一个项目，项目里按任务开几个会话。切项目的时候不用重新解释上下文，切回来还在。

Agent 跑任务时我突然想到别的要求，可以先排队，等它把手头的处理完再接着跑。

这个“排队”看起来是个小功能，但用过之后，我发现自己不用再盯着它跑完才能干别的了。

关掉应用再打开，Session 还在。项目还做了检查点，中断之后会尽量恢复现场。但我不敢完全依赖它，重要代码该 commit 还是 commit，这个习惯没变。

## 改了什么，能直接看

这是我觉得比命令行舒服的地方。Agent 改完代码，Diff 直接在右侧面板显示，命令输出、文件内容、执行记录放在一起。

以前我得切到编辑器里看 Diff，再切回终端看它跑了什么命令，现在一屏就能对完。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/35c5da7541463abf2b3a51d1dfb9b991_MD5.png)

会话里会留下完整的工具调用记录，长会话右侧有缩略导航，可以快速跳到前面的消息。上下文占用和 Token 用量也显示在旁边，虽然这些数字主要用来判断这次调用贵不贵，但至少不用自己估。

## 三种干活方式，我按场景切换

PI-Desktop 把执行方式分成三种，我用下来大概是这么分的：

改小问题、需求明确的时候，直接用 Agent，让它读代码、改文件、跑测试。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/6aafd7bac68466512db5d451495d30ee_MD5.png)

需求比较模糊，或者要动的文件多，先用 Plan。它会先研究仓库，给一份计划，我看完确认了再让它动手。

这个环节救过我几次，有一次它理解的方案和我想要的差很远，好在只是计划，改起来没成本。

Goal 我用得少一些，一般是目标清楚但中间步骤懒得交代的时候用。把验收条件写明白，路线让它自己选。

三种方式都走权限层，改文件、跑命令、调工具都要过一遍。每个会话能自主到什么程度，可以单独调，这点比全局开关灵活。

## 多 Agent：能拆才拆

Subagent 我主要用来做并行调查。比如一个任务要同时看前端和后端的实现，就让两个 Subagent 分头查，各自用独立上下文，查完把结论交回主 Agent。模型可以不一样，设置里能控制哪些模型允许被 Subagent 调用。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/2510ac9bcfb07fe1357ed5a991f65469_MD5.png)

Session Orchestrator 支持一个主会话带多个 Worker，每个 Worker 有完整会话，能单独看也能追加任务。听起来很强，但我实际用得不多。

改一个小文件拆成三个会话，检查成本比收益高。真正适合拆的是那种工作项彼此独立、能同时推进的任务，比如一个大仓库里两个模块互不依赖的改造。

## 插件是个亮点，也是个短板

已经有一些能直接用的插件：Token 统计、SSH 管理、Git Lens、浏览器自动化、终端、Markdown 笔记。

插件能加面板、右侧视图、悬浮组件、主题，也能接 Skills、MCP Server 和后台服务，插件之间还能传消息。市场里能装， `.piplug`  包也能导，仓库里有模板可以照着写。

但说实话，这块目前还比较薄。能用的插件数量有限，质量参差不齐，而且插件本身也是代码，权限审批不等于沙箱隔离，来源不明的我基本不装。它能不能长起来，取决于后续维护者愿不愿意持续投入。

## 模型和数据：都在自己手里

不同会话可以用不同模型，同一会话里也能换，换完不用重开会话讲背景。上下文窗口、最大输出、推理开关、温度都能单独调，自定义模型 ID 和自建网关的 Endpoint 也能填。

![](assets/2026-11-07%20-%20%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E7%AB%AF%E7%A5%9E%E5%99%A8%E6%9D%A5%E4%BA%86%EF%BC%9A%E9%A1%B9%E7%9B%AE%E3%80%81%E4%BC%9A%E8%AF%9D%E3%80%81Diff%E3%80%81%E5%A4%9A%20Agent%EF%BC%8C%E4%B8%80%E4%B8%AA%E7%AA%97%E5%8F%A3%E5%85%A8%E7%AE%A1%E4%BD%8F%EF%BC%81%EF%BC%81/163e5327fbab9322c3a38b42cdb8444a_MD5.png)

数据默认都在本机，API 凭据放在系统钥匙串，模型请求不强制走它的云端，仓库也写了没有遥测。不放心的可以源码部署，让 AI 帮你审一遍。

其他工具留下的本地会话也能导入，不用一次全迁过来，先挑几个试试水。

## 装起来不麻烦

Releases 里下安装包就行，不用配 Node、pnpm、Rust，那些是从源码跑才需要的。

macOS 分 Apple Silicon 和 Intel，Windows 是 x64，Linux 有 x64 和 ARM64，glibc 要 2.35 以上，Ubuntu 22.04+、Debian 12+、Fedora 36+ 都在支持范围里。

装完接上模型，打开一个仓库就能用。第一次建议拿测试仓库练手，把权限提示、Diff、会话记录都过一遍，看看合不合自己的习惯。

## 我的感受

PI-Desktop 解决的是“工作区秩序”的问题，不是“模型能力”的问题。如果你只用一两个 Agent，任务也不复杂，它带来的提升有限，没必要为了换桌面端改自己的工作流。但如果你像我一样，同时开着好几个 Agent，经常在窗口之间搬信息，它会让你舒服不少。

它现在还是 Early Preview，接口和行为都可能变，不适合当唯一的生产工具。但作为一个“把零散环节收拢”的尝试，方向是对的。至于插件生态能不能撑起来，得再看一段时间。
