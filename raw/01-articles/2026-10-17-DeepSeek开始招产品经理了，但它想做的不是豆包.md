# DeepSeek开始招产品经理了，但它想做的不是豆包

> **来源**: 人人都是产品经理  
> **链接**: https://www.woshipm.com/ai/6480007.html  
> **抓取日期**: 2026-10-17  
> **相关性评分**: 1.0

10 月 16 日，关于 DeepSeek 的两条消息几乎同时在朋友圈里刷屏。

一条来自澎湃新闻：DeepSeek 把负责 Agent 运行时的 Harness 团队，和 Web、App、Platform 三个团队合并，成立了「产品部」，统管公司全部的产品、设计和研发。负责人是今年 3 月才加入的崔添翼，他本人向记者确认了消息。

![](https://tu.aixq.cc/wp-content/uploads/2026/10/DeepSeek-01-0879130bcd.jpg)

另一条来自公众号「赛博禅心」：新成立的产品部正在急招产品经理和设计师，连高级别的产品经理也在招。

对一家长期被当作「研究机构」看待的公司来说，这两条消息放在一起，信号已经很明确了：DeepSeek 要开始认真做产品了。

但我想多问一句：它要做的，真的是我们熟悉的那种「产品」吗？

### 01 一个很「素」的 App，靠模型把用户留了下来

2025 年 1 月 DeepSeek App 上线时，官方的功能介绍只有寥寥几条：账号登录、跨端同步聊天记录、联网搜索和深度思考、上传文件提取文字。末尾还特意强调，完全免费，没有广告，也没有应用内购买。

随后就是 R1 带来的春节出圈。App 一度登顶 157 个国家和地区的 App Store，据 QuestMobile 统计，上线次月月活就突破了 1.8 亿。

然后呢？之后一年多，这个 App 的变化少得惊人。

直到 2026 年 4 月，DeepSeek 才第一次在输入框上方做了「快速模式」和「专家模式」的分层。5 月，又有消息说它在灰度测试一个新功能：用关键词搜索自己的历史对话。

「搜索历史对话」在产品经理眼里，几乎算是聊天类产品的基础设施。一家头部 AI 公司到了第二年才灰度这个功能，足以说明过去它的精力放在了哪里。

稳定性也一直是老问题。今年 5 月 8 日，不少用户又刷到了熟悉的「服务器繁忙」；7 月 22 日，联网搜索整整挂了将近 4 个小时。

用户数据是另一面镜子。QuestMobile 今年 7 月发布的半年报告里，国内 AI 原生 App 第一梯队是豆包、千问、DeepSeek，月活分别约 3.82 亿、1.67 亿和 1.30 亿。千问同比增长高达 5792.9%，硬生生把 DeepSeek 挤到了第三。

但同一份报告里还有个很有意思的数字：DeepSeek 使用时长 10 分钟以上的用户占比是 30.0%，比豆包的 27.5% 和 Kimi 的 26.1% 都高。

用户黏、重度用户多，产品却很素。这说明大家是冲着模型来的，不是冲着产品来的。

模型领先时，这不是问题；当豆包和千问把模型差距追近、又在产品和分发上全面压上来，产品层的欠账就会一笔笔显形。

### 02 这次调整的本质：Agent 团队「收编」了客户端

很多人把这次调整理解成「DeepSeek 新建了一个产品团队」。我觉得更准确的说法是：Agent 团队把客户端收编了。

注意合并的方向和挂帅的人。Web、App、Platform 本来就在，这次是和 Harness 团队打通，由 Harness 的负责人统管。这意味着网页端、App 和开放平台，今后都要围绕 Agent 来重新组织。

DeepSeek 内部有个很简洁的公式：Model + Harness = Agent。所谓 Harness，指的是模型参数之外的全部工程，包括上下文管理、工具调用、异常恢复、权限拦截、状态回滚等等。模型负责「想」，Harness 负责让它真的能「干活」。

这支团队过去半年的节奏很快。3 月崔添翼加入；6 月他还在社交平台上说，作为新成立的部门，Harness 组非常缺人、他每天都在面试；8 月 DeepSeek Harness（社区简称 DSH）开放内测并开源，开源六天拿下 16.5 万星，如今已超过 25 万星；10 月 3 日的新版本，甚至加了一个实验性的 Claude Code Mods 兼容层。

有个细节特别值得产品人琢磨：在 DSH 的架构里，桌面客户端只是一个普通插件。

我们熟悉的逻辑是，App 是主体，Agent 是 App 里的一个功能，豆包、元宝基本都是这么长出来的。DeepSeek 恰好反过来：Agent 运行时是主体，客户端只是它的一个外壳。

这次把 Web、App 和 Harness 合并，就是把这套思路从一个开源项目，推广到整个公司的产品线。

### 03 招聘 JD 里，藏着它对「产品」的新理解

要看一家公司怎么理解产品，最好的材料不是发布会，是招聘 JD。这次产品部放出的岗位有四类：AI 产品经理、Agent Harness 产品经理、产品设计师，以及项目经理实习生。

先看 AI 产品经理。这个岗位负责网页端、App 和开放平台的产品策略，从规划、功能设计一直推到上线。要求里出现了几个以前在 DeepSeek 招聘里很少见的词：产品品味、用户洞察、在意日常交互的细节，还有把用户体感、产品直觉和行为数据放在一起做判断的数据意识。

这几乎就是一份标准的 C 端产品经理画像。所以如果你问「DeepSeek 是不是要重视 C 端体验了」，这个岗位就是最直接的答案：是的。

再看 Harness 产品经理，这个岗位更能体现 DeepSeek 的个性。它要规划 Harness 的产品路线图，还要定义一个北极星指标：「Agent 是否真的在更多场景下更深入的帮助到更多的人」。

拆开看，这是三个维度：场景的广度、帮助的深度、覆盖的人数。里面没有日活，也没有使用时长。

它对人的要求也很「新」：会 vibe coding，但不一定要技术背景；懂 Agent Loop、Tool Use、MCP、Memory、Subagent 这些基本机制；对 Context Engineering 和 Harness Engineering 有一手实践；会做问卷、访谈、A/B 测试和灰度，并用统计方法分析；还要能用英文和开源社区书面沟通。

还有一个细节。JD 点名要求候选人是这些产品的高强度用户：Claude Code、Cowork、Codex、Cursor、OpenCode、GitHub Copilot、Manus、OpenClaw、Hermes。清一色是海外或面向全球市场的 Agent 产品，TRAE、Qoder、WorkBuddy 这些国内开发者常用的工具一个都没出现。

这至少说明，DeepSeek 给自己找的参照系，是全球最前沿的 Agent 工具，而不是国内的 AI 助手 App。

设计师岗位同样值得一看。要求对色彩、构图、版式、动效有判断，还要能把判断讲清楚、落下去；熟练使用 Figma 和 AI 设计工具，最好能 vibe coding 把设计直接做成原型。一家过去连「快速 / 专家」分层都要做一年多的公司，开始认真在意「好不好看」了。

最后是项目经理实习生：在 AI 的帮助下跟进需求、Bug 和反馈，排期、追进度、开会、写纪要。要求每周至少 5 天在北京，持续 6 个月以上。

其实早在 6 月底那次「所有部门规模至少扩大一倍」的大招聘里，就已经出现了 AI 产品运营（体验与服务方向）这样的岗位。这次产品部成立，是把这些零散的信号收拢成了一个正式的组织。

### 04 让一个量化工程师来管产品，意味着什么

崔添翼的履历，和「产品经理」几乎不沾边。

![](https://tu.aixq.cc/wp-content/uploads/2026/10/DeepSeek-02-e9c7d76f58.jpg)

本人照片，来源网络

他是 90 后，高中时写的《背包问题九讲》成了中文算法竞赛圈的入门教材；保送浙大后拿过 6 枚 ACM-ICPC 亚洲区域赛金牌；毕业后在顶级做市商 Jane Street 的香港办公室写了近九年 OCaml；2022 年和前同事联合创办对冲基金 TSY Capital；今年 3 月加入 DeepSeek。

浙大出身、量化交易起家，这条线和梁文锋高度重合。DeepSeek 把产品部交给一个系统架构师，而不是一个资深产品人，这个选择本身就是一种表态。

这种背景塑造出的产品，DSH 就是样本。它的内核是一个只有两三千行代码的微内核，核心理念是「一切皆插件」，任何功能注册时都必须同时声明怎么卸载。连 Agent 的主循环，都只是一个可以随时替换的插件。

![](https://tu.aixq.cc/wp-content/uploads/2026/10/DeepSeek-03-117f940170.jpg)

效果很惊艳。Composio 用同一个模型、30 个真实 SaaS 任务做对比，DSH 的完成率略高于 Claude Code，平均每个任务只消耗 8.8 万 Token，大约是后者的七分之一。

但边角很粗糙。有开发者晒账单，因为并发派生子 Agent 打碎了 KV Cache 前缀，同一个任务的成本比竞品高出十倍；有人两小时从零做出原型，接下来却花了好几个小时也没能把 Bug 修收敛；还有人遇到 Windows 路径解析出错，导致整盘文件被静默删除。

内核惊艳、边角粗糙，这是工程师做产品的典型样子。

而产品部要补的，恰恰就是这些边角：新手引导、出错时的提示、成本的可见性、默认的安全兜底。这些不是架构问题，是体验问题，正好是产品经理和设计师的本职工作。

打个比方，发动机已经造好了，现在缺的是车身、座椅和仪表盘。

不过崔添翼对「补体验」也有自己的边界。他在国庆那次更新后公开说过，如果只是照着 Claude Code 或 Codex 抄一个，做出一个技术理念和用户体验都差不多的产品，那一定不算是在推进 AGI。

换句话说，产品部的使命不是追平别人，而是做出别人没有的东西。

### 05 别急着说「从技术驱动转向产品驱动」

接下来几天，你大概会看到很多类似的标题：DeepSeek 从技术驱动转向产品驱动。

我的看法是，这个判断只对了一半。更准确的说法是：技术驱动的产品化。产品是在为技术路线服务，而不是反过来。

证据就摆在那里。负责人是工程师，而不是产品人；崔添翼把 Harness 组的目标定义为从 Harness 的角度推进 AGI；据 Z Finance 的梳理，梁文锋把编程工具看作通往 AGI 路上的「阶段性产物」。在 DeepSeek 的叙事里，产品从来不是终点。

所以有些事，我建议别指望。比如豆包式的全渠道投放和补贴拉新，围绕娱乐、陪伴做的内容生态，或者一个什么都能干的超级 App。至少从目前的组织和 JD 来看，这些都不在它的路线图上。

更可能发生的是另一些事。App 和网页端会越来越像一个 Agent 的入口，工作类、编程类任务的体验会被优先打磨，那 30% 的重度用户会最先感受到变化。

同时，这场转身本身也充满张力。

第一层是战略和战术的错位。一边认为工具只是阶段性产物，一边又在战术上把最多的兵力押在 Harness 上。Z Finance 把这称为典型的技术公司悖论，我觉得说得很准。

第二层是组织的稀释。DeepSeek 原本是一支一百多人的精干团队，6 月喊出所有部门至少扩大一倍，9 月一口气放出约 150 个工程岗位，这次产品部的扩招据说也没设硬性上限。小团队、高密度的研究文化，能不能扛住这种扩张速度，是个真问题。

第三层是节奏的冲突。研究的节奏是憋大招，产品的节奏是每周迭代、每天看数据。JD 里把「和研究员深度协作过」列为加分项，本身就说明这两种节奏怎么磨合，DeepSeek 自己也还在摸索。

所以回到开头那个问题：DeepSeek 是不是要重视 C 端产品体验了？答案是，是，但它理解的 C 端，和豆包、元宝不是一回事。

### 06 写给产品经理：这份 JD 是一面镜子

不管你想不想去 DeepSeek，这份 JD 都值得每个产品经理认真读一遍。因为它几乎就是 AI 时代产品经理能力模型的一个切片。

![](https://tu.aixq.cc/wp-content/uploads/2026/10/屏幕截图_17-10-2026_143041_app.mokahr.com_.jpg)

最显眼的是「深度用户」这个要求。不是「了解」，不是「关注」，而是自己用过、拆过，对模型的能力边界和不同产品的体验差异有真实体感。这件事没法靠看文章补，只能靠一个个小时泡在产品里。

其次是动手能力。不管是产品经理还是设计师，都被要求能在 AI 辅助下自己做原型，会 vibe coding。以前「我有个想法，找研发排期」的流程，在这里被压缩成了「我有个想法，今晚先做个能跑的版本」。

再往下是对 Agent 机制的理解，以及直觉和数据并用的判断力。上下文怎么管理、工具怎么调用、记忆怎么设计，这些过去是工程师的话题，现在成了产品经理的必修课。

反过来看，JD 里没写什么也很有意思。写 PRD、画原型图、拉会对齐，这些我们熟悉的产品经理日常，一个字都没提；项目推进则交给了「在 AI 帮助下」工作的实习生。

这并不是说这些工作不重要了，而是它们正在变成默认能力，甚至被 AI 接管，不再值得写进核心要求。

给国内产品人一个具体建议：别只盯着 JD 点名的那几个海外工具。Claude Code、Codex 当然值得上手，但 TRAE、Qoder、WorkBuddy 这些国内产品同样能帮你练出「拆过」的体感。

更好的练法是挑一个真实任务，分别丢给 DeepSeek、豆包、千问，再丢给一个 Agent 工具，把每一步的体验差异记下来。这份笔记，可能比你简历上的任何一个项目都更能说明你懂 AI 产品。

### 07 怪哥碎碎念

过去一年半，DeepSeek 用自己证明了一件事：模型足够强的时候，产品可以很素，用户照样会来。

接下来它要证明的是另一件事：当模型优势不再碾压，一群工程师能不能把「好用」也做成核心竞争力，而且是用一种和豆包、千问都不一样的方式。

「产品部」三个字出现在 DeepSeek 的组织架构里，本身就是一个信号。它说明在这家公司内部，「模型即产品」的时代结束了。

至于「Model + Harness = Agent」这个公式能不能跑出一个普通人也愿意每天打开的产品，我们拭目以待。
