## 01 原型图绘制skill

做产品经理的第一大痛点，绝对是画原型。

很多同学做原型，一打开 Axure 或者 Figma 就开始头大。一点点拖组件、对齐像素、连交互线、配交互弹窗，折腾大半天。

最崩溃的是什么？

业务方随口说一句这里少了个筛选维度，支付流程再加个优惠券抽屉，好家伙，整套页面动线推倒重画，一下午时间全搭进去了，极其折磨。

这个 Skill 的厉害之处在于，它坚决不让你在组件排版上浪费生命。

你完全不用再去死磕那些现成的组件库，直接把业务场景、用户角色和大白话功能丢给它。它会自己在本地解析信息架构，自动补齐页面层级与组件状态。

更牛的是，它生成的不是死板的静态截图，而是直接在本地吐出一套能跑的自适应 HTML 交互原型。直接在浏览器里点开，抽屉能拉开，滑块能拖动，弹窗能关闭。

拿这个去跟业务方和研发对齐动线，对方点两下就全明白了，根本用不着开会扯皮半天。

## 02 框架图与业务流程绘制skill

产品经理理不清业务链路，评审会就是灾难现场。业务稍微复杂一点，比如涉及了买家、卖家、运营、仓储好几个角色，还有退款、超时、拒收一堆异常分支，直接懵圈了。

很多产品经理习惯在文档里写几千字密密麻麻的文字，但是，文字描述再严密，也抵不上一张结构清晰的流程图。

这个 Skill 就是专门用来帮你给业务理脉络的。

不管多混乱的业务逻辑，你只要把参与角色、主干步骤和已知的几个异常情况告诉它。它会自动帮你提炼出标准的泳道逻辑，直接转化成规范的图表语言。

不仅逻辑严密，而且支持直接生成draw.io 矢量图代码。

这里有个依赖我得提前说一下，因为生成的是标准的 draw.io 矢量图，电脑上需要先安装好 draw.io 软件，或者在 Obsidian 里面装上 Diagram plugin 插件，这样在本地双击就能直接打开、直接二次拖拽修改。

安装方法，给 WorkBuddy 发送命令，

> 帮我把 GitHub 仓库 pmlaowangba-lab/laowang-diagram 安装到 .agents/skills/并可以在专家·技能·连接器中展示

实测提示词如下，

> 用 $laowang-diagram，绘制一张【电商退货退款】跨角色泳道流程图。
> 
> 涉及角色，买家、商家、平台客服、仓储系统。
> 
> 必须包含，正常退货验收流程、卖家超时未处理自动退款、商品验收不合格拒收并引发客服介入 3 条分支逻辑。输出为规范的drawio图，并提供架构分层说明。

## 03 大厂标准 PRD 生成skill

如果说画原型是体力活，那写 PRD 就是很多产品经理的心头大患。

不少产品经理写出来的需求文档，简直漏洞百出。光写了正常路径下点击按钮跳到哪，遇到弱网怎么办？用户重复快速点击怎么防刷？并发扣库存冲突怎么提示？页面权限失效怎么降级？

研发拿到这种文档，一边写代码还得一边骂娘，不仅工期无限延期，上线之后全是线上 Bug。

这个 Skill，就是老王按照大厂最严苛的交付规范训练出来的。

它的核心逻辑非常霸道，只要你给它一个基础功能点，它会启动自带的工业级自检机制。它会自动把前置条件、后置条件、字段字典规则、异常分支处理以及数据埋点字典，全给你一层层递归补全。

但是它不能直接替代你的业务，业务的真实细节，还需要你来手动加入，毕竟业务的信息AI是无法获取到的，也没有参考资料。

安装方法，给 WorkBuddy 发送命令，

> 帮我把 GitHub 仓库 pmlaowangba-lab/laowang-prd 安装到 .agents/skills/

实测提示词如下，

连边界值限制和埋点事件名都给你起得整整齐齐。

研发看完文档甚至想给你递烟，因为他敲代码的时候不需要停下来问你一句细节，所有异常场景全被提前被你搞定了。

老板看完心里只有一句话，你整天忙忙碌碌，到底给业务带来了什么增量？

这就是典型的执行者思维，缺乏管理层视角。

这个产品汇报 Skill，就是专门用来帮你做向上管理和价值升维的。

去网上找那些通用的 AI 工具模拟面试吧，说真的，都太假了。真正的解决方案，是在你本地搭建一个专属于你自己的产品经理数字外脑。

安装方法，给 WorkBuddy 发送命令，

但我得提醒一下，安装 Skill 只是装上了能力，并不等于你建好了知识库。很多同学刚装完，就直接让它挂载本地库去做面试诊断。可你的库根本就是空的，AI 巧妇难为无米之炊啊，测出来的全都是空话，虚话。

而且，案例的质量直接决定诊断的质量。如果库里全是设计了什么功能、推动了什么业务这种空洞描述，AI 诊断只会告诉你缺证据，帮不了太多。

所以这个流程必须分两步走，先建库，再使用。

第一步，录入项目建库。

你得走 deck-build，把自己过往做过的核心项目，按背景、角色、决策、推演、结果、方法论这六段结构沉淀在本地，每条结论都要标注证据等级。

先录入项目建库，实测提示词如下

> 用 $laowang-pm-deck 走 deck-build，这是我做过的核心变现项目复盘笔记【附带项目文档或文字口述】。
> 
> 请帮我按照背景、角色、决策、推演、结果、方法论六段结构，建立标准的本地实战案例卡，标注清楚证据等级，并生成索引清单。

![](assets/2026-09-23-%E5%AE%9E%E6%B5%8B5%E4%B8%AAWorkBuddy%E4%BA%A7%E5%93%81%E7%BB%8F%E7%90%86Skill%EF%BC%9A%E4%BB%8E%E7%94%BB%E5%8E%9F%E5%9E%8B%E5%88%B0%E6%B1%82%E8%81%8C%E5%A4%8D%E7%9B%98%E5%85%A8%E6%90%9E%E5%AE%9A/c8b776d9253a741fa726d22e2d2a230a_MD5.png)

然后，它会在你的本地工作区生成一份结构严谨的案例卡库。有了这个扎实的底座，才来到第二步，挂载知识库做四维诊断与高压对练。

![](assets/2026-09-23-%E5%AE%9E%E6%B5%8B5%E4%B8%AAWorkBuddy%E4%BA%A7%E5%93%81%E7%BB%8F%E7%90%86Skill%EF%BC%9A%E4%BB%8E%E7%94%BB%E5%8E%9F%E5%9E%8B%E5%88%B0%E6%B1%82%E8%81%8C%E5%A4%8D%E7%9B%98%E5%85%A8%E6%90%9E%E5%AE%9A/d75e4be1794210c7cff3bc478d1c7cdc_MD5.png)

这时候，你再把心仪岗位的招聘 JD 发给它，实测提示词如下

> 用 $laowang-pm-deck，挂载我刚建好的本地案例库。这是【腾讯-AI产品经理】招聘 JD。请先做四维证据链诊断，指出我的经历匹配度和核心缺口。以及提供一些眼里的面试官，给我提出一些面试问题。

产出的报告还是比较详细的，能够看出自己的缺陷点，以及需要补充的内容。

![](assets/2026-09-23-%E5%AE%9E%E6%B5%8B5%E4%B8%AAWorkBuddy%E4%BA%A7%E5%93%81%E7%BB%8F%E7%90%86Skill%EF%BC%9A%E4%BB%8E%E7%94%BB%E5%8E%9F%E5%9E%8B%E5%88%B0%E6%B1%82%E8%81%8C%E5%A4%8D%E7%9B%98%E5%85%A8%E6%90%9E%E5%AE%9A/a609555f805e3f80e1fe1f4571372c5b_MD5.jpg)

它不仅把你的真实经历和目标岗位做了四维证据链比对，把缺口扒得清清楚楚，还会顺带列出大厂面试官最可能当场深挖你的刁钻问题。

在正式面试之前，先把自己的薄弱点和证据链全盘摸透，把这些刁钻追问提前准备扎实。到了真正上面试那天，你也不慌了。
