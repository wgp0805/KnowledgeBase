# 又一个国产开源神器！社区版 Pi Agent 桌面工作台来了！

今天给大家分享一个国产开源的 AI 编程桌面端 —— PI-Desktop。Windows、macOS 和 Linux 都能安装，本地项目、Agent 会话、模型配置、代码改动和插件都可以放在一个窗口里，不用分别去几个地方找。

打开本地仓库以后，Agent 可以读代码、改文件、跑命令和测试。中间执行了什么，最后改了哪些内容，也会留在工作区里。项目现在还在 Early Preview，仓库里已经有安装包和比较完整的使用文档。

# 先简单介绍下

PI-Desktop 给 Coding Agent 准备了一个独立的桌面工作区。会话按项目保存，模型自己接，代码修改可以直接检查，插件也能继续往里面加东西。平时要用的项目、会话和审查页面，在一个窗口里都能找到。

软件里没有自带大模型。自己已经有权使用的模型服务可以接进来，本地模型也可以。云端模型、自建网关和兼容接口都能使用，具体怎么选，还是看每个人手头的模型和项目要求。

它的 Agent Runtime 来自开源 Pi 生态，PI-Desktop 负责桌面工作区、会话、权限、插件和多 Agent 编排。

# 功能

### 项目和会话可以一直留着

Coding Agent 用的时间长了，会话很容易散在各个项目里。PI-Desktop 把会话挂在项目下面，左边能看到每个项目最近做了什么。常用的会话可以置顶，暂时不处理的先归档，也能从旧会话开分支或者搜索内容。

几个本地仓库可以同时放在工作区里。换项目的时候，原来的会话还在，不用把之前聊过的内容重新整理一遍。Agent 正在运行时，临时想到的要求也能先排队，等它继续处理。

输入  `@`  可以选择项目里的文件， `/`  则会打开命令。需要让 Agent 看某个具体文件时，这两个入口会比较常用。

应用关掉以后再打开，Session 仍然保留。项目还做了检查点，中断以后会尽量恢复任务现场，这里仍然要以实际恢复结果为准，重要代码该保存、该提交，还是不能省。

全局搜索能查会话、页面、设置和命令。完成的工作、权限请求和更新提醒也会进通知收件箱，之后还能回来查，不会只留一个临时弹窗。

### Agent 做过的内容可以回看

会话里会留下模型回复、工具调用和命令执行记录。Agent 回完以后，我们可以往前翻，看看它中间查了哪些内容，执行到了哪一步。会话特别长的时候，右侧的缩略导航能帮忙定位前面的消息。

代码改完以后，Diff 和命令输出可以直接查看。文件、网页、浏览器预览和计划审批也会在右侧工作面板里打开。检查修改时，文件内容和 Agent 的执行记录可以放在一起看，省去了来回找窗口的麻烦。

![](assets/2026-10-31%20-%20%E5%8F%88%E4%B8%80%E4%B8%AA%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%E7%A5%9E%E5%99%A8%EF%BC%81%E7%A4%BE%E5%8C%BA%E7%89%88%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E5%B7%A5%E4%BD%9C%E5%8F%B0%E6%9D%A5%E4%BA%86%EF%BC%81/c0efd14f77143ca3e3d6be13faec347b_MD5.png)

长期会话与执行过程上下文占用和 Token 用量也会显示在会话里。作者的公开文章里还展示过缓存命中信息，这个数字会随模型服务和任务内容变化，看看本次调用的实际情况就好。

### Agent、Plan 和 Goal

- 日常改代码，可以直接用 Agent。它会读项目、修改文件、运行命令和测试，然后继续处理发现的问题。
- Plan 会先研究仓库，给出实施计划，等我们确认以后再改。影响文件比较多，或者需求只有大概方向时，先看计划会更容易检查。发现它理解偏了，也能在实际修改之前调整。
- 用 Goal 时，需要把目标和验收条件说清楚，执行路线由 Agent 选择。如果结果已经比较明确，中间步骤又不想逐项交代，可以考虑这个方式。

这三种方式都受权限设置约束。改文件、跑命令、调用工具和委派任务时，仍然会经过权限层。每个会话能自主处理多少操作，也可以分别调整。

### 多个 Agent 分任务

Subagent 可以承担独立的后台任务。代码调查、测试分析、某一部分实现和 Review 都能分开做，各自使用独立的上下文，完成以后再把结果交回主 Agent。

模型设置里可以决定哪些模型允许被 Subagent 调用。因此，主 Agent 和 Subagent 不必永远使用同一个模型，可以按任务安排。

需要更长时间的并行工作时，项目里还有 Session Orchestrator。一个主 Session 可以协调多个 Worker Session，每个 Worker 都保留完整会话，能单独查看，也能继续追加任务。

![](assets/2026-10-31%20-%20%E5%8F%88%E4%B8%80%E4%B8%AA%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%E7%A5%9E%E5%99%A8%EF%BC%81%E7%A4%BE%E5%8C%BA%E7%89%88%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E5%B7%A5%E4%BD%9C%E5%8F%B0%E6%9D%A5%E4%BA%86%EF%BC%81/aa593c8b3d7ada213e75433cab1c1050_MD5.png)

多 Session 编排多 Agent 我只会给需要并行的任务用。只改一个小文件，拆任务反而费事，还要多花模型调用和检查会话的时间。工作项本身比较独立，同时处理才方便一些。

### 插件已经有一些实际用法

现在 PI-Desktop 已经兼容一些现成插件了，Token 统计可以看模型消耗，SSH 管理用来集中管理远程主机。Git Lens 会把 Git 历史和相关操作放进侧边栏，浏览器插件则负责页面浏览和自动化。

插件市场里还有终端和 Markdown 笔记。除了 Agent 工具，插件也能添加面板、右侧视图、悬浮组件和主题。Skills、MCP Server、后台服务同样可以接进来，插件之间还能传递消息。

![](assets/2026-10-31%20-%20%E5%8F%88%E4%B8%80%E4%B8%AA%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%E7%A5%9E%E5%99%A8%EF%BC%81%E7%A4%BE%E5%8C%BA%E7%89%88%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E5%B7%A5%E4%BD%9C%E5%8F%B0%E6%9D%A5%E4%BA%86%EF%BC%81/037ade9a58d88f3705ef733836db2150_MD5.png)

插件市场看到合适的插件可以从市场安装，手里有  `.piplug`  包也能导入。仓库里放了面板、Agent 工具、Skill 和完整示例等模板，想自己写插件也有现成的起点。

MCP 服务、Skills 和 Subagents 可以单独管理。某些扩展只在一个项目里需要，就只给那个项目启用，不用全局都打开。

插件本身也是代码，权限审批不等于完整的操作系统沙箱，来源不清楚的插件，不要轻易装。

### 模型和参数都能单独调

不同会话可以用不同模型，同一会话里也能换模型和推理档位。换完以后，原来的项目和对话还在，不需要重新开一个会话把背景再讲一遍。

模型参数可以分别调整，包括上下文窗口、最大输出、推理开关和温度。自定义模型 ID 可以手动添加，接自建网关时也能填写自己的 Endpoint。

### 其他工具的本地会话也能导入

本机以前留下的 Coding Agent 会话，可以挑需要的部分导入 PI-Desktop。原来的工具不用卸，项目也不必一次全部迁过来。

入口在设置的 Import 页面。导入的是本机已有记录，先拿一部分会话过来看看也可以，后面再决定哪些项目适合放到这里。

### 数据默认存在本机

项目、会话、设置和日志默认存在本机，API 凭据放在操作系统钥匙串里。模型请求不强制经过 PI-Desktop 的云端中转，仓库也明确写了没有 PI-Desktop 遥测。

不放心的可以源码部署，让手头的 AI 检查一下风险。

# 快速开始

只是下载使用的话，Releases 里的安装包就够了，不需要拉源码，也不用先准备 Node.js、pnpm 和 Rust，后面这些是从源码运行时才需要的开发环境。

macOS 有 Apple Silicon 和 Intel 版本，Windows 有 x64 版本，Linux 有 x64 和 ARM64 包。Linux 需要 glibc 2.35 及以上，Ubuntu 22.04+、Debian 12+ 和 Fedora 36+ 都在项目列出的常见支持范围里。

![](assets/2026-10-31%20-%20%E5%8F%88%E4%B8%80%E4%B8%AA%E5%9B%BD%E4%BA%A7%E5%BC%80%E6%BA%90%E7%A5%9E%E5%99%A8%EF%BC%81%E7%A4%BE%E5%8C%BA%E7%89%88%20Pi%20Agent%20%E6%A1%8C%E9%9D%A2%E5%B7%A5%E4%BD%9C%E5%8F%B0%E6%9D%A5%E4%BA%86%EF%BC%81/f895ead1a58c47c46f32286e5aeae9d0_MD5.png)

安装以后，接上自己使用的模型，再打开一个本地项目就可以开始。Agent、Plan 和 Goal 没有必须固定使用的场景，按这次任务需要来选就行。

第一次接触这个桌面端，拿测试仓库会轻松一些。权限提示、Diff 和会话记录都看过一遍，基本就知道它和自己的习惯合不合了。

# 我的看法

会话留存和修改审查是我比较在意的两件事，PI-Desktop 都放进了桌面端。模型可以换，插件也已经有能安装使用的东西。平时用 Coding Agent 时会遇到的这些小事，它在一个桌面窗口里照顾到了不少。

多 Agent 我不会什么任务都开。小任务拆开后反而难检查，大一点的仓库、能分开的工作项，才比较适合用。插件这块我倒是更愿意看后续，终端、Git、浏览器这些内容接进来以后，桌面端能做多少事，很大程度上要看插件维护得怎么样，目前这块还是比较薄弱。

项目还在 Early Preview，部分接口和桌面行为会变，已经在用 Coding Agent 的话，可以拿个测试仓库试试；平时没有这类需求，也没必要为了换桌面端硬改自己的工作方式。
