# 为什么越来越多人使用 Jackson 3 ？

**大家好，我是锋哥。**

> 如果你在 Java 圈里待过几年，Jackson 这个名字大概不会陌生。它的作用简单说就是「把对象变成 JSON、再把 JSON 变回对象」 。2025 年 10 月，Jackson 3.0 正式发布，距离上一次大版本跨越已经过去了十三年。很多人一开始只是抱着「看看新版本改了啥」的心态，用着用着却发现：这回不是换了个版本号，而是全新的一次大升级。今天锋哥和大家好好聊聊 Jackson 3 这个版本。

## 先认识一下 Jackson

Jackson 是 FasterXML 维护的一套 Java JSON 处理库。它其实分三层：底层流式读写（ `jackson-core` ）、中间数据绑定（ `jackson-databind` ），再加上一堆注解。日常开发里，我们最常碰到的就是  `ObjectMapper` ：给它一个 Java 对象，它吐出 JSON；给它一段 JSON，它还原成对象。

它能火这么多年，原因很简单。Spring 默认用它，微服务之间传 JSON 用它，配置文件、缓存、消息队列也经常用它。性能够用，注解够全，生态够大。时间一长，它就从「一个库」变成了「基础设施」。

可基础设施也会老。Jackson 2.x 从 2012 年走到现在，为了兼容老代码，很多过时 API 不敢删， `ObjectMapper`  还能在运行时被改配置，包名也一直占着  `com.fasterxml.jackson` 。新项目想用 Java 17 的 Record、模块系统，常常得绕一圈。Jackson 3 要解决的，正是这些问题。

## Jackson 3 到底新在哪

3.0 发布时，作者 Tatu Saloranta 说得很直白：这一版的重点不是堆新功能，而是把地基打干净，让后面十年还能继续演进。真正用起来，你会明显感觉到几处变化。

![](https://mmbiz.qpic.cn/mmbiz_jpg/N3iaBf9dM5ibF2tEw8nztHEpgcRIs9RICfIahlIPe2xanFfbicqD2H3bMJAOuZiaBYRrib0bbysaXWP9nGk8xOMnK0VxHKrlddKJrLkQQFveNtGI/640?wx_fmt=jpeg&from=appmsg)

**最低要求变成 Java 17。** 2.x 还守着 Java 8，3.x 直接站到 17。好处很实际：Record、密封类、模块系统都能原生配合， `java.time`  和  `Optional`  也不用再单独拉模块、手动注册了。

**包名换成了  `tools.jackson` 。** Maven 坐标从  `com.fasterxml.jackson.core`  变成  `tools.jackson.core` 。注解包  `com.fasterxml.jackson.annotation`  暂时没动，所以  `@JsonProperty`  这些老朋友还能照旧写。更妙的是：2.x 和 3.x 可以同时待在 classpath 里，升级不必「全公司同一天切」。

**Mapper 变成不可变的了。** 以前很多人把  `ObjectMapper`  做成单例，却又在某个角落  `configure()`  一下，线程安全立刻变得可疑。3.x 里，配置只能在 builder 上完成， `build()`  之后就不能再改。听起来限制变多，用过之后反而踏实。

**异常不再强制你 catch。** 以前  `JsonProcessingException`  继承  `IOException` ，方法签名上到处是  `throws` 。3.x 改成了非检查异常（基类叫  `JacksonException` ），调用代码干净不少。

另外还有几处默认值更符合现在的习惯：日期默认写成 ISO-8601，而不是时间戳；格式要对口，JSON 用  `JsonMapper` ，XML 用  `XmlMapper` ，不能再拿一个通用  `ObjectMapper`  硬塞工厂。3.1 已经是 3.x 线里第一个 LTS，后面的 3.2 也在修 XML、Object Id 这类老毛病。想长期用，直接瞄准 3.1 及以上即可。

## 上手写几段代码

依赖先换坐标。以目前 Maven Central 上的 3.2.2 为例：

-
-
-
-
-

```xml
<dependency>    <groupId>tools.jackson.core</groupId>    <artifactId>jackson-databind</artifactId>    <version>3.2.2</version></dependency>
```

然后用 builder 造一个不可变的  `JsonMapper` 。注意 import 已经换成  `tools.jackson` ：

-
-
-
-
-
-
-
-

```java
import tools.jackson.databind.SerializationFeature;import tools.jackson.databind.json.JsonMapper;import tools.jackson.databind.DateTimeFeature;
JsonMapper mapper = JsonMapper.builder()        .enable(SerializationFeature.INDENT_OUTPUT)        .disable(DateTimeFeature.WRITE_DATES_AS_TIMESTAMPS)        .build();
```

业务对象可以直接用 Record，不必再写一堆 getter。 `java.time`  也是开箱即用：

-
-
-
-
-
-
-
-

```typescript
import java.time.LocalDateTime;import com.fasterxml.jackson.annotation.JsonProperty;
public record User(        String name,        String email,        @JsonProperty("created_at") LocalDateTime createdAt) {}
```

序列化和反序列化还是那两行，只是再也用不着  `throws` ：

-
-
-
-
-
-
-

```apache
User user = new User("张三", "zhangsan@example.com", LocalDateTime.of(2026, 9, 4, 21, 10, 0));
String json = mapper.writeValueAsString(user);User back = mapper.readValue(json, User.class);
System.out.println(json);System.out.println(back.name());
```

跑出来大致是这样：

-
-
-
-
-

```perl
{  "name" : "张三",  "email" : "zhangsan@example.com",  "created_at" : "2026-09-04T21:10:00"}
```

如果项目一时半会儿迁不完，可以用  `JsonMapper.builderWithJackson2Defaults()`  尽量贴近 2.x 的默认行为，先把编译过了，再慢慢改配置。这比「要么全切、要么不动」友善得多。

## 一次完整的读写流程

从对象到 JSON、再从 JSON 回到对象，3.x 的路径其实更短：配置一次性在 builder 里说完，后面只做读写。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/N3iaBf9dM5ibEibwiauchWGibZXHfibVrO8LIVpT8tJvXh6h0eUIpDHvOXsGBaT6EvY9wjyFvLFNU07ciboOHxmKXaoGszGYic7J7lMO9QtfySmCeGU/640?wx_fmt=png&from=appmsg)

和 2.x 比，少了运行时改配置、少了单独注册 Java 8 模块、也少了满屏的检查异常。流程看起来差不多，写起来却轻快一截。

## 为什么现在切换的人变多了

新版本发布不等于大家立刻跟。Jackson 3 能在这一年里被越来越多项目接住，主要还是时机到了。

![](https://mmbiz.qpic.cn/sz_mmbiz_jpg/N3iaBf9dM5ibEJ45vIIdmcoP8fenYYibU7NM7re8FiaFRfI50xfjqICWfRYu2FXLpf7yev7r7NP3BFSpnCy7aialCGsOe9PopHBYrRkVudjX73sQ/640?wx_fmt=jpeg&from=appmsg)

第一，框架已经接上了。Spring 在 2025 年 10 月就公开了 Jackson 3 支持，后面的新项目默认往 3.x 靠，比自己在业务代码里硬切省心得多。

第二，升级路径是「可并存」的。换包名这件事，当初看起来像破坏兼容，现在反而成了优点：老模块继续用 2.x，新模块先上 3.x，不必停机式重构。OpenRewrite 也提供了 2 到 3 的迁移配方，机械替换能覆盖一大部分。

第三，3.x 把日常痛点按住了。Mapper 不可变、日期默认 ISO-8601、Record 和  `java.time`  内建、异常不再强迫声明——这些都不是炫技，是写业务代码时每天会碰到的摩擦。摩擦少了，口碑自然起来。

当然也不是没有成本。基线是 Java 17，老项目还在 8 或 11 上就暂时别急；不少类和 Feature 改了名字，编译器会老老实实报错。但如果你的项目已经在 17+，又刚好要开新服务或做一次依赖升级，Jackson 3 几乎是「顺手就该换」的选项，而不是一次冒险。
