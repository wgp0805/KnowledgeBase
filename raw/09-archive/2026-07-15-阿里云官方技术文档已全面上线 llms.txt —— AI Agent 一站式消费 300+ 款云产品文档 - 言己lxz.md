## llms.txt 的结构
    
    
    # 产品名称
    > 产品一句话描述（供 AI 快速判断是否相关）
    ## 分类名称
    - [页面标题](URL): 页面描述（告诉 AI 这个页面能解决什么问题）
    - [页面标题](URL): 页面描述

两级索引中链接的区别：

  * 根索引的链接指向 → **产品的 llms.txt** （如 `/zh/oss/llms.txt`）
  * 产品索引的链接指向 → **具体文档页面** （如 `/zh/oss/user-guide/xxx.md`）



AI Agent 消费时，先读根索引定位目标产品，再读产品索引获取具体文档页面，最后按需抓取 Markdown 正文——**三步定位，按需加载，不浪费 token** 。

## 使用示例

### 示例 1：在 AI 对话产品中直接使用

Qoder、Kimi、ChatGPT、Claude 、豆包等 AI 对话产品内置了网页抓取能力，可以直接通过对话指令消费 llms.txt，无需写代码。

**直接给模型发指令：**
    
    
    请读取https://help.aliyun.com/zh/llms.txt，
    找到"函数计算"相关的产品，
    然后帮我查看如何用 Python 编写一个 HTTP 触发器的云函数。

**AI 实际执行过程：**
    
    
    1. Fetch(https://help.aliyun.com/zh/llms.txt)                           ← 读取根索引
       → 找到函数计算条目，获取产品 llms.txt 链接
    2. Fetch(https://help.aliyun.com/zh/functioncompute/llms.txt)           ← 读取产品索引
       → 按关键词匹配到 HTTP 触发器、Python 运行时相关文档
    3. Fetch(https://help.aliyun.com/zh/functioncompute/.../http-trigger-invoking-function.md)  ← 抓取目标页面
       → 获取详细内容，生成回答

AI 会自动完成”根索引 → 产品索引 → 具体文档页面“的三步导航，最终基于真实文档内容回答问题，并附上来源链接。

> **提示** ：回答中引用的文档链接默认为 `.md` 格式，去掉 `.md` 后缀即为对应的 HTML 页面。例如：
> 
>   * AI 返回：`[https://help.aliyun.com/zh/functioncompute/fc/user-guide/http-trigger-invoking-function.md](<https://help.aliyun.com/zh/functioncompute/fc/user-guide/http-trigger-invoking-function.md?spm=a2c6h.13046898.publish-article.29.173f6ffaJaElfJ&file=http-trigger-invoking-function.md>)`
>   * 浏览器访问：`[https://help.aliyun.com/zh/functioncompute/fc/user-guide/http-trigger-invoking-function](<https://help.aliyun.com/zh/functioncompute/fc/user-guide/http-trigger-invoking-function?spm=a2c6h.13046898.publish-article.30.173f6ffaJaElfJ>)`
> 


**在 System Prompt 中配置为知识源（适用于Qoder / 自建 GPTs / Kimi 智能体等）：**
    
    
    你是一个阿里云架构师助手。
    阿里云所有产品文档的索引位于 https://help.aliyun.com/zh/llms.txt
    回答用户问题时，先从索引中定位相关产品，再抓取具体文档页面。
    回答中引用文档链接时，去掉末尾的 .md 后缀，返回 HTML 版本便于用户直接访问。

### 示例 2：在通义灵码 CLI（Qoder CLI）中消费 llms.txt

[通义灵码](<https://lingma.aliyun.com/?spm=a2c6h.13046898.publish-article.31.173f6ffaJaElfJ>) 是阿里云的智能编码助手，其 CLI 模式（qodercli）内置 WebFetch 工具，能够直接抓取 URL。通过项目级 `AGENTS.md` 配置文档查阅规则，即可让它自主导航 llms.txt。

#### 配置方法

在项目根目录创建 `AGENTS.md`：
    
    
    # 阿里云文档查阅规则
    当需要查询阿里云产品文档时，请按以下步骤操作：
    1. 先读取 https://help.aliyun.com/zh/llms.txt 获取产品索引
    2. 根据问题定位到具体产品的 llms.txt（如 ECS → /zh/ecs/llms.txt）
    3. 从产品 llms.txt 中找到最相关的文档页面
    4. 抓取该页面获取详细内容
    5. 回答中引用文档链接时，去掉末尾的 .md 后缀，返回 HTML 版本便于用户直接访问

#### 使用效果
    
    
    $ qodercli
    > 如何使用 OSS 配置跨域 CORS？

通义灵码会自动：

  1. 抓取 `[https://help.aliyun.com/zh/llms.txt](<https://help.aliyun.com/zh/llms.txt?spm=a2c6h.13046898.publish-article.32.173f6ffaJaElfJ&file=llms.txt>)` → 找到对象存储条目
  2. 抓取 `[https://help.aliyun.com/zh/oss/llms.txt](<https://help.aliyun.com/zh/oss/llms.txt?spm=a2c6h.13046898.publish-article.33.173f6ffaJaElfJ&file=llms.txt>)` → 找到 CORS 相关文档
  3. 基于真实文档条目回答，引用 `[https://help.aliyun.com/zh/oss/user-guide/configure-cross-origin-resource-sharing.md](<https://help.aliyun.com/zh/oss/user-guide/configure-cross-origin-resource-sharing.md?spm=a2c6h.13046898.publish-article.34.173f6ffaJaElfJ&file=configure-cross-origin-resource-sharing.md>)`



> **原理** ：通义灵码 CLI 支持三级 AGENTS.md（用户级 `~/.qoder/AGENTS.md`、项目级、本地级），内容会自动加载为上下文。结合其内置的 WebFetch 工具，模型可以按规则自主抓取 llms.txt 完成导航。这与 Claude Code 的 CLAUDE.md 机制同理。

## 常见问题

### Q: llms.txt 和传统文档搜索有什么区别？

传统搜索需要您自己组织关键词去搜索引擎查找，AI 模型面对数万页文档也很难高效定位。llms.txt 提供了一个**结构化的目录和描述** ，让 AI 模型能像开发者查阅 API 文档一样，先看目录再定位具体页面，显著减少 token 消耗和幻觉概率。

### Q: llms.txt 多久更新一次？

阿里云的 llms.txt 随文档发布同步更新。当产品新增文档或修改文档时，对应的 llms.txt 索引 / md文档 会自动刷新。

### Q: 我是开发者，如何在自己的 AI 应用中集成？

推荐方式：在你的 AI 应用的 System Prompt 中加入 llms.txt 的 URL，显式引导模型将其作为阿里云知识源。

### Q: 国际站和中国站的 llms.txt 有什么区别？

两套站点的产品覆盖范围与产品功能会有所不同，llms.txt 索引各自独立维护，内容和语言互不影响。建议根据您的业务部署区域选择对应站点。
