**大家好，我是冰河~~**

前几天在重构一个权限模块，跟 Claude Code 来回聊了一下午，把架构、约束、哪些方案被否了、数据库要兼容旧版本升级，全都交代得清清楚楚。

第二天换了个新会话继续做，它上来就给我一个昨天已经被否掉的方案，还信心满满地说“这样最简洁”。

那一刻我盯着屏幕，感觉像在跟一个每天失忆的同事共事。

这大概是所有重度使用 Coding Agent 的人都碰过的事。模型能力越来越强，改代码、查 bug、跨文件分析都不在话下，但 **只要新开一个对话，之前所有项目层面的默契全部归零** 。你昨天聊明白的事，今天要重讲一遍；上周踩过的坑，这周它照样往里跳。

单纯的“上下文窗口拉大”解决不了这个问题。窗口再大，它也只是把更多对话塞进来，分不清哪句是调试时的废话，哪句是决定后续重构的硬约束。

最近看到 MemoraX Code 这个项目，专门冲着这件事来的。GitHub 上开源，项目地址在文末。我把它的思路和实际效果梳理了一下，值得聊聊。

## 项目记忆

MemoraX Code 的定位是“面向代码智能体的长期记忆系统”。翻译成人话：给 Coding Agent 加一层项目记忆，跨会话、跨 Agent，把历史经验沉淀下来，新开对话不用从头交代。

它把记忆分成两块。 **本地记忆** 盯着代码仓库，抓代码结构、关键入口、Issue 历史和项目演进信息。 **云端记忆** 负责保存跨任务、跨对话、跨 Agent 的项目经验、开发偏好和失败方案，还能在团队之间共享。

关键在召回策略。新任务进来时，它不会一股脑把所有历史塞进上下文，而是根据当前任务的意图做检索，只把真正相关的记忆喂给 Agent。这意味着你在 Codex 里做完一段任务，切到 Claude Code 继续干，之前沉淀的项目认知依然生效。

## 写规则的思路不一样

市面上不少记忆系统走的是另一条路：人工写提示词、硬编码规则，规定什么该存、什么时候召回。这套办法能用，但维护成本高，规则一多就互相打架。

MemoraX Code 做了一套可学习的记忆框架。它构造专门的代码训练数据集，设计记忆评估和奖励信号，让记忆模型自己学：什么信息值得留、什么内容已经过时、什么时机该召回。

训练体系和用户私有记忆数据做隔离，模型能力迭代之后再服务线上任务。

这个设计思路我比较认同。记忆系统的难点从来不是“存不存得下”，而是“该不该在此时此刻想起这件事”。

## Procedure Memory

这是整个项目里我觉得最有意思的功能，叫 **过程记忆** 。

系统从历史开发轨迹里自动提取有复用价值的分析、执行、验证步骤，提炼成结构化的工程经验，给后续同类任务直接复用。

注意，它不是简单记录“上次发生了什么”，而是总结出： **遇到这类工程问题，哪些分析路径、操作步骤、验证手段是有效的** 。

官方做过一组对比实验。从 123 个历史任务片段里自动提炼出 15 条工程经验，归纳成 4 类 Procedure Memory。然后放到一段 3 小时的复杂长程开发任务上对比：

不开记忆，综合得分 11.71，关键检查项只过了 2/13。 开 Procedure Memory，综合得分 70.30，关键检查项过了 10/13。 同时调用成本还降了约 22.6%。

原因其实不复杂。没有记忆的时候，Agent 大量 token 花在重复摸索已经踩过的坑上；有经验沉淀之后，它依然要理解需求写代码，但不用从零重新试错。

当然，记忆不是越多越好，乱召回过时经验反而添乱。内部测试数据显示，85.5% 的记忆触发行为和人的判断一致，81.2% 的记忆内容拿到正向反馈。这两个数字说明它在“该不该想起”这件事上已经做得比较克制了。

## 测评和适配现状

在 AML（Agent Memory Leaderboard）的 Coding Track 榜单上，MemoraX Code 拿了 62 分，排第一，对比 Claude Mem 解题率提升 10%。

目前原生支持 Codex、Claude Code、Deepseek Harness、OpenCode 四款主流 Coding Agent，其他平台还在适配。开发者可以在官方平台查看、编辑、删除自己生成的记忆，这一点比较重要，记忆系统如果不可编辑，用久了会变成黑箱。

## 使用总结

现在大家做 Coding Agent，比拼的基本都是单次任务能力：写代码快不快、bug 修得准不准、复杂任务能不能完成。

但真实的软件工程不是一次性任务。同一个仓库反复迭代，同类问题反复出现，开发者还会在多个 Agent 之间来回切换。 **模型能力决定一次任务能走多远，记忆系统决定下一次任务从哪里开始。**

很多时候拉开差距的，不是第一次任务表现，而是进展到第 N 次的时候，还要不要从头开始。

代码本身不会记录团队踩过的坑、被否决的方案、版本兼容的隐性约束。这些隐性工程知识，恰恰是长期项目最值钱的东西。MemoraX Code 想做的，就是把这些经验沉淀下来，让 AI 协作者真正记住项目过往。
