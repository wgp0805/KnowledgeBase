## 项目简介

GSD Core 是一个开源的 AI 编码工作流项目，核心定位是为 AI 编程工具提供元提示、上下文工程和规格驱动开发能力。

简单理解，它不是一个新的编辑器，也不是替代 Claude Code 或 Cursor 的工具，而是给这些 AI 编码助手加上一层“项目管理大脑”。它会引导 AI 先理解项目，再拆解阶段，然后按计划执行，最后检查结果。

这样做的好处很明显：AI 不再只是根据你的一句话直接开改，而是围绕项目上下文持续工作。对于个人开发者、小团队，或者经常用 AI 辅助开发完整功能的人来说，这种方式会更稳，也更容易掌控。

需要注意的是，这里介绍的是 GitHub 上的 `open-gsd/gsd-core` 项目，不要和其他同名或旧仓库混淆。

## 项目安装与使用

GSD Core 支持 macOS、Windows 和 Linux。只要你的环境中已经安装 [Node.js，就可以通过](http://node.xn--js,-ys9dj4unynj51g7sa/) `npx` 快速安装。

在 macOS 或 Linux 终端中执行：

```
npx @opengsd/gsd-core@latest
```

在 Windows 的 PowerShell 或 Windows Terminal 中，也可以执行同样的命令：

```
npx @opengsd/gsd-core@latest
```

如果你想使用更轻量的安装方式，可以选择最小模式：

```
npx @opengsd/gsd-core@latest --minimal
```

安装时，它会引导你选择要接入的 AI 编码环境，比如 Claude Code、Codex、Gemini CLI、Cursor、Windsurf 等。安装完成后，可以先输入帮助命令查看可用能力：

```
/gsd-help
```

如果你使用的是 Codex，命令形式可能是：

```
$gsd-help
```

举个简单例子。假设你正在维护一个博客项目，现在想新增“文章草稿自动保存”功能。你可以先让 GSD Core 分析现有代码库：

```
/gsd-map-codebase
```

然后创建或更新项目上下文：

```
/gsd-new-project
```

接下来进入需求讨论阶段：

```
/gsd-discuss-phase 1
```

你可以告诉 AI：草稿多久保存一次、失败后是否重试、前端是否需要提示、后端接口怎么设计。讨论完成后，再生成执行计划：

```
/gsd-plan-phase 1
```

确认计划没问题后，让 AI 开始执行：

```
/gsd-execute-phase 1
```

代码完成后，还可以让它验证本阶段工作：

```
/gsd-verify-work 1
```

这样一来，AI 写代码就不再是“想到哪改到哪”，而是有上下文、有计划、有检查地推进。

## 总结

GSD Core 的亮点在于，它让 AI 编码从简单的聊天生成，变成更接近真实开发流程的项目交付。它能帮助你减少上下文丢失、需求跑偏和无序改动的问题，让 AI 更像一个可靠的开发搭档。

作为一个开源项目，GSD Core 可以免费使用，也方便你查看源码、参与贡献。如果你正在用 AI 写代码，却总觉得它不够稳定，不妨亲自试试看。也许从下一个功能开始，你就能让 AI 更靠谱地帮你把项目做完。
