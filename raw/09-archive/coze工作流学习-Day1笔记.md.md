## 一、核心发现：AI 一句话生成工作流

Coze 支持通过自然语言描述需求，AI 自动生成完整工作流（Text-to-Workflow）。

### 工作原理
1. **语义理解**：AI 拆解自然语言为关键步骤
2. **组件匹配**：自动从插件库/工具库选择合适节点
3. **结构生成**：自动规划节点连接、变量传递、条件分支
4. **可编辑交付**：生成后可手动微调，不是黑盒

### AI 生成效果评估

| 场景 | 效果 | 建议 |
| :--- | :--- | :--- |
| 线性流程（搜索→总结→输出） | ⭐⭐⭐⭐⭐ | 直接生成，微调即可 |
| 标准数据处理（JSON解析、格式转换） | ⭐⭐⭐⭐ | 可能需调整变量映射 |
| 复杂条件分支/循环逻辑 | ⭐⭐⭐ | 需手动补充判断条件 |
| 多 API 串联+自定义代码 | ⭐⭐ | AI 搭骨架，代码自己写 |
| 业务状态机/数据库事务 | ⭐ | 必须人工设计 |

### 最佳实践
- Prompt 要具体、结构化，越精确生成质量越高
- 长流程拆成子工作流分别生成，再手动组装
- 生成后务必测试 + Review，不要跳过调试直接上线
- 用它反向学习编排思路，比自己啃文档快

## 二、Day 1 实战：双路径验证

### 实战项目
用户输入一段长文本 → 工作流自动：
1. 判断文本类型（新闻/技术/日常）
2. 根据类型用不同方式总结
3. 输出摘要 + 关键词

### 对比结果

| 维度 | AI 生成 | 手动搭建 |
| :--- | :--- | :--- |
| 搭建速度 | 快，省去固有流程时间 | 慢，需逐节点配置 |
| 提示词质量 | 自动生成，较精准 | 难点，难以保证精准 |
| 流程结构 | 关键词提取与摘要分析**分开** | 提取和摘要分析**合并** |
| 最终效果 | 分析质量更好 ✅ | 能跑通但精度稍低 |

## 三、关键洞察：拆分 vs 合并

> **核心认知：人倾向于合并步骤以简化流程，AI 倾向于拆分步骤以提升精度。**

### 为什么拆分效果更好？

| 维度 | 合并处理 | 拆分处理 |
| :--- | :--- | :--- |
| 注意力分配 | LLM 同时做两件事，顾此失彼 | 每个节点专注单一任务 |
| Prompt 难度 | 复合指令，容易歧义 | 简单明确，准确率高 |
| 可调试性 | 出错不知是哪步的问题 | 可单独检查每个节点 |
| 可复用性 | 耦合，换场景要重写 | 节点可独立复用 |
| Token 效率 | 传入过多无关上下文 | 每步只传必要信息 |

### 设计模式积累（持续更新）
- **模式1：提取与分析分离** → 适用于从原始内容中结构化信息的场景
- **模式2：先分类再路由** → 比直接用条件判断更稳定
- **模式3：摘要前加验证节点** → 防止幻觉传播到下游

## 四、贯穿式学习项目规划

> 用「智能文本摘要 Bot」串联整个 Coze 学习，每学一个新功能就迭代一层能力。

### 4 阶段渐进式改造计划

| 阶段 | 新增能力 | 改造内容 | 核心概念 |
| :--- | :--- | :--- | :--- |
| Day 2: 知识库 | 领域增强 | 判断类型前加知识库检索，技术类挂载文档库 | 切片、召回策略、变量引用 |
| Day 3: 插件/API | 信息增强 | 新闻类→搜索插件补背景；技术类→查 GitHub 验证 | 鉴权、参数映射、错误处理 |
| Day 4: 记忆/变量 | 个性化适配 | 记住用户偏好，累计处理类型分布 | 长期记忆、会话变量、数据库 |
| Day 5: 多Agent/发布 | 协作与交付 | 拆分为分类+摘要+质检 Agent，发布到飞书/微信 | Agent 协作、渠道适配、监控 |

### 执行原则
1. 每阶段开始前**复制当前工作流作为备份**
2. 每次迭代后记录「改造日志」：解决了什么？踩了什么坑？AI 帮了什么？
3. 允许不完美，失败比顺利跑通更有学习价值
4. 最终目标：产出一个可展示、可复用、有真实价值的智能摘要工具
