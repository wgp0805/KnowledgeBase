# 一、写作与内容创作

## 1、Humanizer-zh：AI 写作去痕工具

你平常有没有遇到这样的问题：用 AI 辅助写完一篇文章，内容没什么问题，但通读一遍总觉得「AI 味」很重——开口就是「此外」「至关重要」「深入探讨」，结尾必然是「总而言之」，明眼人一看就知道是机器写的，发出去之前还得自己逐句改一遍？

**Humanizer-zh** 这个技能主要解决的就是「把 AI 写的稿子改成人话」这个问题。它是英文原版 Humanizer 的中文版，规则基础来自维基百科的《AI 写作特征识别指南》——就是维基百科编辑们日常用来识别「这段话是不是 AI 写的」的那份公开指南。它内置了 24 种典型 AI 写作痕迹的识别规则，分成内容模式、语言语法、风格、交流习惯四大类，比如过度使用「AI 词汇」、三段式排比、破折号泛滥、谄媚语气等等。你把整篇文章丢给它，它会逐句对照，把有痕迹的部分重写成自然的表达，同时保留你原本的观点。

比如写完稿子后直接说：

```
/humanizer-zh 请帮我改写 test-article.md 这篇文章，去除里面的 AI 写作痕迹，核心观点保持不变
```

临时改一段话也可以，直接贴进去就行：

```
请用 humanizer 帮我改写这段话，让它更自然：
本研究深入探讨了机器学习在医疗诊断中的关键作用，突出了其在不断演变的医疗格局中的重要性。此外，它为该领域的未来发展奠定了坚实的基础。
```

上面这段话改写之后会变成「本研究分析了机器学习在医疗诊断中的应用，重点是肺癌早期筛查……」这种具体、有信息量的表达。

下面这张图是小灰实测的改写结果。它改完之后会直接写回文件，还会输出一张改动明细表：破折号滥用 4 处全部改掉、「不是 X，而是 Y」的假对比从 3 次减到 1 处、「降维打击」这类拔高词换成了具体说法，而文章的观点、结构和标题层级一个都没动。

## 2、写作蒸馏器：复刻任意作者的写作风格

你平常有没有遇到这样的问题：特别喜欢某个作者的文风，想让 AI 模仿着写，但每次只说「模仿某某的风格」，AI 写出来的东西总是形似神不似？

**写作蒸馏器（Writing DNA）** 这个技能主要解决的就是「把感觉层面的风格变成可执行的规则」这个问题。你给它一个作者的一批文章（官方建议 20 篇左右），它会系统性地拆解出这个作者的「写作 DNA」——用词习惯、句式节奏、段落结构、情绪处理方式，整理成一份可以反复调用的规则文档。之后再让 AI 用这个 DNA 写新内容，风格就稳定多了。

比如小灰这次的实测，蒸馏对象选的是 AI 圈顶流博主「数字生命卡兹克」：

```
/writing-dna-skill 请分析 khazix-articles 文件夹里的所有文章，蒸馏出数字生命卡兹克的写作风格，生成完整的 Writing DNA 文档
```

蒸馏完成之后，还可以马上验收效果：

```
用刚才蒸馏出的 Writing DNA，以这个风格写一段 300 字的开头，主题是「程序员做副业」
```

仿写出来的开头是这样的：「昨天晚上，又一个程序员朋友找我吃饭。饭桌上他没聊股票，没聊房价，就聊了一件事：他想搞个副业……」短句、留白、先共情再泼冷水，熟悉卡兹克的读者应该能认出那个味道。

它自带去 AI 味工具，和上面介绍的 Humanizer-zh 搭配使用效果更好：先蒸馏风格，再去除机器痕迹。

小灰实测的时候，直接把 17 篇「数字生命卡兹克」的文章丢给它（12 篇 Markdown 加 5 篇 PDF），它自己识别出了所有文件，然后一篇一篇通读：

## 3、AI 中文小说创作：从零写完一本长篇小说

你平常有没有遇到这样的问题：心血来潮想让 AI 写个小说，开头两章还挺像样，写到第三章主角的名字都变了，伏笔埋了就忘，前后设定自相矛盾？

**chinese-novelist-skill** 这个技能主要解决的就是「AI 写长篇会失忆」这个问题。它会先通过几轮问答帮你确定题材、主角和核心冲突，然后建立「创作记忆」——人物设定、伏笔线索、章节摘要都会沉淀成文件，每写一章先回顾再动笔，写完还会自动校验一致性。官方说法是支持 10 到 50 章的完整小说创作。

比如：

```
使用 chinese-novelist 帮我写一部 20 章的都市悬疑小说，主角是辞职的刑警，核心冲突是查明当年师傅被害的真相。先生成大纲和第一章。
```

哪怕你没打算真的写小说，让它写一个短篇故事给孩子当睡前读物，也是挺好玩的用法。

小灰实测下来最惊喜的是两点：一是它自己给小说起了书名《停摆》，还给了两个备选；二是写完第一章后，它主动交代「顺手埋了七处伏笔」——表带的缝法、无名指的疤、师父生前最后一句话，全都记进了人物档案，后面章节会自动呼应。

## 4、仓颉技能：把书和播客蒸馏成可以调用的技能

你平常有没有遇到这样的问题：书看了不少，方法论学了一堆，当时觉得醍醐灌顶，过两个月就忘干净了，真正遇到问题的时候根本想不起来用？

**仓颉技能（cangjie-skill）** 主要解决的就是「知识看完用不上」这个问题。它可以把书籍、长视频、播客里的方法论，蒸馏成一个结构化的技能包——没错，就是生成一个新的 Skill，以后遇到对应场景，AI 会自动调用这套方法论帮你分析。

这里特别说明一下它和上面「写作蒸馏器」的区别：写作蒸馏器蒸馏的是**文风**（一个人怎么说话），仓颉蒸馏的是**方法论**（一个人怎么做事、怎么做决策），两者正好互补。

小灰这次的实测素材是张小龙 2019 年微信公开课那场著名的四小时演讲全文（网上有公开文字实录）：

```
/cangjie-skill 帮我把 zhangxiaolong-speeches 文件夹里的演讲内容蒸馏成可调用的结构化技能包
```

蒸馏完成后，你再问「我要设计一个工具类产品，张小龙的产品原则会怎么提醒我」，AI 就会调用他「好的产品是用完即走」「不打扰用户」这些真实的方法论来分析，而不是泛泛而谈。

这个技能相当于一个「技能制造机」，理论上你可以把任何收藏的好内容——书、演讲、播客——都变成技能。

小灰实测跑了 23 分钟，它把两万字的演讲过完了一遍完整流水线，最后编译出一个真正能用的技能包：1 个入口文件、13 张能力卡（比如「原动力校验法」——判断一个功能该不该做时，先别问「能不能做、有没有流量」，先问「它的原动力是什么」），还带校验和术语表。

# 二、视觉设计

## 5、UI UX Pro Max：一句话生成整套设计系统

你平常有没有遇到这样的问题：自己做个小工具、小网站，配色排版全凭感觉，做出来总有一股「土味」，但又说不出专业设计到底差在哪？

**UI UX Pro Max** 这个技能主要解决的就是「先把设计规范定下来，再动手做界面」这个问题。它内置了 79 种可检索的设计风格、192 套产品配色方案、74 组字体搭配和 119 条 UX 准则，一句话就能生成一整套定制化设计系统：配色、字体、组件规范、交互准则全都有。它是整个技能商店里安装量最高的技能之一。

比如：

```
/ui-ux-pro-max 给我生成一套「读书笔记 App」的设计系统，包含配色、字体和组件规范。
```

产出的设计系统页面里有完整的色板、字体搭配和组件示例，之后不管做网页还是做小程序，都按这套规范来，审美直接上一个档次。

小灰实测最直观的一点：它不是拍脑袋给方案，而是真的去查了内置数据库——匹配到「Book & Reading Tracker」产品类，定了 Swiss Modernism 2.0 主风格加 E-Ink 纸感辅风格，配色直接给到具体色值（书棕 + 纸黄），连「不要用彩色渐变堆叠」这种反模式都列了出来。

## 6、归藏社交媒体卡片：文章一键变小红书图组

你平常有没有遇到这样的问题：文章写完了想发小红书或公众号，做配图卡片太费时间——封面、金句卡、内容页，一套做下来一两个小时就没了？

**归藏社交媒体卡片（guizang-social-card-skill）** 这个技能主要解决的就是「把文章直接变成成套的社交媒体图卡」这个问题。它是先用 HTML 排版再本地渲染成图，不依赖生图模型，所以风格非常稳定：小红书 3:4 图组、公众号 21:9 + 1:1 封面、金句卡都能出，瑞士风和电子杂志风两种风格可选。9 月版推荐过同一个作者的归藏 PPT，这个是他的另一款作品，专门做图文卡片。

比如小灰直接把前面 Humanizer-zh 改写好的那篇 test-article.md 丢给它：

```
/guizang-social-card-skill 把 test-article.md 这篇文章生成 3 张小红书封面图：电子杂志风、瑞士风和暗色 Midnight Ink。
```

一篇文章从「AI 味改写」到「多平台图卡」，正好和前面的技能串成一条完整的内容生产链。

小灰实测的三张成品：同一篇文章，电子杂志风给出「一键生成，赚不到钱」，瑞士风给出「往能力差下注」，暗色 Midnight Ink 给出「门槛越低，越不赚钱」——同一个选题，三种完全不同的视觉体系，标题还是各自重新提炼的，不是简单换皮。

# 三、职场与个人成长

## 7、面试准备助手：interview-prep

你平常有没有遇到这样的问题：好不容易拿到面试，却不知道从何准备——这个岗位考察什么、公司关注什么、可能会问哪些问题，全靠自己瞎猜，最后只能临时抱佛脚刷面经？

**interview-prep** 这个技能主要解决的就是「针对目标岗位定制面试准备方案」这个问题。你把岗位 JD 和自己的简历给它，它会生成一份结构化的面试准备文档：岗位要求拆解、你的经历与岗位的匹配点、大概率会被问到的问题、每个问题建议怎么答。

比如：

```
帮我做面试准备，我 3 天后要面美团的增长产品经理岗位，我的简历是 resume.md，岗位 JD 是 jd.md，都在当前目录下。
```

小灰实测下来，它读完简历和 JD 之后给出的判断非常直接：「你是一个懂增长的运营，不是增长产品」——这条 JD 真正想要的是能用产品手段和数据实验规模化解决拉新、留存的人，而简历的缺口集中在产品化经验和数据实验能力上。最后生成了一份 9 个章节的完整准备文档：公司竞品调研、JD 逐条匹配、定制自我介绍、STAR 项目追问预案、21 道高频题、Gap 清单和 3 天冲刺排期，连「面试前必须补 A/B 实验和 SQL」这种具体的补救项都标了优先级。

## 8、产品经理工作流：pm-skills

**pm-skills** 这个技能集合主要解决的就是「把成名的产品方法论变成能直接跑的流程」这个问题。它内置了 68 个产品技能加 42 个工作流，覆盖写 PRD、画机会树、设计实验、定 OKR 和北极星指标这些产品经理的日常工作。你不需要先学框架，直接说出你的问题，它会选用合适的框架带你走一遍。

比如：

/create-prd 针对「小区团购小程序」这个产品想法，写一份简版 PRD。

## 9、AI 共读拆书：human-agent-reading

你平常有没有遇到这样的问题：买了一堆书想认真读，但自己读总是坚持不下来，读完也记不住；让 AI 直接总结吧，得到的又是一份干巴巴的要点列表，跟看百科没什么区别？

**human-agent-reading（百日拆书）** 这个技能主要解决的就是「让读书变成一场对话」这个问题。它用的是一套百日十程的拆书框架：先根据你的阅读经历和当下在做的事情生成一份跨领域书单，分成十个章程；每天和你一起拆解一本书，不是单方面输出总结，而是结合你的生活提出核心问题，读书记录会留存下来，可以追溯。

比如：

```
/human-agent-reading /human-agent-reading 我的阅读经历和近况都在 reading-profile.md 里，读完后帮我生成一份 100 本跨领域书单，分成十个章程，开启长期共读。
```

小灰实测时它建好了一个完整的共读工作台：100 本书的总索引、阅读画像、留档纪律一应俱全，还直接开了 Day 1 的《人类简史》拆解——不是抄书评，而是按「表面论点、核心机制、和你有什么关系」三层往里拆

## 10、小红书虚拟产品选品助手：xhs-product-picker

/xhs-product-picker 我的 HR 背景和实战经验都在 hr-experience.md 里，读后帮我找一个适合做的小红书虚拟产品方向，直接给完整方案。

小灰实测时给它喂了一份 HR 背景文件（3 年招聘经验、筛过 4000 份简历、手里有面试题库），它给出的方向是《HR 视角的应届生简历急救手册》，而且点破了真正值钱的地方：你有的不是「做过 HR」这个头衔，而是 4000 份被淘汰简历的横截面视角、那张求职者永远看不到的面试官评分表权重——这些才是别人花钱也买不到的产品骨肉。最后产出的是完整方案文档，含产品定位、指南目录框架和启动计划。

## 11、GitHub README 美化：beautify-github-readme

你平常有没有遇到这样的问题：自己的开源项目代码写得不错，但 README 就几行干巴巴的文字，访客点进来三秒就关掉了，Star 数一直涨不动？

**beautify-github-readme** 这个技能主要解决的就是「让项目主页一眼就能看懂价值」这个问题。它会帮你重新组织 README 的结构，生成贴合项目主题的专属 SVG 标题横幅，整合真实的项目展示，最后输出好维护的 Markdown 结构。

```

小灰实测时故意只给了它一个三行文字的简陋 README，它没有瞎编功能，而是去核对了项目里 index.js 的真实代码，再提炼出项目定位：受众是谁、一句话价值是什么、视觉主题定成「CLI 终端暗色 + 单一绿色强调」，最后生成的 SVG 横幅里直接把 markdown 转纯文本的效果画了出来。

## 12、Waza：把工程师的工作习惯变成技能

你平常有没有遇到这样的问题：让 AI 帮忙开发功能，它经常上来就写代码，需求没问清楚、方案没对齐，写完才发现不是自己想要的，返工好几轮？

**Waza** 是知名开发者 Tw93（前端圈子很熟悉的名字）开源的技能集合，主要解决的就是「把工程师的好习惯固化成 AI 的工作流程」这个问题。安装后是 8 个子技能：/think、/hunt、/check、/write、/read、/learn、/ui、/health。比如 /think 会先帮你梳理需求、输出完整可执行的开发计划，确认无误再动手；/hunt 会系统性地帮你定位 Bug 的根本原因，而不是头痛医头。

比如：

```
/think 帮我梳理「给博客加一个评论系统」的开发需求，输出完整可执行的开发计划。
```

它的思路是「先想清楚再动手」，特别适合被 AI 的「上来就写」坑过的朋友。

小灰实测时让它规划「博客加评论系统」，它给出的不是通用套话，而是真的去翻了工程代码：发现部署到 GitHub Pages 后路径前缀会让评论组件匹配错 Discussion，还发现项目里没有 React 依赖、不能直接用官方封装——这两个坑不读代码是发现不了的。最后产出的计划里连「明确不做」清单都列好了。

## 13、横木：给项目做架构评审

你平常有没有遇到这样的问题：项目越写越大，心里总觉得架构有问题，但又说不清楚问题在哪；让 AI 帮忙 review，它只会泛泛地说「建议引入分层架构」之类的正确的废话？

**横木（hengmu）** 这个技能集合主要解决的就是「基于证据做架构评审」这个问题。它不会让 AI 凭空评论，而是要求每个架构问题都必须有项目里的实际证据支撑，输出的是一份经过验证的风险清单：问题在哪、证据是什么、怎么修、按什么顺序修。

比如：

```
/project-architecture-audit 帮我审计 demo-repo 这个仓库的整体架构，识别安全边界问题，输出经过验证的风险发现清单和可落地的修复方案。
```

拿自己正在维护的项目试一次，就知道它和普通的「帮我 review 一下代码」有多大区别了。

小灰实测时让它审计一个真实开源仓库，右侧是它画的核心流程信任边界图：哪些输入不可信、在哪里校验、在哪里发布，标得清清楚楚。每个结论都要落到仓库里的实际文件和证据，不是那种「建议引入分层架构」的正确的废话。

# 五、网站与信息获取

## 14、乔木 SEO：给网站做个专业体检

你平常有没有遇到这样的问题：自己的博客或小工具网站上线了，Google 却一直不收录，或者流量莫名下降，完全不知道问题出在哪？

**乔木 SEO（qiaomu-seo）** 这个技能主要解决的就是「像专业 SEO 顾问一样审计你的网站」这个问题。它会抓取并渲染你的网页，检查索引、结构、内容、代码层面的问题，最后输出一份按影响排序的问题清单：哪些问题最伤流量、诊断结论是什么、每一步具体怎么改。除了 Google 和 Bing，它还覆盖了 AI 搜索（也就是 GEO）的优化方向。

比如：

```
/qiaomu-seo 抓取并渲染阮一峰的博客 https://www.ruanyifeng.com，做一遍完整的 SEO 审计，按影响排序输出问题清单和修复建议。
```

没有自己网站的朋友，也可以像上面这样拿任意一个公开网站练手，看看专业审计报告长什么样。

小灰实测拿阮一峰的博客跑了一遍，它通过无头 Chrome 渲染页面，测试 HTTP 行为与 9 种爬虫 UA，还查出一个 P0 级安全隐患：首页被植入可疑第三方脚本，脚本通过 XOR 混淆真实域名，再创建隐藏 iframe 加载内容。这已经超出 SEO 的排查范围，代表网站存在被挂马风险。

## 15、Follow Builders：顶级 AI 创作者的动态简报

你平常有没有遇到这样的问题：AI 圈的信息太多太杂，想跟进一线开发者和顶级 AI 播客的最新观点，但自己没时间去刷 X、听播客，等中文社区的二手消息又总是慢半拍？

**Follow Builders** 这个技能主要解决的就是「帮你盯着二十多位一线 AI 创作者的动态」这个问题。它会定期把顶级 AI 播客和这些开发者在 X、YouTube、官方博客上的动态摘成简报，还能推送到你常用的消息应用。一次性的查询也支持。

比如：

```
/follow-builders 把最近一周顶级 AI builder 的观点整理成 5 条可执行的产品启发。
```

```
帮我设置一个每周一早上的 AI builder 双语摘要，覆盖播客、X 和官方博客。
