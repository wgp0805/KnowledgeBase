# 为什么越来越多人使用 OkHttp 5.5 ？

**大家好，我是锋哥。**

> 写 Java 的人以前提起 OkHttp，第一反应多半是「那是 Android 的库」。这几年这个印象在变。Spring 服务调外部接口、定时任务拉数据、桌面工具发请求，项目里的  `pom.xml`  越来越常出现  `okhttp` 。5.5 把 JVM 这条线又补了一截：加密 DNS、更稳的超时和代理，以及一套 Java 还能照旧用的 Builder。今天锋哥来好好聊聊 OkHttp 这个强大的开源项目 。

## 先认识一下 OkHttp

OkHttp 是 Square 出品的 HTTP 客户端，Android 和 JVM 上的 Java、Kotlin 都能用。你可以把它理解成应用和网站之间的交通调度：你交出一个请求，它负责找地址、建连接、做 TLS、收回响应。用完的连接不会立刻扔掉，下一次还能接着用。

在 Java 里，调用方式和 4.x 几乎一样，还是  `OkHttpClient.Builder`  和  `Request.Builder` 。库本身用 Kotlin 写，会带上  `kotlin-stdlib` ，业务代码不用改成 Kotlin。

很多人并不是亲手  `new`  一个客户端，而是通过 Retrofit 间接用上它。版本一升，超时、证书、拦截器这些行为都会跟着变。5.5 的讨论度不低，也是因为这条依赖已经躺在很多 Java 服务的调用链上，不只是手机 App。

![](assets/2026-10-22%20-%20%E4%B8%BA%E4%BB%80%E4%B9%88%E8%B6%8A%E6%9D%A5%E8%B6%8A%E5%A4%9A%E4%BA%BA%E4%BD%BF%E7%94%A8%20OkHttp%205.5%20%EF%BC%9F/30d38525417cd2836b823f6cdd5b8db7_MD5.jpg)

## Java 项目里也在换它

Java 11 以后，JDK 自带了  `java.net.http.HttpClient` ，简单请求够用。等接口一多，大家还是会去找现成的连接池、HTTP/2、拦截器和失败重试。OkHttp 这些都开箱就有，同步的  `execute()`  和异步的  `enqueue()`  也能并存。所以这几年，纯 Java 的后端、批处理和中间件里，它出现的次数明显多了。

5.0 起，OkHttp 把 JVM 和 Android 拆成了两套产物。Gradle 认模块元数据，写  `com.squareup.okhttp3:okhttp`  就会自动选到 JVM 包。Maven 认的是普通 POM，空的  `okhttp`  构件拉下来没有 class，Java 项目要显式依赖  `okhttp-jvm` 。这是 5.x 里 Java 用户最容易踩的一个坑，也说明官方在认真照顾 JVM 这条线，而不是只给 Android 发包。

同一时期还补上了 GraalVM 原生镜像、JPMS 的  `module-info` ，以及 IPv6 / IPv4 一起试的 Happy Eyeballs。服务要打成原生二进制，或者模块化工程要过编译期检查，这些都比「再包一层 Apache HttpClient」省事。

## 它平时在替你做什么

一次调用看起来就一行  `execute()` ，背后大致是这样：

![](assets/2026-10-22%20-%20%E4%B8%BA%E4%BB%80%E4%B9%88%E8%B6%8A%E6%9D%A5%E8%B6%8A%E5%A4%9A%E4%BA%BA%E4%BD%BF%E7%94%A8%20OkHttp%205.5%20%EF%BC%9F/1f6f5130020bdfc9454cd77336142dc9_MD5.png)

这张图里的每一格，OkHttp 都替你处理过不少麻烦事。HTTP/2 可以在一条连接上并发多个请求，响应默认支持 gzip。连接失败时，它会按自己的策略重试。从 5.0 开始，IPv6 和 IPv4 一起试，谁先连上用谁，避免某个地址族卡住整次请求。

客户端最好进程内共享一份。每来一个请求就  `new OkHttpClient()` ，连接池和线程池都会跟着新建，Java 服务里这是最常见的性能问题。

## OkHttp 5.5 新在哪里

### 域名也可以加密

普通 HTTPS 已经加密了网页内容。握手最开始仍有一段叫 SNI 的信息，里面写着你要访问的域名。咖啡馆的 Wi-Fi、公司网关，往往看不到你点开了哪一篇文章，却看得到你打开了哪个网站。

5.5 可以选配 Encrypted Client Hello，简称 ECH。它把这段域名也加密。路人更多时候只能看到 IP。网站如果挂在大型 CDN 上，同一个 IP 后面有很多站点，光看地址就更难判断你访问的是谁。

![](assets/2026-10-22%20-%20%E4%B8%BA%E4%BB%80%E4%B9%88%E8%B6%8A%E6%9D%A5%E8%B6%8A%E5%A4%9A%E4%BA%BA%E4%BD%BF%E7%94%A8%20OkHttp%205.5%20%EF%BC%9F/f4818c359e74c249eab280c2c297eb68_MD5.jpg)

这件事有前提。系统自带的 TLS 栈得支持 ECH。写这篇文章的时候，只有 Android 17（API 37，2026 年 6 月发布）满足。跑在 JDK 上的 Java 进程，握手里的域名加密还要等 JDK 的 TLS 接上。其他平台补齐之后，OkHttp 会再接进去。

配置本身是同一套。你换上能取到 ECH 配置的 DNS，服务器也发布了对应记录，以后平台一支持就能生效。版本号升到 5.5，只是把这扇门打开了。

开启之后，一次请求会多绕这么几步：

### DNS 不再只返回 IP

ECH 的公钥不写死在程序里，而是放在 DNS 的 HTTPS 记录中。旧的  `Dns.lookup()`  几乎只做一件事：把主机名解析成 IP 列表。公钥、ALPN、端口提示，都没有地方可放。

5.5 为此重做了 DNS。它可以查多种记录，结果可以异步、流式返回，并且带内存缓存。除了地址，还能拿到服务元数据，例如 ECH 配置、服务器支持的协议，以及建议使用的端口。这套 API 在 JVM 上就能用，Java 服务不必等 Android 17。

![](assets/2026-10-22%20-%20%E4%B8%BA%E4%BB%80%E4%B9%88%E8%B6%8A%E6%9D%A5%E8%B6%8A%E5%A4%9A%E4%BA%BA%E4%BD%BF%E7%94%A8%20OkHttp%205.5%20%EF%BC%9F/3f35ea215b06e2b1f8a699e471837eb8_MD5.jpg)

Java 里最实用的打开方式是  `DnsOverHttps` 。查询本身走 HTTPS，公司网络或公共 DNS 就不容易直接看到你在解析哪个域名。下面的例子走 Cloudflare 的  `1.1.1.1` 。Android 工程还可以用  `new AndroidDns()` ，它能向系统解析器要 HTTPS 记录，需要 API 29 以上；系统 DNS 默认不加密，域名仍可能在查询阶段漏出去。在意隐私的话，Java 和 Android 都优先 DoH。

### 顺手修好的几个问题

新特性之外，5.5 还修了一批 Java 服务里会碰到的问题：

- 关闭 multipart 某一段的 sink，不会再把整个请求体关掉。上传文件时，这个坑很具体。
- HTTP/1 会先把请求体刷出去，再摘掉超时，超时可以按预期生效。
- 系统代理选择器抛异常时，改为不走代理，整次调用不会因此崩溃。笔记本上开了系统代理、代理配置又不完整时，以前会直接把请求打挂。
- 默认的主机名校验会拒绝规范化失败的 IP。
- MockWebServer 的  `@StartStop`  可以配合 JUnit 5 的  `@Nested`  。Java 单测里分组测接口时用得上。

OkHttp 和 Retrofit、Okio、SQLDelight 一起加入了 Commonhaus 基金会，构件也换了新的签名密钥。这跟写业务没有直接关系，但说明这条依赖还在被认真维护。

## 三个能直接用的 Java 例子

Maven 用 BOM 锁版本，再显式依赖  `okhttp-jvm` 。Gradle 项目继续写  `okhttp`  即可，构建工具会选到 JVM 产物。

```xml
<dependencyManagement>
    <dependencies>
        <!-- 统一锁定 5.5.0，避免 okhttp 和插件版本不一致 -->
        <dependency>
            <groupId>com.squareup.okhttp3</groupId>
            <artifactId>okhttp-bom</artifactId>
            <version>5.5.0</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <!-- Maven 必须用 okhttp-jvm，okhttp 这个空包里没有 class -->
    <dependency>
        <groupId>com.squareup.okhttp3</groupId>
        <artifactId>okhttp-jvm</artifactId>
    </dependency>
    <dependency>
        <groupId>com.squareup.okhttp3</groupId>
        <artifactId>okhttp-dnsoverhttps</artifactId>
    </dependency>
    <dependency>
        <groupId>com.squareup.okhttp3</groupId>
        <artifactId>logging-interceptor</artifactId>
    </dependency>
</dependencies>
```

### 发一个最普通的 GET

超时仍然用  `TimeUnit` ，Java 不用去碰 Kotlin 的  `Duration` 。响应放进 try-with-resources，结束时会关掉响应体。

```java
import java.io.IOException;
import java.util.concurrent.TimeUnit;
import okhttp3.OkHttpClient;
import okhttp3.Request;
import okhttp3.Response;

// 整个进程共享这一份客户端，连接池才能复用
OkHttpClient client = new OkHttpClient.Builder()
    .connectTimeout(5, TimeUnit.SECONDS)
    .readTimeout(5, TimeUnit.SECONDS)
    .callTimeout(10, TimeUnit.SECONDS)
    .build();

Request request = new Request.Builder()
    .url("https://example.com/")
    .build();

try (Response response = client.newCall(request).execute()) {
    if (!response.isSuccessful()) {
        throw new IOException("请求失败：" + response.code());
    }
    System.out.println(response.body().string());
}
```

### 用加密 DNS 发请求

 `DnsOverHttps`  自己也要发请求，所以先准备一个引导客户端。正式客户端和 DoH 共用它的连接池与调度器。 `1.1.1.1`  本身是 IP，引导客户端不用再解析一次域名。

```java
import okhttp3.HttpUrl;
import okhttp3.OkHttpClient;
import okhttp3.dnsoverhttps.DnsOverHttps;

// 引导客户端只负责帮 DoH 发查询
OkHttpClient bootstrapClient = new OkHttpClient();

DnsOverHttps dns = new DnsOverHttps.Builder()
    .client(bootstrapClient)
    .url(HttpUrl.get("https://1.1.1.1/dns-query"))
    .build();

// newBuilder 会沿用原来的连接池和线程池
OkHttpClient client = bootstrapClient.newBuilder()
    .dns(dns)
    .build();
```

这套配置在普通 Java 进程里就能加密 DNS 查询。ECH 握手要等运行环境的 TLS 支持，目前是 Android 17。Android 工程如果暂时不上 DoH，可以换成：

```java
import okhttp3.OkHttpClient;
import okhttp3.android.AndroidDns;

OkHttpClient client = new OkHttpClient.Builder()
    .dns(new AndroidDns())
    .build();
```

### 拦截器里看一眼请求

拦截器仍是 OkHttp 最好用的扩展点。调试时加一个日志拦截器就够了。5.4 起，拦截器还能改缓存、连接池、DNS 这些原来只在 Builder 上设置的东西，需要自定义  `Call.Factory`  的情况少了很多。Java 服务里给某个下游单独换 DNS、单独加日志，都可以留在拦截器里。

```java
import okhttp3.OkHttpClient;
import okhttp3.logging.HttpLoggingInterceptor;

HttpLoggingInterceptor logging = new HttpLoggingInterceptor();
// BASIC 只打请求行和响应行，调试够用，日志也不会太吵
logging.setLevel(HttpLoggingInterceptor.Level.BASIC);

OkHttpClient client = new OkHttpClient.Builder()
    .addInterceptor(logging)
    .build();
```
