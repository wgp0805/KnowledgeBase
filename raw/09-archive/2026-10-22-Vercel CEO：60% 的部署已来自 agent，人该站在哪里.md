# Vercel CEO：60% 的部署已来自 agent，人该站在哪里

> **来源**: 人人都是产品经理  
> **链接**: https://www.woshipm.com/ai/6482555.html  
> **抓取日期**: 2026-10-22  
> **相关性评分**: 1.0

> Vercel 上编程 agent 的部署占比，从年初的 3% 涨到 60%。Guillermo Rauch 在播客里复盘十年十亿次部署如何变成十个月十五亿次，也谈了人该站在哪里。

![](https://image.woshipm.com/2026/01/13/bc2de7cc-f047-11f0-8f2f-00163e09d72f.png)

你有没有想过，如果有一天你每天在网上刷到的链接，大部分背后都不再是人写的代码，也不再是人点下的发布按钮，那互联网会变成什么样子？这件事其实已经在发生了。Vercel 的创始人兼 CEO Guillermo Rauch 在 Molly O’Shea 的播客 Sourcery 里说，今年年初，Vercel 上只有 3% 的部署来自编程 agent（智能体），现在这个数字是 60%。

Vercel 是做前端云平台的，Next.js 这个被广泛使用的网页框架就出自它们。据报道，它们已经做到 6 亿美元的年化收入，估值 93 亿美元，有 48.5 万个付费团队。这期访谈里，Guillermo 从自己在阿根廷自学编程的经历聊起，一路聊到 agent 时代互联网的形态、软件还要不要买、安全怎么办、开源模型为什么占了大头，以及工程师这个职业会变成什么。他聊得很广，我挑的是“当写代码的主力变成机器，人该站在哪里”这条线，每一节先讲他是怎么说的，再写我自己的想法，分享给大家。

## 花了十年做到十亿次部署，接下来十个月又多了十五亿次

Guillermo 先给了一组数字：Vercel 花了大约十年，才累计到十亿次部署，而从那之后的十个月里，他们又新增了十五亿次。他说，每当你改动一次应用并发布，就是一次部署，所以这个数字的本质是“有多少改动被送到了世界上”。他自己的解释很直接：写代码这件事“并没有变容易，代码依然很难”，但现在有编程 agent 在替人写，而他觉得没有人真正预见到这一点，连身处 AI 领域的人也没有，“超音速海啸”一样，机器接管了。

他特别提醒了一句他自己信奉的原则：“代码是一种负债。”代码可能有漏洞，可能删掉东西，可能泄露客户数据，所以你必须对代码负责。可当编程 agent 变得“超人一样”地擅长写代码时，有一件事没有变：代码自己什么也做不了，它需要被部署到某个地方。他说，Vercel 恰好成了所有编程 agent 汇聚、把代码推向世界的那个地方。所以他每天在 X 上刷到的东西，“几乎每隔一个就是一个 Vercel 部署”，有时候从默认域名就能看出来，有时候则是 OpenAI 和 Meta 这样的大公司在上面部署。

我觉得这段话里最有分量的，是“代码是负债”这个说法。过去一两年大家一直在欢呼“写代码的成本趋近于零”，但 Guillermo 讲的是另一面：生成越便宜，需要被运行、被维护、被验证的东西就越多，负债也越多。部署量的爆发，从另一个角度看，其实是在说明“制造代码”的速度已经远远超过“为代码负责”的速度，而 Vercel 的位置，正好卡在两者之间。

他还提到，Vercel 因为同时看到了编程 agent 的活动，又在分发 AI 的 token（令牌，模型输入输出的计量单位），所以像是一个“AI 往哪里走的指数”。这个视角很特别：一家基础设施公司，不靠预测，而是靠自己的流量表，直接看到行业的风向。

## 拒绝”不求甚解”：用 AI 可以，但要弄明白它在做什么

Molly 问他还写不写代码。Guillermo 说，他最近发过一条很火的推文，叫“reject non-understanding”，也就是拒绝“不求甚解”。他说现在有两派：一派是告诉 AI 想做什么，甚至看都不看，按个按钮就发布；另一派是他推荐给自己孩子的做法，使用 AI，但同时要理解它在做什么。他前一晚还在陪孩子做数学作业。他自己越来越多的时候是让 AI 把它做的事讲给他听，并把自己比作一位工程经理：帮团队排优先级、清障碍，偶尔也自己写代码去验证、挑毛病、做基准测试，把一线的反馈带回来。他说，他认识的最好的工程经理，“首先是爱代码的人”。

他这个周末就写了一个所谓的“证明系统”（proof system），用来保证 AI 不会交付垃圾，也不会误把你的数据扔到外面，而且他“有意识地读了很多代码”，因为代码正在越来越多地运行我们的生活：他提到一级方程式赛车因为一次软件更新引发了很大的风波，引擎怎么工作都由代码决定，去医院也是一样。

同时他又很清醒：他不想做那个告诉所有人“你必须理解每一行代码”的人，因为他小时候在阿根廷学编程，难到不行：软件买不起，手册全是英文，他不得不先自学英语才能学代码，这些门槛现在被削平了，他觉得是“奇迹”。所以他的说法是，系统有两种，一种是小写的 systems，一种是大写的 Systems：前者可以让人尽情去 vibe code（凭感觉让 AI 生成代码），后者承载数据、关键基础设施、国家安全，必须有懂行的、被 agent 武装起来的工程师。

我觉得这是一个很有用的分层。关于“要不要理解 AI 写的代码”，网上常见的争论是二选一，Guillermo 给了一个按后果分级的办法：做个人小工具，可以放手玩；做会影响别人的东西，就得有人能说清楚它为什么对。放到我们每个人的工作里也适用，AI 帮你写的报告、做的表格、跑的分析，不一定要自己重做一遍，但至少要具备判断它哪里可能错的能力。工程经理这个类比也很妙：你的角色不是亲手写每一行，而是知道好的东西长什么样，并且对结果负责。

## 互联网要为 agent 再做一遍：它们不需要好看，只要信号

Guillermo 说，互联网最初是由页面和以人为中心的界面构成的，你打开网站，你是消费者，是机器对人。接下来的时代是 agent 对 agent。他举了一个很具体的例子：当一个 agent 访问 vercel.com，他不会给它看那个带渐变的漂亮三角形动画，“agent 不在乎，agent 要的是纯粹的信号”，所以他们给 agent 的是关于自己业务的、极精确的信息。他说，如果你让 Muse 帮你做个网站，它会去访问 Vercel，获取怎么建软件的信息，然后再为用户做东西，所以你需要对这些 agent“展示你最好的一面”。

他还说，有一个现象很讽刺：互联网在过去很大程度上是被建来挡机器人的，而 Vercel 采取的是相反立场。Molly 转述了 Stripe 的 John Collison 的话：既然什么都是机器人，那还需要机器人检测吗？Guillermo 的回应是，你需要的是 bot intelligence（机器人情报）：搞清楚来的是 ChatGPT、Grok 还是 Claude，它们有没有得到好的体验。因为人们现在发布到网上的，除了静态信息，还有能力，所以你要把自己的工具、产品和服务暴露给 agent。他讲到互联网的底层语言也在变：给人看的是 HTML，给 agent 的是新的协议，比如 MCP（模型上下文协议，用来告诉 agent 一个服务有哪些工具可用），还有机器支付协议和通用商务协议。他们和 Stripe、Shopify 合作，让 agent 能直接交易，现在已经有 agent 在 Vercel 的市场里自己买服务，比如买一个浏览器，“全程没有人介入”。

他还给了一个很实用的提醒：模型有训练截止日期，所以搜索互联网成了 agent 的基础工具之一，企业仍然要把自己的内容放好。他举例说，你做播客，最好附上逐字稿，这样当别人的 agent 问“Molly 说过什么”的时候，就更容易找到你。

我觉得这一节讲清楚了一件事：SEO（搜索引擎优化）之后，下一个要补的功课是“让 agent 读得懂、用得上”。过去我们为人设计页面，要考虑视觉、情绪、动线；将来还得再做一套给机器的版本，它要的不是好看，而是结构清晰、能力可调用。这听上去像是技术问题，但实际上是生意问题：如果你的产品对 agent 不友好，在越来越多的“我让 agent 去办”的场景里，你就等于不存在。Guillermo 说“如果不做这个转变，就会被挡在这个时代最令人兴奋的经济机会之外”，我觉得并不夸张。

## 软件不会消失，只是你不再需要去”买”它

Molly 提到，Salesforce 也走向了 headless（无头，意思是不再依赖前端界面，让别人通过接口使用），问最终的形态是什么。Guillermo 说，他的观点“非常有主见”，几乎站在反面：他不相信把成堆成堆的软件聚合起来、做成最低公约数的软件，他相信的是个性化软件。他说，Vercel 让你对着编程 agent 提示一下，就能生成完全适合你的软件，比如一个正好符合你需要的播客日程笔记 agent。对企业来说，做自己领域专用的工具，回报要大得多。以前有一类 SaaS 叫 no code（无代码），他是反过来的 “yes code”，因为编程 agent 让代码基本免费。所以他说的“致命组合”是：“你买或租一个平台，然后就再也不需要买软件了，因为你可以按需求生成。”

那 Salesforce、SAP 这类公司的位置在哪里？他的回答是：软件需要数据。你可以生成漂亮的会议准备或报告，但它们得从某个地方拿数据：客户历史在哪里，联系人在哪里，会议记录在哪里，工单在哪里，这些是关键的数据基础设施，他“不会叫它软件”。headless 的意思，就是我们不再自己去“头部”那里，由 agent 去系统里取数据，再生成新的软件或可视化。他举了自己的例子：Vercel 内部有个部署在 Slack 里的 agent，他可以说“帮我准备跟 Molly 的会，她多频繁在 Vercel 上部署，报告过哪些问题”，他从头到尾没有打开过 Salesforce。而这样的界面是“生成式”的：问个人，就渲染一份个人资料；问公司，就给出更多公司背景，还会根据你的经验水平调整给你的信息深度，更像电影《少数派报告》里信息主动找你的样子。

我觉得他这套说法里最耐人寻味的，是“软件”和“数据基础设施”的重新划界。过去我们把一整套固定的界面、流程和数据打包卖，叫软件；现在界面和流程可以随时生成，真正稀缺的是那份记录着“事实”的数据。这意味着护城河的位置在搬家：靠界面锁住用户的做法会越来越难，靠“这是唯一可信的记录”锁住用户的做法反而越来越重要。对做 SaaS 的人来说，值得自问一句：如果明天所有人都通过 agent 来用我的产品，我还剩下什么？

## agent 像是被摘掉了前额叶的士兵，所以安全要从沙盒做起

说到安全，Guillermo 先给出了他对过去几年变化的概括：从 ChatGPT 到今天，核心变化是自主性。以前每一步都要人在回路里，“告诉我这个，再告诉我那个”，现在把这件事放进循环，就是 agent，而且我们训练它们跑得越来越久。他说 agent 会“不惜一切代价”完成任务，“像一个前额叶被摘掉的士兵，一路冲”。他举例：你让它找 Molly 的邮箱发生日祝福，四十分钟后它回来说搞定了，可能是翻了 Crunchbase，也可能是从某个 YouTube 评论里翻出来的。体验很好，但风险也在这里：如果那条评论里被人埋了 prompt injection（提示词注入，藏在内容里、专门指向 agent 的恶意指令），agent 就可能被说服去做坏事，而且用的是你的令牌、你的工具、你的资源。

他提到 OpenAI 的 agent 攻入 Hugging Face 的事件，说让他担心的是，agent 第一次逃出来，用的是一个“非常好的沙盒”。他还吐槽了“沙盒”这个词，说它经常被滥用，一台能访问整个世界的电脑算不上沙盒，真正的沙盒应该像把老鼠关在一个你砸不开的玻璃箱里，你看着它转圈。他还说，编程 agent 擅长找漏洞，因为要写好代码，就得懂代码的规则，懂规则就懂得怎么打破规则。为此 Vercel 拿出 100 万美元办了一次沙盒挑战，邀请全世界来攻击，结果只有一个人带着一支 agent 大军取得了进展，这位白帽黑客的贡献还发现了 Linux 里的一个关键漏洞，他们正在与行业同行分享。

他对未来几年的判断是：“好 token 和坏 token 之间会有一场战争。”他不同意因为网络安全风险就禁止开源模型，因为模型之所以擅长网络安全，只是因为它足够聪明，禁止它就等于禁止获取智能，而这份智能可以被用于防守。他同时也说未来几年会“颠簸”，需要加固很多地基。他也留下了一个乐观的方向：他提到 OpenAI 证明了 Navier-Stokes，没有数学家能读懂那份证明，他认为我们的代码会逐渐走向“可以近乎数学地证明正确”，因为 agent 精力用不完，能做到人类中极少数人才能做到的事。

我觉得“前额叶被摘掉的士兵”这个形容很准确，也很值得放在每个想部署 agent 的团队桌面上。agent 的危险往往不在于它恶意，而在于它太会完成任务，任务的定义又恰好有缝隙。所以做 agent 的安全，最重要的不是“让它更听话”，而是事先划清边界：它能碰什么、不能碰什么，别人能不能偷偷改它的目标。至于他说的“可以证明正确的代码”，我觉得是整场里最让人期待的一点：如果机器写代码比人快，那就该让机器同时承担验证的工作，让人把精力放在判断“该证明什么”。

## 八成的 token 来自开源模型，选模型这件事正在变成选零件

Guillermo 说，Vercel 运营着全球最大的 token 分发网络之一，把几乎所有模型厂商和开源模型聚合起来，并把匿名化的汇总数据以 Creative Commons 协议公开出来。他说，今年年初，流量里大头还是 OpenAI、Anthropic、Google 这样的闭源模型，而现在情况几乎完全翻转：他们网络里 80% 的 token 来自开源模型，这条推文也火了。

他给出了几点原因。他自己是全世界最大的开源拥护者之一，却很长一段时间没法“言行一致”，因为开源模型写代码太差。但近几个月出现了几家实验室的开源模型，水准已经非常接近前沿，他前一天还在用其中的一个，感叹“这模型太好用了”。更关键的是企业意识到：自己 80% 的工作只需要某个级别的智能，“我不需要雇爱因斯坦来回答每一张客服工单、检查拼写、给数据分类”。所以现在很常见的做法是，制定计划时用最强的模型，也就是“爱因斯坦级别”的智能来写方案，而执行阶段把计划变成代码和操作，几乎所有开源模型都做得很好。未来是“一个选项组合”：企业不希望被锚定在某一家实验室上，而是把模型当成可更换的引擎，换掉只要一行代码。他甚至希望用户不用先选模型，而是直接提需求，让系统根据上下文和所需智能来路由，当然也要给高端工程师保留自己选择的余地。

Molly 追问：frontier（前沿）模型的风险在哪？他的回答是，最大的风险是很难知道真实的留存。他给年轻创始人的建议是：“盯住那些无法作弊的指标。”顶部漏斗可以花钱买广告买出来，但客户能不能一直留到第十年，才是真的。而模型公司“基本没有忠诚度”。他还说，AI 里有些元素让他想起加密货币的“来得容易，去得也容易”，有人一直在用，有人只是赶热点，也有制造用量、搞免费促销的。他还留意到，如果前沿模型的领先优势真的持久，这些实验室为什么都在做各种应用，今天推个 Slack 的翻版，明天推别的？这说明它们也在从单纯的 token 供应商向外分散。同时他也说，不会说这些公司明天就消失，前沿智能永远有需求，只要你的模型真的聪明，又在经济上撑得住。

我觉得这一节最值得带走的，是“把模型当零件”这个思路。如果换一个模型只需要改一行代码，那么模型之间的竞争就更像是商品之间的竞争，价格会被压低，而忠诚度会转移到离用户更近的那一层：谁最了解你的场景，谁就更难被替换。这也解释了为什么 Guillermo 如此强调“拥有自己的智能栈”。另一点是他说的“无法作弊的指标”，在 AI 这个热闹的行业里，用量、融资、榜单都可能被运营出来，只有客户愿不愿意长期留下，最难伪造。我们自己判断一家 AI 公司，也可以用这把尺子量一量。

## 从”写出漂亮的代码”到”分配 token”，工程师的自我要先死一次

聊到工程师这个职业，Guillermo 说得很坦白。他提到 DHH（Ruby on Rails 的创造者）那场演讲，两个人都曾经热爱为人类设计愉快的开发体验：漂亮的代码、写起来顺手的语言，“是为我们这些灵长类的小手准备的”。但他很多年前就被“AI 的蚊子叮了一口”，意识到把他们带到这里的东西，不会带他们去下一站。他说这需要勇气，因为你得一本正经地站在公司面前说：你们爱上的那个东西，已经不在了。他把这个过程叫做“ego death（自我之死）”，你必须忘记是什么让你走到今天。

他提到 Rust 这门语言：它总在告诉你“你错了”，用接近数学的符号告诉你违反了哪几条规则，过去需要一种特别的性格才能咽下这粒药，而现在这件事交给编程 agent 就好。他说，他们认为所有代码都会变得更安全、更快。接着他引用了 Marc Andreessen 的说法“最后一份工作是风险投资人”，改写成“资本配置者”：工程师现在做的是分配 token，每个人的时钟都一样，而我们手里多了“token 这个超能力”，要把它们投向哪里，让它们去研究什么，用什么语言和工具，这是核心。

他也讲了怎么招人：现在做出一个 demo 已经不稀奇，他想看到的是你能不能指挥一大群 agent，并且从中获得杠杆，有人称之为 agentic engineering（代理式工程）或“软件工厂”。同时他仍然非常看重沟通能力，“我不想读你用 AI 写的推文废话，我想听你真正怎么想”。他还说，Vercel 的客户经理和前线工程师，现在要有高得多的技术水平，因为有好奇心加上会提问，每个领域都变得可以攻克。他们和 Mercedes 的合作就是例子：把旧技术栈迁移到新平台的第一轮，用 agent 只花了五分钟，“这在过去要几个月”。他引用 Splunk 前 CEO 的话：公司里最有价值的两类人，是靠近代码的人和靠近客户的人，而现在这两端是同一种人，这两端现在合在了一起，既要靠近客户，也要靠近代码和 agent。

我觉得“自我之死”这个词用得很重，但值得认真对待。很多人在职业上有一种隐形的骄傲：我写得一手好代码，我对这个领域的细节比别人熟。可当这类技能被商品化，真正拉开差距的就是判断力：该做什么，不该做什么，值不值得。“分配 token”这个说法，把这一点讲得很具体，因为每个人的时间都一样，真正的稀缺是“在哪里下注”。

他讲迁移那个例子也让我想到，过去要靠咨询顾问和敏捷教练长期折腾的事，现在被压缩到几分钟，这意味着，所有“因为太麻烦所以一直没做”的事情，都会被重新放回桌面。这对公司和个人都是机会，也是压力。

## 我自己的一点思考

听完这场对话，我最大的感受是，Guillermo 讲的所有事情，几乎都在回答同一个问题：当机器成了写代码、用互联网、做交易的主力，人要站在哪里？他的答案有三层。第一层，人要继续理解，所以他才说要“拒绝不求甚解”；第二层，人要给机器设边界，所以有沙盒、有证明系统、有对 prompt injection 的警惕；第三层，人要决定方向，所以工程师变成“资本配置者”，每个人都在分配 token。

他有一个观点我格外认同：写代码本身不再稀缺，稀缺的是为代码负责。这在他的“代码是负债”一句里最清楚，而 60% 的部署来自 agent，恰好把这个负债推到了前所未有的规模。你可以乐观地说，这是一场史无前例的创造；也可以谨慎地说，这是一场史无前例的责任转移，机器在写，人却仍然要为后果签字。这两种说法并不矛盾，它们同时成立。

另一个让我印象深刻的是，他对“人”这一端的坚持。他一边说互联网要为 agent 重做，一边又说，真正面向人的体验要做到最有人味，沟通能力会更重要，信任关系依然是人建立的。这听上去有点反直觉，实际上很合理：机器越来越多的时候，人与人的交互反而成了稀缺品，值得投入更多。

最后说一句我自己的判断：接下来几年，真正拉开差距的，不是谁用上了更强的 AI，而是谁在这些 AI 身边，建好了让它既能跑得快、又不会跑偏的那套基础设施和判断力。
