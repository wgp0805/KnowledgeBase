# 扣子（Coze）工作流入门学习笔记

> 学习日期：2026-08-11
> 学习目标：理解工作流的核心概念，通过手动搭建体验工作流的运作方式

---

## 一、关于自动生成工作流的说明

扣子（Coze）实际上已经支持**根据一句话自动生成工作流**。例如输入"帮我做一个文本摘要工作流"，扣子可以自动生成完整的节点和连线。

但本次学习的目的是**理解工作流的核心概念和运作机制**，因此选择**手动搭建**工作流，而非使用自动生成功能。通过手动配置每个节点、连线、数据流和条件分支，能更深入地理解：

- 工作流的数据如何在节点间流转
- 条件分支的判断逻辑
- 多分支汇合时的数据处理
- 每个节点输入输出的对应关系

这些是使用自动生成无法获得的体验。

---

## 二、工作流核心概念

### 1. 什么是工作流

工作流就是把一个复杂任务，拆成若干个有序的步骤，每步的输出是下一步的输入，自动化地跑完整个流程。

### 2. 核心要素

| 要素 | 说明 | 举例 |
|------|------|------|
| 触发器 | 什么时候启动 | 收到输入 / 定时 / 提交表单 |
| 节点(Node) | 每一步做什么 | 调大模型 / 发邮件 / HTTP请求 |
| 数据流 | 数据怎么传递 | 上一步的变量传给下一步 |
| 条件分支 | 不同情况走不同路 | 按文本类型走不同总结逻辑 |
| 变量聚合 | 多分支汇合 | 把多条分支的输出合并 |

## 三、实操项目：智能摘要工作流

### 目标

用户输入一段长文本，工作流自动：

1. 判断文本类型（新闻 / 技术 / 日常）
2. 根据类型用不同方式总结
3. 输出摘要 + 关键词

### 完整流程图

```
[开始]                user_text
  |
[大模型: 判断类型]      text_type
  |
[选择器] --- 新闻 --> [大模型: 总结-新闻版]  -- result --+
        |--- 技术 --> [大模型: 总结-技术版]  -- result ---+--> [变量聚合] --> final_result --> [结束]
        --- 否则 --> [大模型: 总结-日常版]  -- result --+
```

### 搭建步骤

#### 第1步：创建工作流

1. 登录扣子（coze.cn），点击左侧"工作流"
2. 点击"创建工作流"
3. 命名："智能摘要"
4. 描述："输入长文本，自动总结并提取关键词"

#### 第2步：配置开始节点

添加输入参数：

- 参数名：user_text
- 类型：String
- 描述：用户输入的长文本

#### 第3步：添加大模型节点 - 判断文本类型

- 节点命名："判断类型"
- 模型：豆包（默认即可）
- 输入：引用 user_text
- 系统提示词：

```
你是一个文本分类助手。请判断以下文本的类型，只返回一个词：
- 如果是新闻/资讯类，返回"新闻"
- 如果是技术/教程类，返回"技术"
- 如果是日常/生活类，返回"日常"

只返回这一个词，不要其他内容。

文本内容：
{{user_text}}
```

- 输出变量名：text_type

#### 第4步：添加选择器（条件判断）节点

连接：[判断类型] -> [选择器]

配置条件：

- 条件1：text_type 等于 "新闻"
- 条件2：text_type 等于 "技术"
- 否则（false）：走默认分支

#### 第5步：添加三个总结节点

**新闻版总结节点（大模型）：**

```
请将以下新闻总结为3句话，并提取3个关键词。
格式:
摘要：xxx
关键词：xxx、xxx、xxx

新闻内容：{{user_text}}
```

**技术版总结节点（大模型）：**

```
请将以下技术文章总结，按这个格式输出：
核心要点：1句话
步骤概要：分点列出
关键词：3个

技术内容：{{user_text}}
```

**日常版总结节点（大模型）：**

```
请用轻松的语气，将以下内容总结为2句话，并提1个关键词。

内容：{{user_text}}
```

每个节点输出变量名：result

#### 第6步：添加变量聚合节点

将三个总结节点的输出都连接到变量聚合节点：

- 输入：总结-新闻版.result、总结-技术版.result、总结-日常版.result
- 输出：final_result

#### 第7步：结束节点

输出变量 output 引用 {{final_result}}

#### 第8步：测试与发布

1. 点击"试运行"，输入一段文本测试
2. 确认走对了分支，输出正确
3. 发布工作流
4. 可创建 Bot 并关联此工作流，发布到扣子网页版

## 四、遇到的问题与解决

### 问题1：选择器节点的 "false" 端口未连接

**报错信息：**

```
node "选择器"'s port "false" has not be connected
```

**原因：**

选择器节点有多个出口（条件1、条件2、否则/false），每个出口都必须连接到某个节点。当所有条件都不满足时的默认出口（false）没有连接到任何节点，就会报错。

**解决：**

将 false 出口连接到一个节点。两种方式：

- 方式一：直接连到结束节点（不处理默认情况）
- 方式二：加一个"通用版总结"节点处理默认情况（更完整）

**经验：工作流中每个分支出口都必须有去处，不能悬空。**

### 问题2：三个分支输出无法对应结束节点的同一个字段

**问题：**

三条分支（新闻 / 技术 / 日常版总结）各有输出变量 result，结束节点只能引用一个，无法将三个 result 对应到同一个输出字段。

**原因：**

选择器每次只走一条分支，但结束节点需要统一引用一个变量。多分支的输出无法直接合并。

**解决：**

添加"变量聚合"节点，将三个分支的 result 汇聚为一个变量 final_result，结束节点引用这一个变量。

**经验：分支后必须聚合。变量聚合是工作流中处理多分支汇合的标准模式。**

## 五、学习收获总结

通过本次手动搭建，掌握了工作流的以下核心概念：

| 概念 | 实践方式 |
|------|---------|
| 触发器 | 开始节点接收用户输入 |
| 节点 | 大模型节点、条件判断节点、变量聚合节点 |
| 数据流 | 变量在节点间传递 |
| 条件分支 | 选择器节点，按文本类型走不同路 |
| 分支聚合 | 变量聚合节点，合并多条分支输出 |
| AI调用 | 大模型节点 + Prompt 工程 |
| 交付 | 发布为 Bot 供他人使用 |

### 关键经验

1. **每个分支出口必须连接** - 选择器的所有出口（包括 else）都要有去处
2. **分支后必须聚合** - 多条分支汇合时需要用变量聚合节点
3. **数据流是核心** - 理解变量怎么从上一步传到下一步是关键
4. **手动搭建的价值** - 自动生成虽快，但手动搭建才能理解工作流的运作机制
