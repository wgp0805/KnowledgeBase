这时候，Ponytail 就很有意思了。它不是让 AI 更会“炫技”，而是让 AI 学会克制：能不写就不写，能用标准库就别造轮子，浏览器原生支持就别上依赖，一行能解决就别写五十行。简单说，它想把那个“经验丰富、话不多、出手就删代码”的资深程序员，塞进你的 AI 编程助手里。

## 项目简介

Ponytail 是一个开源的 AI Agent 技能项目，核心理念很直接：最好的代码，是你根本不用写的代码。

它主要面向 Claude Code、Codex、GitHub Copilot CLI、Gemini CLI、OpenCode 等 AI 编程工具。安装之后，它会给 AI 注入一套“懒但不敷衍”的开发规则。这里的懒不是偷工减料，而是工程上的高效：先判断需求是否真的存在，再看标准库、平台原生能力、已有依赖，最后才写最少可用代码。

比如你让 AI 做日期选择，普通 Agent 可能会引入 flatpickr，再写一堆封装。Ponytail 的思路可能是：

```
<!-- ponytail: browser has one -->
<input type="date">
```

这就是它的魅力：不是不会写复杂代码，而是先问一句，“真的需要复杂吗？”

Ponytail 还提供了 `ponytail-review` ，专门用来检查过度工程化。它会帮你找出重复造轮子、不必要依赖、空泛抽象、死代码和“为了以后可能用得上”的灵活性。对于经常用 AI 写代码的你来说，这个功能非常实用。

## 项目安装与使用

使用 Ponytail 前，建议你的环境里能正常访问 [Node.js，因为](http://node.xn--js,-f88dj90b/) Claude Code 和 Codex 插件会用到很小的 Node 生命周期 Hook。如果 Node 不在 PATH 中，核心规则仍然能用，只是自动激活能力可能不会完整生效。

在 Claude Code 中安装，可以使用：

```
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
```

在 Codex CLI 中，可以这样安装：

```
codex plugin marketplace add DietrichGebert/ponytail
codex
```

进入 Codex 后，打开 `/plugins` ，选择 Ponytail marketplace 并安装 Ponytail。之后再到 `/hooks` 中检查并信任它的生命周期 Hook，然后新开一个会话即可使用。

如果你使用 GitHub Copilot CLI，可以运行：

```
copilot plugin marketplace add DietrichGebert/ponytail
copilot plugin install ponytail@ponytail
```

在交互式 Copilot CLI 中，也可以使用类似的 slash 命令：

```
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
```

如果你使用 Gemini CLI，安装方式更简单：

```
gemini extensions install 
            https://github.com/DietrichGebert/ponytail
```

OpenCode 用户则需要先拉取这个仓库，然后在 `              opencode.json            ` 中加入插件配置：

```
{
  "plugin": ["./.opencode/plugins/
            ponytail.mjs"
          ]
}
```

安装完成后，你就可以直接在 AI 编程会话中使用 Ponytail 的思路了。比如你可以说：

```
用 ponytail 模式帮我实现一个邮箱校验
```

它可能不会上来就写复杂的正则校验类，而是先判断你的场景。如果只是前端输入提示，它可能建议使用最简单的包含 `@` 判断；如果是真实账号验证，它会提醒你最终应该依赖邮件确认流程，而不是迷信正则。

你还可以切换不同强度：

```
/ponytail lite
/ponytail full
/ponytail ultra
```

`lite` 更温和， `full` 是默认模式， `ultra` 则适合你觉得代码库已经被过度设计折磨过的时候。

如果你想检查当前代码有没有写复杂，可以使用：

```
/ponytail-review
```

它不会像普通 Code Review 那样长篇大论，而是直接告诉你哪里能删、用什么替代、能减少多少行。比如它可能指出：某个只有一个实现的接口可以先删掉，某个日期格式化库可以换成 `              Intl.DateTimeFormat            ` ，某段手写循环可以用标准库一行完成。

## 总结

Ponytail 最吸引人的地方，不是它让 AI “少干活”，而是让 AI 更像真正有经验的开发者：先想清楚，再动手写。它能帮你减少不必要的依赖、样板代码和抽象层，让项目更轻、更直接，也更容易维护。

作为一个免费开源项目，Ponytail 很适合经常使用 AI 编程工具的开发者尝试。你可以把它当成 AI Agent 的“减法思维插件”，让你的助手不再为了显得聪明而写复杂代码。下次遇到小需求，不妨让 Ponytail 帮你先砍一刀，也许你会发现：真正高级的代码，往往就是刚刚够用的那几行。
