## 一、先认识一下这只"猫"

做 Java Web 的同学，几乎没有谁没跟 Tomcat 打过交道。哪怕你从没手动下载过它，只要用过 Spring Boot，启动日志里那句  `Tomcat started on port 8080`  你一定眼熟——Spring Boot 默认内嵌的 Web 容器就是它。

Tomcat 是 Apache 软件基金会的开源项目，前身是 Sun 公司捐出来的 Servlet/JSP 参考实现，1999 年发布第一个版本，到今天已经二十多年了。它的定位一直很清晰：**一个轻量级的 Servlet 容器**。WebLogic、WildFly 这类"全家桶"应用服务器会把 Jakarta EE 几十个规范统统实现一遍，Tomcat 只挑 Web 开发最常用的那几个：Servlet、JSP（现在叫 Jakarta Pages）、EL 表达式、WebSocket 等。少即是多，这也是它启动快、占用小、上手简单的原因。

打个比方，Tomcat 就像公司的前台：外面来的 HTTP 请求先到它这儿，它负责接待、登记、分拣，再交给对应的部门（也就是你写的 Servlet）去处理，最后把结果送回给客户。

其中 Connector（内部代号 Coyote）负责"网络通信"，Engine 到 Wrapper 这一串（内部代号 Catalina）负责"找到谁来处理"。后面要讲的虚拟线程，动的就是 Connector 这一层的线程模型。

目前官方还在维护的有三条版本线，区别主要在规范和 Java 版本上：

| Tomcat 版本 | 对应平台 | Servlet 版本 | 包名 | 最低 Java |
| --- | --- | --- | --- | --- |
| 9.0.x | Java EE 8 | 4.0 |  `javax.*`  | 8 |
| 10.1.x | Jakarta EE 10 | 6.0 |  `jakarta.*`  | 11 |
| 11.0.x | Jakarta EE 11 | 6.1 |  `jakarta.*`  | 17 |

## 二、Tomcat 11 新特性一览

Tomcat 最新版本已经到了 11.0.27，Spring Boot 4.x 默认内嵌的也换成了 Tomcat 11。可以说，它已经是 Java Web 新项目的"默认选项"了。

先放一张全家福，后面挨个聊：

![图片](assets/2026-10-25%20-%20Tomcat%2011%20%E5%88%B0%E5%BA%95%E6%9C%89%E5%A4%9A%E5%BC%BA%E5%A4%A7%20%EF%BC%9F/0bafb9dbf71a2a981034e457f5f86d87_MD5.jpg)

**2.1 底座升级：Java 17 起步，对齐 Jakarta EE 11**

Tomcat 11 最低要求 Java 17（10.1 是 Java 11）。别小看这一步，底座抬高之后，Tomcat 自己的代码可以放心使用新的语言特性，也能更自然地接上 Java 21、Java 25 的新能力。

规范层面，它实现了 Jakarta EE 11 里 Web 相关的这一组规范：Servlet 6.1、Pages（JSP）4.0、Expression Language 6.0、WebSocket 2.2、Authentication 3.1、Annotations 3.0。

好消息是，如果你已经在用 Tomcat 10.1，包名早就是  `jakarta.*`  了，升级基本是平滑的；至于从 Tomcat 9 过来的同学要面对什么，留到 3.3 节再说。

### 2.2 虚拟线程：改一行配置，扛更多并发

这是我个人觉得最值得聊的一点。（10.1 的后期版本其实也能开，但搭配 Java 21+ 和 Tomcat 11 才是现在的主流组合。）

传统模式下，Tomcat 用一个线程池处理请求，默认最多 200 个线程（ `maxThreads="200"` ）。一个请求占一个线程，如果请求里要查数据库、调远程接口，这个线程就只能干等着。干等的线程一多，池子就满了，新请求只能排队——像极了收费站前堵成一串的大货车。

虚拟线程是 Java 21 正式推出的轻量级线程，由 JVM 自己调度，创建成本极低，一台机器上开几十万个都不在话下。更关键的是，它遇到 IO 阻塞时会自动"让出"底层真正干活的平台线程，让别的任务先跑。于是"一个请求一个线程"这种最好写、最好调试的同步代码，也能扛住高并发了。

![图片](assets/2026-10-25%20-%20Tomcat%2011%20%E5%88%B0%E5%BA%95%E6%9C%89%E5%A4%9A%E5%BC%BA%E5%A4%A7%20%EF%BC%9F/2a2228530ee10dadfea5a47f5d465115_MD5.jpg)

在 Tomcat 11 里开启虚拟线程，改  `conf/server.xml`  就行，两种写法任选：

```xml
<!-- 写法一：直接在连接器上打开开关，最省事 -->
<Connector port="8080" protocol="HTTP/1.1"
           connectionTimeout="20000"
           useVirtualThreads="true"
           redirectPort="8443" />

<!-- 写法二：定义一个虚拟线程执行器，多个连接器可以共用 -->
<!-- 注意：Executor 必须写在 Connector 前面 -->
<Executor name="virtualExecutor"
          className="org.apache.catalina.core.StandardVirtualThreadExecutor"
          namePrefix="tomcat-virt-" />
<Connector port="8080" protocol="HTTP/1.1"
           executor="virtualExecutor"
           connectionTimeout="20000" />
```

如果用的是 Spring Boot，更简单，配置文件里加一行：

```ini
# 开启虚拟线程，内嵌 Tomcat 会自动切换到虚拟线程执行器
spring.threads.virtual.enabled=true
```

想确认是不是真的生效了？写个 Servlet 把当前线程打出来看看：

```java
package com.example.tomcat11;

import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;
import java.io.PrintWriter;
import java.nio.charset.StandardCharsets;

/**
 * 线程信息 Servlet
 * 用来直观地看一眼：当前请求到底是不是跑在虚拟线程上
 */
public class ThreadInfoServlet extends HttpServlet {

    /**
     * 处理 GET 请求，输出当前线程信息
     */
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        // Servlet 6.1 新增：可以直接传 Charset 对象，不用再手写 "UTF-8" 字符串
        resp.setCharacterEncoding(StandardCharsets.UTF_8);
        resp.setContentType("text/plain");

        Thread current = Thread.currentThread();
        PrintWriter writer = resp.getWriter();
        writer.println("当前线程：" + current);
        writer.println("是否虚拟线程：" + current.isVirtual());
    }
}
```

我本地访问  `/thread`  的真实输出：

```ruby
当前线程：VirtualThread[#52,http-nio-8080-virt-0]/runnable@ForkJoinPool-1-worker-1
是否虚拟线程：true
```

不过虚拟线程不是万能药，有几点要心里有数：

- 它解决的是"等待"，不是"计算" 。CPU 密集型的接口，开了也不会更快。
- 下游资源会成为新瓶颈 。线程不再稀缺之后，数据库连接池往往最先被打满，记得同步评估连接池大小，或者加上限流。
- Java 版本尽量选新的 。Tomcat 11 本身在 Java 17 上就能跑，但虚拟线程至少要 Java 21；而且 Java 21 里  `synchronized`  代码块会把虚拟线程"钉死"在平台线程上（俗称 pinning），直到 Java 24 才解决（JEP 491）。所以生产环境更推荐直接上 Java 25 LTS。

### 2.3 Servlet 6.1：几个"早就该有"的小改进

Servlet 6.1 没搞什么大动作，更像是把大家吐槽多年的小毛病一次性修了。

**1. 重定向终于能指定状态码了。** 以前  `sendRedirect()`  只会发 302，想发 301、307、308 得自己  `setStatus()`  再  `setHeader("Location", ...)` 。现在一行搞定：

```java
package com.example.tomcat11;

import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;

/**
 * 接口迁移重定向 Servlet
 * 老接口 /old-api/** 永久迁移到 /api/v2/**，并且保留原来的请求方法
 */
public class RedirectServlet extends HttpServlet {

    /**
     * 统一处理所有请求方法，返回 308 永久重定向
     */
    @Override
    protected void service(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        String path = req.getPathInfo() == null ? "" : req.getPathInfo();
        // Servlet 6.1 新增：sendRedirect 可以直接指定状态码
        resp.sendRedirect("/api/v2" + path, HttpServletResponse.SC_PERMANENT_REDIRECT);
    }
}
```

用 curl 验证一下：

```bash
$ curl -i -X POST http://localhost:8080/old-api/users
HTTP/1.1 308
Location: /api/v2/users
```

为什么特意用 308？因为历史上浏览器遇到 301/302 时，习惯把 POST 偷偷改成 GET 再重发，接口迁移时很容易把请求体弄丢；307/308 则明确要求保持原来的请求方法。

**2. 字符集可以直接传  `Charset` 。**  `setCharacterEncoding(StandardCharsets.UTF_8)`  这种写法，IDE 能自动补全，也不用担心字符串拼错，上面的  `ThreadInfoServlet`  里已经用上了。

**3. 输入输出流支持  `ByteBuffer` 。** 配合 NIO 的  `FileChannel`  做文件下载，省掉了"先倒进 byte 数组再写出"的样板代码：

```java
package com.example.tomcat11;

import jakarta.servlet.ServletOutputStream;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;

/**
 * 报表下载 Servlet
 * 演示 Servlet 6.1 新增的 ServletOutputStream.write(ByteBuffer)
 */
public class DownloadServlet extends HttpServlet {

    /**
     * 处理 GET 请求：用 NIO 通道读文件，直接把 ByteBuffer 写给客户端
     */
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
        Path file = Path.of("data", "report.csv");
        if (Files.notExists(file)) {
            resp.sendError(HttpServletResponse.SC_NOT_FOUND, "报表文件不存在");
            return;
        }

        resp.setContentType("text/csv");
        resp.setCharacterEncoding(StandardCharsets.UTF_8);
        resp.setHeader("Content-Disposition", "attachment; filename=report.csv");

        ServletOutputStream out = resp.getOutputStream();
        ByteBuffer buffer = ByteBuffer.allocate(8 * 1024);
        try (FileChannel channel = FileChannel.open(file, StandardOpenOption.READ)) {
            while (channel.read(buffer) != -1) {
                buffer.flip();
                // 以前要先 buffer.get(bytes) 倒进数组再 write，现在一步到位
                out.write(buffer);
                buffer.clear();
            }
        }
    }
}
```

**4. 其他小改动。** 新增了 308、421、422、426 这几个状态码常量（比如 422 对应  `SC_UNPROCESSABLE_CONTENT` ）；请求参数解析出错时， `getParameter()`  这类方法现在会直接抛异常，而不是默默吞掉——这也是 Tomcat 11 把  `FailedRequestFilter`  删掉的原因，它已经没用了。

### 2.4 EL 6.0：JSP 终于认识 record 了

还在用 JSP 的朋友大概遇到过这种尴尬：Java 16 就有了  `record` ，可放进 JSP 里写  `${book.title}`  却取不到值，因为 EL 只认  `getTitle()`  这种 JavaBean 风格的 getter。EL 6.0 新增了默认启用的  `RecordELResolver` ，这事终于翻篇了。顺便，数组也支持  `.length`  了。

先定义一个 record，再用 Servlet 把它塞给 JSP：

```cs
package com.example.tomcat11;

/**
 * 图书信息（Java Record）
 * EL 6.0 起，JSP 里可以直接用 ${book.title} 读取 record 的组件
 */
public record Book(String title, String author, String[] tags) {
}
```

```java
package com.example.tomcat11;

import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;

/**
 * 图书详情 Servlet
 * 把一个 record 对象放进 request，交给 JSP 用 EL 表达式渲染
 */
public class BookServlet extends HttpServlet {

    /**
     * 处理 GET 请求：准备图书数据并转发到 book.jsp
     */
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        Book book = new Book("Tomcat 11 实战笔记", "张三", new String[]{"Java", "Web", "Tomcat"});
        req.setAttribute("book", book);
        req.getRequestDispatcher("/book.jsp").forward(req, resp);
    }
}
```

 `book.jsp`  里直接用：

```javascript
<%@ page contentType="text/html;charset=UTF-8" %>
<html>
<body>
<%-- EL 6.0：直接读取 record 的组件，不再需要 getXxx() 方法 --%>
<p>书名：${book.title}</p>
<p>作者：${book.author}</p>
<%-- EL 6.0：数组终于支持 length 属性了 --%>
<p>标签数量：${book.tags.length}</p>
</body>
</html>
```

页面会正常显示"书名：Tomcat 11 实战笔记""作者：张三""标签数量：3"。

另外两个变化顺带提一下：EL 6.0 还新增了处理  `java.util.Optional`  的  `OptionalELResolver` ，不过默认是关闭的，需要手动加进解析器链；同时 EL 不再强依赖  `java.desktop`  模块，用  `jlink`  裁剪运行时镜像时能更瘦一点。

### 2.5 做减法：该退场的都退场了

一个成熟项目敢删东西，往往比加东西更难得。Tomcat 11 这次删得挺干脆：

- SecurityManager 支持被彻底移除。 Java 17 就把它标记为废弃了，Java 24 更是直接永久禁用（JEP 486），Jakarta EE 11 规范里也删掉了相关内容。说实话，真正在生产上开 SecurityManager 的项目本来就不多，这一刀砍下去，代码清爽了不少。
- HTTP/2 Server Push 被移除。 Servlet 6.1 把它改成了可选功能，Tomcat 干脆不实现了。原因也简单：Chrome 等主流浏览器早就不支持了，大家现在更多用  `<link rel="preload">`  之类的方案代替。
- 历史废弃 API 全部清理。 Tomcat 10.1 里标记为废弃的代码、JSP 3.1 和 EL 5.0 里的废弃 API，都一并删除。如果你写过依赖 Tomcat 内部类的自定义组件（比如自定义 Valve、Realm），升级前务必重新编译检查一遍。

### 2.6 默认更安全，OpenSSL 有了新接法

有几个默认值"悄悄变严格"了，升级时要留意：

- 连接器的  `maxParameterCount`  默认值从 10000 降到了 1000，防止有人构造海量参数的请求搞 DoS 攻击。如果你的业务表单真有上千个字段（比如批量编辑的大表格），记得手动调大。
- Cookie 解析严格遵循 RFC 6265，带引号的 Cookie 值，引号现在会被当作值的一部分。
- 字节转字符失败时直接抛异常，而不是悄悄生成一堆乱码问号。

HTTPS 方面，Tomcat 11 支持通过 Java 的 FFM API（外部函数与内存 API）直接调用系统里的 OpenSSL，官方文档目前写的是 Java 25 起可用。以前想让 Tomcat 用上 OpenSSL，必须额外安装 tomcat-native 这个 JNI 本地库，现在这一步可以省掉了，对容器化部署相当友好。

## 三、动手：十分钟上手 Tomcat 11

### 3.1 Docker 一条命令跑起来

最快的体验方式还是 Docker：

```apache
# 启动一个 Tomcat 11（JDK 21 版本的官方镜像）
docker run -d --name tomcat11 -p 8080:8080 tomcat:11.0-jdk21

# 把自己的 war 包拷进去，Tomcat 会自动部署
docker cp ./demo.war tomcat11:/usr/local/tomcat/webapps/

# 看一眼启动日志
docker logs -f tomcat11
```

这里有个新手常踩的小坑：官方镜像出于安全考虑， `webapps`  目录默认是空的，所以直接访问  `http://localhost:8080`  会看到 404，这是正常现象。默认欢迎页和管理后台都挪到了  `webapps.dist`  里，需要的话自己拷回去就行。

### 3.2 内嵌 Tomcat 11 完整示例

不想单独装 Tomcat？那就直接把它"嵌"进 Java 程序里，Spring Boot 本质上也是这么干的。下面这个小项目把前面提到的几个新特性串在了一起，我在 JDK 25 + Tomcat 11.0.27 上完整跑过一遍。

项目结构：

```swift
tomcat11-demo
├── pom.xml
├── data
│   └── report.csv
└── src/main
    ├── java/com/example/tomcat11
    │   ├── Tomcat11App.java        // 启动类
    │   ├── ThreadInfoServlet.java  // 虚拟线程验证
    │   ├── RedirectServlet.java    // 308 重定向
    │   ├── DownloadServlet.java    // ByteBuffer 下载
    │   ├── Book.java               // record
    │   └── BookServlet.java        // record + EL
    └── webapp
        └── book.jsp
```

 `pom.xml`  的关键部分：

```xml
<properties>
    <!-- 虚拟线程需要 Java 21 及以上 -->
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <tomcat.version>11.0.27</tomcat.version>
</properties>

<dependencies>
    <!-- Tomcat 核心：Servlet 容器 + HTTP 连接器 -->
    <dependency>
        <groupId>org.apache.tomcat.embed</groupId>
        <artifactId>tomcat-embed-core</artifactId>
        <version>${tomcat.version}</version>
    </dependency>
    <!-- JSP 引擎 Jasper：用到 JSP 时才需要 -->
    <dependency>
        <groupId>org.apache.tomcat.embed</groupId>
        <artifactId>tomcat-embed-jasper</artifactId>
        <version>${tomcat.version}</version>
    </dependency>
</dependencies>
```

启动类：

```java
package com.example.tomcat11;

import org.apache.catalina.Context;
import org.apache.catalina.connector.Connector;
import org.apache.catalina.startup.Tomcat;

import java.io.File;

/**
 * Tomcat 11 内嵌启动类
 * 用纯 Java 代码启动一个 Tomcat 11，并开启虚拟线程
 */
public class Tomcat11App {

    /**
     * 程序入口：创建 Tomcat、打开虚拟线程、注册 Servlet 并启动
     */
    public static void main(String[] args) throws Exception {
        Tomcat tomcat = new Tomcat();
        tomcat.setBaseDir(new File("target/tomcat").getAbsolutePath());
        tomcat.setPort(8080);

        // 打开虚拟线程开关（需要 JDK 21 及以上）
        Connector connector = tomcat.getConnector();
        connector.setProperty("useVirtualThreads", "true");

        // 以 src/main/webapp 作为站点根目录，JSP 页面放在这里
        Context ctx = tomcat.addWebapp("", new File("src/main/webapp").getAbsolutePath());

        // 手动注册几个演示用的 Servlet
        Tomcat.addServlet(ctx, "threadInfo", new ThreadInfoServlet());
        ctx.addServletMappingDecoded("/thread", "threadInfo");
        Tomcat.addServlet(ctx, "redirect", new RedirectServlet());
        ctx.addServletMappingDecoded("/old-api/*", "redirect");
        Tomcat.addServlet(ctx, "download", new DownloadServlet());
        ctx.addServletMappingDecoded("/download", "download");
        Tomcat.addServlet(ctx, "book", new BookServlet());
        ctx.addServletMappingDecoded("/book", "book");

        tomcat.start();
        System.out.println("Tomcat 11 启动成功：http://localhost:8080/thread");
        tomcat.getServer().await();
    }
}
```
