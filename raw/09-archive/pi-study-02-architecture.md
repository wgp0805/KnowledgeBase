## 1. 架构分层总览

Pi 的整体架构分成**两大层、多个子层**：

- **核心层（Core）**：Pi 内置的基础能力，不可替换
- **扩展层（Extensions）**：通过扩展机制加入的能力，用户可控

中间通过 **ExtensionContext（扩展上下文）** 连接。扩展通过它访问核心能力，核心通过它触发扩展的事件回调。

### 架构图

```
┌─────────────────────────────────────────────────┐
│                扩展层 (Extensions)               │
│  ┌──────────────────────────────────────────┐   │
│  │  Level 4: Package（打包分发）             │   │
│  │  Level 3: Extension（TS 扩展模块）        │   │
│  │  Level 2: Skill（技能）                   │   │
│  │  Level 1: Prompt Template（提示词模板）   │   │
│  └──────────────────────────────────────────┘   │
├─────────────────────────────────────────────────┤
│         ExtensionContext（扩展上下文）           │
│         扩展 API / 事件总线 / 状态管理          │
├─────────────────────────────────────────────────┤
│                核心层 (Core)                     │
│  ┌──────────┬──────────┬──────────┬──────────┐   │
│  │ LLM Loop │ 工具系统 │ Session  │ TUI 界面 │   │
```

## 2. 核心层四件套

### 2.1 LLM Loop — 运行循环

Agent 的心脏。核心是一个循环：

```
while 任务未完成:
    1. 把当前上下文发给 LLM
    2. LLM 返回回复（文字或工具调用）
    3. 如果是工具调用 → 执行工具 → 把结果加回上下文
    4. 如果是最终回答 → 结束循环
```

**工程化细节（Harness 的价值所在）**：
- 上下文太长 → Compaction（压缩）
- 工具调用失败 → 错误回灌让模型重试
- 模型死循环 → 步数限制 + 干预钩子
- 用户打断 → 中断信号处理

> 同样的模型，套在不同的 Harness 里表现天差地别。

### 2.2 工具系统 — Tool System

负责工具的注册、调度、安全、结果处理。

**职责**：
- **注册**：管理哪些工具可用（内置 + 扩展注册的）
- **调度**：模型请求调用时，找到并执行
- **安全**：调用前权限检查、参数校验
- **结果处理**：输出截断、格式化、脱敏

**内置工具**：`bash`、`read_file`、`write_file`、`glob` 等基础编程工具。

**关键设计**：工具定义是结构化的（名称、参数 schema、描述），这个定义放进系统提示词，LLM 根据描述决定是否调用。

### 2.3 Session 管理

Session 是 Pi 的"记忆"，格式为 JSONL（每行一个 JSON 事件）。

**记录内容**：用户消息、模型回复、工具调用请求和结果、系统事件

**职责**：
- 持久化保存（磁盘存储，重启不丢）
- 分支与导航（回到某一步重新走）
- 上下文压缩（太长时自动压缩早期内容）
- 会话命名和搜索

> 类比：Session 就像游戏存档，随时可以读档、分支走不同路线。

### 2.4 TUI 界面

TUI = Terminal UI，终端里看到的界面。用 Ink（React for Terminal）写的，组件化。

**职责**：
- 渲染对话（Markdown、代码高亮）
- 渲染工具调用状态
- 处理用户输入和快捷键
- 状态栏、侧边栏等 UI 组件


## 3. 扩展层的四个层次

从浅到深，能力逐级递增：

### Level 1: Prompt Templates（提示词模板）
- **是什么**：把常用提示词变成一个 `/命令`
- **例子**：`/review` 触发代码审查提示词
- **难度**：2 分钟，纯 Markdown
- **能力边界**：只能改模型看到的提示词，不能改行为

### Level 2: Skills（技能）
- **是什么**：按需加载的 Markdown 技能包，包含知识、步骤、脚本
- **例子**：PDF 处理技能、代码审查技能
- **难度**：几分钟到几小时
- **能力边界**：给模型投喂知识和流程，但模型可以选择不用
- **标准**：Agent Skills 标准，Pi / Hermes / Claude Code 都支持

### Level 3: Extensions（扩展 — TypeScript）
- **是什么**：TypeScript 模块，可以注册工具、监听事件、加命令、做 UI
- **例子**：权限守卫扩展、Git 检查点扩展
- **难度**：30 分钟到几天，需要 TS 基础
- **能力边界**：几乎可以改任何东西（工具、事件、UI、Provider）
- **关键区别**：代码级能力，模型绕不开

### Level 4: Packages（包）
- **是什么**：把前三层打包成 npm/git 包，一键安装分享
- **例子**：包含 3 个扩展 + 5 个 Skill + 主题的完整包
- **难度**：主要是组织和打包
- **定位**：分发单元，不增加新的能力维度

### 关键记忆
Extension 是真正有"代码级能力"的扩展，前三层（Package 是分发单元不算）都是"提示词级"或"声明式"的。

## 4. ExtensionContext — 核心与扩展的桥梁

扩展加载时，Pi 传给扩展一个 `ExtensionContext` 对象（通常叫 `ctx`）。扩展通过它和核心交互。

### API 分类

**读取类**：`ctx.cwd`、`ctx.mode`、`ctx.hasUI`、`ctx.isProjectTrusted()`、`ctx.getContextUsage()`、`ctx.getSystemPrompt()`

**操作类（通过 pi 对象）**：
- `pi.registerTool()` — 注册新工具
- `pi.registerCommand()` — 注册斜杠命令
- `pi.sendMessage()` — 往对话发消息
- `pi.exec()` — 执行 shell 命令
- `pi.setModel()` — 切换模型
- `pi.compact()` — 触发压缩
- `pi.newSession()` — 新建会话
- `pi.shutdown()` — 关闭 Pi

**事件系统（pi.on()）**：
- `tool_call` — 工具调用前（可拦截修改）
- `tool_result` — 工具返回后
- `model_request` — 模型请求前
- `model_response` — 模型响应后
- `session_loaded` — 会话加载后
- `user_input` — 用户输入后

**UI 类（ctx.ui）**：
- `ctx.ui.confirm()` — 确认对话框
- `ctx.ui.select()` — 选择对话框
- `ctx.ui.input()` — 输入框
- `ctx.ui.notify()` — 通知
- `ctx.ui.custom()` — 完全自定义组件

### 关键洞察
扩展的所有能力都来自 `ctx` 和 `pi` 对象。Pi 的扩展能力之所以强，就是因为它暴露的 API 非常多。


## 5. 扩展加载流程

1. **发现**：启动时扫描扩展目录（全局 `~/.pi/agent/extensions/` + 项目级 `.pi/extensions/`）
2. **加载**：用 jiti（即时 TS 编译器）加载每个 `.ts` 文件
3. **执行**：调用扩展导出的默认函数，传入 ExtensionContext
4. **注册**：扩展调用 `pi.registerTool()`、`pi.on()` 等完成注册
5. **就绪**：扩展开始工作，监听事件、提供工具

**热重载**：输入 `/reload` 重新加载所有扩展，改代码不用重启 Pi。

```
用户在终端输入指令
    │
    ▼
┌──────────────────────────────────────────────────┐
│  TUI 层（终端界面）                                │
│  接收输入 / 渲染输出 / 快捷键                      │
└─────────────┬────────────────────────────────────┘
              │
              ▼
┌──────────────────────────────────────────────────┐
│  LLM Loop（运行循环）                              │
│  思考 → 工具调用 → 观察 → 再思考 → ...             │
└──────┬───────────────┬───────────────────────────┘
       │               │
       ▼               ▼
┌──────────────┐ ┌─────────────────────────────────┐
│  工具系统     │ │  ExtensionContext（扩展上下文）  │
│  内置工具     │ │  - 扩展 API（注册工具/命令...）  │
│  扩展注册工具 │ │  - 事件总线（监听/拦截）        │
└──────────────┘ │  - UI 组件 API                  │
                 │  - 状态/会话管理 API             │
                 └──────────────┬──────────────────┘
                                │
                       ┌────────┴────────┐
                       ▼                 ▼
                ┌──────────┐   ┌───────────────┐
                │ Extension│   │    Skill      │
                │ (TS代码) │   │  (Markdown)   │
                └──────────┘   └───────────────┘
```

### 看图理解扩展开发
- 你写的 Extension 代码跑在最底层右边
- 通过 `pi.registerTool()` 把工具加到工具系统
- 通过 `pi.on('tool_call')` 监听 LLM Loop 里的事件
- 通过 `ctx.ui.xxx()` 调用 TUI 层的界面能力
