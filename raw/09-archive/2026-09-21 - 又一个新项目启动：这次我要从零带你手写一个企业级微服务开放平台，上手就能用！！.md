在现代企业级软件开发中，系统之间的集成变得越来越复杂。传统的点对点集成方式已经无法满足日益增长的系统对接需求，一个统一、标准、安全的服务接入层成为了解决这一问题的关键。本文将详细介绍 open-system 项目的设计思路、架构方案和实现细节。

open-system 是一个基于微服务架构的企业级系统开放平台，它作为统一的服务接入层，为多个业务系统提供标准化的 API 调用接口。通过这个平台，开发人员可以轻松实现系统间的互联互通，大大降低了集成复杂度。

## 一、项目背景与核心价值

### 1.1 集成痛点

在多系统并存的企业环境中，系统集成面临以下挑战：

- 集成复杂度高 ：不同系统使用不同的技术栈、通信协议和数据格式，点对点集成会导致"集成爆炸"
- 安全性难以保障 ：直接暴露接口容易导致系统被恶意调用，缺乏统一的鉴权机制
- 幂等性问题 ：重复提交会导致数据重复处理，影响业务正确性
- 日志管理困难 ：每个系统各自记录日志，问题排查需要跨多个系统追踪
- 扩展性差 ：新增系统接入需要修改大量现有代码

### 1.2 解决方案

open-system 通过以下设计解决了上述痛点：

| 解决方案 | 实现方式 | 带来的价值 |
| --- | --- | --- |
| ** 统一接入层 ** | 提供标准化的 RESTful 接口 | 降低集成复杂度，屏蔽底层技术差异 |
| ** 幂等性保证 ** | 基于事务ID + 服务编码的历史记录机制 | 防止重复提交，保证数据一致性 |
| ** 灵活调用模式 ** | 支持异步和同步两种接口调用方式 | 适应不同业务场景，提升系统性能 |
| ** 独立日志管理 ** | 每个请求生成独立日志文件 | 便于问题追溯和调试，提升排查效率 |
| ** 安全机制 ** | 系统标识验证、RSA+AES 混合加密 | 保证数据传输安全，防止非法调用 |

### 1.3 适用场景

open-system 适用于以下场景：

- 企业级 API 网关参考实现 ：作为统一的服务入口，管理所有对外接口
- 微服务系统集成平台 ：连接多个微服务，实现服务聚合和编排
- 多系统对接的统一服务层 ：不同业务系统之间的数据交互
- 需要幂等性保证的业务接口 ：支付、订单、数据同步等关键业务

## 四、核心功能流程

### 4.1 异步接口调用流程

异步模式适合处理耗时操作，接口会立即返回，业务结果通过 HTTP 回调推送：

![](https://mmbiz.qpic.cn/sz_mmbiz_png/mciaHGibPzCIQgBkUKKicpzNj1O8Vyxf9Hs47NW2YqzBibz2TLoPvvwtBfVQRxVFuGym5iajsQBRJFibPIj39ldBykLtxOYogO5GClyNcMQGA5LIQ/640?wx_fmt=png&from=appmsg)

#### 流程说明

- 请求接收 ：客户端发送 HTTP POST 请求到  `/genSI/gsInterface`
- 参数验证 ：平台接收请求后进行参数校验，检查必需字段
- 系统验证 ：验证系统标识 sysId 是否在白名单中
- 历史查询 ：根据 transId 和 serviceCode 查询历史记录
- 幂等处理 ：
- 如果历史记录存在，直接返回历史结果（防止重复处理）
- 如果历史记录不存在，执行业务逻辑

- 业务执行 ：调用 Dubbo 服务实现具体的业务逻辑
- 结果推送 ：通过 HTTP 回调将结果推送给客户端
- 日志记录 ：记录完整的请求和响应日志

#### 优势

- 响应速度快 ：接口立即返回，不需要等待业务完成
- 适合耗时操作 ：可以处理需要长时间计算或调用的业务
- 降低客户端负担 ：客户端不需要长时间等待结果

### 4.2 同步接口调用流程

同步模式适合需要实时结果的业务场景，接口会等待业务完成后返回结果：

![](https://mmbiz.qpic.cn/sz_mmbiz_png/mciaHGibPzCIRibf0ibs5p1YVOIwybAIvTicibg81Ss0NKjHnXFgHKBvmWUfPzjlNg2uoLqQPoElG14l74uzlAgkVmyebDlI1vmChvS3fYcLuyMibg/640?wx_fmt=png&from=appmsg)

#### 流程说明

- 请求接收 ：客户端发送带加密参数的请求到  `/genSI/gsInterfaceSync`
- 报文解密 ：平台使用 RSA+AES 混合加密技术解密请求
- 参数验证 ：校验请求参数，检查必需字段
- 系统验证 ：验证系统标识 sysId
- 历史查询 ：根据 transId 和 serviceCode 查询历史记录
- 幂等处理 ：根据历史记录决定是否执行业务逻辑
- 业务执行 ：调用 Dubbo 服务实现具体业务
- 结果返回 ：将业务结果同步返回给客户端

#### 优势

- 实时性好 ：客户端可以立即获取业务结果
- 实现简单 ：客户端不需要处理回调逻辑
- 适合实时需求 ：适用于需要立即知道结果的业务场景

## 五、核心功能特性

### 5.1 幂等性设计

#### 设计目的

在分布式系统中，由于网络延迟、重试机制等原因，同一个请求可能被多次发送。幂等性设计确保相同的请求多次执行，系统的最终状态是一致的。

#### 实现原理

open-system 采用基于 transId + serviceCode 的历史记录机制来实现幂等性：

**数据库表设计**

```
CREATE TABLE`gsrequest` (
`transId`varchar(100) NOTNULLCOMMENT'事务ID (唯一标识一次请求)',
`reqBody` longtext COMMENT'请求体',
`rspBody` longtext COMMENT'响应体',
`intime`varchar(50) DEFAULTNULLCOMMENT'请求时间',
`rsptime`varchar(50) DEFAULTNULLCOMMENT'响应时间',
`serviceCode`varchar(50) DEFAULTNULLCOMMENT'服务编码',
`sysId`varchar(50) DEFAULTNULLCOMMENT'系统标识',
  PRIMARY KEY (`transId`),
KEY`idx_service_code` (`serviceCode`)
) ENGINE=InnoDBDEFAULTCHARSET=utf8;
```

**查询策略**

```
-- 根据事务ID和服务编码查询历史记录
SELECT * FROM gsrequest
WHERE transId = 'xxx'
  AND serviceCode = 'search_mobile_area';
```

**索引优化**

- transId 字段建立主键索引，确保唯一性查询性能

#### 报文加密

open-system 采用 RSA+AES 混合加密方案，兼顾安全性和性能。

- body ：使用 AES 密钥加密请求体
- 解密流程 ：客户端使用 RSA 私钥解密 header.key，获取 AES 密钥，再解密 body

### 5.5 结果推送机制

open-system 支持两种结果推送方式：异步推送和同步推送。

#### 异步推送

**实现方式**

```
public class MobileAreaCallbackV2 implements Runnable {
    private String sysId;
    private PhoneTagInfo phoneTagInfo;
    private GsrequestService gsRequestService;

    @Override
    public void run() {
        try {
            // 1. 调用业务服务
            String desc = mobileAreaService.getMobileArea(...);

            // 2. 构造响应对象
            ServiceResponseMsg responseMsg = new ServiceResponseMsg();
            ServiceResponseHeader header = new ServiceResponseHeader();
            header.setTransId(phoneTagInfo.getTransId());
            header.setServiceCode("search_mobile_area");
            header.setIntime(new Date().toString());
            responseMsg.setHeader(header);
            responseMsg.setBody(result);

            // 3. 保存历史记录
            Map<String, Object> rspInfo = new HashMap<>();
            rspInfo.put("transId", phoneTagInfo.getTransId());
            rspInfo.put("rspBody", JSON.toJSONString(responseMsg));
            gsRequestService.addRequestHis(rspInfo);

            // 4. HTTP 推送结果
            ServiceUtils.sendAsyn(sysId, responseMsg);

        } catch (Exception e) {
            // 异常处理
            log.error("回调处理失败", e);
        }
    }
}
```
