# 腾讯司内实践：手把手教你如何用 Skill 与 AI 协作

> **来源**: 人人都是产品经理  
> **链接**: https://www.woshipm.com/ai/6483517.html  
> **抓取日期**: 2026-10-23  
> **相关性评分**: 1.0

> 学了很多却说不清学会了什么，换个对话又得从头交代——这是 AI 学习的普遍困境。一位腾讯产品经理把"定目标、分步学、做练习、勤复盘"固化成 Learning Skill，用 WorkBuddy 生成专属学习助手，并以 RAG 项目完整演示从建计划到结项的全过程。

![](https://image.woshipm.com/2024/07/02/083e0566-386b-11ef-90af-00163e142b65.png)

AI 时代，我们如何面对海量信息，真正用 AI 能力帮助自我迭代？这位腾讯员工给出了他的答案，他把日常学习、设计和构建项目的方法，做成了三个 Skill，帮助个人成为超级个体。

![](https://image.woshipm.com/wp-files/2026/10/nggl0BS3LZOJVOx8ZSKg.png)

Balance Li，腾讯产品经理

这篇文章重点介绍其中的 Learning skill，为大家介绍怎样用 WorkBuddy 演示生成专属学习 Skill，再用它制定计划、练习、复盘和保存笔记。

以下是 Balance 的自述，你也可以换成自己的主题，跟着步骤尝试。

## 01 从工作出发：工作不断变化，好的方法值得留下

**我做产品工作，负责法务****AI****建设。日常主要做三类事：学习一个新领域、设计产品方案，以及制作****Skill****或系统****Demo。**

以知识库为例，做方案前，我需要弄清楚相关技术能解决哪些问题；设计时，要想清楚谁会用、怎么用，以及哪些需求暂时不做；之后，再做出 Demo，检查方案是否可行。任务各不相同，做事的方法却有不少共通之处。

用 AI 学习时，可能会遇到这样的情况：聊了很多，也看懂了不少解释，却越来越不清楚自己究竟要学到什么程度。等到工作中需要做判断，才发现自己记住了术语，却不知该怎么用。换个对话，之前学到哪儿、还有什么没弄懂，又要重新交代。

于是，我想把学习中几件容易漏掉的事固定下来：先说清目标，再按步骤学习，学完做练习，最后记下进度和收获。能不能让 AI 持续按这套方法帮我？

另外，我也将我自己的三个高频工作场景需要固定下来的内容做成了 skill 生成器，按任务需要选用，三个场景可以单独使用，也可以按项目需要接着做。

  1. **系统学习：** 理解陌生领域，学会作出有依据的判断
  2. **产品设计：** 想清目标和限制，形成可供评审的方案
  3. **构建与验证：** 实现 Skill 或 Demo，检查结果是否满足目标



## 02 把方法做成工具：三个生成器，为不同任务准备专属 Skill

围绕这三类工作，我开发了 Learning、Design、Build 三个 Skill 生成器，都已上线公司内部市场。你可以把 Skill 理解为一份给 AI 助手的工作说明：该按什么步骤做、遇到什么情况要追问、怎样检查结果，以及哪些内容需要保存。

我把它们设计成生成器，是希望同一套方法能适应不同任务：先了解你的需求，再生成一个**专属的子****Skill** 。例如，同样用 Learning 生成器，学 SQL 和学英语时，目标、学习内容和练习方式都会有所不同。

![](https://image.woshipm.com/wp-files/2026/10/G2QKQkcTC8ETBZpO6BVa.png)

这些生成器产出的子 Skill，会根据项目进展引导下一步。比如，做设计时发现新信息与原先的判断矛盾，就会建议重新检查需求或方案；做开发时测试发现问题，就会回头检查设计或技术选择。进度和重要决定会保存在项目文件里。

WorkBuddy·学习流程示意·分两步使用，先生成学习项目子 Skill，再用它制定计划、安排练习和保存笔记。

① 你的需求

主题 / 目标 / 基础 / 条件

② 生成器

澄清需求，生成并预览

③ 专属子 Skill

项目背景，流程与保存规则

④ WorkBuddy 引导学习

讲解 / 练习 / 记录 / 继续

第一步·生成专属 Skill

生成器交付 SKILL.md 和配套指南。

第二步·使用子 Skill

在 WorkBuddy 中调用它，开始学习。

Build 生成器先交付一份指导构建工作的 Skill。接下来，还要按它的引导制作、测试业务 Skill 或 Demo。三个生成器可以配合使用，但需要你按任务选择，并不会自动依次运行。

我选择 Learning 来展开介绍，是因为几乎每个人都有学习需求。用它做例子，更容易看清一套方法怎样落实到与 AI 的每一步对话中。

## 03 Learning怎样引导学习：把“学完能做什么”，放进每一步

我给 Learning 安排的第一步，是帮你明确学习目标。“了解 RAG”太笼统，不容易判断是否学会。换成“能画出基本流程、分析可能出错的环节、提出方案评审问题”，就能据此决定学什么、学多深。

目标确定后，AI 助手会把内容分成几个模块，再把每个模块拆成较小的学习点。每个学习点按下面五步进行，合起来就是一次学习闭环：

一个学习点的五个步骤·你 × WorkBuddy

01 输入 — 讲清概念，明确本次目标

02 学习 — 讨论与追问，逐步展开

03 确认— 发现盲区，纠正理解

04 验收— 练习或案例，检验会不会用

05 沉淀 — 保存笔记，更新进度

理解有偏差就补讲，验收未通过，就补练后再次检验。完成一个学习点，再学下一个。

这里的“验收”，就是用一个任务检查自己是否学会了：可以写一段查询、分析一个案例，或模拟一次工作讨论。我保留了跳过某次验收的选择，但建议第一次尝试时先做一次练习，因为实际做过，往往才能发现哪些地方还不会。

学完一个模块，还要回头想一想：这些知识点有什么关系？之前没懂的地方解决了吗？遇到一个复杂问题，能不能一起用上？整个项目结束时，再整理成框架或总结，也记下还需要继续学的内容。

AI 可以帮助解释、出题和整理。是否真的学会，要看自己能否解释清楚、实际用上。

为了让学习能持续下去，我也把保存记录的规则写进了子 Skill：计划里记进度，笔记里记收获和疑问，模块总结里梳理知识之间的关系。下次对话时，AI 助手重新读取这些文件，就能知道接下来该学什么。**它靠项目文件记住进度。**

## 04 完整实操：跟着一个 RAG 学习项目走一遍

下面，我选一个贴近自己工作的主题——RAG（检索增强生成），用 WorkBuddy 演示具体用法。简单说，RAG 就是先找相关资料，再让模型参考这些资料回答问题。

![](https://image.woshipm.com/wp-files/2026/10/gMsPGqXktQZQUk708Nur.png)

为方便大家照着操作，我把下面的学习计划、WorkBuddy 对话和成果都写成了示例，重点展示每一步怎么做。

### 01｜在 WorkBuddy 中准备好学习环境

先从市场获取 skill-creator-learning： https://github.com/balancegsr/skill-creators/tree/main/learning，再按你所用版本的安装方式，将它配置到 WorkBuddy。准备一个学习工作空间，用来保存计划和笔记。

开始前，确认 WorkBuddy 已识别 skill-creator-learning，并能在当前工作空间保存文件。学习涉及技术版本、工具参数等容易变化的信息时，还需要能检索外部资料。

我用 WorkBuddy 展示这套用法，配图是流程和对话示意。具体安装入口和操作界面，以你使用的版本为准。

### 02｜一次提供四项信息，减少来回补问

安装后，在 WorkBuddy 中输入下面这段话。说清主题、目标、基础和时间即可；如果对讲解或练习方式有偏好，也可以一起说明。

**WorkBuddy·输入学习需求**

> -请使用 skill-creator-learning，帮我生成一个 RAG 学习项目 Skill。
> 
> -主题：RAG，以及它在知识库中的应用。
> 
> -目标：学完能解释基本流程，分析错误可能发生在哪一环，并提出有依据的方案评审问题。
> 
> -基础：我是产品经理，了解大模型基本概念，没有系统学过检索与评估。
> 
> -时间：预计六周，每周约三小时。
> 
> -我偏好先看全貌，再理解原理。请用案例检验理解，等我回答后再给反馈。

生成器会补问还不清楚的地方。例如，你只说“精通 AI”，它会继续问“具体想用来做什么”；已经说清的基础和时间，就不用再问。

### 03｜先确认学什么、学多深，再生成 Skill

WorkBuddy·需求汇总示例

主题：RAG 在知识库中的应用。

基础：了解大模型概念，尚未系统学习检索与评估。

目标：解释流程、分析失败原因、提出方案评审问题。

时间：预计六周，每周约三小时。

推荐：完整模式，结合案例练习与模块复盘。

这些信息有需要修正的吗？确认后，我将生成 Skill 预览。

生成器会根据预计投入的时间，推荐轻量或完整模式，你也可以自己选择。短期集中学一个主题，可以选轻量模式；打算分模块持续学习，可以选完整模式。实际讲解和复盘的深度，仍会随内容难度调整。

确认需求后，WorkBuddy 会展示生成的 SKILL.md 和配套指南清单。重点看三件事：**目标是否符合需要，内容有没有超出范围，练习方式是否合适。** 例如，你可以说：“我暂时不需要自己实现向量数据库，请把重点放在方案判断上。”

确认预览后，再选择子 Skill 的交付方式：“直接安装到当前工作空间”便于马上使用；“打包为 ZIP”便于转移或分享。选择 ZIP 时，还要在准备使用它的环境中完成安装，确认能够调用。

### 04｜现在，开始实际学习项目

启动子 Skill

假设生成的子 Skill 叫 learn_rag_review。生成器的工作到这里就完成了。接下来，在 WorkBuddy 中调用这个子 Skill：“请使用 learn_rag_review，开始学习。”

第一次使用时，子 Skill 会根据你的目标和基础，提出学习模块和具体学习点。你确认后，它会把计划保存为 learning_plan.md，再创建各模块的文件夹和目录说明。下面是一份计划示例。

![](https://image.woshipm.com/wp-files/2026/10/ED4cOevUF8zAixCzETwv.png)

确认计划时，看看是否从适合自己的基础开始、有没有超出目标、每个学习点是否太大。实际计划还应列出推荐资料和预计用时，上表只展示主要内容。

### 05｜自己回答一次，看看哪里还没弄懂

完成一个学习闭环

以“找到了相关材料，为什么还可能答错”为例。先请 WorkBuddy 解释原因，再讨论、练习。我在示例中安排了一个不完整的回答，让大家看到：理解有遗漏时，Skill 会怎样引导补充和练习。

![](https://image.woshipm.com/wp-files/2026/10/6lje9JiZ3WysK5eedZfI.png)

案例中的制度为虚构材料。资料是否相关、回答是否有依据、结论是否正确，要分别检查；不同时间的材料也可能互相冲突。这个案例把这些检查用在了工作场景中。参见 Microsoft Learn：RAG 评估、RAG 提示设计。

练习通过后，子 Skill 会保存笔记，并在计划中更新进度。笔记要写清自己理解了什么、还有什么没弄懂，以及它与其他知识点有什么关系。

![](https://image.woshipm.com/wp-files/2026/10/DnL6pOkMQvPKlq4r0BsX.png)

### 06｜从文件恢复进度，再继续

换一个对话

下次在 WorkBuddy 中打开同一个工作空间，调用这个子 Skill，说“继续学习”。它会先读取计划和相关笔记，回顾上次学了什么，再说明接下来学什么。完整模式先读当前模块的文件，需要时再查旧笔记和总结。

保存在哪里

> {skill_prefix}/learn_rag_review/ ← 平台支持的 Skill 目录
> 
> ├── SKILL.md
> 
> └── references/
> 
> learn_rag_review/ ← 工作空间中的学习项目目录
> 
> ├── learning_plan.md
> 
> ├── file_structure.md
> 
> └── module_3_回答质量/
> 
> ├── notes_有引用仍可能答错.md
> 
> └── summary.md（复盘后）

WorkBuddy·继续学习

读取学习记录后的回复·示例：

当前进度：模块 3。

上次完成“有引用仍可能答错”。

接下来学习如何设计评估样例。

1\. 读学习计划，确认学到哪里。

2\. 读当前模块和需要参考的旧笔记。

3\. 回顾进度，再开始下一个学习点。

如果它记错了进度，就让它重新读取计划和上次的笔记，核对后再继续。旧笔记会一直保留，只是不必在每次对话时全部读取。

### 07｜用一个综合问题，串起学过的内容

模块复盘

学完一个模块，可以开新对话说：“请复盘模块 3，先让我回答一个综合问题，再看看还有哪里没懂。”子 Skill 会读取笔记，梳理知识点之间的关系，找出还没解决的问题，并据此调整后面的学法。

例如可以问：“答案很完整，也有引用，但引用的是过期文件。问题出在资料、检索还是生成回答的环节？你还需要检查什么才能确定？”要回答这个问题，就得把前面学过的内容连起来用。

完整模式默认建议每个模块都复盘；轻量模式通常在学习点较多时建议复盘。简单的模块可以只总结要点，发现重要问题的模块就多花些时间。完成后，把模块总结保存为 summary.md。

### 08｜整理出下次工作用得上的判断清单

结项与应用

完成计划中的模块和相应复盘后，就可以结项。完整模式通常生成认知框架，也就是把知识之间的关系和重要判断整理出来；轻量模式通常生成简要总结。形式可以调整，重点是让自己下次遇到问题时知道该怎么看、怎么做。

![](https://image.woshipm.com/wp-files/2026/10/8ykkYYC73WxSvK25rsLf.png)

结项时还会生成 project_feedback.md，记下哪些引导有帮助、哪些步骤多余、模式是否合适，方便以后改进。还没掌握的部分，也要如实记在总结里。

## 05 卡住时，怎么调整：有了固定步骤，也要按自己的情况调整

实际使用时，目标不清、讲得太快或练习太简单，都可能影响学习。遇到下面几种情况，可以直接请 WorkBuddy 调整。

![](https://image.woshipm.com/wp-files/2026/10/rv03ZLWrZr5VYdLCFUsH.png)

## 06 换个目标，继续使用：同一套方法，放进不同的学习场景

RAG 只是一个例子。换个主题时，可以重新使用 Learning 生成器，准备一个新的项目 Skill。学习内容、资料和练习会变，但仍然可以按“明确目标—分步学习—做练习—复盘—记笔记”的方法进行。

![](https://image.woshipm.com/wp-files/2026/10/9Z9AgyKJy0TUTXQIYrOO.png)

同一套步骤，可以搭配不同的练习。英语示例先练文字表达；发音和口语练习还需要工具支持语音。

换主题时，先想清两件事：**我想学会做什么？用什么小任务能检查自己会不会？** 说清楚这两点，就可以开始规划学习。

## 07 从你的第一个主题开始：挑一个近期真要解决的问题

选一个与最近工作有关、范围较小的主题。安装 skill-creator-learning 后，在 WorkBuddy 中复制下面的模板，填好四项信息：

> **WorkBuddy·你的学习启动模板**
> 
> -请使用 skill-creator-learning，为我生成学习项目 Skill。
> 
> -我想学习：【主题】。
> 
> -我目前的基础是：【已有经验与主要缺口】。
> 
> -我希望学完能：【一个具体、可以检验的行动】。
> 
> -预计投入：【周期与每周时间】。
> 
> -请先确认关键需求，给出子 Skill 预览。确认并交付后，请告诉我子 Skill 的名称和使用方式。
> 
> 生成的子 Skill 安装好、能被 WorkBuddy 识别后，再说：“请使用【生成的子 Skill 名称】，带我制定学习计划，并开始第一个学习点。”

第一次尝试，可以先完成一个学习点。看看自己是否比开始时解释得更清楚、判断得更有依据。再检查笔记有没有保存，下次能不能接着学。

我把这些方法做成 Skill，就是希望同事们也能用起来。大家要学的主题不同，但都可以从一个小目标开始：边学边练，及时复盘，把记录留下来。也欢迎把使用中的收获和问题告诉我，帮助我继续改进这三个 Skill。

把一个真实问题学明白，再把有效的学习方法留下来。
