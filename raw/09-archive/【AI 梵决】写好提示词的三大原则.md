# 正文内容

## 1. Pi-Agent 的三大使用方式

### 方式 1：学习参考（适合新手）

通读源码，理解标准 Agent 工程架构，解决「Demo 能跑、上线崩溃」的常见问题。学习循环管控、上下文管理、工具调用容错三大生产级核心能力。

### 方式 2：二次开发（适合极客 / 研发）

基于 pi-agent 底层框架，自定义工具、新增拦截钩子、改造上下文压缩策略，搭建专属业务智能体（代码 Agent、数据分析 Agent、运维 Agent 等）。

### 方式 3：直接落地（适合业务开发 / 懒人）

不改动底层核心逻辑，直接复用框架能力，仅配置提示词、工具列表，快速产出可上线的生产 Agent，规避大量工程坑。

## 2. Agent 基础运行机制（循环模型）

完整循环流程：

1. 用户提交任务请求
2. 大模型接收上下文，进行推理决策
3. 模型二选一决策分支
    
    - 分支 A：**需要调用工具** → 解析工具参数 → 执行工具 → 将工具运行结果追加进上下文 → **回到步骤 2，开启新一轮循环**
    - 分支 B：**不需要调用工具** → 整理答案直接回复用户 → **终止整个循环**
    

> 关键思考题：为什么模型判定无需调用工具，循环就要结束？
> 
> 逻辑解释：
> 
> Agent 依靠工具扩展能力；当模型判断当前信息充足、不需要任何外部工具查询 / 操作，代表现有信息足以完成任务，继续循环没有收益。持续循环只会无限消耗 token、产生无效轮次，甚至诱发死循环。

## 3. 极简 Coding Agent 实战（200 行代码目标）

### 功能目标

一个简易代码智能体，具备能力：

- 读取本地代码文件
- 分析代码存在的 Bug
- 修改源码文件
- 多轮迭代修复问题

### 极简 Coding Agent 核心组成（对应 Agent 三要素）

1. **大模型**：推理、理解需求、生成代码、决定是否调用文件操作工具
2. **工具集（最小集合）**
    
    - read_file：读取指定路径代码文件
    - write_file：覆盖修改本地代码
    
3. **执行循环**
    
    持续接收工具返回结果，反复询问模型，直到模型确认不用工具，输出最终结论。

### 极简循环伪代码框架

python

运行

```
# 核心循环
context = []
while True:
    # 1. 调用大模型推理
    response = llm.chat(context)
    # 2. 判断是否需要调用工具
    if need_call_tool(response):
        tool_result = execute_tool(response.tool_name, response.params)
        context.append(tool_result)
    else:
        # 无需工具，输出结果，终止循环
        print(response.content)
        break
```

> pi-agent 就是这套极简模型的**工程增强版本**。
> 
> 在基础循环之上增加：循环最大轮次限制、上下文截断与压缩、工具参数校验、安全拦截、错误自愈、全流程生命周期钩子。

## 4. Pi-Agent 架构与极简 Agent 对比

表格

|项目|200 行极简 Coding Agent|Pi-Agent 完整框架|
|---|---|---|
|核心骨架|模型 + 工具 + 循环（基础版）|同样骨架，叠加生产工程能力|
|循环管控|无保护，容易死循环|最大轮数限制、全链路 10 个干预钩子|
|上下文处理|直接追加，容易溢出|工具输出截断、阈值自动压缩|
|工具调用|缺少参数校验、异常容易崩溃|参数校验、安全检查、执行错误回灌自愈|
|适用场景|本地 Demo、学习演示|企业线上环境、高稳定性要求|

## 5. 核心知识点总结

1. 所有智能体底层原理万变不离其宗：**大模型 + 工具 + 循环**。任何复杂 Agent 框架都只是在基础循环上增加各类工程防护。
2. pi-agent 价值：封装所有生产环境必须的稳定性、安全机制，不用从零实现循环管控、上下文优化、工具容错。
3. 循环终止标准：**模型不发起工具调用，循环结束**，这是标准 Agent 设计通用准则。
4. 学习路径建议：先跑通 200 行极简 Demo 理解运行原理，再研读 pi-agent 源码学习工程化解决方案。

## 核心前言

很多人使用大模型时，输出结果不稳定、答非所问、内容空洞，本质问题并不是模型能力不足，而是提示词构建逻辑混乱。

高质量 Prompt 不需要复杂堆砌，掌握三大底层原则，就能持续获得稳定、符合预期的 AI 输出。

## 一、原则 1：清晰界定角色（身份锚定）

### 核心含义

先给 AI 明确身份、定位、专业背景，限定思考视角。

模型会根据分配的角色调整语言风格、知识深度、思考方式。

### 错误示范

> 帮我写一份方案

### 正确示范

> 你是一名拥有 5 年后端架构经验的技术专家，擅长 Java 智能体项目落地，请帮我撰写 Agent 项目上线优化方案。

### 使用要点

1. 角色尽可能具体，不要笼统描述（不要只写 “专家”“顾问”）；
2. 附带角色的工作场景、能力边界；
3. 角色定义放在 Prompt 最开头，优先生效。

## 二、原则 2：明确任务与边界（目标约束）

### 核心含义

清晰说清**要做什么**，同时写明**不要做什么**。

只提目标不提限制，AI 容易自由发挥，产生大量无关内容。

包含三要素：执行任务、交付格式、约束条件。

### 要素拆解

1. 任务：需要 AI 完成的具体工作；
2. 输出格式：markdown / 表格 / 代码 / 逐条列表；
3. 边界限制：禁止虚构内容、禁止长篇闲聊、不要拓展无关话题、严格基于给定素材。

### 示例

> 任务：梳理 Pi-Agent 三大落地难点
> 
> 输出格式：Markdown 分点文档
> 
> 约束：不堆砌底层源码细节，重点总结工程落地方案，不要凭空编造未提到的功能。

## 三、原则 3：提供参考上下文（信息输入）

### 核心含义

把任务需要的全部参考资料、背景信息、原始素材一并交给模型。

AI 没有记忆，不主动猜测你的背景信息；信息缺失就只能依靠通用知识作答，极易产生幻觉。

### 实操方式

1. 简短需求：直接粘贴原文、数据、需求描述；
2. 长文本素材：可以分段传入，或者要求模型分段读取；
3. 重点信息可以标注【重点】，引导模型优先关注。

### 反面问题

只下达指令，不附带背景材料：

> 分析这段视频的知识点（但是不粘贴视频文字内容）
> 
> AI 缺少素材，无法精准回答。

```
【参考上下文素材】
粘贴所有相关资料、文本、需求信息
```

## 四、三大原则总结速记

1. **定角色**：赋予 AI 明确身份，确定思考立场；
2. **明任务**：规定做什么、输出样式、划定内容边界；
3. **给素材**：补齐所有必要上下文，减少模型猜测与幻觉。

## 补充实战小贴士

1. 三大原则不分家，优质 Prompt 尽量同时满足三条；
2. 不要大量无意义词语堆砌，简洁、结构化优于长篇流水文字；
3. 如果结果依然不达标，优先检查：角色是否模糊、约束是否缺失、关键素材有没有提供。
