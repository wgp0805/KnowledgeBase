## 核心摘要
文章整理了 8 种常见但会导致 MySQL 性能暴跌的 SQL 写法，并给出重写方案：① 大偏移量 LIMIT 分页（用上一页最大值做游标条件替代 `LIMIT 1000000,10`）；② 字段类型不匹配导致隐式转换、索引失效（varchar 字段用数字查）；③ UPDATE/DELETE 关联子查询要手工重写成 JOIN（7 秒降到 2 毫秒）；④ 混合排序（ASC+DESC）无法走索引，按状态拆分 UNION ALL 再合并；⑤ EXISTS 嵌套子查询改写为 JOIN（1.93 秒降到 1 毫秒）；⑥ 条件下推——聚合/LIMIT/UNION 子查询外层条件下推到内层；⑦ 提前缩小范围——先对主表过滤排序取 LIMIT 再做左连接；⑧ 中间结果集下推——全表聚合子查询只聚合主表匹配的数据，并用 WITH（CTE）消除重复子查询。核心观点：数据库编译器并非尽善尽美，程序员需了解其特性、把算法意识带进 SQL 设计，复杂 SQL 养成用 WITH 语句的习惯。
