## 核心摘要
程序汪（2026-11-14）转载 PostgreSQL 取代 MySQL 的选型分析。数据背景：Stack Overflow 2026 开发者调查（12,061 人）PostgreSQL 使用率 57.9% vs MySQL 35.1%，且 2023 年调查就已反超。核心论点是"AI 时代 PostgreSQL 少维护一套系统"——文档存储、搜索、向量检索全用扩展解决，少部署一套搜索/向量数据库、少做一份数据同步。能力盘点：①pgvector 向量检索（原有表加向量列、SQL 计算距离、按需建索引，`<=>` 余弦距离）；②PostGIS 地理信息扩展；③内置全文检索（分词方案要按中文实际试，词项拆解影响召回）；④pg_search（ParadeDB）BM25 扩展；⑤混合检索——两路各查一批再按名次融合（RRF，避免量纲不同直接相加）。与业务数据同库的实务要点：检索 SQL 直接带租户/状态条件（团队编号必须后端从登录态取，不能信任客户端传参）；原文与向量同库用**数据库事务**避免"原文已更新向量只更新一半"；多版本并发用带版本条件更新/行锁或先存待处理版本事务切换；JSONB 放结构不固定字段、常查字段单独建列。平台辅助：Supabase（认证/对象存储/实时订阅组合，元数据入库）、Neon 数据库分支（改表结构先在分支试迁移，但分支数据不自动脱敏）。验证方法论：pgvector 可做精确检索，也可 HNSW/IVFFlat 近似索引加速（**近似索引过滤后可能不足 LIMIT 条数**）；0.8.0 起支持迭代索引扫描（默认关闭需显式开启）；验证要看"真实问题能否找到"+带条件后的结果数量+并发负载下业务查询是否受影响，不能只看"返回了 5 条"。结论：从零做需要检索的 AI 应用可先考虑 PostgreSQL；已跑得好好的 MySQL 项目按需求来。内容已并入 [[PostgreSQL]]、[[pgvector]]、[[混合检索]]。
