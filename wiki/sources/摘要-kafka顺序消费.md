## 核心摘要
小哈学Java（公众号，2026-10-22）的 Java 面试题拆解：Kafka 如何实现顺序消费。三个考察层次：①边界——Kafka 只保证**分区内有序**，从不承诺全局有序，上来就说"Kafka 是有序的"直接露馅；②生产端——乱序不只发生在消费端，重试机制同样会打乱写入顺序，知不知道**幂等生产者**（idempotent producer）是"用过"和"用懂了"的分水岭，同时可配置 max.in.flight 之类参数防乱序写入；③消费端工程——按业务维度保序的通用方案是 **key 哈希分区** + 消费端按 key 路由到内存队列，同 key 消息串行、不同 key 并行，兼顾吞吐与顺序；配合**粘性分区策略**减少分区抖动，以及消费组 rebalance 导致的重复消费需要幂等消费兜底。完整拆解已并入 [[Kafka]] 实体页的「顺序消费」章节。
