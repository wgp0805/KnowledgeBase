## 核心摘要

[[Zoe产品手记]] 基于半年 Agent 落地复盘提出：90% 的 Agent 产品只是套了对话壳的升级版聊天机器人——界面换成智能体、加了工具调用、写满自主执行，核心逻辑仍是"用户提问 → AI 回答 → 对话结束"，没有进度、留存、结果交付与迭代，因此上线即沉寂。真正的 Agent 与传统 Chat 产品的本质区别是"人机单次交互"与"机器自主循环迭代"之别，其核心是一套 [[任务闭环]]：目标输入 → 任务拆解 → 分步执行 → 结果校验 → 状态沉淀 → 迭代优化，循环往复直至目标达成。作者给出可复用的**五层任务闭环模型**：意图感知（把口语转成标准化任务卡片）、任务规划（自主拆解原子步骤，可标准化流程走固定 DAG，不确定场景由大模型动态拆解）、工具执行（宁可话术笨一点也绝不执行出错）、校验反馈（规则层 + 模型层双层校验，不通过自动重试补全）、状态沉淀（任务、进度、偏好、历史产出持久化，支持断点续做）。落地复盘还指出四个设计坑：过度美化对话界面、所有任务都让用户手动确认、只做单次闭环不做长期任务、把工具堆叠加成能力而非流程闭环。

### 关键要点

- **伪 Agent 的四大通病**：无状态、无自主规划、无执行落地、无校验闭环。
- **设计范式切换**：Chat 时代设计人机交互界面，Agent 时代设计可自主运行的工作流系统。
- **进度可视化优先于对话体验**；确认弹窗按风险分级（低风险自动执行、高风险分级确认）。
- **自查清单 6 问**：能否结构化任务卡片、能否自主拆解、是否产出业务结果、是否有双层校验、状态是否持久、确认是否按风险分级。
