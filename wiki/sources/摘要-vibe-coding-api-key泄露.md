## 核心摘要

运营背景的 Vibe Coding 开发者 [[张亮-leo]] 复盘了一次真实的 API Key 泄露事故：一把 3 月创建的 DeepSeek Key 从 8 月 23 日起连续一个月被他人盗用，累计消耗 ¥80.58、1,752 次请求、1.07 亿 token。全盘扫描本机后发现这把 Key 散落在 **22 个文件、7 种藏法** 中（代码 fallback、各类 .env、.env.example、部署脚本、测试桩、文档、AI 工具的项目记忆）。根因既不是事故也不是恶意，而是开发"卫生问题"——AI 每一步都在认真完成任务，却没人告诉它"密钥不能到处放"。作者给出 8 条止损建议：一个项目一把 Key、Key 只进环境变量不留 fallback、新仓库先写 .gitignore（忽略所有 .env*）、不把 Key 贴进任何 AI 对话框、设消费限额、下线即作废、发现异常先撤销 Key 再排查。

### 关键要点

- **泄露面是"22 个地方"，而不是某一次事故**：任何一个外流都足以造成损失，因此问题应被定义为密钥治理而非追查单点责任。
- **AI 的默认行为会主动扩散密钥**：为保证"能跑通"，AI 会写 fallback、把完整命令抄进文档、把 Key 当"有用信息"记进笔记——需用 [[API密钥安全]] 规则显式约束。
- **限额即止损线**：被盗用时消费限额是最有效的兜底；发现异常应先撤销 Key 再排查（作者上午烧 7 元、下午排查又烧 2 元）。
- **服务器没了，Key 还活着**：项目/服务器下线必须同步作废其使用过的密钥。
