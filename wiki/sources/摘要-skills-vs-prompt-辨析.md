## 核心摘要
沉默王二以"面试问答"形式系统辨析 Skills 与 Prompt 的本质区别。开篇即点破常见误区——"Skills 就是封装好的 Prompt"只是表象，二者关键差异在于**沉淀、复用、进化**三能力：Prompt 是一次性指令（散落在笔记/聊天记录，版本不可控），Skills 是可迭代、可分发、可统一标准的动态模块。

文章核心论点：
- **本质差异**：Prompt 模板化是静态的，Skills 是动态可进化的。Skill 把一类问题的解决方案固化为可反复调用模块，发现漏项即更新，所有使用者立刻享受改进，避免团队执行标准不统一。
- **团队协作价值**：文档给人看（理解/记忆/应用会变形），Skills 给 AI 用（执行确定、不走样）。以代码审查为例，AI Skill 辅助将 PR 审查从 60 分钟降至 30 分钟，误报率约 2% 且可持续优化。
- **工作原理**：采用 [[渐进式披露]] 架构避免上下文爆炸——发现阶段只加载元数据（名称/描述/触发词），语义匹配阶段基于向量相似度计算命中相关 Skill，执行阶段才加载完整内容。
- **与 MCP 的关系**：互补而非竞争。MCP（机械臂）解决 AI 与外部系统连接，Skills（使用说明书）解决 AI 做事能力封装，二者结合才是完整生产力工具。
- **设计要点**：提出"自由度分级"理念——高自由度（纯文本指令）/中自由度（伪代码+参数）/低自由度（特定脚本）按一致性需求取舍；并拆解 Claude Code create-skill 六步流程（Understanding→Planning→Initializing→Editing→Packaging→Iteration），打包前需过六重验证。
- **竞争力提升**：效率提升→经验沉淀→影响力扩大三层跃迁，并预测 Skills 标准化与商店化两大趋势。

文末建议初学者"从一个最小场景开始"，强调 Skills 是长出来的、不是设计出来的。
