## 核心摘要
GPT-6 Astra 把异步工具调用、状态延续推到 Agent Runtime 一层，只换模型名称只能用上最表层。后端从模型网关升级为任务运行时，前端从聊天窗口变为任务控制台，百万上下文不会结束 RAG（重心从检索更多内容转向装载正确证据和正确能力），同步接口让位于事件流（SSE/WebSocket/事件总线），测试从输出比对走向完整执行轨迹评测，安全控制变成独立的 AI Control Plane 一层，成本指标从 Token 转向完整任务。Astra 只支持 Responses API，Chat Completions API 不在支持范围。

## 关键信息

### 调用入口分水岭
- Astra 定位端到端任务：操作电脑/浏览器/调用工具/持续处理复杂工作/中途反馈带回任务
- **只支持 Responses API**，Chat Completions API 不在支持范围
- 只改模型名称=只用最表面一层能力

### 后端：模型网关 → 任务运行时（Agent Runtime）
Agent Runtime 至少负责：
- 为长任务分配独立任务 ID
- 保存模型状态、工具结果和执行进度
- 管理并行工具、超时、重试与取消
- 对重复提交幂等处理
- 高风险动作前暂停等待人工确认
- 将过程事件持续推送给前端

### Responses API 接管更多编排工作
- 承载工具调用、远程 MCP、电脑操作、代码执行、文件检索、多轮状态
- Astra 支持 Tool Search 和 Skills：需要时再加载工具定义与能力说明，避免一次塞进上下文
- Agent 框架短期不消失，但纯粹做工具转发的中间层价值下降；留下来的部分是企业连接器/流程规则/可观测性/权限控制/异常恢复

### 百万上下文不结束 RAG
- 上下文窗口 1,050,000 token，最大输出 128,000 token，知识截止 2026-04-30
- 长上下文解决"装得下"，RAG 还要解决"找得准、来源清楚、权限正确、版本有效"
- **RAG 重心从检索更多内容转向装载正确证据和正确能力**
- Tool Search 和 Skills 推动 RAG 继续细分：按需选择知识源/业务工具/处理方法

### 同步接口 → 事件流
- 前端从聊天窗口变成**任务控制台**：当前目标/执行计划/已调用工具/正在等待步骤/引用材料/下一项动作
- SSE/WebSocket/事件总线/任务队列比一次性 JSON 响应更常见
- 过程透明 ≠ 把内部推理全部摊开；用户需要可操作信息（访问哪个系统/修改什么/为何暂停/需确认哪项风险）

### 测试：输出比对 → 完整执行轨迹
- OSWorld 得分 72.6%（高于 GPT-5.4 的 65.7%），电脑任务完成时间减少 47%
- 单元测试只证明函数正常，Agent 任务还要检查：选了哪个工具/访问哪些数据/重试几次/人工何时介入/结果能否回放
- 企业需准备自己的任务评测集：历史工单/真实故障/典型业务流程测完成率/人工接管率/错误类型/耗时/成本

### 安全控制变成独立一层（AI Control Plane）
- Astra 首个在 OpenAI Preparedness Framework 下达 Critical 网络安全能力的广泛部署模型
- 安全控制贯穿整个任务：最小权限短期凭证/环境隔离/白名单人工审批/统一留痕/沙箱/异常中止
- AI Control Plane 负责：模型路由/权限策略/成本预算/内容安全/任务评测/日志审计/紧急停止

### 成本指标：Token → 完整任务
- API 价格：每百万输入 $10、缓存输入 $1、输出 $50；超 272K token 输入 2 倍/输出 1.5 倍计费
- 长任务多轮推理+多次工具调用+失败重试，只看单次 token 数难解释成本
- 企业需计算"完成一张工单花多少钱""每次代码修复节省多少人工时间""哪类任务经常重试"
- 模型路由逐渐像数据库读写分离一样成为常见工程配置

### 迁移路径
- 无需重写整套系统：保留稳定业务服务/数据库/消息体系，外面增加可替换 Agent Runtime
- 盘点现有 AI 功能：一次问答/固定流程/复杂长任务分开
- 新旧流程并行运行比较任务完成率/人工接管率/总耗时/错误影响/单任务成本
- 权限只开放到测试环境，高风险动作保留人工确认
