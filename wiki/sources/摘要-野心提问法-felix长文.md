## 核心摘要

老章拆解 Anthropic 工程主管 Felix Rieseberg 的万字长文：多数人只把顶级模型当改邮件、查资料的助手，等于"开着歼-20 送外卖"。Felix 呼吁 **Be More Ambitious（更有野心）**——"速度"（同样的事更快）人尽皆知且拉开不了代差，真正的野心在三个维度：**高度（Altitude）、深度（Depth）、广度（Range）**，配套心理学"自我效能感"破局与审查成本的冷思考。老章将其打包为可复制的"野心提问法"。

## 关键信息

### Felix 背景
Anthropic 负责 Claude AI、Cowork、Claude Code Desktop 等核心产品工程；此前是 Electron 长期核心维护者，任职过 Notion、Stripe、Slack、微软。陶哲轩评顶级模型："能力在某些方向上令人惊叹，在另一些方向上又显得笨拙"。

### 高度：跳出具体指令，追问最终结果
- 下指令前先问："这件事搞定之后，我真正希望发生什么？目标背后的终极目标是什么？"
- 案例一：从"帮我修一个又一个崩溃"拉升到最高层级**"让客户端应用持续保持零崩溃"**——工作流全变：给 Claude 拉取崩溃报告权限、版本号映射 Git commit、接入 Win/macOS/Linux 三套测试环境，自主复现→验证→提交补丁→全自动回归
- 案例二：QBR 三步升维——①把数字填进 PPT 模板让 AI 润色；②喂全部一手业务数据，问"这季度发生了什么变化、为什么、该采取什么行动，梳理最紧急的 3 个决策并正反论证"；③追问 QBR 制度诞生初衷（当年数据分散需人肉整理），让 Claude **设计一套比季度 PPT 更好的全新机制**，用历史数据证明它能更早发现问题、下季度并行试跑
- **判断标准**：当前工作后续还需要频繁开会讨论拍板的，大概率适合用"高度"重新思考

### 深度：逼模型像顶级专家一样下场干活
- 症结：只在提示词里让模型"扮演资深架构师"，它往往只换了一套行业黑话，方法丝毫没长进
- 五条秘诀：①强制使用行业顶尖专家的真实武器（工业级数据库、统计回归、因果推断，只吐 Markdown 表格就打回去）；②提出看似不可思议的超高目标并坚定说这很合理（要 10 秒→5 秒？直接要求 200 毫秒，模型叫苦就告诉它"工程上完全可以解决，继续深挖"）；③用原始底层数据反向对抗既有假设（"管理层认为流失是新手引导问题，请完全基于原始日志复现证实"）；④挖掘盲区创造新知识（微观用户行为模拟器预测从未见过的数据）；⑤**必须引入客观外部裁判——绝对不要让模型自己评判自己的答案**
- **黄金深度提示词**（老章汉化版）：在重写任务提示词之前先回答四件事——①该领域最顶尖专家会做什么而我根本没想到？②他们会从什么最原始的底层素材开始、放弃哪些二手结论？③他们会具体使用哪些专业工具、统计模型与工作方法？④除你我之外有什么客观外部标准或工具能证明结果完全正确？然后按这个专家标准重写提示词——**把"如何成为专家"的思考负担反抛给模型**

### 广度：打破学科隔离，召集跨界天团
- 绝招一：**把名词换成动词**（IDEO《创新艺术》技巧）——"一份 PPT"动词化后是"30 分钟里让一群极度忙碌的人看懂因果关系，并敢于在不确定局面下迅速做出重大决断"，思路瞬间打开
- 绝招二：组建跨界特遣队与红队审查：数据分析师/调查记者/主编/动效音频设计师/做空机构分析师/法务会计师
- **特别提醒：不要让模型玩劣质角色扮演**——扣个"你是做空机构经理"的帽子只会让对话油腔滑调，正确做法是要求模型直接调用做空机构分析师**实际使用的研究方法和审计步骤**

### 破局：自我效能感与冷思考
- 心理学"自我效能感"（Self-efficacy）：对自己能力有强烈信念的人往往取得远超常人的成就，很多人不是能力不行而是被过去认知边界困住
- 三个历史案例：①1939 年丹齐格把黑板上两道"作业"解开，实为统计学悬而未决的世界级难题（不知道不可能，所以做成了）；②1954 年班尼斯特破 4 分钟一英里，**46 天后第二人就突破**（信念枷锁打碎后极限不复存在）；③林纳斯写 Linux 时自称"只是业余爱好"，卸下包袱反而成就最伟大的 OS
- levelsio 爆料：Felix 常在骑自行车时用手机语音给 Claude 下宏观指令搭 3D 个人主页

### 代价与反驳（评论区交锋）
- 创意工作者 Alex Dobrenko：纯艺术的神来之笔来自漫无目的游荡，高度太高会不会抹杀偶然性？Felix 直接回复"我认为你说得很对"（但高度仍帮创作者摆脱格式泥潭、专注故事内核）
- **审查成本指数级飙升**（工程师 Rajesh）：抽象层级拉太高，人类对产出的审查成本指数上升，看不懂就验证不了，野心会变成灾难
- **错误滚雪球**（开发者 JohnKocdr）：长程任务第一步的微小错误会在十几步里急剧放大
- 落点：有野心 ≠ 扔给 AI 撒手不管——越高层级的任务，越需要搭建严密自动化测试、版本控制与客观外部校验的执行沙盒
