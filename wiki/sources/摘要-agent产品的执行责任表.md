# 摘要：Agent产品的执行责任表

## 核心主旨
DeepSeek Harness 发布后，Agent 从回答问题走向真实操作（修改文件、运行命令、调用工具）。产品经理真正该关注的是：用户如何知道 Agent 做了什么、为何能做、出问题谁负责。本文提出"执行责任表"作为 Agent 产品设计的核心工具。

## 关键论点
1. **执行过程必须可观察**：模型生成工具调用只是"提出动作"，Harness 接收并执行后文件才会被改。产品若只展示问题和答案，中间过程被压缩成"任务已完成"，用户无法判断 Agent 是否越界。
2. **审批按钮要提供足够信息**：不能只有"允许/拒绝"。用户需在点击前看懂动作内容（改哪个文件、在什么目录运行、是否访问网络、失败后是否留中间状态）。
3. **权限预设的两项独立设置**：沙箱模式（动作能影响哪里）+ 审批策略（何时询问）。`workspace-write` 限制文件范围但不等于网络/凭据都安全；`danger-full-access` 允许跳出工作区且可能不再逐次询问。
4. **执行记录要记当时事实**：采用追加式会话日志，旧事件不为后续结果被改写。区分失败类型：命令非零退出、沙箱拒绝、审批被拒、运行器不可用、超时、用户取消——恢复动作各不相同。
5. **插件化让责任边界更复杂**：每个插件需声明读取哪些数据、是否访问外部网络、返回内容是否进入模型、日志保留在哪。最终单向拒绝机制保证后续逻辑只能收紧不能放行。
6. **执行责任表的核心列**：动作描述、谁作决定（模型/策略/用户）、系统需留下什么记录、失败后的下一步。

## DeepSeek Harness 权限预设
- `workspace-write`：文件影响限制在工作区，需要时询问用户
- `danger-full-access`：允许更大访问范围，可配置不逐次询问
- `custom`：沙箱和审批组合不匹配任何命名预设时的状态
