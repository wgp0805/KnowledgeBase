## 核心摘要
至知发布开源项目 **IQuestRT**，专门优化 IQuest-Q1 模型的推理执行过程，目标直指"用 AI 编程助手时总得盯着屏幕等"的痛点。它从执行路径入手减少反复出现的等待：**推测解码**（递归多词元预测 + 候选验证一体化 + 按已生成候选在显卡上决策是否继续预测、预测深度可调）、**准备提前开始**（底层调度让后续程序提前备输入，与前一计算重叠）、**用数据本身判断"齐了没有"**（缓冲区初始填 NaN，读到无 NaN 即所有卡写完，免标志位免单独同步）、**专家预取**（提前预测 MoE 专家并把权重预热进缓存）。性能为 8 卡 TP=8 下单请求解码 911 tokens/s，对比 vLLM 基线 309.83 tokens/s（2.94 倍）。

## 关键信息
- **模型 vs 引擎**：IQuest-Q1 是模型（理解需求/推理/生成），IQuestRT 是推理引擎（安排底层计算、显卡通信、数据传输）
- **推测解码**：候选生成、验证和后续状态处理一起纳入优化；关键不只看"一次预测多少个"，而看候选通过多少 + 预测与验证总耗时（每生成一个有效 token 的平均时间）
- **NaN 同步**：每张卡写的那块缓冲区初始填 NaN，哪张算完改写真实结果；汇总看到 NaN 就知道没齐、直接再读一次；靠缓冲区轮换 + 有序 NaN 重填防上一轮值混入（依赖 NVLink 组播能力）
- **专家预取**：混合专家（MoE）下提前预测将用到的专家权重进缓存；预取消耗资源——活跃验证行 4-5 行时从 MLP 尾部旁分支预热有收益（每步省 20.5-23.2 微秒），6-8 行不启用（支路结束太晚）
- **官方性能（仅自测）**：911 tokens/s vs vLLM 309.83 tokens/s（2.94 倍）；测试样本 400 条 Claude Code 交互轨迹 ×2 随机种子 = 800 次解码、32 万 token；每轮推测解码 3.558ms 输出 3.24 token；每输出 token 1.098ms
- **门槛**：8 张 NVIDIA GPU（算力 10.0 Blackwell）、NVLink 组播、TP=8、权重约 330GB；只支持 IQuest-Q1 一个模型
- **功能边界**：支持流式输出/客户端工具调用/接入 Claude Code/Anthropic Messages 接口；不支持图像输入、约束式结构化输出、连续批处理、自定义采样参数（固定温度 1、top-k 20、top-p 0.95）
- **指标口径注意**：单请求解码速度只测生成（解码）阶段，不含输入处理与模型加载等准备环节，不代表提交任务到拿到最终成果的全部耗时
