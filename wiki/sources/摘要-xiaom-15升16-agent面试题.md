## 核心摘要

沉默王二以「xiaom 15 升 16 的晋升体感」引出 AI 部门是增量方向的话题，随后给出 5 道 Agent 面试题的完整作答，覆盖代码质量评测、代码审查防漏检、RAG 与长上下文的关系、长短期记忆治理、KV Cache 五条主线，并附 [[PaiCLI]] 的简历写法。

**Q1 代码质量评估**——三层验证：①写完立刻静态语法与编译检查（钩子在 Agent 每次写/改 Java 源码后调用 JavaParser 解析 AST，把语法诊断追加进上下文，让模型当轮先修低级错误）；②自建评测集 [[NativeAgentBench]]，覆盖代码定位、缺陷修复、终端操作、MCP 工具编排、长上下文压缩；候选 Agent 放进**断网且根文件系统只读**的 Docker 容器独立执行，API 密钥留在宿主机侧防止联网搜答案或读取测试脚本作弊，结束后宿主验证器把预设隐藏单元测试拷进隔离目录，不经任何 Shell 字符串拼接，直接用进程参数数组执行；③软性指标交给 [[LLM-as-Judge]] 按评分表打分。防位置偏见与标准漂移的做法：单样本评分器把待测代码与执行轨迹全部标为不可信数据，要求裁判只针对每个维度输出 1~5 整数分和简短证据，返回未知/重复/缺失维度或越界分数时解析器直接抛异常，加权总分与一票否决全部由确定性 Java 代码计算；成对比较时把同一对答案送进模型评测两次（基线在前 / 位置对调），只有两次选出同一胜者才承认胜负，否则强制降级为平局；裁判标准漂移则用不同厂商模型担任裁判，并定期抽样 10% 样本交资深研发人工盲评，一致率跌破阈值就校准评分表。

**Q2 代码审查 Agent 防漏检**——把几百行 Git Diff 丢给通用模型说「看看有没有安全漏洞」漏报率一定很高：长文本注意力分散，且越权访问、二次 SQL 注入、未受控反射等高危问题跨多文件，只看被改的几行看不出完整攻击路径。解法是**用确定性静态扫描给大模型当眼睛，做前置证据冻结**：先用 JavaParser 语法树分析器、污点追踪规则、密钥正则扫描器过变更文件，标出拼接 SQL、子进程执行、反序列化外部输入、硬编码凭证、路径未规范化位置，并提取导入/继承/上下游调用关系；Controller 方法改了参数结构就顺调用图把下游 Service 的权限校验和上游过滤器配置一并读取，打包成冻结的脱敏证据快照。然后拆成 3 条相互独立的只读审查通道，用固定大小为 3 的线程池并发：外部输入边界与注入风险（SQL 注入、命令注入、SSRF、目录穿越与软链接逃逸）、身份认证与多租户接口越权、敏感凭证泄露与子进程环境变量污染及不安全第三方依赖。每路专家必须给出四项内容——可观察到的安全后果、精确到文件行号的证据边界、最小修复责任点、可执行的验收方法；三路返回后由独立主审模型（Lead Reviewer）交叉核验，剔除没有污点传播路径或上游已有白名单拦截的猜测性警告，只保留证据确凿的漏洞并评高/中/低风险，最终由确定性 Java 代码落盘生成结构化清单与可视化报告。

**Q3 RAG 与长上下文**——互补关系，谁也替代不了谁：长上下文解决「资料找出来之后怎么一口气读完整」，RAG 解决「怎么在海量、动态、带权限的数据里把那几页关键资料挑出来」。算账可知 1M 窗口装不下中型企业知识库或几十万行代码仓库；即便刚好 80 万 Token，每次问简单问题都要做 80 万 Token 预填充，TTFT 飙升到数秒甚至十几秒，API 账单与显存开销涨一两个数量级；且百万级长文本仍存在中间位置注意力衰减。更硬的伤是企业级多租户权限隔离——把全公司文档塞进提示词再叮嘱模型「不要回答非本部门内容」，遇到简单提示词注入就会跨部门泄密；只有把权限条件写进 ES 的 BM25 布尔过滤器和向量 KNN 的 pre-filter，才能从物理上保证进入上下文的每个字符都是有权限的。落地黄金组合是**小分块精准检索 + 大窗口完整阅读**：入库按自然段和标点切不超过 512 字符的子块保证向量语义纯粹；检索 BM25 + KNN 双路并行召回前 150 条，RRF 融合 + gte-rerank-v2 重排取 Top-K 小分块；交给模型前由**父块扩展器**按文件哈希、所属用户、分块序号取回前后相邻分块，去重叠后合并成最高 1500 字符的完整父块（单次检索总预算 6000 字符内）；同一父块命中多个子块时按文件哈希 + 起止序号生成唯一键复用，只发一次完整段落，同时保留小分块的精确页码和首句锚点供前端高亮。

**Q4 长短期记忆**——按信息生命周期与作用范围划分的两套存储体系：短期记忆是当前任务工作台（对话消息、工具参数、工具返回原始结果），生命周期绑当前会话；长期记忆是跨会话经验笔记本（编码偏好、构建规范、表结构约定），让 Agent 下次启动不用用户从头交代背景。短期侧不搞内存副本，直接就是发给模型的消息列表 + 只追加写入的 JSONL 会话账本；每次调模型前按代价从小到大做三档渐进治理（详见 [[上下文压缩]]）。长期侧同时维护显式项目指令（用户全局目录 → 项目根目录 → 本地私有指令文档按序合并，最多 3 层相对路径导入、24000 字符上限）与动态结构化记忆（项目级/全局两作用域，JSON 存储，进程内锁 + 文件锁 + 临时文件原子替换）。三类脏数据治理：外部网页提示词注入污染、同一事实的新旧版本冲突、代码改了但旧记忆还在。**防注入**：自动事实提取器只从用户本轮亲手输入的原话里逐字摘取，过滤密钥/手机号与「这次、临时、先这样」类短期指令并打待核实标签；一旦本轮读过外部网页/浏览器页面/MCP 资源或执行过网络抓取，立即锁死记忆写入，除非用户当前原话明确下令「记住」。**防冲突**：去重器只合并标点或空白差异的完全重复项，冲突检测器把同域记忆里的数字和版本号替换成统一掩码字符，掩码后文字一致（说明只有版本号或数值变了）或字符二元组 Dice 相似度 ≥ 0.8 就阻止静默写入，把新旧条目同时交给用户决定替换还是共存。**防过时**：检索注入按窗口大小的 1/200 控制预算（夹在 500~5000 Token），每条记忆带写入时间与最后核实时间，超过 30 天未核实、或关联源码文件 mtime 比核实时间更新，就降低排序权重并显式打「可能已过时」标记，系统提示词要求模型把长期记忆当线索而非绝对事实，改代码前必须以磁盘真实内容为准。

**Q5 KV Cache**——自回归推理里用显存换计算时间的核心加速机制，把预填充与解码阶段已算出的历史词元 K/V 缓存在显存，避免每生成一个新词都把前面所有词重算一遍，单步解码复杂度从平方级降到线性级。**只缓存 K 和 V 不缓存 Q** 是由自回归注意力矩阵的运算方式决定：第 i 步生成时用当前词元的 Q 去和第 1~i-1 个词元的 K 做点积算相关性权重再加权求和，历史位置的 Q 在各自生成那一步已用完，后续任何新词元都不会再读旧的 Q，留着纯属浪费显存；因果注意力掩码下前面位置表示不受后面新词元影响，K/V 算过一次就永远固定。优化要模型架构、推理引擎、Agent 应用三端配合：架构侧用 GQA/MLA 减 KV 头数与缓存维度，引擎侧用 vLLM 的 PagedAttention 分页管理消除碎片 + FP8 量化把单元素字节减半，Agent 场景「发一个短动作调用、换回一大段长工具观察结果」导致预填充占比极高，[[HySparse2]] 在 80B 总参（激活 3B）MoE 上只保留少数全注意力层并做跨层 KV 共享，在 1M 上下文、FP8 精度下把 KV Cache 从混合滑动窗口注意力的 12.09GB 压到 2.69GB、预填充计算量降 5.02 倍；再加上 NVIDIA Dynamo 的 KV 感知路由把同一会话的第 N 轮精准路由到已缓存前 N-1 轮 KV 块的 GPU 节点。应用侧最直接的是围绕**前缀缓存**做上下文布局——推理引擎按词元序列严格前缀匹配，中间改一个字符后面全部失效，所以把系统提示词 9 层按稳定度从高到低排列（永不改变的放最前、按天变化的放中间、每轮动态检索的项目上下文与长期记忆放最末），工具 Schema 按名称字典序固定排序，按需加载的 Skill 正文作为同轮独立 user 消息追加在尾部而不改顶层 system 提示。NVIDIA 实测：保持前缀逐字节稳定能让多轮编码 Agent 流量的 KV 缓存命中率达 85%~97%，首字延迟降低约 5 倍，输入 Token 成本省下大半。
