## 实测案例

### 办公 Agent 任务：会议、设备、咖啡

视频中展示了一个复杂办公任务，大意是让模型：

1. 帮用户订一个下午 3 点的线上会议。
2. 邀请指定人员入会。
3. 在 10 分钟后打开办公室空调。
4. 调整办公室灯光。
5. 降下窗帘。
6. 按“老规矩”订瑞幸咖啡。

模型返回的结果包括：

- 线上会议已创建。
- 会议时间已设置。
- 会议邀请已发送。
- 检测到部分参会人存在日程冲突，并发送提醒。
- 已设置办公室设备定时任务：中央空调开启、办公室灯光调至 80%、窗帘降下 50%。
- 瑞幸咖啡订单已生成：大杯、冰、少甜、小黄油拿铁，优惠后约 21 元，并提供微信扫码或支付链接。

作者强调，这类任务需要模型调用多个真实接口，例如摄像头、飞书、智能家居、瑞幸接口、会议系统、日历系统。这个案例主要用于证明 Seed2.1 Pro 的跨工具执行能力。

### 长任务能力：生成 100 个手绘风 UI 组件

视频中展示了一个很长的前端 PRD，要求模型生成一个完整的组件库页面。任务要求包括：

- 生成一个可直接在浏览器打开的 `index.html`。
- 包含 100 个功能不同的 UI 组件。
- 组成一个 Component Gallery。
- 所有组件保持统一风格。
- 每个组件都要能真实交互。
- 页面整体具有手绘动效。
- 交付组件清单，包含编号、名称和分区。

PRD 对视觉风格有详细约束：干净黑白手绘风、Notion 手账涂鸦风、手绘抖动线条、纸白背景、卡片白、墨黑线条、浅灰辅助色、卡片轻微错落旋转、胶带和回形针等黑白灰装饰，并要求使用 [[SVG]] 滤镜实现手绘线条效果。

画面中可以看到模型生成了类似“手绘组件画廊”的页面，包含基础元素、主按钮、次按钮、文字按钮、深色纸模式、命令面板、通知组件、弹窗组件和空状态组件。作者的判断是：Seed2.1 Pro 对长 PRD 的理解、风格保持、组件交付能力表现不错。

### 视频转文字 + 飞书文档 + 白板看板

视频中还展示了一个内容处理任务。用户要求模型：

1. 把一条视频转成完整文字稿。
2. 生成通顺中文翻译。
3. 单独创建一个飞书原文文档。
4. 在文档中放入访谈中英对照全文和原始链接。
5. 再创建一个主飞书文档。
6. 在主文档开头制作一个漂亮的白板总结看板。
7. 把关键内容清晰、不遗漏地列出。
8. 在看板下附上原始素材文档链接。
9. 最后把主文档链接发给用户。

执行结果画面显示：

- 模型调用了 `yt-dlp` 下载原始访谈视频。
- 调用了飞书妙记相关能力提取访谈内容。
- 使用 `lark-cli` 操作飞书文档和白板。
- 创建了主文档链接。
- 生成了可编辑的飞书白板，而不是普通截图。

这个案例主要展示 Seed2.1 Pro 的长链路任务能力，包括下载视频、提取文字、翻译整理、文档生成、白板生成、链接交付和多工具串联。
