## 核心摘要
小哈（犬小哈）从面试视角系统讲解异地多活架构：在不同地理位置的多个机房同时对外提供服务，任一机房故障其他机房可快速接管。核心难点不在搭机房而在数据同步——跨地域网络延迟高（北京到上海专线 RTT 约 30ms），普遍采用异步复制牺牲强一致性换性能。业界主流解法是**单元化（Cell-based）**，按用户 ID 哈希划分主写单元，避免跨机房双写冲突。蚂蚁 SOFAStack 将部署单元分为 RZone（可拆分核心业务）/GZone（全局数据）/CZone（共享服务）三类。CAP 上异地多活普遍选 AP，最终一致。成本极高（至少 3 套机房、专线月费百万级），仅适合大厂核心业务、金融两地三中心硬要求、跨国公司等场景。

## 关键信息
- **核心三关键词**：异地（物理距离拉开防城市级故障）、多活（每个机房都在干活非备胎）、业务可用（允许少量数据丢失）
- **方案对比**：冷备（几小时/低）→ 热备（分钟级/中）→ 同城双活（秒级/中高）→ 异地多活（秒级/高）
- **架构四层**：流量入口层（智能 DNS 路由）、应用层（每机房完整集群）、数据层（DTS/Canal/Otter 异步同步）、路由策略（单元化按用户 ID 切分）
- **关键组件**：智能 DNS、数据同步通道（DTS/Canal+Otter/Debezium）、全局唯一 ID（雪花算法/Leaf/数据库号段）、配置中心（Nacos/Apollo）、服务网关（Spring Cloud Gateway）
- **记忆口诀**：异地防灾难，多活防停摆，单元化是关键，最终一致是底线
