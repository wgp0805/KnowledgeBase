## 核心摘要
腾讯集团高级执行副总裁、CSIG CEO 汤道生深度复盘过去两年 AI 实践。核心观点：AI 马拉松才跑完头一公里，"熬得久比起得早更重要"。WorkBuddy 源自一个险些被砍的 DevTools 项目（coding.net 代码托管 + Web IDE + 代码沙箱），沿 AI Coding 做出 CodeBuddy，在"龙虾"走红后将同一套 Agent 能力推向办公场景。混元大模型因公司算力严重不足拖慢训练与产品发展。元宝在增长压力下走过弯路，现在与混元 Hy3 Co-Design 后搜索体验持续改善。提出个人 Agent（站在用户侧）与服务 Agent（遵循服务提供者意图、对数据输出承担责任）的并存互补关系。强调模型与产品 Co-Design、AI 原生组织（小团队办大事、跨界常态）、长期主义与以人为本。

## 关键信息
- **WorkBuddy 起源**：来自降本增效阶段险些被收缩的 DevTools 项目（coding.net + Web IDE + 代码沙箱）
- **演进路径**：DevTools → CodeBuddy（2024 私有化部署）→ WorkBuddy（2026 初，龙虾爆火后推向办公场景）
- **迭代速度**：上线三个月迭代四十多个版本，代码基本由 AI 生成，人转向"做判断、调试和把关"
- **算力问题**：公司整体算力严重不足，拖慢混元训练与产品发展
- **元宝复盘**：增长压力下花较多精力做推广引流，模型与产品都没 ready；现在与混元 Hy3 Co-Design 后留存率提升、单位运营成本下降
- **个人 Agent vs 服务 Agent**：个人 Agent 站用户侧创造/完成任务；服务 Agent 连接企业 CRM/知识库/工单/OA/ERP，对数据输出承担责任
- **服务 Agent 搭建**：腾讯云 ADP 智能体开发平台提供开箱即用配置；也可用 tRPC/langchain 开源框架自建；或用 CodeBuddy 从零搓
- **AI 原生组织**：产品经理可 vibe code 完成简单功能；角色边界模糊；小团队办大事；模型与产品 Co-Design
- **案例**：北京密云基层干部用 WorkBuddy 开发防汛小程序，一人一小时完成 16 个乡镇预警下发和转移统计
