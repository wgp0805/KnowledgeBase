## 核心摘要
作者张富春（ahfuzhang）以一个"现实矛盾"切入：理论上商业闭源 SaaS 软件应优于开源客户端（云端易升级、保密形成知识壁垒、算力存储优势），且云端 Agent 理应比本地 Agent 更强（大规模计算、长时间执行、并行、持久环境、集中知识库），但现实中云端与本地 Agent 的智能差距远没有预期大，SaaS 模式 Agent 平台也几乎无人做。他复盘自己的思想实验——为行业专家提供云端 Agent 平台、向客户卖"AI 员工"（虚拟化产品经理/架构师/前后端/测试/SRE 角色，客户在"虚拟 AI 人才市场"按月薪聘用，工资覆盖 token 成本，平台与专家分成）——并用 Richard Sutton 2019 年的《The Bitter Lesson》（苦涩的教训）解释自己为何想错了。该文核心：AI 历史上最终取得巨大进步的往往不是把人类知识精巧写进系统，而是能随计算量增加不断变强的通用方法——搜索（search）+ 学习（learning）；关键在可扩展性（scaling），"更多算力/数据/经验能持续转化成更强智能"的方法最终胜出（AlphaGo/AlphaZero 用神经网络+蒙特卡洛树搜索+海量计算超过人工规则），所谓"苦涩"即研究者精心编码的人类知识优势长期总是被通用算法抹平。由此作者推出暴论：Agent 上的能力提升相比模型智能提升不值一提，下一代模型智能会直接抹平过去几年 Agent 编排的努力；别指望靠长期投入 Agent 研发建立技术壁垒，Agent 更像薄薄的胶水层、注定是昙花一现的技术，投入应主打短平快、选杠杆率最高的工作；普通开发者别跟风卷 Agent 开发技术（Agent 功能像 10 年前一周即下线的运营活动 HTML 页）；OpenAI、Anthropic 敢开源 Agent 正因强化 Agent 与苦涩的教训矛盾；提示词工程→上下文工程→Harness 工程→Loop Engineering→图工程等新词汇本质都是在 Agent 上做强化，终被模型智能提升吸收；他还点名近期受关注的腾讯 WorkBuddy——若其长期壁垒建立在人为编排的 workflow/harness 上，而这些能力会被基础模型持续吸收，壁垒将快速贬值，属"错误的战略"。
