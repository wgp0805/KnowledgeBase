## 核心摘要
沉默王二介绍 G 哥（GPT-6 Astra）分享的《Rethinking skills and prompts for GPT-6 Astra》，500 多万浏览。核心结论：**模型能力变强后，Skill 要少一些，Memory 中陈旧的记忆要删掉，AGENTS.md 和 CLAUDE.md 也要精简**。两步实操：第一步提示词——按焚诀审查当前项目的 AGENTS.md 和 Skills，找出**过宽的 Skill 触发、无关文档强制读取、重复检查、冲突规则、频繁要求确认的指令**，逐条给出问题和最小修改建议；第二步提示词——根据审查结果优化，**缩小 Skill 触发范围、删除无关文档读取、合并重复检查、解决冲突规则、减少低风险任务中的无意义确认**，保留安全边界、敏感操作确认和必要测试。建议先挑一条有明确依据的建议改掉，然后用熟悉日常任务跑一遍观察模型行为变化。四个优化方向：**1) Skill 描述做减法**——Postgres 迁移 Skill 描述写成"涉及数据库时使用"就太宽（写个 SQL 查询也触发），收窄到"新增或修改迁移、审查迁移发布时使用"；Claude Code 项目里 browser-act Skill 描述覆盖"fetch URL/take screenshots/fill forms and click"几乎所有浏览器操作，沾一点网页就加载。自检清单：描述能否一两句话说清"做什么"和"什么时候用"、触发条件是否过宽、多个 Skill 描述是否重叠、详细步骤是放子文档还是全塞描述里。**2) CLAUDE.md 要瘦身**——反面例子"每次编辑前都读 architecture.md、database.md、deployment.md"，改法给每份文档加读取条件（"涉及服务边界时读 architecture.md，修改表结构时读 database.md，准备部署时读 deployment.md"）；**OpenAI 建议给安全工作流显式授权**（本地测试用一次性 fixture、无生产环境访问权限→直接跑测试、修失败、重跑受影响的测试，不必每一步等确认）。**3) 放松决策边界**——老模型时代"修改文件前必须先问我""禁止自动执行 shell 命令"等限制在新模型上反而让 Astra 过度谨慎。**安全底线保留**（不要自动 push 到远程仓库、不要删生产数据、涉及密钥必须确认），**日常低风险操作确认交给模型**（读文件、写测试、跑格式化）。**4) 在开始之前就定义完成标准（define completion before starting）**——Bad「帮我实现用户登录功能」（写完代码就停）→ Good「实现用户登录功能。完成后跑通本地测试套件，修复因这次改动导致的测试失败，确认所有测试通过、没有报错后再汇报结果」。测试停止条件也要写清楚。

## 核心观点
- **模型能力变强 → 老模型的约束反而变成枷锁**，该放手的地方要放手
- **给安全工作流显式授权** 是减少不必要确认的关键——不是加更多限制
- **完成标准的定义比"多测几遍"管用**——具体到跑哪些测试、通过什么条件、交付什么产物
- 详细步骤放子文档而非描述里；老模型的 SOP 对新模型是过度约束
- 一个模型合适的约束，可能对另一个模型就是过度约束
