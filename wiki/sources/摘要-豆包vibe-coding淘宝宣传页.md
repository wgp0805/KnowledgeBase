## 核心摘要

[[安全沼]]（人人都是产品经理，2026-09-28）因 Codex Token 额度耗尽，临时用 [[豆包工作]] 接手淘宝宣传网页项目，意外发现其 Coding 能力远超预期。初版在模糊提示词（"炫酷""丝滑"）下即产出可用效果，虽不及 Codex 但对一个低价/免费 Agent 已超出预期。

**项目难点与解法**：素材用 [[Seedance]] 2.0 生成，但长视频会被跳切破坏商品丝滑切换，被迫切成单商品短片段再由豆包整合。视频衔接的细微差异（背景像素漂移、模特表情微变）导致卡顿，经历了三轮方案迭代：
1. 后台偷换视频（依赖用户停留看文字的假设，不稳）
2. 动效遮盖卡顿（有效但破坏页面调性，不够优雅）
3. **最终方案：点击后延迟 200 毫秒响应，利用这个用户感知不到的时间窗口在后台完成视频替换**——一句话指令豆包即精确实现（"延迟两百毫秒"不会被曲解成两秒）

**三大感受**：
1. **低价工具够用论**：68 元/月套餐甚至免费版即可完成宣传页/落地页/活动页类需求，Codex 更强但强出的部分多数人感知不到
2. **进步是跳跃式的**：年初 Trae 时代理解不了的技术细节，现在说一遍就懂——对 AI 工具应定期重试而非一票否决
3. **Agent 一站式 vs 补全式助手**：豆包工作自己拆步骤、调工具、交付成品，与"写一段补一段需全程盯"的传统助手是两种体验；短板在复杂业务逻辑、大型架构与精细性能优化

整个项目仅耗数小时、少量 prompt，创意迭代"想法→跑起来→换"全程连贯不被工具打断。飞书生态联动（成品直接丢进飞书文档）是加分项。
