## 核心摘要
双亲委派模型是 [[Java]] 类加载器的核心工作机制：当一个类加载器收到加载请求时，不会自己先加载，而是**委派给父加载器**处理，只有父加载器无法完成时子加载器才尝试自行加载。核心源码位于 `ClassLoader.loadClass()` 方法中，逻辑三步走：先检查是否已加载、再委派父加载器、最后自行 `findClass()`。该机制保证类的唯一性和安全性——无论哪个加载器加载 `java.lang.Object`，最终都委派到 Bootstrap ClassLoader，防止恶意替换核心类。JDK 自身有三次"破坏"双亲委派：第一次是 JDK 1.2 历史遗留（用户重写 `loadClass()` 覆盖委派逻辑，JDK 引入 `findClass()` 打补丁）；第二次是 [[SPI机制]]（如 JNDI/JDBC，接口由 Bootstrap 加载但实现在 classpath 下，通过**线程上下文类加载器**绕过限制）；第三次是 OSGi 模块化和 [[Tomcat]] 的类隔离需求（Tomcat 的 `WebAppClassLoader` 优先加载 Web 应用目录下的类，实现多应用共存与 JSP 热加载）。面试核心：委派流程讲清 + SPI 和 Tomcat 两个破坏例子即满分。
