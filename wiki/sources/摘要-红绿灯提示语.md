## 核心摘要
卡尔 & yc星辰针对"Agent 永远不会主动说做完了、每轮都抛新优化清单"的老毛病，手搓不到 300 字的进度提示语：每轮回复末尾用绿黄红三色灯汇报进度——绿灯表示原始需求还有未达项（顺手改进只记进搁置），黄灯表示原始需求已全部达成且超出项能构成带证据的后续计划（落盘 plan/handoff 文件等人决定），红灯表示原始需求已达成但超出项零散不值得开新一轮（三行存档结束）。配套 hook 让每个对话自动生效，不依赖 skill。作者指出"Agent 推荐下一步做什么"本身就是认知陷阱，红绿灯的本质是给疯涨的 Agent 能力装上制动装置，把判断的权利留给人。

## 关键信息

### 问题：Agent 刹不住车
- Agent 从不会主动说"做完了"：一个半小时的需求拖成一下午——第一个小时做完，后面一直在处理 Agent 列的优化清单，每改完一批又来新的一批
- 多任务并行时更容易被拉着盲目走；二选一建议有时还是错的（如明确知道数据错误发生在飞书日报里，但更多时候是模型说啥我点啥）
- 朋友的尖锐观察：**Agent 推荐下一步做什么，这个功能本身就是认知陷阱，它让你永远觉得任务没完**

### 方案：不到 300 字的进度提示语
- **结构**：开工第一轮用一行钉住原始需求（目标：A、B、C），此后每轮只对照清单干活，清单只在用户追加需求时才变
- **🟢 绿灯**：还差 B、C｜搁置 X——原始需求有未达项，任务继续；顺手发现的改进只记进搁置（一行以内），先放着
- **🟡 黄灯**：原始需求已全部达成，以下可做成下一轮 Plan——每项都附证据；超出项能构成有明确目标和验收标准的后续计划，落盘成 plan/handoff 文件给路径，等用户决定是否启动
- **🔴 红灯**：原始需求已全部达成，以下仅供存档——每项都附证据；超出项零散不构成可执行计划，压成三行以内存档清单，结束
- **黄/红判定规则**：超出项能否串成一个有清晰目标的 Plan？能→黄灯，不能→红灯
- **停止纪律**：转黄/转红之后都停手，等用户下指令；用户追加需求则更新目标清单、进度条回到绿灯

### 从两态到三态的演进（踩坑记录）
- 最初只有绿灯和红灯，红灯下的"超出范围"区会列一堆东西，与模型输出的千字长文建议混在一起，用户还要离开对话自己再分一遍——真实案例：红灯下列了 PR 合并等确认、远端分支未删、生产迁移后续步骤三件事，用户懵了，新开对话查证发现三件一件都没做
- 加入黄灯后：模型自动把"能构成完整下一步计划"的超出项整理成计划（真实案例输出 37 行后续计划），用户只需集中判断"下一步跑还是不跑"
- 子代理同样适用：Sonnet 子代理跑完数据库迁移验证后回复末尾一行绿灯，用户只看最后一行就能区分"我要它做的"和"它自己额外加的"

### 使用效果
- **心理上**：每个任务开始有"完成的时刻"——以前像一条河不知对岸在哪，现在有终点线；一天协作十几个任务时这种确定感特重要
- **效率上**：黄灯直接做整合和去重，区分黄红后计划质量比以前好得多
- 不止写代码：整理旧会话残留事项、配运维等所有类型任务同一套规则同一行 emoji

### 核心论点
- 行业在卷怎么让 Agent 更强（更大上下文、更多工具、更长自主运行），但没解决怎么让它停下来
- **每一种强大的能力背后都跟着一个制动装置**（人类造了汽车花几十年才发明安全带）；Agent 现在能一口气做 100 小时任务（700 多篇数学论文、还原 1/3 紫外线没观察到的天空），能力在疯涨，但可以把判断的权利留给自己——"装个红绿灯"
