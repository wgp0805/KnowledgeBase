## 核心摘要
小哈学Java 公众号发布的操作系统面试题解析。用户态（Ring 3）与内核态（Ring 0）是 CPU 的两种特权级，前者只能访问本进程用户空间、不能执行特权指令，后者可访问全部内存与硬件。两者之间通过**三种方式**切换：系统调用（主动）、异常（被动）、外部硬件中断（被动），每次切换都伴随寄存器保存/恢复、栈切换、CPU 流水线 flush、TLB 部分失效等开销（纯特权级切换约 100ns 量级）。文章强调"减少系统调用"是高性能编程的核心实践，如 epoll 替代 select、DirectByteBuffer 共享内存、BufferedReader 缓冲、Java 19 虚拟线程减少线程切换开销。

## 关键信息

### 用户态 vs 内核态对比
| 对比项 | 用户态 | 内核态 |
| --- | --- | --- |
| 特权级（x86） | Ring 3 | Ring 0 |
| 可访问内存 | 本进程用户空间 | 全部内存空间 |
| 可执行指令 | 普通指令（不能执行特权指令） | 所有指令（含 I/O、关中断） |
| 是否可直接访问硬件 | 否 | 是 |
| 运行的代码 | 应用程序 | 操作系统内核 |

### 三种切换触发方式
1. **系统调用（主动）**：`read/write/open`、`fork/exec/exit`、`socket/connect/accept`、`mmap/brk`、`gettimeofday/nanosleep`。x86-64 通过 `syscall` 指令触发（32 位为 `int 0x80`），系统调用号放入 `rax` 寄存器，跳转到内核入口 `entry_SYSCALL_64`。
2. **异常（被动）**：缺页异常（Page Fault）、除零异常（SIGFPE）、非法指令异常。
3. **外部硬件中断（被动）**：时钟中断（进程调度时间片）、I/O 完成中断（网卡/磁盘）、键盘中断。

### 切换成本
| 开销类型 | 说明 |
| --- | --- |
| 寄存器上下文保存/恢复 | 用户态和内核态寄存器都要存一遍、再恢复一遍 |
| 栈切换 | 从用户栈切到内核栈 |
| CPU 流水线 flush | 特权级切换会清掉 CPU 流水线里的指令 |
| 指令缓存失效 | 内核代码可能不在 icache 里，要重新加载 |
| TLB 部分失效 | 伴随地址空间切换时 TLB 可能要刷新 |
| 安全检查 | 内核要校验用户传进来的参数是否合法 |

纯特权级切换硬件开销约 100ns 量级，完整系统调用通常在几百纳秒量级。

### 减少系统调用的工程实践
- **epoll 替代 select/poll**：一次系统调用处理大量连接
- **Java NIO DirectByteBuffer**：内核与用户态共享内存，省掉数据拷贝
- **BufferedReader/BufferedWriter**：缓冲区攒一波再读写
- **Java 19 虚拟线程（Loom）**：大量用户级线程映射到少量 OS 线程，减少线程切换的内核态开销

### 切换流程（用户态 → 内核态 → 用户态）
1. **触发阶段**：系统调用 / 异常 / 中断
2. **切换阶段**：CPU 从 Ring 3 切到 Ring 0，保存寄存器/PC/栈指针到内核栈
3. **执行阶段**：内核根据系统调用号找到对应函数（如 `sys_read`）执行
4. **返回阶段**：恢复用户态上下文，通过 `iret`/`sysret` 切回 Ring 3

### 面试高频追问
- **为什么要分离**：保护系统不被搞坏，特权隔离是现代操作系统根本
- **栈怎么变**：每个进程有用户栈和内核栈，切换时 CPU 自动切到内核栈（栈指针从 TSS 取出）
- **线程切换 vs 系统调用**：不是一回事。系统调用不一定发生线程切换；线程切换往往伴随进程地址空间切换，开销更大

### 记忆口诀
**"两态三种切，主动被动分清楚"**：两态（Ring 3/Ring 0）、三种切（系统调用主动、异常被动、中断被动）。切换成本记一句：**"保存恢复上下文，栈要切、流水线要 flush"**。
