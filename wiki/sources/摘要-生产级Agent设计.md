## 核心摘要
以 PaiCLI（开源终端 Agent）为案例，深入探讨生产级 Agent 设计的 11 个核心工程问题，涵盖多模式运行架构、上下文压缩与摘要策略、记忆系统的时间衰减加权、事实提取与重要信息过滤、API 指数退避重试、Token 消耗排查、Skill 渐进式披露机制、智能客服 Agent 四层架构设计，以及电商大促流量尖峰的五道防线。

## 关键信息

### PaiCLI 核心架构
- 三种运行模式：ReAct 主循环、Plan-and-Execute 先规划后执行、Multi-Agent 多角色协作
- 三种模式共用一套工具注册表、记忆系统、安全审批、审计日志
- GitHub 开源：https://github.com/itwanger/PaiCLI-Python

### 上下文压缩（Map-Reduce 分片摘要）
- 三步走：切片（每 5 条一组）→ Map 摘要（独立生成片段摘要）→ Reduce 合并（合并为整体摘要）
- 压缩后清空旧消息，保留摘要 + 最近 3 轮完整对话
- 三层防护：事实提取（存长期记忆）+ 摘要指令（明确保留关键信息）+ 近期缓冲（保留最近几轮）

### 记忆系统
- 时间衰减加权：24 小时从满分衰减到半分，新记忆自动排在前
- 关键词匹配检索（非向量数据库），毫秒级出结果，可解释可调试
- 事实提取：压缩前从对话中提取跨会话稳定事实，存长期记忆
- 重要信息三层过滤：排除临时任务、排除推测、保留持久信号

### 指数退避重试
- 默认最多 3 次，间隔 500ms → 1s → 2s，上限 30s
- 加 20% 随机抖动，避免集中重试打挂服务端
- 区分可重试（408/429/5xx、网络层异常）和不可重试（SSL 错误、JSON 解析错误、线程中断）
- 支持 Retry-After 头

### 渐进式披露（三阶段）
- 阶段一：启动时索引注入（名称 + 一句话描述，单条 ≤ 500 字符，最多 20 个 Skill）
- 阶段二：按需加载（模型调用 load_skill 工具加载完整指引）
- 阶段三：注入缓冲（最多同时保留 3 个 Skill，LRU 淘汰）

### 智能客服 Agent 四层设计
1. 意图识别（产品咨询、售后投诉、退换货、物流查询）
2. 知识检索（RAG 接产品文档、FAQ，chunk 512-1024 token + 20% 重叠 + Reranker 重排）
3. 工具执行（查订单、查物流、发起退款）
4. 兜底升级（连续两轮无有效回答或用户要求转人工）

### 电商大促流量尖峰五道防线
1. 请求队列异步化（消息队列 + Worker 按容量消费）
2. 模型分层（简单问题走小模型/规则引擎，复杂问题走大模型）
3. 热点缓存（标准答案提前生成缓存，注意活动规则调整时手动失效）
4. 限流保护（每用户每分钟请求数设上限）
5. 熔断降级（LLM 延迟超标或错误率飙升时切换模板答案或转人工）
