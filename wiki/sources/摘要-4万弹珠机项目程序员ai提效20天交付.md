## 详细内容

### 项目概况
- 开发周期20天，开发人数2人，整体费用4万，走正规合同

- 业务模式：远程真实弹珠机娱乐系统（类似"云抓娃娃机"），用户通过APP远程操控线下真实弹珠机，观看实时直播游戏，胜利获积分兑换实物商品

### 技术栈选型
| 层级 | 技术选型 | 选型理由 |
|---|---|---|
| APP端 | uniapp(Vue3+Vite) | 一套代码编译Android/iOS，直播/支付插件丰富 |
| 后端 | Python FastAPI | 异步高性能，自动生成OpenAPI文档 |
| 实时通信 | MQTT(EMQX)+Redis Pub/Sub | 低延迟双向通信 |
| 视频流 | RTMP推流+WebRTC播放 | 延迟~800ms，适合实时操控 |
| 视频直播 | 腾讯云快直播(LEB) | 无需自建流媒体服务器，按量付费 |
| 数据库 | MySQL 8.0+Redis 7 | 关系数据+缓存/房间状态/限流 |
| 硬件主控 | ESP32-S3/树莓派Zero 2W | WiFi+BLE，成本~¥35 |

- 商城：商品分类、积分兑换、等级V3-V6

### MQTT主题设计
- `device/{id}/cmd`：服务端→设备，控制指令（QoS1）
- `device/{id}/event`：设备→服务端，事件上报（QoS1）
- `device/{id}/result`：设备→服务端，游戏结果（QoS2确保不丢不重）
- `device/{id}/heartbeat`：心跳，每15s（QoS0）
- `device/{id}/status`：在线/离线状态（LWT遗嘱）

### 防作弊机制
游戏结果（弹珠落位）由硬件传感器直接上报，服务端只做校验和积分发放，APP端不参与判定。MQTT QoS2+session_id绑定，防止重复计分和伪造结果。

2. **需求与方案设计（提效60%）**：芯片选型对比、电路方案选型、通信协议设计、需求文档，AI一次拉齐。芯片选型AI直接给STM32F103 vs ESP32 vs GD32对比表
3. **联调与测试（提效60%）**：AI生成Python模拟后端代码，硬件没完全好就能先模拟联调。测试用例、自动化测试代码AI直接出
