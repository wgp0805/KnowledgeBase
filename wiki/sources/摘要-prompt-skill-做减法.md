# 模型越聪明，为什么 Prompt 和 Skill 越要做减法？

## 核心摘要
随着大模型能力跃升，过去为补足模型缺陷而堆积的 Prompt 规则和 Skill 配方正从"帮助"变为"负担"。Claude Code 为适配 Opus 5 删除了 80% 的系统提示词，GPT-6 Astra 对上下文中的冲突规则更加敏感。本文提出 Prompt 瘦身的三类保留原则：模型无从知道的信息、必须由人做出的选择、不应允许临场发挥的边界。

## 关键要点
- Claude Code 适配 Opus 5 时删除超过 80% 的系统提示词，消融测试显示去掉旧补丁后模型有时表现更聪明
- GPT-6 Astra 能遵循更长指令，但对 Skill、AGENTS.md 等指令文件更加敏感，冲突规则会导致模型过早停止确认
- ETH Zurich 与 LogicStar.ai 实验显示：自动生成的仓库级上下文文件未带来显著成功率提升，却使成本增加约 20%-23%
- Prompt 内容分两层：任务定义（来自真实业务）和能力补丁（来自旧模型失败经验），后者应优先清理
- Agent Skills 采用"渐进式加载"设计：先看名称说明，确认相关后读取完整指令，需要时才调用附加资料
- 瘦身应保留三类内容：模型无从知道的信息、必须由人做出的选择、不应允许临场发挥的部分
- 能用代码确定的工作应交给脚本和校验器，自然语言负责表达意图，确定性工具负责守住硬边界
- 有效瘦身从最小版本和真实验证开始：先移除原有提示，再逐条恢复并观察每条的实际影响

## 详细内容

### 旧规则为何成为负担
早期大模型需要具体引导，Prompt 通常包含角色设定、任务背景、执行步骤、输出格式、禁止事项和参考示例。这些内容分两层：
- **任务定义层**：写给谁看、解决什么问题、可用材料、交付格式——来自用户和真实业务
- **能力补丁层**：要求模型先列计划、按固定顺序执行、每步自检、套用模板——来自过去失败经验

问题在于这些内容只增不减。一次失败增加一条规则，时间久了难以分辨哪些是业务要求，哪些只是旧模型留下的补丁。

### 实验数据支撑
ETH Zurich 与 LogicStar.ai 在 300 个 SWE-bench Lite 任务和 138 个 CTXbench 任务上测试多种编码 Agent：
- 自动生成的仓库级上下文文件：无显著成功率提升，成本增加约 20% 和 23%
- 开发者亲自编写的文件：约 2.4% 平均提升，统计不显著，同样增加成本
- 成本增加与文件长度无明显关系，更可能来自每条指令触发的行为

### 瘦身的三类保留原则

**1. 模型自己无从知道的信息**
组织内部事实、项目历史、用户偏好、数据口径、已有资产和当前环境。稳定通用的信息进入 Skill，当前任务背景留在 Prompt，大体量资料通过索引和渐进式加载提供。

**2. 必须由人做出的选择**
目标、受众、优先级、取舍、验收标准和停止条件。有效写法是交代目标、给出资源、明确边界、说明可接受结果，路径交给模型选择。

**3. 不应允许模型临场发挥的部分**
安全、权限、合规、不可逆操作、固定数据格式和关键验证规则。能用代码完成的交给脚本、校验器和权限系统。

### 优先清理的内容
泛泛的角色设定、情绪化鼓励、僵硬的固定步骤、重复表达的禁止项、为旧模型准备的大量示例，以及"每次都读完所有资料""无论改动大小都跑全部测试"之类的全局要求。

### Skill 的周期性检查
模型升级后，删除旧规则，运行真实任务，记录重复出现的问题，只为稳定复现的缺口增加指令。某条规则如果长期没有改善结果，或只会带来额外步骤，应被改写、下沉到按需资料或直接移除。
