## 核心摘要
本文为 PM 转 FDE（Forward Deployed Engineer，前沿部署工程师）先泼冷水再给路径。FDE 本质一句话：带着公司的产品和技术扎进客户现场，把客户的业务问题真正解决掉，并把现场认知带回来改造产品——三个关键词是"扎进现场""真正解决掉（考核的是客户业务指标变化而非交付功能数）""带回来"；AI 时代 FDE 重要是因为大模型能力与企业实际价值之间隔着很宽的沟（数据脏、流程隐性、知识在老员工脑子里、好坏标准没人写下来），FDE 就是填沟的人。与产品经理/售前架构师/实施顾问相比，FDE 是"一个人的创业团队"：自己发现问题、定义方案、写代码、对结果负责，且是生产级构建。PM 的三大优势（问题定义、业务抽象、跨角色沟通）真实存在，但三个错觉要警惕：①"懂业务技术可以慢慢补"——技术在 FDE 岗位上是入场券不是加分项，AI coding 能帮你做 demo 但很难帮你扛生产环境；②"FDE 是更高级的 PM"——恰恰相反，是从"判断该做什么然后交给别人做"变成"自己做完"，文档/评审/对齐能力权重下降；③"做 FDE 是追风口"——日常大量不体面工作（洗数据、扯权限、凌晨排查）。真正的挑战：技术硬门槛（Python/SQL/API/RAG/Agent 编排/评估体系/部署，其中评估能力是 PM 可建立优势之处——本质是把业务标准翻译成可测量指标）、从"规模化思维"转向"做不能规模化的事"（先为一个客户做到极致，跳过这步直接追求可复用是 PM 出身 FDE 最常见失败模式）、中国 B 端特殊难度（定制化泥潭、数据合规驻场耗时、组织政治）、与总部产品团队的张力（无回流机制会沦为高级实施）、岗位鱼龙混杂（很多只是实施换名）。转型六步：诚实诊断差距（两周独立做出可被真实用户使用的 AI 应用原型）、以"能交付"为标准补技术（Python/SQL → API → RAG/Agent/评估 → 部署运维，理解每段生成代码）、在现岗位"预演"FDE、用作品而非简历说话（2-3 个端到端案例讲清问题/判断取舍/亲手构建/业务指标变化）、面试选对公司并识别真假 FDE（问考核指标、回流机制、团队关系、商业模式）、心态从"对的方案"转向"跑起来的方案"。结论：真正的危机不是你是不是 FDE，而是是否停留在"只会写文档、只会传话"的中间层——这一层在 AI 时代会被快速压缩。
