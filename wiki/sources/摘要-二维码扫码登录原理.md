## 核心摘要
《Java 技术指北》分享抖音/阿里/腾讯/京东/小红书等大厂高频面试题——"二维码扫码登录原理"。**登录的本质**是两件事：告诉系统我是谁 + 向系统证明我是谁。扫码登录基于已登录手机端，通过二维码 ID 在服务端临时绑定 PC 设备与手机账号，再下发 PC 端专属 token 实现"同账号跨端登录"。完整链路：① PC 请求二维码 → 服务端生成 ID 并绑定 PC 设备信息 → PC 渲染二维码并开始**轮询**；② 手机扫码 → 解析 ID → 上传账号信息绑定 → 服务端下发**临时 token**给手机；③ 手机用临时 token 确认 → 服务端根据二维码 ID 关联生成 PC 专属 token → PC 轮询拿到 token 完成登录。三大状态：**待扫描 → 已扫描待确认 → 已确认**。

**关键安全要点**：
- 手机端**不存储密码**，只存 token，token 与"账号 ID + 设备 ID + 设备类型"绑定——即使 token 泄漏，换设备也无法用
- 临时 token 只用一次，确保扫码与确认是同一台手机
- 扫码登录适用于"同一系统跨端登录"；第三方扫码登录（如微信扫码登录掘金）是另一套流程
