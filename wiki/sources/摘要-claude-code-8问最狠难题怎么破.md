# 摘要：Claude Code 8问，最狠难题怎么破

## 核心摘要
本文针对 Claude Code 进阶用户最常遇到的 8 个卡点问题，给出了系统化的排障路径。核心观点是：AI 编程工作流的稳定性不取决于工具数量，而取决于每个工具的职责边界是否清晰、证据链是否完整。文章将 Skill 不触发、MCP 不调用、代码图谱过期、PDF 图表答错等问题归结为工程边界问题，而非模型能力问题。

## 关键要点
- Skill 不触发的根因是「发现-路由-执行」三层链路只通了一层，应先显式调用再查 description 和路径
- 同名 Skill 存在多份来源是最危险的配置，必须只保留一个权威来源
- system prompt 管全局行为、CLAUDE.md 管项目事实、Skill 管可复用流程，三者职责不可混淆
- `--append-system-prompt` 是护栏而非外挂，只适合追加安全边界、权限范围和输出格式
- MCP 注册不等于会被调用，需排查启动、描述、任务路由三层
- Skill 跨 Agent 复用应拆分核心层（任务方法）和适配层（宿主配置）
- 代码图谱是导航而非目的地，索引过期时必须回源读代码
- PDF 检索要先按问题类型分流：文字走 RAG，图表走多模态，不能为省 Token 关闭视觉通道

## 详细内容

### 速查表：现象-根因-对策

| 现象 | 根因 | 先做什么 |
|------|------|----------|
| Skill 装了不触发 | 发现/路由/执行三层有一层没通 | 先显式调用，再查 description 和路径 |
| 全局和项目 Skill 打架 | 同名 Skill 有两份来源 | 只保留一个权威来源 |
| 规则写了但不听 | 四层提示词职责混在一起 | 把事实、流程、全局约束拆开 |
| 追加 system prompt 后行为变怪 | 替换和追加、全局和临时规则混用 | 先用 `--help` 核对参数，再只加边界 |
| MCP 注册了不用 | 工具能启动不等于 Agent 会选择 | 查启动、描述、任务路由三层 |
| 同一套 Skill 换 Agent 失效 | 核心流程和宿主配置绑死 | 拆核心层和适配层 |
| 代码图谱越用越错 | 索引是缓存不是真相 | 先校验更新时间，再回源读代码 |
| PDF 省 Token 却答错图表 | 文本检索绕过了视觉通道 | 文字走 RAG，图表走多模态 |

### Skill 三层链路排障模型
Skill 不触发的排查顺序：先在对话里显式调用一次确认 Skill 本体能执行 → 再看 `description` 是否具体 → 最后才怀疑模型能力。一个能被正确路由的 `description` 必须写清触发场景、任务边界和不适用场景，而非产品宣传词。

### Skill 分三类管理
- **个人习惯**：放用户级目录，换项目也成立
- **项目规则**：放项目级目录，离开仓库不生效
- **团队能力**：放团队仓库或固定 plugin，需版本管理

### 提示词四层职责划分
- **system prompt**：全局行为规则（驾驶规则）
- **CLAUDE.md**：项目事实（入职手册）
- **Skill**：可复用流程（操作手册）
- **当前对话**：只对当前轮有效的临时边界

判断标准：把这句话复制到另一个项目还成立吗？成立放全局，不成立放项目上下文，只有做某类任务才需要放 Skill。

### MCP 排障四动作
```
claude mcp list      # 看注册
cat .mcp.json        # 看项目级配置
command -v node      # 看运行时
node --version       # 看版本
```
工具描述要写「什么时候用」而非「我能做什么」。MCP 返回的是证据线索，不是最终答案。

### Skill 跨 Agent 复用策略
拆分两层：核心层只写任务方法（检查清单、领域术语、验收步骤），适配层写各宿主的 MCP 名称、配置目录、权限语法。最常见失败是把 Claude Code 专用的 `CLAUDE.md`、MCP 工具名原封不动塞给另一个 Agent。

### 代码图谱三条规矩
1. 先查更新时间和当前分支，再相信关系查询
2. 图谱只负责缩小范围，命中的文件必须回源读
3. 涉及写操作时至少再看一遍测试和调用方

实测数据：sense 工具调用从 19 次降到 10 次，Token 从 228K 降到 156K。省下来的调用次数应拿去做验证，不是省略验证。

### PDF 问答分流表

| 问题类型 | 推荐路径 | 原因 |
|----------|----------|------|
| 条款、定义、章节、关键词 | 本地 RAG | 文本检索精准，输入小 |
| 表格中的数字 | 先文本检索，再核对原页 | 防止列错位和单位误读 |
| 架构图、流程图、扫描件 | 原生多模态 | 必须保留版式和视觉关系 |
| 既问正文又问图表 | 两路结果合并 | 文本和视觉各负责一半 |

### 排障脚本
文章提供了一个只读检查脚本 `claude-code-doctor.sh`，可快速筛出「目录不存在」「配置文件不在」「CLI 不在 PATH」「MCP 列表为空」等低级问题。
