## 核心摘要
小哈学Java 面试视角拆解操作系统「时间片（Time Slice / Time Quantum）」概念：CPU 时间被切成小段轮流分给每个进程，谁也不能一直霸占。时间片是分时调度（RR）、CFS 等调度算法的核心参数，典型大小几毫秒到几十毫秒。文章梳理了「时间片用完 → 时钟中断 → 调度器介入 → 上下文切换」完整链路，并详解 Linux CFS 完全公平调度器基于 sched_latency（默认 6ms）和进程权重动态分配时间片的机制，以及 Linux 6.6 被 EEVDF 调度器替代的演进。

## 关键信息
- **本质**：CPU 时间的一段配额，实现分时、公平调度、避免独占
- **大小权衡**：太大退化成独占响应慢，太小上下文切换频繁 CPU 利用率低；经验值 10ms-200ms
- **CFS 核心参数**：
  - `sched_latency`（目标调度延迟，默认 6ms，按 `750000 * (1 + ilog(ncpus))` 动态计算）
  - `sched_min_granularity`（最小调度粒度，默认 0.75ms）
  - 每个进程实际时间片 = `sched_latency / 进程数`
- **上下文切换开销**：现代 x86 Linux 单次约 1-7 微秒，常见 1.3-3.5 µs
- **演进**：Linux 6.6（2023）CFS 被 EEVDF（Earliest Eligible Virtual Deadline First）替代
- **关键概念**：上下文切换、抢占式调度、时钟中断
