## 核心摘要

微信公众号「沉默王二」2026-03-25 发布的面试纪实文，以「老王面试官让手搓一个 Claude Code」为叙事线，借助开源教程项目 **learn-claude-code**（shareAI-lab）的 12 层架构，从面试题角度层层拆解一个类 Claude Code Agent 的构造思路。文章核心命题用一句话概括：**"The model is the agent. The code is the harness."**——模型本身即 Agent，代码只是为它提供运行环境（harness）。

九大拆解层：

1. **Agent 的本质**：普通聊天机器人是「输入-输出」，Agent 是「输入-思考-行动-观察-再思考」的循环，关键差别在 **工具**。Agent 是有状态的，状态转移由模型自主决定（比预定义状态机更灵活），从「顾问」跨越到「执行者」。
2. **工具调用机制**：模型只认识工具的 `description` 与 `input_schema`，描述质量直接决定调用准确率。工具失败分三态——执行出错、超时（Claude Code 转后台执行）、返回格式不匹配。工具设计四条最佳实践：描述具体、参数 3-5 个、错误信息对模型友好、设默认值与约束。[[FunctionCalling]]
3. **任务规划与动态调整**：用 `PLAN_SYSTEM_PROMPT` 让模型先拆步骤再执行。与静态任务队列的区别在「动态性」——执行中可根据反馈跳过/插入/重排步骤，并附带资源估算与风险评估。
4. **Sub Agent 多 Agent 协作**：子 Agent 拥有独立上下文，执行完汇报主 Agent，类似微服务但拆分组合是动态的。靠 **工作树隔离**（每个子 Agent 独立工作目录，类比 Docker 容器）保证安全、并发、可复现。子 Agent 还可扮演「专家系统」（前端/后端/数据库专家），完成后「懒销毁」避免资源占用。
5. **技能按需加载**：不把全部工具塞给模型，按任务类型动态加载技能（一组相关工具的集合，粒度比单工具更粗）。好处：省 token、提高调用准确率；通过命名空间（`file.read` vs `db.read`）解决冲突，按拓扑排序处理依赖，并支持热更新。[[Skill]]
6. **上下文压缩**：不是简单截断，而是区分「事实性信息」（路径/代码/参数，必须保留）与「过程性信息」（试错/推导，可压缩）。分级压缩（近-轻-重三档）+ 用户介入确认。可与长期记忆结合：短期记忆会话级、长期记忆跨会话（外部存储）。[[context-compression]]
7. **任务并行 DAG**：把无依赖任务组织成有向无环图并行执行，靠工作树隔离避免冲突，主 Agent 最后合并结果；共享资源场景需加锁或消息队列协调。
8. **Harness Engineering**（全文题眼）：旧式 AI 应用是「设计工作流让模型在每个节点干活」，Agent 时代则是「模型即 Agent，工程师做的是提供工具、知识、权限、上下文的运行环境」。本质是「信任模型」——像带团队一样设定目标、给资源、放手让其发挥，而非事无巨细地硬编码指导。[[AgentHarness]]
9. **落地三步走与三大坑**：先搭最基础 Agent 循环 → 按需逐层加能力 → 复杂度上来再加子代理/DAG/压缩。三大坑：过度设计（一次性堆所有功能）、忽视边界情况（文件不存在/超时/权限）、工具设计差（描述不清、参数不合理）。

文末给面试者的建议：不要停留在「用过」层面，要能讲清原理；选一个开源项目深入研究；学会把技术细节包装成有逻辑的故事。学习路径推荐先通读 12 层架构文档，再从 s01 逐层跑代码，最后自己实现简化版。
