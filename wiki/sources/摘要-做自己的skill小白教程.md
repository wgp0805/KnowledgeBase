## 核心摘要

秋芝2046（2026-11-24）以"去 AI 味"为练手任务，手把手演示七步做出一个真正属于自己的 Skill。核心论点：**网上下载的 Skill 是照别人习惯做的，最顺手的还得自己做；专属 Skill 的关键是"你独有的标准和要求"**。

- **开工前认知**：Skill 本质是一个文件夹，核心是 SKILL.md（上写"什么时候用"，下写"整体怎么干"），更细的步骤作为附件放在其他文件里——本质是"给 Agent 的任务说明书"
- **第一步 选高频、AI 又做不好的任务**：两条原则——你会反复做、直接让 AI 做它做不好。"去 AI 味"绝对高频。用亚马逊云科技 [[Kiro]] Crew（开源 Agent 工作台，左 Agent 右文件编辑，支持 DeepSeek/MiniMax/GLM/Qwen，可切 [[DeepSeekHarness]]）开会话选 GLM-5 裸跑一次，结果"换了一套新的 AI 味出来"
- **第二步 找 Skill 底子**：先让 Agent 搜现成的（没有就用官方 [[SkillCreator]] 当底子）。下载的现成 Skill 要留意更新时间——老模型写的写死规矩会束缚新模型；换新模型记得关掉 Skill 裸跑一次，不如不用就删。去 AI 味最火的是 blader 的 [[Humanizer]]（7 万星，归纳 6 种常见 AI 腔）
- **第三步 从样本提炼个人标准**：SkillsBench 研究——AI 凭空自编 Skill 用了比不用还差 8~12 个点；网上热门 Skill 大半装了跟没装一样；人结合真实任务磨出来的平均涨 16.6 个点。方法：找 10 篇以上自己写的语料（最好没用 AI 之前写的）→ 让 Agent 分析句子长短/标点/口头禅/开头转折并附原文证据 → 人工过一遍分成"要留的、要改的、想加的"（作者发现自己 60 段有 10 段"那"开头，属于要改的味儿）
- **第四步 边改边教**：拿真事带它做一遍（[[Humanizer]] + 个人风格清单），逐句评论"不像你"的地方并告诉它你会怎么写，反复几轮直到像你，这一轮又沉淀出细节标准
- **第五步 整理成 Skill**：调 [[SkillCreator]] 说"在 Humanizer 基础上把风格清单和做法改进去，存成新 Skill 并起自己的名字，保留原作者署名和 MIT 协议"；然后**砍掉多余内容**（AI 只增不删，但 Skill 越短越有效——删掉 AI 本来就会的、与自己目标无关的英文习惯）与**拆分文件**（SKILL.md 只留主流程和目录，习惯清单/样文/统计放 reference/，检测脚本放 scripts/）
- **第六步 对比测试**：同一提示词同一件活儿，让 Agent 调三个子 Agent 盲评——一个不用 Skill、一个用原版 [[Humanizer]]、一个用改好的文风 Skill，三份打乱标 A/B/C 让人选，借此看清到底哪些指令影响了结果
- **第七步 使用中迭代**：①**用规律替代禁令**（别不停加"不要这样"，要问为什么、找到背后的规律和模式）；②**把复盘规则写进 SKILL.md** 让 Agent 主动复盘再由人决定是否写入；③定期更新 reference 里的参考，模型更新后关掉 Skill 裸跑一次删掉过时规矩
- **收尾**：专属 Skill 的关键是独有标准；网站上云/Agent 云端部署这类专业活官方有现成 Skill（亚马逊云科技 Agent 云服务工具包，新用户最高 200 美元免费额度），复制控制台提示词粘回 Agent 即可跑完官方部署流程
