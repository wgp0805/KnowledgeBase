## 核心摘要
基于《Claude Code 实战》一书，解释同款工具同款模型下团队成员效率差距的根源：把工程经验外化成机制。第一层分水岭是"每次开新对话要不要重讲项目背景"——工具假设对比上，Copilot 假设"知道怎么写只是手速慢"、Cursor 假设"知道改哪里需要精确工具"、Claude Code 假设"瓶颈是把想法变成跨文件实现的认知负担"，心态应校准为"30 秒给出 80% 可用草稿"。拉开差距的四件套：[[CLAUDEmd]] 三层体系（全局/项目/目录，内层覆盖外层），写四类内容且**禁止事项投入产出比最高**、写错误信息比不写更糟；[[Hooks]] 把软约束变纪律（PreToolUse 可拦截、PostToolUse 自动格式化/测试，2 秒内返回否则拖慢响应，Hook 是把关人不是拦截器）；[[AgentSkills]] 渐进式披露（平时只加载 description，写"用户会怎么说"决定自动触发，过期 Skill 比没有更糟）；[[子Agent编排]]（无先验上下文须写全任务书、独立上下文与工具权限、配 git worktree 隔离；**单任务超 20 分钟且弱依赖才值得并行**，3 个子 Agent 即 3 倍 token）。地基是上下文：窗口如固定桌面、每次回车整段对话重新打包故无跨轮记忆，污染四症状（记错/重复否定/废话/变慢）出现前两个就动手，决策树：任务完成且无关 /clear、完成且相关 /compact、死循环 /clear；跨天写 session-notes.md 快照后 /clear 重开而非 /resume。最后强调**判断权不能外包**：架构选型、安全评审、产品决策三类任务的核心是判断，正确用法是让 AI"梳理利弊不给推荐，我自己决定"。
