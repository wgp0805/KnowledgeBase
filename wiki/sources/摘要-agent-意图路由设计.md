## 核心摘要
面试向的 Agent 意图路由设计指南：用户一句话进来，先判断交给哪条处理路径（子 Agent、工作流分支或更便宜/更强的模型），这一步就是意图路由。反模式是"把所有子 Agent 介绍塞进提示词让大模型自己选"——慢且贵。OpenAI Agents SDK 的做法是**分诊 Agent**：把每个子 Agent 包装成 `transfer_to_{name}` 工具（描述为 handoff_description），选中即调用即 handoff，准确率全看介绍写得清不清楚；Anthropic 建议分类任务用枚举参数或结构化输出。**生产级四层路由**：①关键词明确的（"查订单""退款"）用规则；②向量比对（semantic-router 为每条路由备示例，问题转向量取最近 5 条示例按路由求均分，超阈值即走）；③固定选项上决策模型（TypeSafe AI 的 Jev 延迟 70–500ms，OpenAI Decisions API 单任务 150ms，而 GPT-6 轻量模型 Luna 要 1.6 秒）；④都判断不了的模糊请求才交大模型（简单给 Sonnet 5.5、困难给 Opus 5.5）。**兜底与纠错**：分数低于阈值或同时命中多意图就带选项问用户；子 Agent 超范围可转回分诊 Agent 但要设转回上限防互相踢皮球；多意图请求事先写明优先级，意图超 20 个分层分类；准备标注测试集按意图统计准确率/召回率，把相似已标注问题检索进提示词可将准确率从 71% 提到 93%。**置信度靠不住**的三种可信替代：logprobs 阈值（OpenAI Cookbook：超阈值自动分类、低于阈值人工复核）、向量相似度、做过校准的决策模型（报 90% 把握实际正确率接近 90%）。一句话总结：**确定的用规则，相似的用向量，有固定选项的用决策模型，模糊的交给大模型，拿不准的问用户。**
