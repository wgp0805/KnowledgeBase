## 核心摘要
如此AI-小赵提出：vibe coding 时代，代码不再是项目唯一核心，文档管理才是决定成败的关键。AI 是「能力很强但短期记忆有限、极度依赖输入质量的短期协作者」，你给它的文档质量基本决定它的工作质量。文档在 vibe coding 中承担四个角色：项目记忆、协作协议、约束系统、复用入口。真正拖慢 vibe coding 的不是写得慢，而是上下文失真（README 旧、架构图过期、决策无记录），导致 AI 产出「局部正确，整体错误」的最难排查 bug。文章给出五类关键文档：项目总说明、架构与运行时约束、编码约定、平台/模块状态文档、决策记录。

## 关键信息
- **核心论点**：vibe coding 里唯一真正重要的，是管理好文档
- **AI 定位**：短期协作者，不是长期记住项目的程序员
- **文档四角色**：项目记忆、协作协议、约束系统、复用入口
- **上下文失真表现**：代码增加、功能推进、讨论变多，但共识变少
- **AI 失真典型问题**：局部正确，整体错误（每段像那么回事，连起来不对）
- **五类关键文档**：
  1. 项目总说明（项目是什么/边界/技术栈/目录/原则）
  2. 架构与运行时约束（哪些 API 可用/纯函数化/特定端能力）
  3. 编码约定与目录约定（命名/职责/错误处理/日志/类型）
  4. 平台或模块状态文档（做到什么程度/已验证/已知问题/跳过原因）
  5. 决策记录（为什么当时没那样做）
- **好文档四标准**：明确不优雅、面向任务不面向展示、与现状同步、能被快速检索
- **vibe coding 本质**：不是把开发外包给 AI，而是把上下文工程化
- **稀缺资源转移**：从代码转移到清晰目标、稳定约束、可复用上下文、持续更新的知识体系
