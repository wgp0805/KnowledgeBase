## 核心摘要

沉默王二（二哥）以一条帖子切入算力红利话题：32 岁在张江做芯片相关研发，税前 80 万，没有互联网那么卷。作者的判断是——**随着 AI 发展，底层算力越来越紧俏，离硬件近的地方反而成了香饽饽**。而招得最多、缺口最大的并不是画电路板搞硬件的人，恰恰是**夹在硬件和大模型之间的软件全栈工程师，尤其是 AI 编译器和算子开发**。

原因：不管是英伟达 H100/Blackwell 还是华为昇腾、寒武纪这些国产卡，硬件账面算力再高，如果**没有编译器把计算图翻译成贴合硬件存储层级的机器码，计算单元大部分时间都在空等显存搬数据**。字节在算力底座方向开源了不少硬核项目：[[ByteIR]]（基于 MLIR 的模型编译方案）、[[TritonDistributed]] 与 [[Flux]]（解决多卡训练推理时计算与通信如何重叠）。作者提示：即便做上层 Agent 和 RAG，摸清硬件与编译器怎么配合依然必要——面试大厂 AI 工程岗时，面试官喜欢顺着推理延迟和显存占用往下深挖一层。

文章主体是一份 AI 编译器岗位的面试逐题总结（与"RAG 面试题"来自同一家公司），共五问：

1. **AI 编译器岗位大致做什么**——把算子的数学描述翻译成在特定硬件上执行最快的机器码：往上接框架导出的计算图（PyTorch）或 StableHLO 这类中间表示，往下接硬件指令集（NVIDIA 上是虚拟指令集 PTX 与机器码 SASS）。具体工作从算子内部往外扩展：算子调度（分块让数据留在寄存器/共享内存）、向量化、搬运算算重叠成流水线；再放大到整张计算图：相邻算子融合省掉中间结果来回读写显存、数据排布与显存复用；最后需要自动调优机制搜索参数（换输入维度或换显卡，最优参数就变）。作者自己的判断：这个岗位的评价标准只有一个——**在目标硬件上快了多少倍**，所以要能读硬件手册、会用 profiler 看计算单元有多少时间空闲。
2. **CPU 与 GPU 架构的主要区别**——① 晶体管花在哪：GPU 把更多晶体管用于数据处理而非数据缓存与流程控制（CPU 用多级缓存/分支预测/乱序执行"避免等待"，GPU 用多线程切换"让等待被别人用掉"）；② 线程组织方式：SIMT，SM 以 32 线程为一组（warp）创建调度，`if/else` 让同一 warp 内分叉时两条分支都要走，所以分支差异要尽量发生在不同 warp 之间（Volta 之后有独立线程调度与 per-thread PC，但同 warp 分叉的硬件开销仍在）；③ 规模：H100 SXM5 有 132 个 SM（完整 GH100 为 144，PCIe 版 114），每 SM 可驻留几十个 warp——CPU 优化是减少指令数与分支预测失败，GPU 优化是提高占用率与做好访存合并。
3. **GPU 有哪些缓存和存储层级**——以 H100 为例自近及远：寄存器（每 SM 64K 个 32 位寄存器 = 256KB，单线程最多 255 个，用得越多占用率越低）→ L1/共享内存/纹理缓存合并成的 256KB 片上空间（A100 为 192KB，共享内存最多 228KB，单线程块最多 227KB，CUDA 运行时预留 1KB；静态声明上限仍是 48KB，超过必须动态分配）+ 常量缓存（总量 64KB，每 SM 工作集 8KB）→ L2（H100 50MB / A100 40MB，全 SM 共享，访问外部显存的必经之路）→ 显存（H100 SXM 80GB HBM3，白皮书 3TB/s vs 数据手册 3.35TB/s 需注意出处；B200 为 180GB HBM3e / 最高 8TB/s，网上流传的 192GB 是物理堆栈总容量而非可用容量；GB200 L2 为 126MB）。Hopper 新增两样机制：**TMA（张量内存加速器）**，异步搬运一维到五维张量并支持写回时做逐元素归约；**线程块簇（Thread Block Cluster）**，CUDA 计算能力 9.0 引入，同簇线程块保证被调度到同一 GPC，可移植最大 8 个（开启非可移植开关可用到 16 个），用于实现分布式共享内存（跨 SM 读写/原子操作对方共享内存，总容量 = 簇内线程块数 × 每块共享内存）。Blackwell 又新增**张量内存（Tensor Memory）**：仅数据中心版（sm_100）有，按线程块组织，每块 512 列 × 128 行 × 32 位 = 256KB，按列分配（最少 32 列、列数必须为 2 的幂），须由同一 warp 申请释放，每个 warp 只能访问属于自己的 32 行；配套指令 `tcgen05.mma`，Hopper 的 `wgmma.mma_async` 在 Blackwell 已弃用。规律很固定：**离计算单元越远，容量越大、带宽越低、延迟越高**，所以算子优化的绝大部分工作就是想办法把数据留在上面几层片上存储里。
4. **对 LLVM、MLIR 有什么了解**——从"深度学习编译器为什么不直接把模型转成 LLVM IR"切入：LLVM IR 抽象层次太低，只有标量（单个数字）和定长一维向量，没有多维张量类型与多层循环嵌套结构，一个矩阵乘法会退化成三层嵌套跳转加标量乘加，循环依赖、可交换顺序、可融合算子这些高层信息全部丢失；LLVM 擅长的是转到底层之后的寄存器分配、指令选择与调度。[[MLIR]] 的解法是**渐进式降级（progressive lowering）**：分很多层逐步往下转，每层用一种方言（dialect）表达，不同抽象层次的方言可共存于同一模块。常见方言按抽象层次从高到低：`linalg`（结构化算子，分块与融合在这一层做最方便）→ `tensor`/`memref`（数学张量值 vs 实际物理内存，两者之间要经过 bufferization 内存化转换）→ `affine`/`scf`（循环结构，affine 限制更严格但依赖分析更准）→ `arith`（基础算术）→ `gpu`（GPU 线程/线程块概念）→ `nvvm`（NVIDIA 内建函数）→ `llvm` 方言，交给 LLVM 后端生成机器码。用 [[Triton]] 编译器看最直观：Python 源码 → TTIR（以数据块为单位、与显卡型号无关）→ TTGIR（带上 GPU 硬件信息：warp 间数据分布、访存合并、共享内存排布，其间跑 remove_layout_conversions / accelerate_matmul / optimize_dot_operands 等 pass）→ LLVM IR → PTX → ptxas 汇编成 cubin；各硬件后端把这些阶段注册在自己的 `compiler.py` 里，AMD 后端前三级完全一样，最后换成 amdgcn 与 hsaco。MLIR 的来历：2018 年 Google 内部启动，2019 年 4 月先在 TensorFlow 仓库开源，同年 9 月 Chris Lattner 在 llvm-dev 发起提案，10 月 LLVM 基金会正式接受，12 月底代码合入 LLVM 主仓库（目录名 `mlir`），属于 LLVM 官方项目的一部分。
5. **了解哪些 AI/GPU DSL**——按抽象层次从低到高：**CuTe DSL**（NVIDIA 从 CUTLASS 4.0 起提供的 Python 接口，核心抽象与 C++ 版 CuTe 一一对应，仍要直接面对内存排布/张量切分/硬件原子操作，PyPI 包名 `nvidia-cutlass-dsl`，仍标 public beta）与 **ThunderKittens**（斯坦福 Hazy Research 的 C++ 库，基本数据结构是 warp 级 16×16 矩阵块，线程块级代码固定按"加载→计算→写回→收尾"模板写）——性能上限极高但要求作者清楚每块数据在寄存器与共享内存中的具体位置；**[[Triton]]**（事实标准，开发者只管数据块级逻辑，块内如何分给 32 个线程、共享内存怎么分配全交编译器自动决定，写起来像 NumPy、性能能达到手写 CUDA 的大部分水平；仓库已迁至 triton-lang 组织；PyTorch 的 torch.compile 底层生成的就是 Triton 代码）；**Helion**（Meta 开发、PyTorch 基金会仓库，写法比 Triton 更接近普通 Python 函数，编译产物是自动调优后的 Triton 代码，内置最优分块参数搜索调优引擎；2025 年 4 月建仓、10 月发 Beta）；**cuTile**（CUDA 13.1 引入，含虚拟指令集 CUDA Tile IR + 面向 Python 的 cuTile Python + 直接编译 Tile IR 字节码到 SASS 的编译器；2025 年 12 月随 CUDA 13.1 公开，首发针对 Blackwell 架构——意味着以数据块（tile）为单位的编程模型已被 NVIDIA 正式吸收进 CUDA 官方底座）。工程实践结论：在 NVIDIA 显卡上手写自定义算子，**Triton 依然是最省力的入口**（社区现成代码最多、报错最容易搜到解法）；只有当业务真要榨干硬件最后百分之几的极限性能时，才需要下沉到 CuTe 或 C++ 这一层。国产硬件：华为昇腾走兼容适配 Triton 的路线（`triton-ascend` 已迁至 triton-lang 官方组织，2025 年 5 月开源、2026 年 1 月发 3.2.0 正式版，底层依赖 CANN 社区版 9.0.0；写更底层自定义算子用 Ascend C）；寒武纪是另一套体系（通用并行编程模型 BANG，算子语言 BANG C，自研编译器 CNCC 把 BANG C 编到自家底层指令集 MLISA，再用汇编器 CNAS 汇编成目标二进制，另有基于 Python 的算子开发接口 BANGPy）。

结尾作者的态度：以前看到 LLVM、MLIR、GPU 寄存器与共享内存这些词，做后端和做业务的同学本能在划走，觉得那是"底层神仙"才碰的东西；但现在不一样了——**有 Opus 5.5、DeepSeek V4.1 Flash 这些顶级模型在手边，以前啃半个月硬件手册都未必看明白的底层机制，一个下午就能摸清来龙去脉**。学习的目的是"让自己的脑子学会学习"。
