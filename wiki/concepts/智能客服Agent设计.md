## 定义
智能客服 Agent 的四层架构设计，从意图识别到兜底转人工，覆盖客服场景的完整链路。

## 关键信息

### 四层架构
1. **意图识别**：用户第一句话先分清是产品咨询、售后投诉、退换货还是物流查询，分类决定后面调哪些工具、查哪些知识库
2. **知识检索（RAG）**：接产品文档、FAQ、退换货政策等知识库。chunk 切分 512-1024 token + 20% 重叠，加 Reranker 重排做二次排序。检索不到的必须回复"不太确定，帮您转接人工客服"，不能瞎编
3. **工具执行**：查订单、查物流、发起退款等操作，Agent 调用对应后端接口，结果回传给模型组织成回复
4. **兜底升级**：连续两轮没有给出有效回答，或用户明确表示要找人工，立即转接人工客服

### 额外考虑
- **准确性**：chunk 切分策略 + Reranker 重排
- **延迟**：流式输出 + 高频问题答案缓存
- **安全性**：防提示词注入，工具返回内容按不可信数据处理；敏感信息脱敏
- **兜底**：意图分不清、知识库查不到、模型不确定的，全部走人工。宁可多转几次人工，也不让模型编答案

### 云梯的受控 AI 客服架构（2026-11-05，详见 [[摘要-云梯saas智能客服]]）

生产级 SaaS 的完整落地（[[云梯智能客服系统]]），核心原则：**AI 不直接写业务库，模型输出回到 Java 服务，由业务规则和权限决定是否执行**。

1. **两套 LangGraph 状态机**（详见 [[LangGraph]]）：客服大脑（意图→情绪→转人工判断→知识召回→回答→状态持久化）、Agentic RAG（检索→召回判分→需要时改写→二次检索→生成→引用校验）；无 LangGraph 环境自动退化为线性实现，业务不中断
2. **规则/训练向量/大模型混合识别**：先跑低成本规则和版本向量；置信度 ≥0.6 + 情绪强度 <20 + 未命中转人工关键词时跳过模型分析（省一次调用和 1~2 秒）；模型意图必须落在租户配置清单内，情绪取规则与模型更严重一档；模型建议转人工只是参考，最终动作由客户明确要求与业务规则决定
3. **意图训练中心**：训练的是租户意图样本向量索引（非大模型权重）——人工语料 + 高置信度历史问法 → 1024 维向量化 → 留一法评估 → 版本/灰度（20%，按租户+会话稳定哈希）/回滚
4. **多轮槽位**：`bot_dialogue` 按租户+会话号保存轮次/意图/情绪/订单号手机号邮箱槽位/转人工原因；**规则抽取优先，大模型只补空缺槽位，不能覆盖正则确认的订单号**
5. **Agentic RAG**（详见 [[AgenticRAG]]）：向量分与关键词分量纲不同阈值分别配置；资料不足时规则改写最多重检一次；回答带 [1][2] 引用并剔除越界引用；无向量密钥退回关键词检索不假装语义检索正常；无模型密钥返回检索原文不编答案
6. **多模态进主链路**：图片 OCR/截图判读/订单号金额抽取 → 坐席工作台 + 文本上下文进客服大脑；ASR 转写供质检、TTS 做 IVR
7. **租户级模型路由**：模型名优先判厂商、租户配置优先平台默认、缺密钥显式切厂商、最终生效模型可体检
8. **AI 成本治理**：业务 AI 配额与真实 Token 成本分开计量；预算达阈值可仅告警/降级跳过模型/暂停转人工；ops 不可用时正常放行（避免成本系统扩大成 AI 全站故障）
9. **[[双速质检]]**：实时规则质检（秒级、不调模型）+ 会话结束后 AI 全量质检 + 人工复核
