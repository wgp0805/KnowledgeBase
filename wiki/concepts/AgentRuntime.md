## 定义
Agent Runtime（智能体运行时）是 GPT-6 Astra 时代后端升级的核心层。当任务从同步问答变为持续数分钟甚至更久的 AI 长任务，后端需要从"模型网关"升级为"任务运行时"，负责长任务的全生命周期管理。

## 关键信息

### Agent Runtime 至少负责
- 为长任务分配独立任务 ID
- 保存模型状态、工具结果和执行进度
- 管理并行工具、超时、重试与取消
- 对重复提交进行幂等处理
- 在高风险动作前暂停，等待人工确认
- 将过程事件持续推送给前端

### 为什么需要
- 传统架构：前端提交问题→后端拼接提示词→向量库检索→调用模型→返回，类似一次 HTTP 请求
- 长任务场景（登录测试环境/检查页面/修改代码/运行测试/查看报错/重新修复）无法塞进一次同步请求
- GPT-6 Astra 把异步工具调用、中途纠偏和跨步骤状态延续放到重要位置
- 模型可在工具仍运行时继续推进其他工作，用户也可在任务执行期间发出新指令，系统不必推倒重来

### 对现有基础设施的影响
- API 网关、消息队列、缓存、数据库仍然有用，但角色会变化
- 过去围绕业务请求运转，今后还要支撑可能持续数分钟甚至更久的 AI 任务
- 任务跑到哪里、调用过什么、花了多少钱、在哪一步被人修改，都需要被记录

### 迁移路径
- 无需重写整套系统：保留稳定业务服务/数据库/消息体系，外面增加可替换 Agent Runtime
- 盘点现有 AI 功能：一次问答/固定流程/复杂长任务分开
- 复杂长任务选一两个闭环场景接入 Responses API（测试缺陷修复/合同材料核对/数据质量问题排查）
- 新旧流程并行运行比较任务完成率/人工接管率/总耗时/错误影响/单任务成本

### Agentic Runtime 的框架化落地：Eino ADK（2026-10-21，详见 [[摘要-为什么越来越多人用eino]]）
[[Eino]] v0.9 版本围绕"Agentic Runtime"做的大量增强，是上述职责在具体框架中的工程化实现：
- **Cancel** —— 从外部主动终止正在运行的 Agent，支持安全点取消与 checkpoint 持久化
- **Model Retry** —— 重试决策可读取模型输出、拒绝不满足条件的输出、修改下一次输入（比"同参数重试"更精细）
- **Model Failover** —— 主模型调用失败后切换备用模型，支持优先复用上一次成功的模型
- **Middleware** —— 在 ReAct 循环的生命周期点位注入行为（上下文压缩、工具搜索、文件系统操作）
- **中断与恢复** —— 任意节点中断、精确恢复；Agent 执行到某节点时暂停等待人工输入，再从断点继续，不必从头重跑

作者对这些能力的共同点给出判断：**它们解决的是"Agent 在生产环境跑不稳"，而不是"Agent 能不能跑起来"**。没有中断恢复，一个跑了十分钟的 Agent 因为需要一次人工确认就要全部重来，成本和时间都不可接受。
