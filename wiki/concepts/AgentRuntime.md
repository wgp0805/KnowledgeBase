## 定义
Agent Runtime（智能体运行时）是 GPT-6 Astra 时代后端升级的核心层。当任务从同步问答变为持续数分钟甚至更久的 AI 长任务，后端需要从"模型网关"升级为"任务运行时"，负责长任务的全生命周期管理。

## 关键信息

### Agent Runtime 至少负责
- 为长任务分配独立任务 ID
- 保存模型状态、工具结果和执行进度
- 管理并行工具、超时、重试与取消
- 对重复提交进行幂等处理
- 在高风险动作前暂停，等待人工确认
- 将过程事件持续推送给前端

### 为什么需要
- 传统架构：前端提交问题→后端拼接提示词→向量库检索→调用模型→返回，类似一次 HTTP 请求
- 长任务场景（登录测试环境/检查页面/修改代码/运行测试/查看报错/重新修复）无法塞进一次同步请求
- GPT-6 Astra 把异步工具调用、中途纠偏和跨步骤状态延续放到重要位置
- 模型可在工具仍运行时继续推进其他工作，用户也可在任务执行期间发出新指令，系统不必推倒重来

### 对现有基础设施的影响
- API 网关、消息队列、缓存、数据库仍然有用，但角色会变化
- 过去围绕业务请求运转，今后还要支撑可能持续数分钟甚至更久的 AI 任务
- 任务跑到哪里、调用过什么、花了多少钱、在哪一步被人修改，都需要被记录

### 迁移路径
- 无需重写整套系统：保留稳定业务服务/数据库/消息体系，外面增加可替换 Agent Runtime
- 盘点现有 AI 功能：一次问答/固定流程/复杂长任务分开
- 复杂长任务选一两个闭环场景接入 Responses API（测试缺陷修复/合同材料核对/数据质量问题排查）
- 新旧流程并行运行比较任务完成率/人工接管率/总耗时/错误影响/单任务成本
