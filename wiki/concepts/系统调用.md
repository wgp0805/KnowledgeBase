## 定义
系统调用（System Call）是用户态进程主动请求操作系统内核提供服务的机制，是用户态 → 内核态切换的三种方式之一（另两种为异常和外部硬件中断）。用户程序需要内核帮忙做事（如读文件、网络 I/O、创建进程）时，通过系统调用进入内核态执行。

## 典型场景
- **文件操作**：`read()` / `write()` / `open()`
- **进程操作**：`fork()` / `exec()` / `exit()`
- **网络操作**：`socket()` / `connect()` / `accept()`
- **内存操作**：`mmap()` / `brk()`
- **时间**：`gettimeofday()` / `nanosleep()`

## 底层机制（x86-64 Linux）
1. 应用程序调用 C 库函数（如 glibc 的 `read`）
2. 库函数把系统调用号放到 `rax` 寄存器
3. 执行 `syscall` 指令（32 位时代是 `int 0x80` 软中断）
4. CPU 立刻从用户态切到内核态，跳到内核入口 `entry_SYSCALL_64`
5. 内核根据调用号查表执行对应函数（如 `sys_read`）
6. 执行完毕通过 `sysret` / `iret` 返回用户态

## 切换成本
系统调用不是免费的，一次切换成本主要包括（详见 [[上下文切换]]）：
- 寄存器上下文保存/恢复
- 栈切换（用户栈 → 内核栈）
- CPU 流水线 flush
- 指令缓存失效（内核代码可能不在 icache）
- TLB 部分失效（伴随地址空间切换时）
- 安全检查（内核校验用户参数合法性）

纯特权级切换硬件开销约 100ns 量级，完整系统调用通常在几百纳秒量级。高并发场景下每个请求做几十次系统调用，累积成本很高。

## 减少系统调用的工程实践
- **epoll 替代 select/poll**：一次系统调用处理大量连接，不用每次遍历所有 fd
- **Java NIO DirectByteBuffer**：直接在内核和用户态之间共享一块内存，省掉数据拷贝的切换
- **BufferedReader / BufferedWriter**：缓冲区攒一波再读写，减少 read/write 次数
- **Java 19 虚拟线程（Loom）**：把大量用户级线程映射到少量 OS 线程上，减少线程切换带来的内核态开销（详见 [[虚拟线程]]）

## Java 代码示例
一段简单的 `FileInputStream` 读取代码至少触发三次系统调用：`open`、`read`、`close`，每次都经历完整的用户态 → 内核态 → 用户态往返。
