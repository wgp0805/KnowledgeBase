## 定义

会话保持（Session Affinity）是 LLM 网关/多模型路由中，在"重新选模型/账号"机制之外约束**一次选择保持多久**的机制。动因：Agent 收到一条消息后往往连调好几次工具，每次结果回传都可能产生新请求——这些请求若不断换账号或模型，会丢掉前面对话的 prompt 缓存优势；有些厂商还不接受别家模型写出来的 reasoning，必须粘在同一账号/模型上。

> 消歧：[[CleanSession]] 是 MQTT 语境的"会话保持标志"（离线会话保留），与本页 LLM 网关语境的同名不同义。

## 关键信息

以 [[Magpie]] 网关的四档设置为例（magpie 在分组策略之外用此表控制换不换）：

| 设置 | 保持多久 |
| --- | --- |
| 自动（默认） | 同一轮内保持；跨轮时看厂商缓存的那部分还值不值得留 |
| 整个会话 | 只要还能正常响应，整个会话都用同一个 |
| 一轮之内 | 本轮的工具调用保持不变，用户再次发言时重新选 |
| 关闭 | 每次请求都重新选 |

- **"一轮"的定义**：从用户发出消息开始，到 Agent 回完为止（中间可能多次请求）
- **保持的例外**：当前账号答不了仍会换；上下文涨过当前模型可装上限会迁给容量更大的模型
- **与路由策略的分工**：**路由策略**（智能/按顺序/轮流/最少使用/重置前用完）决定"重新选择时的顺序"；**会话保持**决定"是否/多久重新选择"——两者是正交的两层
- **缓存经济性**：会话保持的直接收益是 prompt 缓存命中（跨请求复用已缓存前缀），丢了缓存优势就意味着同一轮对话反复付全价输入 token
