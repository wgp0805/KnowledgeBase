## 定义
意图路由（Intent Routing）：用户发来一句话后，系统先判断该交给哪条处理路径——某个子 Agent（如电商客服背后的查商品/查订单/退换货）、某个工作流分支，或一个更便宜/能力更强的模型——这一步即意图路由。核心设计原则是**分层递进**：确定的用规则，相似的用向量，有固定选项的用决策模型，模糊的交给大模型，拿不准的问用户；能用向量比对和决策模型解决的就不上大模型（又慢又贵）。

## 关键信息
- **反模式**：把所有子 Agent 的介绍写进提示词让大模型自己选——慢且烧钱（"发几个 hello，20 刀订阅就没了"）
- **handoff 机制（OpenAI Agents SDK）**：分诊 Agent（triage agent）把每个子 Agent 包装成工具，工具名 `transfer_to_{子agent名}`、描述为该子 Agent 的 handoff_description；选中哪个就调用哪个工具完成对话移交，准确率全看介绍写得清不清楚。Anthropic 建议：分类任务用枚举参数或结构化输出，只让模型在给定选项里选
- **生产级四层路由**：①规则——"查订单""退款"等关键词明确的直接处理；②向量比对——semantic-router 为每条路由准备示例（如订单路由放"我的快递到哪了"），问题转向量取最近 5 条示例按所属路由求均分，超阈值即走，不调用大模型；③决策模型——TypeSafe AI 的 [[Jev]] 延迟 70–500ms，OpenAI Decisions API 单任务 150ms（对比 GPT-6 轻量模型 Luna 需 1.6 秒）；④大模型兜底——简单问题给便宜模型（Sonnet 5.5），困难问题给强模型（Opus 5.5）
- **路由出错的兜底**：分数低于阈值、或同时命中两个以上意图 → 带选项问用户；子 Agent 遇超范围问题可转回分诊 Agent 重新分配，但**转回次数要设上限**，否则互相踢皮球
- **规模化建议（Anthropic 工单路由指南）**：多意图请求事先写明优先级；意图超过 20 个就分层分类，先大类再小类
- **评测方法**：准备标注好意图的测试问题，按每个意图分别统计准确率与召回率；从向量库检索相似已标注问题放进提示词，准确率可从 71% 提到 93%
- **置信度不可信**：不能让模型自报置信度；可信做法三种——logprobs 对数概率阈值（超阈值自动分类、低于阈值转人工复核，见 OpenAI Cookbook）、向量比对相似度、做过校准的决策模型（[[Jev]] 报 90% 把握实际正确率接近 90%，校准误差 0.07）
- **网关侧实现（magpie，2026-10-27 来源：[[摘要-magpie替代cc-switch]]）**：判断请求意图用一个独立"判断模型"——输入是最新用户消息＋截断后的上一条用户消息及其后助手最后一条文字回复（用于理解"继续""修一下"这类追问）；系统提示、思考内容、工具调用参数与结果、Claude Code 的 `system-reminder` 都不发过去。判断默认最多等 8 秒（设置可调，上限 60 秒）；出错/超时/回答无效时，若上一轮意图仍在本轮候选中就沿用，无可用沿用才按其他规则或默认策略走。判断是一次额外模型调用（用量页单独可见），也可用 [[Ollama]] 或 [[LM_Studio]] 的本地模型充当
