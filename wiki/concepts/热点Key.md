## 定义
热点 Key 是 Redis 集群中承受远超平均访问量的单个 Key。秒杀峰值下，全站请求集中打向少数 Key，该 Key 所在节点会瞬间变成整个集群最热节点，被单独"烤糊"——即使集群其他节点负载正常。

## 典型场景
### Redisson RRateLimiter 限流器陷阱
- `RRateLimiter` 底层是 Lua 脚本，每次 acquire 走一次 Redis 往返
- **限流器自己就是一个 Redis Key**：全站请求都往同一个限流 Key 上打
- 该 Key 瞬间变成整个集群最热的热点 Key，把它所在的那个节点单独烤糊
- **结果**：为了保护系统加的限流，成了第一个倒下的组件

### 秒杀库存 Key
- 所有抢购请求都要扣减同一个库存 Key
- 该 Key 所在节点承载全站写流量

## 解决思路
- **本地粗筛**：Guava RateLimiter 或信号量，按实例数把总配额粗略切分，绝大部分超额请求在进程内就被挡掉，根本不出网
- **分布式精算**：漏下来的那一小部分再走分布式限流做精确控制
- 参见 [[两级限流]]
