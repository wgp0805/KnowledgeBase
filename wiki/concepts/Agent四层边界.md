## 定义
给"替人做事"的 Agent 设计边界的四层框架（易安说AI 提出）：**先定义状态保存在哪 → 再定义 Agent 以什么身份行动 → 然后限制它能执行的动作 → 最后设置哪些节点必须由人确认**。四层缺一层，产品就容易在便利与失控之间越线。

## 关键信息
- **对应四类产品**（都叫 Bot，做的不是同一件事）：
  | 产品 | 核心 | 长期状态 | 外部动作边界 |
  | --- | --- | --- | --- |
  | [[GrokBot]] | 多专业 Bot 分工协作 | Bot 各自对话与记忆，共用云端工作环境 | 文件/浏览器/应用任务的协作交接 |
  | [[Dots]] | 任务跨时间持续推进 | 云端电脑、浏览器、任务笔记与进度 | 等待条件变化后继续，必要时回来询问 |
  | [[Cue]] | 真实世界执行身份 | 电话、邮箱、钱包和电脑 | 联系/沟通/预算内支付，需严格授权 |
  | [[MetaMuse]] | 管理零散个人生活事务 | 日历、待办、目标与长期偏好 | 围绕生活安排给建议或推进后续 |
- **四类核心风险**：多 Bot 共享 → 共享状态与重复操作；长任务 → 任务漂移；钱包电话 → 对外代表用户；长期记忆 → 隐私与错误画像
- **工程要求**：多 Agent 可用不能只靠"放进群聊"，要任务幂等、共享状态隔离、结果可追溯、外部操作有审批点；持续执行 Agent 需四类明确输入（任务目标/可访问数据/可使用账号/必须回来确认的决策）
- **理想形态**：不是无限自主的 Bot，而是"在正确时间自主、在高风险节点暂停、在所有外部动作后留痕"的系统
