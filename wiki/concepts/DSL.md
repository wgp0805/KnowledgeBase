## 定义

DSL（Domain Specific Language，领域特定语言）在 GPU 编程里特指**专门用来写高性能算子的编程语言或编程库**。本页记录按抽象层次从低到高的五层图谱，以及各层适合的场合。

## 关键信息

### 第一层：最贴近硬件（性能上限最高，门槛也最高）
- **CuTe DSL**：NVIDIA 从 CUTLASS 4.0 开始提供的 Python 接口，核心抽象与 C++ 版 CuTe 一一对应。开发者依然要直接和内存排布、张量切分、硬件原子操作指令这些底层概念打交道；Python 安装包名为 `nvidia-cutlass-dsl`，目前仍标着公开测试版（public beta）。
- **ThunderKittens**：斯坦福大学 Hazy Research 团队开源的 C++ 库。基本数据结构是 warp 级别的 16×16 矩阵块，线程块这一级的代码固定按"加载数据 → 执行计算 → 写回存储 → 收尾处理"模板来写。
- **共同特点**：性能上限极高，但要求写代码的人清楚每一块数据在寄存器和共享内存里的具体位置。

### 第二层：事实标准
- **[[Triton]]**：设计取舍是让开发者只管**数据块这一级**的逻辑，至于一个数据块里的数据怎么分给 warp 里的 32 个线程、片上共享内存怎么分配，全部交给编译器自动决定。写起来很像写 NumPy 数组运算，跑出来的性能却能达到手写 CUDA 代码的大部分水平。开源仓库已迁到 `triton-lang` 组织（原 `openai/triton` 地址重定向）。PyTorch 里 `torch.compile` 自动生成的 GPU 算子代码，底层生成的就是 Triton 代码。

### 第三层：比 Triton 更高
- **Helion**：Meta 团队开发，位于 PyTorch 基金会仓库。写法比 Triton 更接近普通 Python 函数，**编译产物就是经过自动调优的 Triton 代码**，最核心的机制是内置了自动搜索最优分块参数的调优引擎。2025 年 4 月建仓，同年 10 月发布 Beta 版本。

### NVIDIA 官方的新动作
- **cuTile**：CUDA 13.1 引入，包含三个组成部分——一套新的虚拟指令集 **CUDA Tile IR**、一套面向 Python 开发者的接口 **cuTile Python**、再加一个把 Tile IR 字节码直接编译成硬件原生机器码（SASS）的编译器。2025 年 12 月随 CUDA 13.1 正式公开，首发针对 Blackwell 架构。值得关注之处在于：**以数据块（tile）为单位的编程模型，已经被 NVIDIA 正式吸收进了 CUDA 官方底座。**

### 工程实践结论
在 NVIDIA 显卡上手写自定义算子，**Triton 依然是最省力的入口**——社区里能参考的现成代码最多，遇到报错也最容易搜到解决办法。只有当业务真要榨干硬件最后那百分之几的极限性能时，才需要下沉到 CuTe 或 C++ 这一层。

### 国产硬件路线
- **华为昇腾**：走兼容适配 Triton 的路线（`triton-ascend` 已迁至 triton-lang 官方组织，2025 年 5 月开源、2026 年 1 月发布 3.2.0 正式版，底层依赖 [[CANN]] 社区版 9.0.0）；写更底层的自定义算子用 [[AscendC]]。
- **[[寒武纪]]**：另一套体系——通用并行编程模型 **BANG**，算子语言 **BANG C**，自研编译器 **CNCC** 把 BANG C 编译成自家底层指令集 **MLISA**，再用汇编器 **CNAS** 汇编成目标二进制；另有基于 Python 的算子开发接口 **BANGPy**。
