## 定义

原子性（Atomicity）、可见性（Visibility）、有序性（Ordering）是语言内存模型对共享变量并发访问的三项核心保证：Atomic RMW 不可被其他线程插入拆分；一次更新的效果能被其他线程观察到；被观察到的操作之间遵守规定的先后次序。三者在 Java 与 Go 中由公开的 Atomic API + 内存模型条款共同定义，在 Python 应用层则没有对称的通用 API。

## 关键信息

### Java（`AtomicInteger` / `VarHandle`）
- 原子性：`incrementAndGet()` 是不可分割的 Atomic RMW
- 可见性：写入带 `setVolatile` 内存语义、读取用 `getVolatile`；JLS §17.4.4 规定 volatile 写与后续任意线程的 volatile 读构成 **synchronizes-with**
- 有序性：JLS §17.4.5 happens-before 同时给出"可见"与"先于"；传递链 `A1 →program order→ A2 →synchronizes-with→ B1 →program order→ B2` 推出 `A1 happens-before B2`，故不会出现 `counter == 1 && ready == false`

### Go（`sync/atomic` / Go Memory Model）
- 原子性：`atomic.Int64.Add` "atomically adds delta to x"
- 可见性："If the effect of an atomic operation A is observed by atomic operation B, then A is **synchronized before** B"
- 有序性：所有 Atomic 操作表现得像处在 "some sequentially consistent order"；happens-before 定义为 `sequenced-before` 与 `synchronized-before` 的传递闭包，传递推理与 Java 同构

### CPython / Python
- 标准库目前没有与 `AtomicInteger`、`atomic.Int64` 对称的通用整数 Atomic API
- `counter += 1` 不是语言层定义的 Atomic；不能因某 CPython 配置存在 GIL、或 Runtime 内部使用 `_Py_atomic_*`，就把它当作应用层可依赖的跨实现 Atomicity/Visibility/Ordering 保证
- `_Py_atomic_*` 如何落到编译器与 CPU 是实现层问题，不属于 Python 应用层公开语义

### 共同结构
三种语言的推理骨架一致：**程序内顺序 + 跨线程同步关系（synchronizes-with / synchronized-before）+ 传递性 ⇒ happens-before**，进而同时得到可见性与有序性。
