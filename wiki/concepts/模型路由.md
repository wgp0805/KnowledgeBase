## 定义
模型路由是在多个 AI 模型之间动态选择和分发请求的机制。OpenRouter 将其产品化，GPT-6 Astra 时代它将逐渐像数据库读写分离一样成为常见的工程配置。

## 关键信息

### OpenRouter 的路由理念
- 路由真正出售的不是技术，而是**选择权**
- 让开发者随时接入最新模型，降低对单一实验室和云厂商的依赖
- 检测到某家服务商在质量/速度/价格上有改进，路由器会立即给它更多流量
- 对大型模型这类变化几乎全天候发生，可能每五分钟就会出现一次

### 路由不会被商品化
- 很多公司因为路由"很时髦"而去做网关，但只把网关当副业会比专注公司落后很多个月
- 一个不能覆盖完整市场、没有足够灵活性和可定制性的网关，实际上会把用户从一些所需能力中排除出去

### 未来 Agent 架构中的路由
- 前沿模型负责规划和编排，确定性任务交给更便宜的开放模型与子 Agent
- 由一个编排模型在需要时调用子 Agent：子 Agent 成本更低，适合输出形态明确/问题类型已知/解法较确定的任务
- 编排模型读取结果，继续完成更开放、更不确定的任务

### 成本管理驱动
- 简单分类/抽取/格式转换交给更便宜的模型
- 复杂判断与长任务交给 Astra
- 稳定结果进入缓存
- 超过预算的任务自动降级或转人工
- 模型路由逐渐像数据库读写分离一样，成为常见的工程配置

### OpenRouter 收费模式
- 按量付费计划收取 5.5% 抽成
- 基于承诺消费的企业计划：承诺消费部分不收取这项费用
- 企业自带推理服务或自带密钥，相关费用取消

### Claude Code 的三层模型级别路由（2026-09）
来自 [[摘要-claude-code-多agent账单分层路由]]。Claude Code 内部按任务复杂度把调用分三级：**复杂推理用「Opus 级」、标准任务用「Sonnet 级」、快速查询与子 Agent 用「Haiku 级」**，具体映射到哪个模型由环境变量决定，默认全部指向 Anthropic 官方 Claude 系列——这是多 Agent 账单翻倍的隐藏原因（子 Agent 无单独控制）。重指路由的典型配置：
- `ANTHROPIC_DEFAULT_OPUS_MODEL` / `ANTHROPIC_DEFAULT_SONNET_MODEL` → `deepseek-v4-pro[1m]`（主 Agent，`[1m]` 解锁 1M 上下文）
- `ANTHROPIC_DEFAULT_HAIKU_MODEL` + `CLAUDE_CODE_SUBAGENT_MODEL` → `deepseek-v4-flash`（子 Agent 双保险，覆盖内置 Explore）
- 效果：同一 240 万 token 重构任务，全 Sonnet 4.6 $22.4 → 分层 $1.29（1/17）
- 风险：模型名写错时兼容端点静默 fallback 到更便宜模型，账单降了质量也掉了，需去控制台核对实际调用模型
- 与 OpenRouter 的编排层路由同构：前沿模型规划编排，确定性任务交给更便宜的子 Agent

### 按任务自动选模型的入口产品（2026-09，详见 [[摘要-jev哑巴模型产业改变]]）
来自 [[摘要-jev哑巴模型产业改变]]。[[Jev]] 等"判断模型"把能力切细后，"任务本身成为 Agent 的核心，按任务调用不同模型"落地为两类入口产品：
- **腾讯 WorkBuddy Auto 模式**：系统根据用户任务的类型、复杂度与上下文特征自动选择当前最适合的模型响应；用户不知道选哪个模型或面对混合型任务时交由系统决定
- **Cursor Router（2026-08 推出）**：每个请求交给模型前先按任务类型、复杂度、上下文判断，从多个模型中选最合适的一个——简单任务给快速便宜模型，困难、长周期任务给前沿模型
- **共同思路**：把"调度模型"交给系统按任务自动完成，用户只管提出任务；模型从"谁更强谁替换谁"变成"各司其职、同框协作"（[[模型分化]]），一个能灵活调配多模型的 Agent 入口因此越来越重要
