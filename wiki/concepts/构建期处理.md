## 定义

构建期处理（Build-time Processing）是一种框架架构模式：把传统框架留在运行时做的工作（类路径扫描、注解解析、Bean 定义构建、依赖注入、动态代理生成）全部前移到构建阶段完成，运行时只加载预生成代码。它是相对于"运行时反射模型"的设计哲学反转——"Spring Boot 把活儿留到运行时干，Quarkus 在构建时就把活儿干完了"。

## 关键信息

- **动机（运行时反射模型的三重困境）**：① 启动时间——类加载、Bean 实例化、自动配置扫描在主线程串行执行，JIT 未介入时解释执行放大延迟（5-15 秒）；② 内存占用——最简 Spring Boot Web 应用常驻 200MB+，K8s 按副本线性计费；③ 预热——JIT 需数千次调用识别热点，启动后前几分钟吞吐只有稳定期 30%-50%
- **收益**：启动 JVM 模式 1.3 秒 / Native 约 200ms；空闲内存 88MB；运行时行为完全确定（Spring Boot 的条件注解带来启动行为不可预测）
- **与 Native Image 的关系**：构建期处理使应用天然满足 GraalVM Native Image 的闭世界假设（closed-world assumption），是 Native Image 可用于生产级 Java 应用的前提
- **代表实现**：Quarkus ArC（依赖注入构建时生成字节码，如直接生成 `new GreetingService(new GreetingBean())`）
- **代价**：运行时动态性受限，依赖运行时反射的第三方库需要额外适配；生态与学习成本
