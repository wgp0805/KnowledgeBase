## 定义
多智能体编排（Multi-Agent Orchestration）是指通过一个主控 Agent 调度多个子 Agent 协作完成复杂任务的 AI 架构模式。主控根据任务分解触发子 Agent 执行，子 Agent 各司其职，结果汇总后输出最终答案。

## 关键信息
- **调度机制**：主控 prompt 触发 `agent_spawn` 调度子 Agent
- **子 Agent 声明**：通过 `SubagentDeclaration` 定义子 Agent 角色与能力
- **执行模式**：同步调用与 SSE 流式两种
- **解耦设计**：编排层不直连大模型，通过适配器复用 LLM 网关的路由、降级与计费

## 典型实践（企业智能招聘系统）
- **面试评估**：主控调度 4 个子 Agent 协作，六维度评估（技能/沟通/逻辑/协作/学习/抗压）
- **简历→Offer 五阶段流水线**：解析 → 筛选 → 人工审核 → 面试评估 → Offer 预测，每阶段记录真实 Agent 任务，可一键运行、全程可观测

## 降级链设计
多 Agent 编排失败时的多级降级：
- 多 Agent 编排 → 单 Agent → LLM 直调 → 启发式评分

## 两种路线对照：AgentScope 主控模式 vs Paperclip 公司模式（2026-10-29，详见 [[摘要-paperclip-多智能体公司]]）

| 维度 | AgentScope 主控模式 | Paperclip 公司模式 |
|------|--------------------|--------------------|
| 定位 | 主控 Agent 调度多个子 Agent 完成任务分解 | 编排层"公司"，给各 Agent 安排岗位/汇报线/预算/进度 |
| 核心机制 | agent_spawn 动态创建、同步/SSE 流式执行 | 心跳唤醒、预算刹车、审批控制、审计日志、依赖关系 |
| 角色模型 | 主控 + 子 Agent（动态委派链） | 组织架构（CEO/CTO/工程师/设计师，汇报关系固定） |
| 管理性 | 偏任务执行（拆解→委派→汇总） | 偏治理（能查、能回滚、能审批，防额度烧光） |
| 典型载体 | 企业智能招聘系统（六维评估流水线） | AI 一人公司（多 side project 并行） |

两种路线互补：AgentScope 解决"任务怎么拆"，Paperclip 解决"多个 Agent 怎么管"。
