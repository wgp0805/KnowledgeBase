## 定义
API 密钥安全（密钥卫生）是 AI 辅助开发过程中对模型服务 Key 的全生命周期治理：一个项目一把 Key、Key 只存在于环境变量、仓库从建仓起就忽略所有 `.env*`、Key 永不进入对话与文档、设消费限额、下线即作废、异常先撤销再排查。其要义是把泄露面从"单点事故"重新定义为"散落位置的数量问题"——一把 Key 躺在 N 个地方，任何一个外流都足以造成损失。

## 关键信息

来自 [[张亮-leo]] 的真实事故复盘（详见 [[摘要-vibe-coding-api-key泄露]]）：

### 泄露的 7 种藏法（实测 22 个文件）
1. **代码 fallback**：`process.env.XXX || 'sk-真实Key'`——源码与编译产物各一份
2. **各类 .env**：开发/生产/服务端，每个项目一份
3. **.env.example**：本该放占位符的样例文件里放了真 Key
4. **部署脚本与 docker-compose**：单脚本 3 处明文
5. **测试文件**：测试桩里写死真 Key
6. **文档**：修复报告、部署总结、测试计划、手动部署指南原样贴 Key
7. **AI 工具的项目记忆**：AI 把 Key 当"需要记住的信息"存进笔记

### 为什么会发生
- 非技术背景的 Vibe Coding 开发者注意力全在"能不能跑起来"，缺开发卫生习惯
- AI 的默认行为是保证任务跑通：写 fallback、抄完整命令、把 Key 当有用信息记录——**AI 每一步都没做错，错在没人给它密钥约束**（需用 [[VibeCoding]] 场景下的显式规则约束）

### 8 条止损清单
1. 一个项目一把 Key，命名写成「项目名-环境-云服务商」
2. Key 只放环境变量，代码不留 fallback——报错好过被悄悄薅
3. 新建仓库第一件事写 `.gitignore`，忽略所有 `.env*`（不只 `.env`）
4. `.env.example` 只放占位符
5. 不把 Key 贴进任何 AI 对话框（AI 会记住并写进笔记/文档）
6. 设消费限额——被盗用时**限额就是止损线**
7. 项目或服务器下线时同步作废其使用过的 Key（"服务器没了，Key 还活着"）
8. 发现异常先撤销 Key 再排查（否则排查期间持续烧钱）
