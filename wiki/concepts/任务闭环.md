## 定义
任务闭环是 Agent 产品区别于聊天产品的核心机制：机器自主循环迭代——目标输入 → 任务拆解 → 分步执行 → 结果校验 → 状态沉淀 → 迭代优化，循环往复直至目标达成。没有任务闭环的 Agent 都是伪智能体；用户要的不是"更会说话的 AI"，而是能把一件事从头到尾做完、做好、做对的 AI。

## 关键信息

来自 [[Zoe产品手记]] 的半年落地复盘（详见 [[摘要-agent任务闭环五层模型]]）：

### 五层任务闭环模型（ToB/ToC 通用）
| 层 | 解决什么 | 设计要点 |
|----|---------|---------|
| 1. 意图感知 | 输入模糊口语化 | 转为标准化**任务卡片**：目标、资源、约束、截止；信息缺失时精准反问 |
| 2. 任务规划 | 复杂任务不会处理 | 自主拆解原子步骤：可标准化流程走固定 DAG，不确定场景由大模型动态拆解；步骤可溯源、可断点续传 |
| 3. 工具执行 | 只会输出话术 | 真实调用工具产出业务结果；**宁可话术笨一点，也绝不能执行出错** |
| 4. 校验反馈 | 闭环的灵魂，多数产品缺失 | 双层校验：规则层（格式/必填/权限/合规）+ 模型层（是否匹配原始需求）；不通过自动重试补全 |
| 5. 状态沉淀 | 对话结束一切归零 | 任务、进度、偏好、历史产出持久化，隔天可继续未完成任务；粘性来自任务资产而非对话 |

### 对照：传统 Chat vs Agent
- 传统 Chat：人机单次交互，用户主动提问/补充/推进/收尾
- Agent：机器自主循环迭代，替代人完成工作流

### 四个致命设计坑
1. 过度美化对话界面、弱化任务流程 → 优先任务进度可视化
2. 所有任务都让用户手动确认 → 低风险自动执行、高风险分级确认
3. 只做单次闭环，不做长期持续任务 → 持续服务与长期目标管理
4. 把工具堆叠加成能力 → 工具要能串联成完整业务闭环才有效

### 自查清单 6 问
能否结构化任务卡片 / 能否自主拆解 / 是否产出业务结果 / 是否双层校验自动重试 / 状态是否持久支持断点续做 / 确认弹窗是否按风险分级。
