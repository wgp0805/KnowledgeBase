## 定义

**规范驱动开发（Spec-Driven Development，SDD）** 是为 AI 编程时代设计的工程方法论：**先把"做什么、按什么规矩做、怎么做"用结构化规范明确，再让 AI 据此实现**，以对抗 [[VibeCoding]] 带来的"AI 跳步骤、乱改架构、质量靠运气"问题。其核心主张可概括为 GitHub Spec-Kit 的官方表述：**"规范不只是指导文档，而是可执行的——能直接生成工作代码"**。

## 关键信息

### 三大代表工具对照

| 维度 | [[Superpowers]] | [[OpenSpec]] | [[SpecKit]] |
| --- | --- | --- | --- |
| 解决问题 | "怎么干" | "改了什么" | "按什么规矩干" |
| 核心机制 | 14 个 Skill + 五阶段流程 | Delta-Based 增量规格 + DAG | 七阶段流水线 + 项目宪法 |
| 适用项目 | 通用 | 棕地（已有代码库） | 绿地（新项目） |
| 学习曲线 | 中 | 低 | 陡 |
| 官方背书 | Anthropic 插件市场 | 社区 | GitHub 官方 |

### 共同方法论要点

1. **未对齐需求禁止动手**：通过强制头脑风暴 / explore / specify 流程把需求结构化
2. **变更可追溯**：每次修改都有 proposal → spec → design → tasks → archive 闭环
3. **执行有纪律**：强制 TDD、强制 Code Review、子 Agent 隔离
4. **规范是活文档**：随项目演进而增量更新，而非一次性撰写

### 组合实践

理想工作流：用 **Spec-Kit** 定项目宪法（一次性）→ 用 **OpenSpec** 管每次变更的提案与归档 → 用 **Superpowers** 约束 AI 执行纪律。社区已有 Comet 工具将 OpenSpec 与 Superpowers 组合。
