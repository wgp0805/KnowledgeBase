## 定义
一种内容组织原则，指 Agent 按需加载信息，而不是一次性将所有内容塞进上下文。核心思想是"不用的 Skill 不进上下文，用到的时候再展开"。

## 关键信息
- 核心思想：让 Agent 按需加载信息，而不是一次性提供全部
- 应用场景：Skill 文件夹中的脚本、模板、引用文档等
- 优势：节省上下文空间，提高信息利用效率
- 假设有 20 个 Skill，每个完整指引平均 2000 token，全部常驻 system prompt 就是 4 万 token

### 三阶段实现（PaiCLI 方案）
1. **启动时索引注入**：Agent 启动时，把所有启用 Skill 的名称和一句话描述注入 system prompt。只放名称和简介，单条描述控制在 500 字符以内，最多 20 个 Skill
2. **按需加载**：模型在对话过程中判断当前任务匹配哪个 Skill，主动调用 load_skill 工具加载完整指引
3. **注入缓冲**：加载的完整指引写入一个缓冲区，下一轮对话时自动拼到用户消息前面。缓冲区最多同时保留 3 个 Skill 的指引，超出的按 LRU（最近最少使用）淘汰

### Skill 文件夹内的落地形态（2026-10-21，详见 [[摘要-如何从0-1写好一个skill]]）
Skill 不是一个简单的 markdown 文件，而是一个完整文件夹，至少四部分：
1. **SKILL.md 核心定义** —— Skill 系统的"CPU"，负责意图识别与指令分发。Markdown 本质是"对信息进行约束"，把散文改写成机器较好理解的议论文
2. **References 参考规范** —— AI 输出内容的强约束模块，核心价值是"易错点"：把 AI 经常出错的地方记下来整理成"错题本"并持续更新。官方优质 Skills 都是从几行文字日积月累叠加出来的
3. **Assets 物料资源** —— 按需调用的固定知识（图片、模板、配置文件、现成素材），AI 需要时才读取
4. **Scripts 自动化脚本** —— 承接确定性高的重复性任务（格式检查、版本校验、批量处理），让 Skill 实现自主操作与更新

**References 与 Assets 共享同一核心逻辑**：不要把所有内容都堆在一个文件里。详细的 API 说明放进 `references/api.md` 或 `assets/` 目录，在 SKILL.md 主文件里标注"这些文件分别在哪里"，AI 会在需要时主动分类阅读——准确率更高，也更节省资源。
