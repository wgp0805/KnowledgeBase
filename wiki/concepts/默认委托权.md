## 定义
默认委托权指用户把事情交给某个 AI Agent 的"这件事交给你"从偶尔尝试变成默认习惯的竞争地位——Personal Agent 赛道真正的胜负手不是谁功能多、模型强，而是谁能成为用户的默认委托入口。

## 关键信息
- **提出背景**：六款产品（[[Dots]]、[[MetaMuse]]、Gemini Spark、[[Instinct]]、[[GrokBot]]、[[OpenClaw]]）看似都在做"个人助理"，实际争夺不同入口、数据与授权关系，横向功能排名容易失真
- **评估五维度**：入口（在哪里交给它）、上下文（能获得哪些持续信息）、权限（能读什么/改什么/哪些要确认）、执行（能否送到终点并在受阻时交还给人）、信任（可见/可纠正/可撤回/可追责）——五维相互牵制，难点是找到用户愿意接受的组合
- **Personal Agent 四条件**：持续身份（下次回来不必重新解释）、能进入真实工具执行动作（跨过"建议"与"行动"边界）、处理跨时间任务（应用关闭后继续）、用户仍能控制（数据范围/单次审批/撤回纠错）
- **与功能数量的关系**：模型与浏览器操作会逐渐成为可采购能力，独占上下文（邮件、日历、行业系统、长期偏好）更难复制；优化指标应是委托率（任务完整委托数、无需接管步骤、批准前修改比例）而非对话次数
- **权限阶梯**：先读后写、先草稿后发送、先单次确认后有限放行——权限设计是核心体验而非上线前补一页隐私协议
- **终局判断**：更可能是"一个总入口 + 多个专业 Agent"的结构，竞争也将发生在 Agent 与 Agent 之间（谁拿总入口、谁做专业执行、权限与结果如何交接）
