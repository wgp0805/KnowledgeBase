## 定义

图像差分（Image Diff）是在 AI 辅助开发中，让多模态大模型**只关注发生变化的局部像素**的验收手段：对修改前后两张截图做数学差分并配合精准的局部裁剪，把"全图对比"降维成"差异高亮图 + 量化相似度指标"，就像 Git 对代码做 Diff 一样。

## 关键信息

### 为什么不能直接丢两张图
事实极其残酷：把修改前后的两张大图直接扔给多模态大模型时，模型往往**极其难以准确识别细微的改动**，更不用说量化评估改动是否在逼近最终目标。这种来自海量原始像素的干扰本身就是一种隐蔽的[[上下文污染]]——盲目向模型灌入高分辨率截图，会严重模糊其对任务进展的感知，最终导致 Agent 与人类双双困惑。

举例：指令是"把图中的骷髅变成海盗"，但除了核心修改区域外，整张图（含绿色高亮框内的所有无关像素）都会被塞进上下文，LLM 不仅在分析要求的修改，还在被动处理整张图的杂乱信息。

### 正确做法
1. **引擎侧准备**：在引擎中增加**自由切换 UI 层与玩法层渲染开关**的能力，验证 UI 样式时关闭背景动态 3D 渲染，杜绝背景动画对视觉评测的干扰。
2. **图像差分**：使用现成工具（推荐开源命令行工具 [[odiff]]）计算差异，输出高亮标注差异的 Diff 图像。
3. **量化反馈**：让工具把量化相似度数值（如 `85% similar`）直接打印到标准输出——**LLM 对纯文本数值极其敏感**，在连续 Agent 轮次中可将该百分比作为坚实的基准评估函数，自主朝"降低差异/提高相似度"的目标稳步收敛。

### 在飞轮中的位置
视觉验证之下还有更关键的内部状态推进循环：Agent 会在无视觉渲染的环境下先自主跑很多轮纯逻辑迭代，最后才触发截图对比。核心原则是**确保每一次改动都是达成目标所需的最小改动，并能被毫秒级验证**——这需要稳定性极高、近乎"乏味"的代码基线，以在近乎完全隔离的真空环境中执行推演。
