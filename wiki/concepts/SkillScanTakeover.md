## 定义

存量扫描接管是 AgentBro 解决"已散落在各 Agent 目录的历史 Skill"的机制。扫描已安装的 Agent，把未被中心库管理的 Skill 放入待处理区：无冲突者批量接管并将原副本替换为指向中心库的软链接；有冲突者单独标出，人工决策。

## 核心原则

1. **全量扫描**：覆盖手动复制、安装器放入、共享目录等所有来源
2. **分类处理**：无冲突批量收；同名冲突停下来看内容
3. **软链接替换**：接管后原副本换成指向中心库的软链接
4. **中心库版本优先**：默认原则，仅确认需并存时重命名，或确认 Agent 版本更新时反向覆盖

## 关键信息

**实战数据：** 一次扫描发现 86 个可接管 Skill 和 19 个同名冲突

**冲突处理原则：**
- 同名 ≠ 内容相同：可能是旧副本，也可能是两套碰巧重名的 Skill
- 系统不自动覆盖，扫描结果单独标出"未管理项"与"同名冲突"
- 默认：中心库版本优先
- 例外：确认两份内容确需并存 → 重命名；偶尔 Agent 目录版本更新 → 反向覆盖中心库
- 无冲突可批量收；名字撞车必须停下来看内容，不能塞进"一键覆盖"

**重要性：** "只管以后新装的 Skill，旧目录不收，过一阵还是会乱回来" — 必须处理存量。
