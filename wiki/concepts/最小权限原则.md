## 定义
Agent 权限设计原则：每一步只获得完成当前任务所需的最低权限，而不是一次授权全部能力。登录、付款、发送邮件、披露敏感信息等高风险动作需要明确授权，Agent 不能自行扩大权限范围。

## 关键信息
- **Meta Muse 的落地**：连接邮箱遵循最小权限——若用户要它发邮件，就针对"发邮件"这一操作明确授权，而不是一接入邮箱就拿到全部权限；用户可把某一类操作设为长期允许，但范围不能被 Agent 自我扩展
- **配套机制**：独立凭据存储（信用卡、密码、一次性卡号不暴露给核心 Agent，仅在必要时调用）、监控 Agent 检查进出虚拟机流量并识别提示词注入、机密虚拟机保证连平台方也读不到用户内容；高风险动作触发人工确认
- **分寸感要求**：个人 Agent 还需判断哪些信息可对外披露——如知道用户怀孕，订餐厅时可筛选提供无酒精鸡尾酒的店，但不必向餐厅解释原因
- **消费场景的分层实践**：支付宝阿宝把权限分成"无资金风险任务全自动 / 小额消费关键支付节点强制用户确认"两层；AI 只做信息收集与方案筛选，不触碰最终确认权
- **产品启示**：产品真正落地，不是模型能做什么，而是你敢让它做什么；权限边界是消费执行 Agent 的第一命题
