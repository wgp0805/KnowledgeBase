## 定义
MySQL 中使用 `INSERT INTO A SELECT FROM B` 语句进行数据迁移时，在默认事务隔离级别下，A 表会被直接锁表，B 表记录会被逐条加锁。如果 SELECT 查询走全表扫描，会长时间持有锁，阻塞正常业务写入操作。

## 关键信息

### 锁机制
- `INSERT INTO A SELECT B`：A 表直接锁表，B 表逐条加锁
- 全表扫描时锁持有时间长，阻塞并发写入
- 部分记录被锁定导致其他写入拿不到锁，超时或失败

### 典型事故场景
- 迁移百万级数据，WHERE 条件字段无索引
- 测试环境数据量小且无并发写入，无法复现
- 生产环境晚上执行，第二天财务对账发现数据丢失

### 解决方案
- 对 WHERE 条件字段建立索引，避免全表扫描
- 分批次迁移，控制每次迁移的数据量
- 评估是否可以使用 pt-osc 或 gh-ost 等在线 DDL 工具

### 测试注意事项
- 测试环境需模拟真实业务并发场景
- 数据量要与生产环境相当
- 需要同时进行写入操作验证锁冲突
