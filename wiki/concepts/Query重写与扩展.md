## 定义

在把用户问题扔进检索器**之前**增加一层「提问预处理层」：用轻量级、响应极快的小模型把历史聊天记录与当前提问结合，重写成一个具体且独立的检索词；还可以顺手做 Query 扩展，让模型变异出三四个近义问题做多路并发检索。

## 关键信息

### 为什么必须做
业务里用户提的问题往往**极度口语化，且严重缺乏上下文**。多轮对话场景：

```
User: OA系统怎么登录？
System: 您可以通过企业微信扫码...
User: 密码忘了怎么办？
```

如果直接拿「密码忘了怎么办」这几个字去检索文档库，召回的结果大概率是各种乱七八糟业务系统的密码找回规则，**毫无针对性**。

### 重写逻辑（伪代码）
```java
String userQuery = "密码忘了怎么办";
String chatHistory = "[User: OA系统怎么登录, System: 您可以通过企业微信扫码...]";

// 利用小模型进行意图重写
String rewrittenQuery = fastLlm.generate(
    "根据以下聊天历史，将用户的最新提问重写为一个具体且独立的查询请求。历史：" + chatHistory + " 提问：" + userQuery
);
// rewrittenQuery: "OA系统密码忘了怎么找回"
List docs = retrievalPipeline.search(rewrittenQuery);
```

### Query 扩展
让模型根据用户的原始提问，变异出三四个近义问题，用**多路查询去并发检索**——这能极大弥补用户自身表达不准导致的数据遗漏。

### 与其他环节的关系
- 属于 RAG 的「查询侧」预处理，与切分侧的 [[结构化感知分块]]、[[元数据注入]] 互为补充
- 与 [[混合检索]] 配合：重写后的检索词同时送进 BM25 与向量两路召回
- 与 [[RAG动态评估]] 共同构成「检索前处理 + 检索后评估」的完整链路
