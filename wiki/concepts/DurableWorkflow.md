## 定义

**可持久化工作流**：一种把执行状态持久化、可在任意步骤安全重试、失败后能从中断点继续的基础设施原语。与普通**任务队列（job queue）**的核心区别在于：普通队列崩溃后重启要把第一步、第二步、第三步**重放一遍**，这会出很多问题；durable workflow 是**可以安全重试的，失败之后直接从第三步接着做**。

## 关键信息

### 为什么要区分两者
让 agent 做一个复杂任务要走第一步、第二步、第三步，中间碰到基础设施故障——这是 always-on agent 的常态场景，因为 agent 要连续干几周甚至几个月，**可靠性不是锦上添花，而是前提**。

### 落地选型
Lee Robinson 的团队没有自己从头造这套复杂的东西，而是使用开源工具 [[Temporal]]。

### 在 Agent 体系中的位置
- 每个**子智能体**本身也是一个 durable workflow——崩溃了、内存用爆了，重启后接着干，不丢进度
- 主 agent 像一个同事在管一份待办清单：可以去查进度、发消息、停掉某个帮手
- 这套设计很大程度上是照着「怎样扩大一个工程师团队去解决复杂问题」的理想方式来设计的

### 唤醒/休眠也是状态问题
服务器和 agent 能用的那台电脑平时都是睡着的，被消息或触发器唤醒时才加载 agent 的所有状态把它启动起来；状态保存在数据库里，包括对话记录、记忆、例行任务。
