## 定义
索引下推（Index Condition Pushdown，ICP）是 MySQL 5.6 引入的优化：把本应在**回表后**执行的过滤条件下推到**索引遍历阶段**执行，从而减少回表次数。它不消除回表，只是让回表发生在"过滤之后"。

## 关键信息

### 触发条件
- 使用联合索引，且 WHERE 中有**可被索引覆盖但不满足最左前缀**的条件
- 典型场景：`INDEX(name, age)` + `WHERE name LIKE '张%' AND age = 25`
  - `name LIKE '张%'` 是范围条件，按 [[最左匹配原则]] 范围之后的 `age` 无法用于定位
  - 但 `age` 的值就在索引条目里，可以**就地判断**

### 为什么有用：回表次数的差别
| 模式 | 执行过程 | 回表次数 |
|------|----------|----------|
| 无 ICP | 用 `name LIKE '张%'` 找出所有主键 → **全部回表** → 再过滤 age | 命中 name 的全部记录 |
| 有 ICP | 索引层先用 age 过滤 → 只有同时满足两个条件的记录才回表 | 仅最终命中记录 |

索引条目本身含 `age`，判断它几乎不要钱；而每次回表都是一次随机 IO。ICP 的收益正比于"name 命中量"与"最终结果量"的差距。

### 开关与确认
- 默认开启：`SHOW VARIABLES LIKE 'optimizer_switch'` 中 `index_condition_pushdown=on`
- 手动开关：`SET optimizer_switch='index_condition_pushdown=on';`
- `EXPLAIN` 的 `Extra` 出现 `Using index condition` 即表示生效

### 边界
- **仍是回表**：要消除回表需靠 [[覆盖索引]]（`Extra: Using index`）
- 只有条件列**在索引里**才谈得上下推；不在索引里的列只能回表后过滤
- 依赖版本（5.6+），老版本 MySQL / 部分分支可能不支持
