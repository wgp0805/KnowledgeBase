## 定义
缓存击穿指某个**热点 key 在缓存过期的瞬间**，大量并发请求同时发现缓存失效、一起穿透到数据库加载数据的现象。与"缓存穿透"（查询根本不存在的数据）和"缓存雪崩"（大量 key 同时失效）不同，击穿的焦点是**单个热点 key 失效的瞬间**——因为该 key 承受的并发量远超平均，失效一刻的回源压力足以拖垮连接池。

## 关键信息
- **发生条件**：Redis 虽性能高，但单 key 请求都落到同一台机器同一线程，热点集中时网卡和 CPU 先到上限；这个 key 再同时过期，大量请求就穿透到 MySQL，一条慢查询可能拖垮连接池
- **与热 key 的关系**：热 key（[[热点Key]]）是缓存击穿的高发载体——大促零点爆款商品集中到同一个 key 就是典型。这类热点往往**发生前无法预知**，所以被动加过期时间的缓存挡不住击穿
- **JD-hotkey 的解法**：在请求到达 Redis/DB 之前由 client 把访问上报给独立 worker 判定热 key，判热后推送到应用所有机器 JVM 内存，之后对该 key 的请求直接读本地 Caffeine 缓存、不再访问 Redis——从源头绕开了"单 key 失效瞬间集体回源"的路径
- **通用缓解手段**：互斥锁（同一 key 只放一个请求回源、其余等待）、热点数据永不过期 + 逻辑过期异步刷新、多级缓存兜底
