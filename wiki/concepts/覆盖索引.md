## 定义
覆盖索引（Covering Index）指**一个索引包含了查询所需的全部列**，因此 MySQL 可以直接从索引拿到数据、无需回到聚簇索引取整行。它要解决的是**回表**问题。

## 回表：先理解代价来源
1. InnoDB 的**二级索引**叶子节点存的是 **主键值**，不是完整行
2. 通过二级索引定位到主键后，还必须拿主键去**聚簇索引**查一次完整行
3. 这次追加查询就是**回表**，且是**随机 IO** —— 一页一页跳到不同的聚簇索引页

因此"用上索引"不等于"快"：一个低选择性的二级索引可能让你回表回上百万次，优化器权衡后干脆全表扫描；而一个覆盖索引能把这次随机 IO 直接省掉，常见收益是数倍到数十倍。

## 关键信息

### 判定标准
看 `EXPLAIN` 的 `Extra` 列：
- `Using index` → 覆盖索引，未回表
- `Using index condition` → 用了 [[索引下推]]（ICP），仍可能回表
- `Using where` / 无提示 → 需要回表

### 实践示例
```sql
-- 低效：只有 idx_id_card，查 name/age 必须回表
SELECT name, age FROM user WHERE id_card = 'xxx';

-- 高效：把要查的列一起放进索引
ALTER TABLE user ADD INDEX idx_id_card_name_age (id_card, name, age);
SELECT name, age FROM user WHERE id_card = 'xxx';
-- Extra: Using index
```

### 优缺点
| 维度 | 说明 |
|------|------|
| 优点 | 消除回表，大幅减少随机 IO |
| 缺点 | 索引体积变大，写入时维护成本上升 |
| 适用 | 高频、字段固定的查询组合（用户信息、订单简要列表） |

### 与相邻概念的边界
- **和 [[索引下推]]（ICP）的区别**：ICP 是"在索引层提前过滤、减少回表次数"，仍要回表；覆盖索引是"完全不用回表"。两者可以叠加
- **和前缀索引的冲突**：前缀索引（如 `email(10)`）**无法成为覆盖索引**，也无法支持 `ORDER BY` / `GROUP BY`
- **和 `SELECT *` 的冲突**：`select *` 几乎不可能被覆盖（除非索引含全部列），这也是"避免 `select *`"的真实理由之一（另一个理由是解析成本与字段漂移风险，见 [[索引失效]]）

### 何时不值得
覆盖索引本质是**用空间换 IO**。如果该查询 QPS 很低，或者加宽索引会显著拖慢高频写入，就不该为它单独造一个宽索引 —— 更好的选择是重新审视查询本身（是否真的需要那些列）。
