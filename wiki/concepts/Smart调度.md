## 定义
MiMo Desktop 内置的任务调度模式，自动评估任务类型、复杂程度、交付要求和执行成本，再匹配执行路径。设计意图是把"该选哪个模型"这个决策从用户手里拿走。

## 关键信息

### 三层结构
1. **任务评估**：识别属于办公、编程、研究、设计还是混合场景，判断需要多深的推理、多大的工具范围、什么交付标准
2. **[[多模型路由]]**：在标准模型与旗舰模型之间动态选。日常任务走标准模型（快、便宜），复杂推理、长链路执行与高质量交付走旗舰模型
3. **Harness / Agent / Skill 路由**：按任务类型选办公、代码或研究 Harness/Agent；大任务可拆给多个 Agent，分别负责调研、规划、执行、复核，过程中自动调用不同 Skill 扩展能力

### 配套能力：多会话协同
按需组成多角色会话团队，多会话之间自动通信协作，每个会话有独立的记忆、工作区和任务状态。

### 观察
- 模型路由本身不算新鲜事，但把路由下沉到 Harness / Agent / Skill 三层，说明内部是把能力当工程组件拆的——这一点比口号更值得关注
- 对使用者的实际价值：无需理解模型规格差异，也无需手动指定执行方式，降低了使用门槛
- 风险：路由决策对用户不可见时，出错难以归因；预览阶段尤其需要观察长任务的失败率与稳定性
