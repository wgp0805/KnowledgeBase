## 定义
上下文切换（Context Switch）是 CPU 从一个执行上下文（如用户态/内核态，或一个线程/进程）切换到另一个执行上下文时，保存当前上下文状态、恢复目标上下文状态的过程。在用户态/内核态切换场景下，上下文切换是系统调用开销的本质来源。

## 用户态/内核态切换的开销
| 开销类型 | 说明 |
| --- | --- |
| 寄存器上下文保存/恢复 | 用户态和内核态的寄存器都要存一遍、再恢复一遍 |
| 栈切换 | 从用户栈切到内核栈 |
| CPU 流水线 flush | 特权级切换会清掉 CPU 流水线里的指令 |
| 指令缓存失效 | 内核代码可能不在 icache 里，要重新加载 |
| TLB 部分失效 | 伴随地址空间切换（如进程切换）时 TLB 可能要刷新 |
| 安全检查 | 内核要校验用户传进来的参数是否合法 |

## 性能量级
- **纯特权级切换**（用户态 ↔ 内核态）：硬件开销约 100ns 量级
- **完整系统调用**：通常在几百纳秒量级
- **进程切换**：往往伴随地址空间切换，开销更大（TLB 刷新等）

## 模式切换 vs 线程切换
- **模式切换**（用户态/内核态切换）：不一定发生线程切换，开销相对较小
- **线程切换**：操作系统把当前线程挂起、调度另一个线程执行，往往伴随进程地址空间切换，开销更大

## 减少上下文切换的工程实践
- **epoll 替代 select/poll**：一次系统调用处理大量连接
- **Java NIO DirectByteBuffer**：内核与用户态共享内存，省掉数据拷贝
- **BufferedReader/BufferedWriter**：缓冲区攒一波再读写
- **Java 19 虚拟线程**：大量用户级线程映射到少量 OS 线程，减少线程切换的内核态开销（详见 [[虚拟线程]]）

## 时间片用完后的上下文切换（2026-08，详见 [[摘要-时间片-调度]]）
- **触发链路**：时间片用完 → 时钟中断 → 调度器介入 → 上下文切换
- **进程状态变化**：从「运行态」变成「就绪态」，进入就绪队列等待下次调度
- **现代 x86 Linux 单次切换开销**：1-7 微秒
- **上下文切换内容**：保存旧进程寄存器/PC/内存映射，恢复新进程状态
- **时间片大小权衡**：
  - 太大：接近独占，响应慢，但切换开销小
  - 太小：更公平，响应快，但切换频繁，CPU 时间浪费在切换上
  - 经验值：10ms - 200ms
