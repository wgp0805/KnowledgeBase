## 定义
Agent 主动性（Proactivity）：agent 在用户没有明确要求的情况下主动发现机会、规避风险、把事情做掉的能力。a16z 对话中的核心判断——**proactivity 才是把 agent 产品区分开来的真正护城河**，而不是功能多少，也不是用了哪个底层模型；但它是把双刃剑，存在一条越界即失去全部信任的红线。

## 关键信息
- **哇塞时刻的来源**：Twitter 上分享的 agent 体验几乎全与主动性有关——"我的 agent 帮我把这件事做了，我根本没想到它会去做"（自动 check-in 航班、发现保险可换更便宜的、航班降价自动退差价）
- **边界框架（David Pawlan）**：agent 的行动不需要用户做任何后续动作、不需承担后果 → 可以主动去做（省钱、整理邮件、起草回复）；行动带来不可逆变化或需用户承担后果 → 必须先问（换保险公司要用户点头）
- **越界的代价**：信任极度脆弱——agent 只要一次做了用户完全没预期的事，用户当天就可能关掉它；Anish 的玩笑式红线示例："我注意到你对她好像没那么感兴趣，我已经帮你分手了"
- **产品启示**：需要在产品层面想清楚"自主行动区"与"必须询问区"——这不只是用户体验问题，是信任设计问题；边界设计某种程度上比能力设计更重要
- **与 Invisible Agent 的关系**：最好的 agent 是你感觉不到的那个——后台默默运行、偶尔告诉你"我刚把这件事搞定了"然后消失；骑车 30 分钟语音指挥，到办公室邮件已分类、日历邀请已发出（inbox zero）。产品越不被感受到、越自然融入生活，用户越依赖
- **社交场景的主动性**：群聊里的最优解是沉默 agent（Doc 只听不说、后台记 action item、需要跟进时单独私信当事人）——主动性实现方式恰恰是"让 agent 消失"而非"让 agent 出现"
- **省钱优于省时间**：省时间是抽象的（很难感到今天赚到 20 分钟），省钱是具体的（账单少 200 块立刻知道有价值）——主动性的第一批消费者场景大概率集中在有明确货币价值的金融类事务
