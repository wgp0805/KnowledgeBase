## 定义
上下文工程（Context Engineering）是 vibe coding 时代的核心方法论：不是把开发外包给 AI，而是把上下文工程化。文档是上下文工程化的主要载体。AI 是「能力很强但短期记忆有限、极度依赖输入质量的短期协作者」，你给它的文档质量基本决定它的工作质量。

## 关键信息
- **核心论点**：vibe coding 里唯一真正重要的，是管理好文档（上下文工程化）
- **AI 定位**：短期协作者，不是长期记住项目的程序员；从你提供的材料里重建你的项目
- **文档四角色**：
  1. 项目记忆（人会忘 AI 更会忘，固定「想明白了」的事）
  2. 协作协议（文档越清晰 AI 猜得越准）
  3. 约束系统（边界条件、平台限制、运行时约束）
  4. 复用入口（能复用的不是 prompt 是沉淀后的文档）
- **上下文失真**：代码增加、功能推进、讨论变多，但共识变少
  - 表现：README 旧、架构图过期、平台能力表没更新、适配器规范写一半、历史决策无记录
  - AI 放大失真：人能凭经验判断过期，AI 会混合吸收给出「综合平均答案」
  - 典型问题：局部正确，整体错误（每段像那么回事，连起来不对，最难排查）
- **五类关键文档**：
  1. 项目总说明（项目是什么/边界/技术栈/目录/原则，建立正确世界观）
  2. 架构与运行时约束（哪些 API 可用/纯函数化/特定端能力）
  3. 编码约定与目录约定（命名/职责/错误处理/日志/类型/是否静默降级）
  4. 平台或模块状态文档（做到什么程度/已验证/已知问题/跳过原因，项目现实地图）
  5. 决策记录（为什么当时没那样做，减少无意义返工）
- **好文档四标准**：明确不优雅、面向任务不面向展示、与现状同步、能被快速检索
- **稀缺资源转移**：从代码转移到清晰目标、稳定约束、可复用上下文、持续更新的知识体系
