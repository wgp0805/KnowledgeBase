## 定义
通用 Agent（General Agent）：不聚焦单一场景，而是由 Agent 自主判断何时调用搜索、浏览器、代码、视频、外部数据、自动化等对应工具，为用户承担跨任务链条的入口与调度的 AI 产品形态。核心主张是"通用更像一套调度方式"——用户不必自己决定下一步该打开哪个 AI 产品；与之相对的是垂直工具，只需把自己那一块做深。

## 关键信息
- **行业争论**：2025 年 3 月 Manus 上线时最吵的问题是 Agent 该做全能通用型还是聚焦单一场景；垂直工具（开发者编码、研究检索、视频、设计、营销、自动化各自成熟）使通用 Agent 容易"样样通、样样松"
- **从定位到体验**：[[Manus]] 2.0 把 General Agent 做成体验——Studio 整合视频编辑/游戏开发/网站应用文档幻灯片，新 Agent Harness 平时轻量、按需引入专业模块，由 Cascade 服务调度；能力单项市面都有，价值在"任务之间"（如做落地页时顺带出短片+主视觉+动画并进时间线协作）
- **运行环境是入场券**：通用 Agent 不能困在聊天框，需要自己的运行环境（常驻云端的独立计算环境、接入用户正在使用的设备、长任务保持在线）——[[MetaMuse]] 的 Muse Secure VM、Grok Bot 的常驻云电脑、Manus 的 Cloud Computer 底层架构几乎一样：常驻云端独立计算环境 + 连接用户账号 + 长时间自主执行 + 关键节点找用户确认
- **形态分野**：Meta Muse 是"给你一个管家"，[[Manus]] 的 Cue 是"给你一支有身份的小团队"（每个 Agent 配邮箱/电话/钱包/电脑，群聊分工）；腾讯 [[LightVela]] 则选择"住进微信对话框"而非另开新 App
- **风险**：链条越长，任何一个环节出现偏差，最终结果都受影响；通用 Agent 要管整条任务链，而垂直产品只需做深单点
- **关键指标**：决定个人 Agent 生死的不是下载量，而是任务完成率、复用率、用户愿意授权多深、每完成一个任务花多少钱
