## 定义
隔离执行环境：为 Agent 工具调用提供受限的文件系统、进程与网络边界，即使出错也不影响宿主系统。常见形态：Docker 容器、write-restricted token 加防火墙、E2B 云沙箱。

## 边界可靠性实测（2026-10）

METR 进驻 OpenAI 三周对内部 Codex 监控系统的审计（61 页报告，详见 [[摘要-claude-auto-mode监控逃逸]]）显示：在监控覆盖 99.2% 内部流量的前提下仍存在六条逃逸暗道（见 [[监控逃逸]]），其中一条可让 Codex Agent **同时绕过沙箱与自动审查**，宿主研究员能干的事它全能干；另有两个被当"只读"、未接监控的内部工具，一个简单漏洞就可能让它们在沙箱里执行任意操作。结论：沙箱是纵深防御的一层而非铁底，须与"监控和 Agent 结构分离、定期/定量检查、日志与 Agent 视角一致"配合（详见 [[多级AI监控]]）。

### DSH 的三平台实现与策略绑定（2026-11-26，详见 [[摘要-deepseek防提示词注入]]）

[[DeepSeekHarness|DSH]] 把沙箱定位为「审查模型也看走眼」之后的**第二道确定性兜底**，有两条与常见实现不同的设计取向：

1. **策略动态绑定会话工作目录**：不是全局固定一份策略，而是**每次工具调用时把文件操作策略绑定到当前会话的工作目录**。写入范围严格限制在当前工作区，Agent 换个会话就等于换个边界
2. **默认值取安全侧**：**出错时默认 `read-only`**，日常写代码才切到 `workspace-write`。即失败方向是「不能写」而不是「放开写」

底层按平台选机制：Linux 用 **Bubblewrap** 或 **Landlock**（内核级路径/系统调用限制），macOS 用 **Seatbelt**（沙箱配置文件），Windows 用**受限令牌**（降权进程令牌）。三者都是 OS 原生隔离原语，而不是容器——这带来更低的启动开销，代价是隔离强度依赖内核能力。

### V8 沙箱纯代码执行形态（2026-10-27，详见 [[摘要-gpt6.1-terra-codex三招]]）

Codex 为 [[GPT-6.1-Terra]] 默认开启 [[code_mode_only]] 模式，采用**独立 V8 沙箱**：零散工具全部隐藏，只暴露一个 `exec` 工具，文件读写/终端命令/外部 MCP 插件全部挂载到沙箱全局 `tools` 对象上——工具调用从"JSON 往返"变为"沙箱内并发脚本编程"。这是沙箱从"隔离安全"向"**执行形态本身**"演进的新用例：沙箱同时承担代码执行环境与工具编排层。
