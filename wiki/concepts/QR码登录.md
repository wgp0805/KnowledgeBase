## 定义
**二维码扫码登录**（QR Code Scan Login）是一种跨端登录认证方式，通过已登录的手机端扫描 PC/Web 端展示的二维码，在不输入账号密码的情况下，让 PC/Web 端登录到同一账号。常见场景：手机微信扫码登录 PC 微信、手机淘宝扫码登录 PC 淘宝。

## 关键信息

### 登录认证的两件事
所有登录认证本质上做两件事：
1. **告诉系统我是谁** — 账号密码登录中是账号；扫码登录中是手机端已登录的账号信息（通过二维码 ID 绑定传递）
2. **向系统证明我是谁** — 账号密码登录中是密码；扫码登录中是**已通过手机端登录态间接证明**——只要确认"是这部手机且是这个账号"操作，就等同证明身份

手机端**不存储密码**，存储的是基于 Token 的认证凭证（详见 [[Token认证机制]]）。

### 二维码三大状态
```
待扫描 → 已扫描待确认 → 已确认
```

### 完整流程

#### 阶段 1：二维码准备（待扫描）
1. PC 端打开扫码登录界面，向服务端请求二维码，**附带 PC 设备信息**
2. 服务端生成**唯一二维码 ID**，并将 ID 与 PC 设备信息绑定
3. 服务端返回二维码 ID，PC 渲染为二维码（内容可以是 ID 本身，或包含 ID 的 URL）
4. PC 端开始**轮询**服务端（如每秒一次），查询二维码当前状态

#### 阶段 2：扫描（已扫描待确认）
1. 手机端扫描二维码，解析出二维码 ID
2. 手机端调用服务端 API，将**手机账号身份信息 + 二维码 ID** 一起发送
3. 服务端将身份信息与二维码 ID 绑定，并生成**临时 token** 返回手机端
4. PC 端轮询发现状态变为"已扫描"，更新 UI

#### 阶段 3：确认（已确认）
1. 手机端弹出确认登录界面，用户点击确认后携带**临时 token** 调用服务端确认接口
2. 服务端验证临时 token，根据二维码 ID 绑定的 PC 设备 + 账号信息，**生成 PC 专属 token**
3. PC 端下一次轮询拿到 token，登录成功

### 临时 Token 的作用
临时 token 只能用一次，用过即失效。它的存在是为了**确保扫码与确认是同一部手机操作**——防止扫码后被其他设备截胡确认。

### 二维码内容的两种选择
- **二维码 ID 本身**（纯字符串）
- **包含 ID 的 URL 地址**（更通用，未安装 App 时可降级为下载页）

### 安全设计
- 密码**永不离开服务端**，手机端只存 token
- Token 与"账号 ID + 设备 ID + 设备类型"三元组绑定，换设备无效
- 每次 API 调用同时传递 token 与设备信息，服务端校验一致性
- 临时 token 一次性使用，杜绝重放
- 整个过程基于 HTTPS

### 与其他登录方式对比
| 方式 | 告诉我是谁 | 证明我是谁 |
|------|------------|------------|
| 账号密码 | 账号 | 密码 |
| 短信验证 | 手机号 | 验证码 |
| 扫码登录 | 已登录的手机账号 | 手机端登录态 + 临时 token |
| 第三方扫码（如微信登录掘金） | 微信 OpenID | OAuth 流程（另一套机制） |

### 思考延伸
- 扫码确认时用户取消怎么处理？→ 服务端将二维码状态置为已取消，PC 端轮询感知后提示
- 二维码过期机制？→ 通常 1-2 分钟有效期
- PC 端轮询频率与服务端性能权衡？→ 可改用 WebSocket / SSE 长连接减压
