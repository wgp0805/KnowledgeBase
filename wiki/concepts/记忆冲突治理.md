## 定义

长期记忆用久了必然出现三类脏数据——**外部网页提示词注入污染**、**同一事实的新旧版本冲突**、**代码改了但旧记忆还在的过时污染**——需要一整套写入与读取两侧的治理机制。

## 关键信息

### 一、防注入污染：只从用户原话逐字摘取
- 自动事实提取器**只从用户本轮亲手输入的原话里逐字摘取事实**
- 自动过滤包含密钥、手机号的敏感词，以及带有「这次、临时、先这样」的短期指令
- 摘取的事实打上**待核实标签**
- **回合策略锁死写入**：一旦本轮会话读取过外部网页、浏览器页面、MCP 资源或执行过网络抓取命令，立即锁死记忆写入——除非用户在当前原话里明确下令「记住」，否则完全禁止调用记忆保存工具和自动提取

### 二、防新旧冲突：掩码变体 + Dice 相似度
- **去重器**只合并标点或空白差异的完全重复项
- **冲突检测器**把两条同域记忆里的所有数字和版本号替换成统一的特殊掩码字符
- 若掩码后文字一模一样（说明只有版本号或数值变了），或**字符二元组（Bigram）的 Dice 相似度达到 0.8 以上**，系统就**阻止静默写入**，把旧条目和新条目同时列出来交给用户决定是替换还是共存
- 典型场景：上个月记了「项目用 Java 17」，今天升级成「项目用 Java 21」

### 三、防过时污染：检索时降权 + 打标记
- 检索注入阶段结合关键词分词与语义向量做混合召回，按**窗口大小的 1/200** 控制注入预算（夹在 500~5000 Token 之间）
- 每条记忆带**写入时间**与**最后核实时间**
- 触发降权条件（满足其一）：
  - 超过 **30 天**未核实
  - 记忆关联的**源码文件 mtime 比记忆核实时间更新**
- 降权后显式打上「可能已过时」标记，并在系统提示词里明确要求：**把长期记忆当线索而非绝对事实，动手改代码前必须以当前磁盘上的真实文件内容为准**

### 与「记忆可回滚」思路的一致性
这一套设计与 [[摘要-可回滚的数据清洗规则]] 共享同一条原则——**AI 项目里沉淀下来的中间结论必须版本化、可审计、可回滚**，而不是默默覆盖。
