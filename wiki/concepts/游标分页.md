## 定义
游标分页（Cursor-based Pagination / Keyset Pagination）是一种基于排序字段值的分页方式，用上一页最后一条记录的某个字段（如 `id`）作为游标，通过 `WHERE id > last_id LIMIT N` 查询下一页。与传统的 OFFSET 分页不同，游标分页不"跳过"记录，而是"过滤"记录，因此在大数据量和深翻页场景下性能更稳定。

## 关键信息

### 核心思想
- 不要 OFFSET，用上一页最后一条记录的某个字段做游标
- 每次查询直接定位到上一页末尾，走索引扫描 N 条

### 示例 SQL
```sql
-- 第一页
SELECT * FROM t_order ORDER BY id DESC LIMIT 10;
-- 第二页（传上一页最后一条的 id）
SELECT * FROM t_order WHERE id < ? ORDER BY id DESC LIMIT 10;
```

### 在分库分表场景下的优势
- 每个分片永远只返回 N 条数据，性能不随翻页深度增加而下降
- 实现简单，每个分片 SQL 都走索引
- 大厂生产环境广泛使用：朋友圈、微博 feed 流、订单列表（手机端）

### 缺点
- **不能跳页**：用户无法从第 1 页直接跳到第 10 页，只能一页一页翻
- **业务体验受限**：传统分页 UI 不适用，需要改成"加载更多"或瀑布流
- **需要有序的唯一列**：游标列必须唯一且有序，通常使用自增主键或时间戳

### 与 OFFSET 分页的本质区别
| 对比项 | OFFSET 分页 | 游标分页 |
|--------|-------------|----------|
| 原理 | 跳过 N 条，再取 M 条 | 条件过滤，直接定位 |
| 复杂度 | O(n+m)，需要扫描 N 条 | O(log N + m)，走索引定位 |
| 深翻页 | 越翻越慢 | 性能恒定 |
| 跳页支持 | 支持 | 不支持 |
