## 定义
短链接系统（Short URL System）是将冗长 URL 映射为简短字符码的网络服务，核心提供两个能力：长链生成短链（写流程）、短链跳转回长链（读流程）。是典型读多写少的高并发系统——短链生成一次可能被访问百万次，性能瓶颈在跳转读取。

## 关键信息

### 短码生成方案对比
- **MD5 哈希截取（反模式）**：对长链 MD5 取前 6/7 位。存在 [[哈希碰撞]] 风险，高并发下小概率碰撞必然发生，导致跳转错误地址，不适用亿级流量
- **分布式发号器 + Base62（推荐）**：[[分布式发号器]] 生成全局唯一递增 ID，转 [[Base62编码]] 得短码，数学上保证不冲突

### 写流程（长链生成短链）
1. 校验长 URL 合法性，过滤恶意网址
2. 判断长链是否已生成过短链，存在直接返回旧短链
3. 调用发号器获取全局唯一 ID
4. ID 转 Base62 得短码
5. 数据库存储映射关系（短码建唯一索引），写入 Redis 缓存
6. 返回短链接

> 优化：高并发可 MQ 异步落库，先返回结果，后台异步持久化

### 读流程（短链跳转，系统性能瓶颈）
> 短链接是典型**读多写少**：生成一次，可能被访问百万次，性能重点在跳转读取。

1. 用户访问短链接，解析 url 拿到短码
2. 优先查询 [[Redis]] 缓存：
   - ✅缓存命中：拿到长链接执行重定向，异步埋点统计点击、UV、PV
   - ❌缓存未命中：查询 [[MySQL]] 数据库
     - 数据库不存在：返回 404
     - 数据库存在：校验链接是否过期；有效则回写 Redis 并重定向；过期返回 404

> 数据库只做兜底，绝大多数请求走 Redis，保障高并发

### 重定向状态码选择
跳转用 [[HTTP重定向]]：默认 302 临时重定向（可统计点击），不用 301 永久重定向（浏览器缓存导致无法统计）。

### 高并发优化点
1. **Redis 缓存**：key=短码 value=长链，TTL 随机打散防 [[缓存雪崩]]；热点短链叠加 [[Caffeine]] 本地缓存
2. **过期策略**：支持链接过期；不立即删，惰性删除（访问时判断过期返回 404）；后台定时任务清理
3. **分库分表**：数据量巨大时按短码哈希 [[sharding|分库分表]]，解决单表瓶颈
4. **安全风控**：校验长链接拦截恶意、钓鱼网址；IP 限流防刷
5. **统计埋点**：点击数、来源、UV/PV 走 MQ 异步日志，不阻塞跳转流程
6. **布隆过滤器**：前置过滤不存在短码，防缓存穿透

### 数据库表设计参考
```sql
CREATE TABLE short_url (
    id BIGINT PRIMARY KEY COMMENT '发号器原始ID',
    short_code VARCHAR(10) NOT NULL COMMENT '短码',
    long_url TEXT NOT NULL COMMENT '原始长链接',
    expire_time DATETIME COMMENT '过期时间，null代表永久有效',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_short_code(short_code)
) ENGINE=InnoDB;
```
