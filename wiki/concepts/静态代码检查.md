## 定义
静态代码检查：在不运行程序的前提下分析源代码，发现规范问题、潜在 bug 与结构隐患的自动化手段，用于降低 code review 工作量、反向提升代码编写能力。IntelliJ IDEA 生态的五款代表工具按能力维度分工：规范、风格、安全规则、缺陷检测、整体健康度。

## 关键信息
- **五款工具选型对照**：
  - **Alibaba Java Coding Guidelines**：查代码规范首选——OOP/并发/控制语句/命名/常量/注释，Blocker>Critical>Major 三级，大部分可自动修复，支持实时检测
  - **CheckStyle**：只管文法层风格（命名、Javadoc、空格、超长方法、多余 Import），对 bug 几乎无发现能力；默认 Sun/Google 配置过严需导入自定义配置
  - **PMD**：安全编码规则 + 数据流/路径分析，查潜在 bug（空 try/catch）、死代码、循环体新建对象、资源未关闭；自定义规则能力强
  - **FindBugs**：专注找真实 bug——空指针、资源未关闭、用 == 比较字符串；8 类错误信息（Bad practice、Dodgy code、Performance、多线程正确性等），适合给新员工做 bug 培训
  - **SonarLint**：层级最高——除静态 bug 外还看代码质量、包依赖、耦合、复杂度、重复代码等整体健康度；插件（自用自审）+ Sonar 平台（团队他审）双形态，commit 时可自动检查
- **选型口诀**：查规范用 Alibaba 规约；找 bug 用 PMD + FindBugs + SonarLint 互补（PMD 自定义规则强、FindBugs 找 bug 强、SonarLint 覆盖面全）
- **价值逻辑**：代码审查难度大、缺陷不易发现、审查工作量随代码量线性增长——用工具把"人查"变"机器查 + 人复核"，让开发者在关注质量的同时减少 review 负担
- **工程背景**：业务发展使系统庞大、迭代后复杂度上升、潜在风险暴露——提高代码质量是防止服务不稳定造成业务价值损失的前置手段
