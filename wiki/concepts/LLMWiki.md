## 定义
LLM Wiki 是 Andrej Karpathy 于 2026 年初提出的一种知识库组织模式：把碎片化信息编译成结构化、高度相互链接的 Wiki 式知识库，使知识既可供人类阅读，也可供 LLM/Agent 高效读取、维护与交换。**[[OpenWiki]] 是这个理念的第一个完整工程实现**——LangChain 照着这套思路做出来的 CLI 工具，把代码库「编译」成一套 Agent 可以快速查阅的 Wiki，让 Agent 不用每次都从头翻代码。

## 关键信息
- **核心思想**：知识以「人能打开、能审查、能版本管理、能迁移的文件」形式存在，而不是锁在某个向量数据库/Agent 框架/模型 Memory 里
- **与 OKF 的关系**：OKF 把 LLM Wiki 模式正式定义成开放、厂商中立、可移植的知识格式标准；LLM Wiki 是 OKF 的前身模式
- **实践形态**：本仓库（wiki/ 编译输出层 + raw/ 不可变层）即 LLM Wiki 的具体实践
- **双向链接**：页面之间通过 [[wikilink]] 强制相互连接，杜绝孤岛页面
- **可验证性**：知识附带来源、状态、时效性，使 Agent 在使用知识前能判断是否值得相信；工程实现见 [[Claims溯源]]
- **解决的核心痛点**：AI 编程工具的「短期记忆」够了但「长期记忆」没有——每次任务都是全新开始，之前积累的理解完全浪费，你花时间让 AI 理解的项目架构，下个任务它完全不记得
- **设计原则反直觉**：为 Agent 写文档不是为人写文档。传统项目文档是给人看的，人类能容忍模糊、能脑补上下文；但 Agent 上下文窗口有限，每行无用信息都在消耗 Token，所以输出应是针对 LLM 上下文优化的结构化 Markdown，而非人类喜欢的叙事铺垫和背景介绍
- **一句话总结**：**RAG 让 AI 帮你找答案，OpenWiki 让 AI 记住你的项目**（详见 [[编译器模式vs解释器模式]]）
