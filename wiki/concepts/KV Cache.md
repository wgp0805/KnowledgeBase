## 定义
KV Cache（Key-Value 缓存）是 LLM 推理时缓存历史 token 的 Key 和 Value 向量，避免每次生成都重新计算，是降低推理成本、提升速度的关键机制。

## 关键信息
- **核心思想**：缓存历史 token 的 KV 向量，避免重复计算
- **成本影响**：KV Cache 大小随上下文长度线性增长，是长上下文成本的主要来源
- **三铁律**：控制上下文长度、复用缓存、避免频繁切换模型（切换模型导致缓存失效）
- **应用**：Agent 长任务、RAG 场景的成本优化

### 机制细节（2026-10-21，详见 [[摘要-xiaom-15升16-agent面试题]]）
- **作用**：把预填充（Prefill）与解码（Decode）阶段已算出的历史词元 K/V 缓存在 GPU 显存，避免每生成一个新词都把前面所有词从头重算，单步解码复杂度从平方级降到线性级
- **为什么只缓存 K 和 V 不缓存 Q**：第 i 步生成时用当前词元的 Q 与第 1~i-1 个词元的 K 做点积算相关性权重再加权求和；历史位置的 Q 在各自生成那一步已用完，后续任何新词元都不会再读旧的 Q，留着纯属浪费显存。因果注意力掩码下前面位置的表示不受后面新词元影响，K/V 算过一次就永远固定
- **显存瓶颈**：占用随批次大小与序列长度线性膨胀，长上下文与并发请求下容易超过模型权重本身，把解码阶段推向**显存带宽受限（Memory-bound）**

### 三端优化路线
1. **模型架构侧**：GQA / MLA 减少 KV 头数与缓存维度；[[HySparse2]] 在 80B-A3B MoE 上只保留少数全注意力层并做跨层 KV 共享，1M 上下文 FP8 精度下把 KV Cache 从 12.09GB 压到 **2.69GB**、预填充计算量降 5.02 倍
2. **推理引擎侧**：vLLM 的 PagedAttention 分页管理消除碎片；FP8 量化把单元素字节数减半；NVIDIA Dynamo 的 KV 感知路由把同一会话第 N 轮路由到已缓存前 N-1 轮 KV 块的节点
3. **Agent 应用侧**：按稳定度排列系统提示词，保障最长公共前缀命中（见 [[前缀缓存稳定布局]]）；NVIDIA 实测多轮编码 Agent 流量下命中率 **85%~97%**、首字延迟降低约 5 倍

### 磁盘级 KV 缓存与 SWA Bounded Replay（2026-10-21，详见 [[摘要-deepinfer-deepseek开源推理框架]]）
[[DeepInfer]] 把 KV Cache 从"显存里的临时缓存"推到"存储集群里的长期资产"：
- **100 PiB 独立分布式存储**：基于自研 3FS 分布式文件系统搭建约 100 PiB SSD 存储集群，峰值聚合读取带宽达 **10 TiB/s**，把按 128 个 Token 分页的块缓存全部写入硬盘，**KV Cache 保留时间达到 72 小时**
- **SWA KVCache 的取舍**：只在活跃会话里有效的滑动窗口缓存写硬盘会占掉近一半容量，全量重算代价又太高，因此只留在机器内存里保存约 **180 秒**，换来线上命中率超 **98%**
- **SWA Bounded Replay**：未命中时不重算整段上下文，只截断重算最近 **128 个 Token**，把重算代价变成与上下文长度和层数无关的常数，使预填充在解码层的总计算量减少近一半
- **Agent 侧红利**：需要人工审批或跨天恢复的 Agent，只要固定好开头的系统提示词与工具定义，**暂停两天依然能命中服务端缓存**
