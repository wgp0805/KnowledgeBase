## 定义
双亲委派模型是 [[Java]] [[类加载器]]的核心工作机制：当一个类加载器收到加载请求时，不会自己先加载，而是把请求**委派给父加载器**处理，只有父加载器反馈无法完成时，子加载器才尝试自行加载。口诀：子找父，父找爷，爷干不了才回子——往上委派，往下兜底。

## 关键信息
- **加载流程**（`ClassLoader.loadClass()` 源码三步走）：
  1. 先检查本加载器是否已加载过该类（`findLoadedClass`），有则直接返回
  2. 没加载过则调用 `parent.loadClass()` 委派给父加载器（父为 null 则委派 Bootstrap）
  3. 父加载器也加载不了（返回 null），才调用自己的 `findClass()` 加载
- **设计目的**：
  - 保证类的唯一性：无论哪个加载器加载 `java.lang.Object`，最终都委派到 Bootstrap ClassLoader，全 JVM 只有一个 Object 类
  - 保证安全性：防止恶意替换核心类，即使自定义 `java.lang.Hack`，Bootstrap 会先尝试加载，且 `java.lang` 包有额外的包密封检查
- **三次破坏**：
  - 第一次：JDK 1.2 历史遗留，用户重写 `loadClass()` 覆盖委派逻辑 → JDK 引入 `findClass()` 引导重写
  - 第二次：[[SPI机制]]（JNDI/JDBC），接口在 rt.jar 由 Bootstrap 加载，实现在 classpath 下，通过**线程上下文类加载器**绕过限制
  - 第三次：OSGi 模块化热部署和 [[Tomcat]] 类隔离（`WebAppClassLoader` 优先加载 Web 应用目录下类）
- **注意事项**：双亲委派不能保证一个类在 JVM 中只被加载一次——不同类加载器加载同一 `.class` 文件得到的 `Class` 对象不同，`==` 比较返回 false，"唯一性"仅在同一个类加载器命名空间下才有保证
- **自定义类加载器**：应重写 `findClass()` 而非 `loadClass()`，后者内部已实现委派逻辑
