## 定义

NewSQL 是兼具 NoSQL 水平扩展能力与传统关系数据库 ACID/SQL 能力的新型分布式数据库。按 Pavlo 的 NewSQL 综述（`pavlo-newsql-sigmodrec`）分类：Spanner、TiDB、OceanBase 属于"新架构型"；ShardingSphere、Mycat、DRDS 等"中间件+分库分表"属于第二种中间件方案（另有云数据库第三类）。本文语境下 NewSQL 特指新架构型。

### 三代数据库演进（补充来源：[[摘要-tidb-newsql入门]]）
1. **SQL**：传统关系型数据库（MySQL 等）——架构基因里没有分布式，海量 + 7×24 在线时靠升级硬件（有天花板）或数据分片（引入中间件复杂度：跨库 join、跨库事务）
2. **NoSQL**（MongoDB、Redis 等）：放弃强事务与关系模型，换取高可用、可扩展、极高灵活度；代价是不保证强一致性、不支持 SQL、兼容性差
3. **NewSQL**：= NoSQL 的可扩展性 + 关系模型 + 成熟 SQL + ACID；生于云时代、天生分布式，扩容缩容对业务层透明、自动容灾

NewSQL 主要特性：支持复杂查询与大数据分析的 SQL、支持 ACID 与隔离级别、弹性伸缩透明、高可用自动容灾。

## 关键信息

### 相对"中间件+分库分表"的架构先进性
- 传统数据库面向磁盘设计，NewSQL 基于内存的存储管理与并发控制更高效
- SQL 解析与执行计划只在一处生成，无中间件与底层 DB 的重复劳动
- 分布式事务相对 XA 做了优化，性能更高
- 存储原生基于 Paxos/Raft 多副本，相比主从（半同步转异步会丢数）实现真正的高可用高可靠

### 必须清醒的局限
- **未突破 CAP**：Spanner 宣称"实际上是 CA"，本质是私有全球网避免网络分区 + 高效运维，普通环境不成立
- **分布式事务完备性参差**：2PC 在 commit 阶段异常时类似最大努力提交，故障恢复前无法保证原子性与一致性；有友商称已知 NewSQL 的分布式事务支持都不完整
- **2PC 性能损耗**：GID 获取、网络开销、prepare 日志持久化，跨节点越多越明显（如银行批量扣款上万账户）
- **统一分片策略未必最优**：按主键 range 分片与领域划分（客户/账户/流水同写）不一致，反而制造分布式事务
- **功能取舍**：普遍不支持存储过程、视图、外键；SQL 兼容面限于 MySQL 或 PostgreSQL 协议；依赖 CBO（有分布与统计信息），中间件只能 RBO
- **成熟度与人才**：多用于互联网与传统企业非核心系统，银行等高风险行业仍审慎试点

### 选型自测清单
肯定项达 2-3 个可考虑 NewSQL：强一致事务是否必须在库层解决、数据增速是否不可预估、扩容频率是否超出运维能力、相比响应时间更看重吞吐、是否必须对应用完全透明、是否有熟悉 NewSQL 的 DBA。反之（最终一致可接受、数据量可预估、有维护窗口、对响应时间敏感、需兼容存量关系库、有传统 DBA 积累、可容忍分库分表侵入）则继续分库分表。
