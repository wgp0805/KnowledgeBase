## 定义
分布式任务调度框架解决"在多台服务器的集群环境里，如何可靠地在特定时刻触发任务、且同一任务不被重复执行、还能弹性扩缩容与监控告警"的问题。它区别于单机定时任务（Timer / ScheduledExecutorService / Spring 定时器），核心挑战是**多节点部署时任务不能重复执行**、**高可用**、**弹性扩缩容**与**动态分片**。主流实现按协调机制分两派：基于数据库（如 [[XXL-JOB]]、[[Quartz]]）与基于 Zookeeper（如 [[ElasticJob]]）。

## 关键信息
- **与消息中间件的边界**：定时任务可被 MQ 部分替代但非全部——时间驱动 vs 事件驱动（爬外部价格每小时一次只能时间驱动）、批量 vs 逐条（月度结算只能批量）、实时 vs 非实时（VIP 升级不需实时）、系统内部 vs 系统解耦（调度一般在系统内部，MQ 用于跨系统）
- **两大协调流派**：数据库派靠 DB 锁保证一次调度只触发一次（X-Job 调度中心通过 DB 配置区分集群，节点仅需配置一致）；Zookeeper 派靠 ZK + Curator 做注册中心协调分布式作业（E-Job 重写了 Quartz 基于 DB 的分布式功能改用 ZK）
- **九维度选型对照**（详见 [[摘要-分布式定时任务框架选型]]）：社区力量、集群部署、任务不重复、日志追溯、监控告警、弹性扩缩容、并行调度、高可用、失败处理、动态分片。X-Job 侧重的业务实现简单与管理方便，失败与路由策略丰富，适合用户基数少、服务器数量适中的场景；E-Job 关注数据、增加弹性扩容与数据分片，学习成本高，适合数据量大、服务器多的场景
- **动态分片**：把一个任务拆为 n 个独立任务项由分布式服务器并行执行。X-Job 分片广播以执行器为维度、支持动态扩容执行器增分片；E-Job 支持多种分片策略（平均分配 / 哈希奇偶决定 IP 升降序 / 轮转）且可自定义，分片由主节点分配，新 Job 加入、现有节点下线、主节点选举都会触发分片算法
- **失效转移**：E-Job 可在本次作业运行中用空闲服务器抓取孤儿分片执行（牺牲部分性能）；X-Job 靠失败告警（默认）与失败重试策略
- **和 Quartz 的关系**：Quartz 是 Java 事实标准但关注任务非数据、无分布式并行调度，X-Job 与 E-Job 都在其基础上补分布式能力或直接重写
