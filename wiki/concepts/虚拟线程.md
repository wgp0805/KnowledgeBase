## 定义
虚拟线程（Virtual Thread）是 Java 21 引入、Java 25 深度优化的轻量级线程机制，由 JVM 而非操作系统调度，每个请求一个虚拟线程，资源占用极低，适合高 IO 并发场景，几十万并发不再是瓶颈。

## 关键信息
- **调度方式**：JVM 调度（非操作系统级），挂起/恢复成本极低
- **资源占用**：相比平台线程（OS 线程）内存占用大幅降低
- **适用场景**：AI 异步生成、SSE 事件流、邮件发送等高 IO 等待场景
- **吞吐量**：显著提升，几十万并发可承载

## 与平台线程对比
| 维度 | 平台线程 | 虚拟线程 |
| --- | --- | --- |
| 调度 | 操作系统 | JVM |
| 成本 | 高（MB 级栈） | 低（KB 级栈） |
| 数量上限 | 数千 | 数十万 |
| 适用 | CPU 密集 | IO 密集 |

## 实测对比（小哈 2026-08，详见 [[摘要-虚拟线程vs传统线程池]]）
10000 个并发 HTTP 请求任务：
- **传统线程池**（200 线程）：需排队执行，50 秒完成
- **虚拟线程**：直接创建 10000 个，1 秒完成

### 最佳实践
- **不要池化**：用完即弃，每次新建
- **避免 `synchronized`**：会 pin 平台线程，改用 `ReentrantLock`（JDK 21 已优化但仍有边界）
- **警惕 `ThreadLocal`**：虚拟线程数量巨大，每个 ThreadLocal 都占用内存
- **创建执行器**：`Executors.newVirtualThreadPerTaskExecutor()`
- **Spring Boot 集成**：`spring.threads.virtual.enabled=true` 一键开启，Tomcat/TaskExecutor/@Async 自动使用

### 生产环境三大坑（2026-08，详见 [[摘要-java21-虚拟线程生产落地]]）
原始抓取仅含标题与摘要，无正文内容。标题指向 Java 21 虚拟线程在生产环境的 3 大坑，90% 的人不知道。结合已有实践，常见坑点包括：
- **synchronized pin 线程**：会 pin 平台线程，改用 `ReentrantLock`
- **ThreadLocal 内存泄漏**：虚拟线程数量巨大，每个 ThreadLocal 占内存
- **池化陷阱**：虚拟线程用完即弃，不要池化

### Tomcat 侧落地（2026-10，详见 [[摘要-tomcat-11-new-features]]）
- 传统模式：Tomcat 线程池默认 `maxThreads="200"`，请求占线程干等（查库/调远程接口），池满即排队——虚拟线程动的正是 Connector（Coyote）层线程模型
- Tomcat 11 开启方式：① Connector 上 `useVirtualThreads="true"`；② 定义 `org.apache.catalina.core.StandardVirtualThreadExecutor`（Executor 须写在 Connector 前，可多连接器共用）；③ Spring Boot 一行 `spring.threads.virtual.enabled=true`
- 验证：Servlet 输出 `Thread.currentThread().isVirtual()`，实测线程名 `VirtualThread[#52,http-nio-8080-virt-0]/runnable@ForkJoinPool-1-worker-1`
- pinning 时间线精确化：Java 21 中 `synchronized` 代码块会把虚拟线程钉死在平台线程上，直到 Java 24 才由 JEP 491 解决；虚拟线程至少 Java 21，生产推荐 Java 25 LTS（Tomcat 11 本身 Java 17 即可运行）
- 边界补充：只解决"等待"不解决"计算"，CPU 密集接口开了也不会更快；线程不再稀缺后，下游数据库连接池往往最先被打满，需同步评估连接池大小或加限流
