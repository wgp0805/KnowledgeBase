## 定义
Agent 文件入口反转指一种 AI 产品交互范式的转向：不再要求用户把文件搬进 Agent 的工作区/对话框（"你去它的世界"），而是让 Agent 能力直接附着在用户原本"打开文件"这个四十年不变的桌面动作上（"Agent 坐在你打开文件的地方"）——右键打开文件，AI 就在旁边，改的就是原文件。

## 关键信息
### 反转前的两条旧路及其痛点
- **终端路线**（如 [[ClaudeCode]]）：改的文件一定在文件夹里不会乱，但对话绑定工作区——文件不在工作区预览打不开、每次要多点授权；多对话并行难管理
- **桌面路线**（如 [[Codex]]）：对话可整理分类，但反复修改生出多版本散落各处；上传慢需鼠标宏抓路径；产出默认落 Documents 要手动搬回；文件链接时间一长就断
- 共同点：要求用户离开"桌面、文件夹、双击打开"的基本动作，把文件带进 Agent 的世界

### 反转后的形态（以 WorkBuddy 文件浏览器为例）
1. **右键即开**：任意本地文件右键用 WorkBuddy 打开，左文件右对话的独立窗口
2. **多标签+独立上下文**：每个文件一个标签，AI 对话上下文随文件切换
3. **人机双写**：Office 文件 AI 与人改同一份、存回原文件，不产生新副本、不上传不另存为
4. **原地渲染编辑**：Markdown 实时渲染、HTML 可看可改，圈选段落 AI 翻译/改写直接追加
5. **顺手入库**：处理完的文件一键存进知识库（ima），下次对话直接引用——"用到哪个文件，哪个文件就顺手流进知识库"，用使用行为自然筛选，替代周末大迁移式整理

### 为什么是关键设计
- 不需要决定先开哪个工作区、不需要搬文件、不需要想路径怎么传、不需要担心版本是否最新（因为改的就是原文件）
- 与既有工作流互补而非替代：写代码跑项目仍在终端，文件浏览与办公产物由入口反转的 Agent 接住
- 知识库逻辑与 [[Obsidian]] 的"流动而非迁移"经验同构：过一两个月回头把从没碰过的文件整批归档腾空间
