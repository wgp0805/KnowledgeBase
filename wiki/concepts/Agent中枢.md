## 定义
作者赵晗通过三个纯 AI 项目实践提出的企业 AI 架构范式——**企业 AI 赋能应该就是一个 Agent 中枢**：中枢里有通用能力或工具（用户、基础数据、权限、三方工具），通过 MCP 向所有被授权的 AI 开放（也就是企业内部员工），所有 AI 都可以通过调用底层数据或工具完成自己的业务闭环。

## 中枢架构

### 中枢职责
1. 承载通用能力：用户、基础数据、权限、三方工具
2. 通过 MCP 协议向所有员工 AI 开放这些通用能力
3. 提供发布申请通道：员工 AI 完成业务闭环、测试通过后，通过 MCP 服务向中枢发起服务申请
4. 上线前调用**通用测试 Agent** 跑基础安全性问题（不对业务逻辑和信息做调整）
5. 通过测试即发布上线

### 员工 AI 项目
- 每个员工 AI 发布的项目/服务，可以在企业 Agent 中枢中**开放自己的 MCP 服务**
- 供其他员工的 AI 调用，形成"AI 内循环"
- 业务独立解耦，但业务之间有关系
- 覆盖所有应用体系：网站、小程序、app

### 实践验证的三个项目
1. **居然分期计算器**：2 小时开发上线，AI 自主完成设计/研发/测试，20 分钟修复计算规则反馈
2. **基于 Obsidian 的企业知识库**：AI 基于 Obsidian 做知识库，通过钉钉 dws 授权访问钉钉，进入钉钉群自主回复群内问题（@ 触发），可限定行业范围
3. **居小然 AI 问答**：涉及视频动作、语音转文字大模型，仍在数据验证阶段

## 关键洞察
- **企业基础设施要提供 MCP 接入通道**：允许每个员工发布项目，是"非常好的雏形"
- **通用测试 Agent 是快速发布的守门人**：只跑基础安全，不改业务逻辑——比传统"需求评审-设计出图-开发-测试-验收-发布"链路快得多
- **AI 的行业上限 = 你知识库的上限**：知识库限定行业后，AI 在这个行业内的回答就有了边界
- **AI 提效 ≠ 替代人**：懂技术的人在 AI 层面会更 6，"一个之前是大动脉的人，在 AI 的时代，只会变成一个更大的动脉，而不是需要舍弃"

## 与既有概念的关系
- **B 端 Agent 分层**：Agent 中枢 = 通用能力层 + 员工 Agent 编排层 + 服务发布层，与"FDE B 端 Agent 产品分层"呼应
- **MCP 作为员工 AI 与 Agent 内循环的协议**：与"AI Agent 中枢"呼应
- **通用测试 Agent**：呼应"Agent 产品分层里 LLM 节点 + 确定性下沉"的思想
