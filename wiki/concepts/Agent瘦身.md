## 定义
Agent 瘦身指像电脑定期清理垃圾文件一样，定期诊断并削减 Agent 常驻上下文包袱（规则、记忆、技能、连接器、会话卫生）的运维方法论，目标是恢复响应速度并控制 token/积分消耗。

## 关键信息
1. **核心机制（滚雪球）**：日常不断安装的 Skill 与 MCP 连接器、持续累积的记忆与 Agent 规则像滚雪球一样越滚越大，每次执行任务都全量塞进上下文——"装了不等于免费，常驻即成本"；叠加单会话几十轮甚至上百轮对话的习惯，即使 Agent 会自动压缩，未触发时上下文仍是"爆炸性的存在"
2. **四诊断维度（[[WorkBuddySlim]] 实践）**：规则膨胀、记忆超限、技能与连接器堆积、会话卫生
3. **治理原则**：只诊断不动手＋红黄绿分级＋用户逐项确认→非破坏性瘦身；避免粗暴卸载弄坏承载真实工作流的插件、MCP 与 Skills（与 [[上下文压缩]] "不要粗暴卸载"一致）
4. **治理手段**：关闭不常用技能与连接器（WorkBuddy 官方建议启用工具不超过 80 个，否则可能影响 AI 回复质量）；对 MEMORY.md 等记忆文件做一轮 [[记忆蒸馏]]；会话卫生——别在单窗口堆几十上百轮，阶段完成就收尾换任务（呼应 [[上下文压缩]] "任务不要无限续下去"）
5. **与压缩的关系**：压缩是事后兜底，瘦身是源头减负，二者互补；缓存命中率主要取决于前缀稳定性与任务类型，减包袱与稳前缀（[[前缀缓存稳定布局]]）需双管齐下
6. **成本维度**：不同模型积分倍率与干活风格不同（同一任务 DeepSeek-V4.1-Flash 十几个积分、MiniMax-M3 暴涨十倍），瘦身之外选对低倍率模型同样关键
