## 定义

**计划模式（Plan Mode）** 是 Claude Code 的一种交互模式，在该模式下 Claude 只研究和规划，不写任何代码。用户确认计划后再切换回正常模式执行。这是 Claude Code 官方推荐工作流的核心入口阶段。

## 关键信息

### 进入方式
- 按 `Shift+Tab` 两次进入计划模式
- 也可通过 `--plan` 参数启动 Claude Code 会话
- 权限模式映射：Plan Mode → `plan` 权限级别（所有写操作被阻止，只读模式）

### 官方推荐流程
**探索 → 规划 → 实现 → 提交** 四阶段递进。复杂任务应先在计划模式中梳理清楚需求、架构和实现路径，确认后再动手。

### 与采访流程配合
给出简单需求描述后，让 Claude 用 `AskUserQuestion` 工具采访用户，发现忽略的边缘情况。采访完成后应开新会话执行（采访对话会污染上下文）。

**工具层面的三条设计（源码视角，2026-10-15，详见 [[AskUserQuestion]]）**：
- **Schema 锁死问法**：`questions` 数组最少 1 个最多 4 个，要求把相关问题打包在一次调用里问完；每题必须给 2 个选项并写清名称与方案；有倾向时把推荐项放第一个并标 Recommended；**严禁模型自己生成 Other 选项**（留给用户输入）。
- **复用权限审批挂起循环**：`requiresUserInteraction` 固定 true、`checkPermissions` 固定返回 `ask`，因此即便在跳过全部审批的自动模式下也会被强制拦下；交互处理器创建未决 Promise 放入确认队列，Agent Loop 在 `await` 处挂起，不额外消耗 Token；用户提交后经 `updatedInput.answers` 唤醒，以 `tool_result` 回传。
- **提问前先查事实**：只有[[偏好与取舍]]才值得问，[[DiscoverableFacts]] 必须先调用只读工具查清——"Never ask what you could find out by reading the code"。

无人值守（后台任务/Headless/Sub-agent）时无法提问，需靠工具层拦截 + [[Assumptions假设清单]] 兜底。

### 典型场景
- 架构设计、技术方案讨论
- 大型重构前梳理影响范围
- 多模块并行开发的任务拆分
- 任何"还没想清楚"的复杂任务

### 注意事项
- 计划模式本身不产代码，所有操作均为只读
- 3-5 分钟能完成的小任务不需要进入计划模式，直接用原生 Claude Code
- 复杂工作流（Superpowers、Workflows 等）适用于多文件、多步骤的大任务
