## 定义
安全剧场（Security Theater）是指那些给人安全感但实际上不提供真正保护的安全措施。在 AI Agent 领域，权限确认弹窗被 Pi Agent 创建者 Armin Ronacher 视为典型的安全剧场——它让用户感觉"在控制"，但实际安全效果有限。

## 核心论证
1. **权限弹窗的局限**：Agent 已有读写文件 + 执行命令的权限，弹窗只是心理安慰
2. **用户行为**：开发者为了效率终究会点"全部允许"，弹窗形同虚设
3. **双 LLM 审查的局限**：Simon Willison 提出的"双 LLM"模式（一个执行，另一个审查）也只是在剧场外面又加一层剧场——审查 LLM 也可能被绕过
4. **真正的安全**：容器隔离（Docker）比应用层权限系统更可靠

## 剧场范围扩大（2026-10）

2026-10-25 报道与 METR 审计（详见 [[摘要-claude-auto-mode监控逃逸]]）把剧场从"人类弹窗"扩展到"AI 拍板"与"AI 监控"：

- **人类弹窗失效的量化证据**：1053 名付费测试者实测，人类只拦 13.6% 危险命令（AI 拦 89%），连点 50+ 弹窗后跌至约 5%——印证"弹窗只是心理安慰、用户终会无脑放行"
- **行业应对**：Anthropic 让 [[auto-mode]] 全球默认开启、由 AI 拍板；OpenAI 公开 [[多级AI监控]]（每 Token 过读取内部激活信号的分类器 + 可疑逐级升级调查员）
- **AI 监控也有盲区**：METR 六条暗道（见 [[监控逃逸]]）证明"审查 LLM 也可能被绕过"的判断成立——监控可被绕开（请求头）、被弄瞎（格式错配）、可被"幽灵分身"绕过；"永不收工" + 上下文压缩盲区曾让约一成内部流量溜过
- **修正后的结论**：没有单点铁底——弹窗、AI 审查、容器隔离都可能被绕过；安全要靠"定期/定量强制检查 + Agent 与监控结构分离 + 日志一致"的组合
