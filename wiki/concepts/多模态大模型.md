## 定义
多模态大模型（Multimodal LLM）指能同时处理文本以外的输入模态（图片、扫描件、图表、PDF 等）的大语言模型。相比传统 OCR 的"机械识别"，多模态模型不仅**看懂**图像内容，还能**理解语义、组织结构、执行下游任务**（提取结构化字段、还原流程逻辑、给出业务结论）。

## 核心能力（对生产场景的意义）
| 能力 | 传统方案的痛点 | 多模态模型的优势 |
|------|----------------|-----------------|
| **视觉理解 + 语义提取** | OCR 识别机械、误差大、无字段归属能力 | 一次给出结构化 JSON（如发票 12 字段），一张成本 <1 分钱 |
| **流程/关系图还原** | 需人工口述流程图给 AI，易漏步骤 | 直接 `@图片` 让 AI 抽取步骤、参与方、逻辑链 |
| **多模态输入组合** | 需要多套工具串联（OCR→NLP→规则） | 一次调用完成"看+理解+执行" |

## 生产可用性评估三维度
苏三在 [[摘要-多模态大模型横评-苏三]] 提出的评估标准，通用于任何多模态模型落地评审：

1. **质量**：一次对话能否给出可直接使用的结果，是否需要反复追问 / 人工兜底。
2. **速度**：端到端返回是否足够快，能否嵌入 Agent 高频调用循环。
3. **成本**：Token 单价 × 消耗量，以及**返工带来的隐性人工成本**。

**评估纪律**：只保留"模型"这一个变量，其余（提示词、输入图片、参数、工具）全部对齐；不看公开跑分榜，而是拿**真实业务样本**跑一轮。

## 国内主流玩家（2026-07 视角）
- [[Step3Flash]] — 阶跃星辰 Step 3.7 Flash，两场景横评综合最优（速度快、Token 省、稳定性优）
- [[MiniMax]] — MiniMax M3，长上下文（1M/512K）优势，逻辑严谨但 Token 消耗较大
- [[Qwen]] — 阿里通义千问 3.6-flash，稳定但速度和 Token 消耗中等

## 典型生产场景
- **Agent 内使用**：截图/流程图/架构图 → 方案还原 → 编码计划（如 Claude Code 里 `@图片`）
- **业务 API 使用**：发票/票据/合同/身份证 → 结构化字段抽取 → 系统自动录入，替代传统 OCR
- **图表/报表理解**：财报表格 → 关键数据点问答（对比 [[摘要-国产大模型实战横评]] 的英伟达年报 PDF 场景）

## 常见陷阱
- **一模型覆盖所有场景不现实**：即便综合胜出的模型，也要用**自家业务样本**再验证一轮才能上生产。
- **只看跑分不看真实任务**：公开榜单亮眼的模型在具体任务里可能歇菜。
- **忽略隐性成本**：Token 单价便宜但需要人工重跑校正的模型，实际总成本反而更高。
