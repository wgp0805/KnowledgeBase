## 定义
Agent 客户端把推理预算开放为用户可选档位的产品机制：用户在选模型之外显式调节思考档位，在质量、速度、Token 成本之间做权衡。

## 关键信息
- **实例**：[[KimiCode]] 为 [[K3.1Pro]] 提供思考强度三档 **Low / High / Max**（2026-10-24 首测实测选 High）；ChatGPT [[Codex]] 侧对应「推理强度」档位（实测选「高」）——两边构成对等评测口径
- **效果观察**：思考强度 High 下 K3.1 Pro 表现为「先规划后动手」——任务开始先花 16 秒规划再写文件，宁可慢 3~5 倍也要先自测再交付（详见 [[Agent交付前自测]]）
- **既有结论一致**：与 [[提示词工程]] 中「提高思考强度：推理强度拉满很多问题迎刃而解，但 Token 消耗更多」的判断一致
- **反向档位**：高速取向是低思考、快交付——[[K2.7]] Code Highspeed（快但粗糙）、客户端 Highspeed 提速选项（首测建议预算敏感者选用）
- **取舍规律**：高强度思考 + 交付前自测 ≈ 慢 3~5 倍但零返工；赶时间出活则选低档位/高速模型

### 隐藏的 ultra 第六档（2026-10-27，详见 [[摘要-gpt6.1-terra-codex三招]]）

- **公开 API 只有 none~max 五档**，但 Codex 内部给 [[GPT-6.1-Terra]]/[[Astra]]/Sol 加了**隐藏第六档 `ultra`**
- 切到 ultra 时：主模型推理强度映射到 `xhigh`，同时调用 `spawn_agent` 派生多个并行 Sub-agent
- 配套 `fork_turns` 控制上下文继承：修小函数传 `none` 零负担启动，复杂模块改造传 `all` 继承完整上下文
- 定位：最高强度 + 自动任务委派，见 [[子Agent编排]]
