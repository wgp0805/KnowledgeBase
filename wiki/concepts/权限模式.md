## 定义

权限模式（Permission Mode）是 AI Agent 的安全配置维度，决定 **Agent 动手之前要不要先问用户**：有的模式每一步都问，有的只问危险动作，有的不弹窗直接拒绝，有的全部放行。弹窗只是权限模式的一种结果，而非其全部。与之互补的另一个安全维度是**沙箱**——权限模式决定"问不问人"，沙箱决定"执行的命令能读写哪些文件、能不能联网"。

## 关键信息

### 各产品的权限模式谱系
| 产品 | 模式 |
|------|------|
| [[ClaudeCode]] | 六种（用户视角）：Manual / acceptEdits / plan / auto / dontAsk / bypassPermissions；源码视角归为 7 级（含子 Agent 的 bubble） |
| [[DeepSeekHarness]] | 三种：仅查看 / 工作区内修改 / 完全权限 |
| [[Pi]] | 无内置权限系统：不限制文件/进程/网络/凭证访问，官方主张真正的边界是资源隔离（容器/VM/沙箱），审批需求自行写扩展（permission-gate.ts） |
| [[WorkBuddy]] | 默认权限（敏感操作确认）/ 完全访问（减少弹窗） |

### Claude Code 的 auto 分类器机制（2.1.210+）
- 由独立分类器（默认跑在 Sonnet 5，不随 /model 变化）后台审查每个动作：读取文件和工作目录内编辑直接放行，其余送审
- 分类器输入：用户消息 + Claude 发起的工具调用 + CLAUDE.md；**剔除工具结果**（防网页/文件藏恶意指令操纵分类器）与 **Claude 自己的输出**（防说服分类器给自己放行）
- 审查分两级：先输出一个 token 快速判断放行/可疑，可疑动作再用思维链仔细复核
- 用户授权可放开部分拦截：明确说"强制 push 这个分支"才算授权，只说"清理一下仓库"不算
- 降级机制：连续拦截 3 次或累计 20 次，auto 暂停退回人工弹窗
- 官方数据：正常操作误拦率 0.4%，越权动作放行率 17%（Anthropic 自称 "the honest number"）

### 规则体系：allow / ask / deny
- 权限规则分三种：直接放行（allow）、先问（ask）、直接拒绝（deny）
- 判定顺序：**先 deny → 再 ask → 后 allow**，第一个命中的规则说了算
- **deny 在任何模式下都生效**，包括 bypassPermissions；任一配置文件（全局/团队项目/本地）写了 deny，其他文件的 allow 都放不开
- 对根目录等关键路径执行 rm，任何模式都不会自动放行
- 命令真正跑起来后规则管不到（如无害命令里跑脚本读 SSH 私钥外发），必须靠操作系统沙箱限制文件与网络

### 实用建议
- 日常使用推荐 auto 模式；绝不能读写的文件与不能执行的命令写进 deny 规则
- 全部放行模式（bypassPermissions）官方只建议在容器或虚拟机里用；Linux/macOS 下用 root 运行会直接拒绝启动
- 沙箱之外的真实边界观（Pi 立场）：盯着对话记录、事后审查改动都算不上安全边界，真正的边界是限制 Agent 能访问和影响的资源
