## 定义

服务器入侵应急响应指服务器被攻破后的排查与处置流程：确认现象与入口 → 遏制（收紧访问面）→ 取证定位痕迹 → 清除持久化与后门 → 还原被篡改的系统 → 加固与监控。核心难点是攻击者往往已替换基础命令、给文件加锁并注入隐藏进程的后门。

## 关键信息

### 常见入侵入口
- SSH 密码过于简单（境外 IP 不到 500 次尝试即破解 root 的实例）
- 云安全组放行范围过大（SSH 对全网开放）
- 面板类（宝塔等）弱口令

### 攻击者的典型驻留手段
1. **替换系统命令**：`ps`、`top`、`chattr`、`lsattr` 被换成恶意版本，并用 `chattr +ia` 锁定文件**和所在目录**（如 `/usr/bin/`），导致无法删除或覆盖
2. **隐藏定时任务**：`crontab -l` 与 `cat /etc/cron.d/*` 看起来是空的（文件被写成 data 类型或含特殊字符），但 `/var/log/cron` 每 5 分钟仍在执行 `/sbin/httpss`、`/usr/lib/mysql/mysql` 之类的任务
3. **开机启动项**：`/etc/rc.local` 追加指向不存在文件的执行行
4. **LD_PRELOAD 预加载后门**：循环脚本持续把 `/usr/local/lib/libprocesshider.so` 写入 `/etc/ld.so.preload`（并 `lockr/chattr +ai` 锁定），动态链接器会以高于 `LD_LIBRARY_PATH` 的优先级加载它，从而对 `ps` 等工具隐藏恶意进程
5. **清场脚本**：`while true` 循环 `killall/pkill` 大量竞争挖矿进程与杀毒扫描（masscan、clamscan 等），并 `rm -rf` 痕迹目录

### 标准处置步骤
1. **遏制**：安全组限制 SSH 只放行自己 IP；修改 root 密码；备份并清空 `/root/.ssh/authorized_keys`；可关闭外网（安全组/路由/NAT）
2. **取证**：`last` 或 `grep 'Accepted' /var/log/secure` 找异常登录来源；`cat /etc/passwd` 找新增用户并 `usermod -L` 锁定；检查 `/root/.ssh/authorized_keys`
3. **验证命令是否被篡改**：先从同版本机器拷贝 `chattr`、`lsattr` 到 `/tmp`，执行 `/tmp/chattr -ai /usr/bin/chattr` 与 `/tmp/chattr -ai /usr/bin/` 解锁后还原，再依次还原 `top`、`ps`
4. **清持久化**：检查 `/var/spool/cron/`、`/etc/crontab`、`/etc/cron.d/`、`/etc/rc.local`、`/var/log/cron`；清空被篡改的 `/etc/ld.so.preload` 并删除其引用的 `.so`（注意必须先 kill 掉循环改写它的进程/脚本，否则清了还会回来）
5. **定位异常进程**：`netstat` 看异常连接反查进程；找不到就看异常进程与其对应脚本，kill 进程并删脚本

### 加固清单（入侵后启示）
- 关键文件 MD5 监控：`/etc/passwd`、`/etc/shadow`、`/etc/group`、`/root/.bash_history`、`/root/.ssh/authorized_keys`、`/etc/ssh/sshd_config`、`/etc/profile`、`/var/spool/cron/root`、`/etc/crontab`、`/etc/ld.so.preload`、`/etc/rc.local`
- 关键命令监控：`lsof`、`ps`、`netstat`、`top`、`ls`、`pstree`、`last`、`history`、`sudo`、`password`、`chattr`、`lsattr`
- 密码复杂化 + 安全组最小放行是第一道防线
