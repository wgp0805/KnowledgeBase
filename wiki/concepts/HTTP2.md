## 定义
HTTP/2 是 HTTP 协议的第二版，与 HTTP/1.1 有本质区别。最核心能力是多路复用——在一个 TCP 连接上同时处理成百上千个请求，互不阻塞。gRPC 跑在 HTTP/2 上，是其高性能的基础之一。

## 关键信息
- **与 HTTP/1.1 对比**：
  | 特性 | HTTP/1.1 | HTTP/2 |
  | --- | --- | --- |
  | 连接模型 | 每个请求一个连接 | 一个连接多路复用 |
  | 连接建立 | 3 次握手/请求 | 1 次握手/会话 |
  | 数据传输 | 文本 | 二进制帧 |
  | 并发请求 | 串行/有限并行 | 真正的并行 |
  | 服务端推送 | ❌ | ✅ |
- **多路复用**：一个 TCP 连接同时处理成百上千请求，互不阻塞
- **连接建立**：1RTT（HTTP/1.1 需 3RTT），「一次握手，多次使用」
- **二进制帧**：数据传输格式，比文本更高效
- **服务端推送**：支持
- **高并发优势**：避免频繁建立连接的开销，吞吐量优势明显
- **服务端推送现状（2026-10 注记，详见 [[摘要-tomcat-11-new-features]]）**：Server Push 已被 Chrome 等主流浏览器淘汰；Servlet 6.1 将其降级为可选功能，Tomcat 11 已移除实现；业界改用 `<link rel="preload">` 预加载替代。上表与上一条的 ✅ 仅描述协议能力，实际生态已不再使用。
