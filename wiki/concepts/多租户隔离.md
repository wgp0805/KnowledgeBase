## 定义
多租户隔离是 AgentScope Java 2.0 的核心安全能力，通过 RuntimeContext 穿透和统一文件系统抽象，实现全链路的强制隔离，解决多用户共用一套环境时数据互相泄露、文件被篡改的问题。

## 关键信息
- **核心机制**：
  - RuntimeContext 穿透 — userId 和 sessionId 沿着工作区路径、存储命名空间和沙箱状态槽一路传下去，参与每一次资源寻址
  - 统一文件系统抽象 — 所有文件操作被收敛到一层统一的 AbstractFilesystem 上，每次调用都自动带上当前会话与用户的身份信息
- **隔离粒度**（按业务语义选择）：
  - 每段对话各跑各的 — 完全隔离
  - 同一用户的多次会话共享工作区 — 用户级共享
  - 公共工具型智能体全员共享 — 全局共享
- **优势** — 不依赖业务代码自觉，框架层强制约束数据隔离
- **部署一致性** — 本地磁盘、容器沙箱、远端存储三类后端共用同一套上层语义，开发→测试→生产的三段部署路径不需要改代码

### 通用多租户隔离的四条纵深（2026-10-20，详见 [[摘要-jd-codex辞职信-agent面试题]]）
来自"派聪明"与 PaiCLI 的实战面试题解答，与 AgentScope 的框架层隔离互为补充：

1. **知识库数据隔离**：MySQL 分块向量表唯一键设 `(file_md5, user_id, chunk_id)`，ES 文档 ID 拼 `fileMd5_userId_chunkId`，MinIO 分片路径带 `chunks/{userId}/...`——解决不同用户上传同一份 PDF（MD5 相同）导致索引互相覆盖删除的问题
2. **检索时权限前置**：Redis 读当前用户有效组织标签，把权限条件注入 ES BM25 布尔过滤器与 2048 维向量 KNN 的 **pre-filter**（三选一：用户私有 / 标记公开 / 组织标签命中），召回候选阶段就只扫有权文档，杜绝"先召回再过滤把结果置空或跨租户串联"
3. **模型资源隔离**：租户级配额（账户表独立 LLM/Embedding Token 余额，超限抛异常跳过重试）+ Redis Lua 原子令牌桶限频 + 按调用范围/供应商建 Resilience4j 并发与熔断；QPS 令牌桶分在线/后台优先级，后台请求必须给在线留 30% 余量（`onlineReserveRatio=0.3`），企业级再按租户等级挂并发信号量与加权公平队列
4. **沙箱分级**：单机/内部受信用轻量进程沙箱（路径守卫拦软链接逃逸、启动前剥离 `*_API_KEY`/`*_SECRET`/`*_PASSWORD` 只留白名单、macOS Seatbelt / Linux bubblewrap 只读根文件系统 + 断外网）；**多租户云端必须**按会话/租户分配 Firecracker MicroVM 或 Kata Containers（独立内核与网卡），cgroup 划 CPU/内存/进程数/块设备 IOPS，网络出口经 eBPF 白名单代理，阻断横向探测与宿主机元数据访问
