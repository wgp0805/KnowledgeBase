## 定义
Agent 快慢分工是正在成为共识的 Agent 架构模式：**昂贵的大模型负责规划、推理、生成这类"慢思考"，高频、原子化的分类、选择、评分这类"快判断"交给 [[Jev]] 这类轻量决策模型**，确定性逻辑交给普通代码。生成负责表达，判断负责分流，代码负责执行。

## 关键信息

### 四层架构分工
| 层次 | 职责 | 典型组件 |
| --- | --- | --- |
| **慢思考层** | 规划、解释、生成、复杂推理 | GPT / Claude / Gemini |
| **快判断层** | 路由、筛选、评分、门禁 | Jev / Jev-like 模型 |
| **确定性层** | 权限、状态、副作用、回滚 | 普通代码 |
| **兜底层** | 高风险或低置信度处理 | 人工 / 更强模型 |

### 定位
- Jev 最适合的位置**不是 Agent 的大脑，而是 Agent 的反射神经**
- 它不是"更便宜的 GPT"：不适合写文章、解释复杂代码、做长链路规划；只适合输出空间固定、调用频率高、又需要语义理解的小判断
- 三个变化：效率变化（不再为每个小判断启动一次完整生成链路）、能力变化（路由/筛选/评分/门禁可以沉淀成统一接口）、模式变化（Agent 从"全靠大模型思考"变成"生成、判断、执行分层协作"）

### 与人类公司的类比
之前的 AI 模型不管多强，它都在**输出内容**——内容是给人看的，人看完自己做决策，这个过程中 AI 是秘书、你是老板，秘书给的材料越多你做决策的成本就越高。Jev 不一样：它不是秘书，它是那个**替你拍板的人**，或者说是一个决策引擎。它不给你看材料，它直接告诉你结果，而且结果是带概率的。置信度低时人工介入，置信度高时直接自动化——这一下把人类从无限的**决策疲劳**里解放出来了。

### 生产场景的克制
生产场景下 Agent 的实际使用场景其实不多，更关心**稳定、成本和可控性**。业务不需要的自主性，没必要为了追求架构先进硬加上去。真遇到处理路径无法提前确定的任务，再引入有边界的 Agent 也完全来得及。这与 [[确定性下沉]]/[[不确定性上浮]] 的分层理念同源。
