# CMS（内容管理系统）

## 核心定义
管理数字内容的软件系统。给内容建立结构和身份，管理内容从创建、修改、审核、发布到数据回流的全过程。CMS 是一类软件系统，产品方法和技术框架都是实现手段。

## AI 时代的变化
AI 改变了内容生产规模和参与角色。原来系统主要接住人工编辑内容，现在还要接住 Agent 任务、批量候选、模型与 Prompt 版本、人工接管、自动检查和多轮返工。生成变快后，内容能不能被管理、审核、组装和追溯，比"能不能生成"更早成为问题。

## 六个核心问题
1. 系统管理什么内容
2. 内容现在进行到哪一步
3. 谁可以对它做什么
4. 它为什么成为现在这一版
5. 它怎样交付给用户
6. 上线结果又怎样回到下一轮生产

## 六大核心对象
- **知识点**：Agent 出题和人工审核的上游标准
- **题目**：有题型、答案、解析、素材、审核和发布生命周期
- **标签**：用于展示筛选，也约束生成和批量操作
- **生成批次**：保存一次 Agent 任务的参数、版本和结果集合
- **审核记录**：保存质量判断与修改责任
- **发布版本**：线上系统实际调用、可替换和回滚的冻结快照

## 判断独立对象的标准
- 有无独立生命周期
- 是否被多处引用
- 能否独立审核或复用
- 变化后是否影响其他内容

## 状态链
候选 → 草稿 → 待审核 → 退回修改 → 审核通过 → 已发布 → 已下架 → 已归档

## MVP 原则
- 先切一条垂直链，不要每个模块各做 20%
- 推荐起点：知识点 → Agent 出题 → 自动校验 → 人工审核 → 发布 → 追溯
- 用真实内容验收：跑通正常路径与异常路径
