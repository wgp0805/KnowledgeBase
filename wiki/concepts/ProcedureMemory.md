## 定义
Procedure Memory（过程记忆）是从历史开发轨迹中**自动提取可复用的分析、执行、验证步骤**，提炼成结构化工程经验供后续同类任务直接复用的记忆形态——对应认知科学三分法（[[Agent记忆三型]]）中的"程序记忆"（应该怎么做），由 MemoraX Code 在 Coding Agent 场景落地（[[MemoraXCode]]）。

## 关键信息
- **与事件记录的区别**：不是简单记录"上次发生了什么"（那是情景记忆），而是总结出"**遇到这类工程问题，哪些分析路径、操作步骤、验证手段是有效的**"——经验被抽象到可迁移的粒度
- **提取方式**：系统自动从历史任务片段提炼（官方数据：123 个历史任务片段 → 15 条工程经验 → 归纳为 4 类 Procedure Memory），无需人工编写规则
- **效果数据（3 小时复杂长程开发任务对比）**：
  | 配置 | 综合得分 | 关键检查项 | 调用成本 |
  |---|---|---|---|
  | 不开记忆 | 11.71 | 2/13 | 基准 |
  | 开 Procedure Memory | 70.30 | 10/13 | 降约 22.6% |
- **生效原理**：没有记忆时 Agent 大量 token 花在重复摸索已经踩过的坑上；有经验沉淀后它依然要理解需求写代码，但不用从零重新试错——省的是试错 token，不是理解成本
- **克制性前提**：记忆不是越多越好，乱召回过时经验反而添乱——配套的触发判断（该不该此时想起）比存储本身更关键（MemoraX 数据：85.5% 触发与人的判断一致）
- **概念定位**：与 [[Agent记忆三型]] 中程序记忆对应；与 [[记忆蒸馏]]（把累积记忆蒸馏压缩）是相邻但不同的动作——过程记忆在"提取什么值得沉淀"，蒸馏在"沉淀太多时怎么瘦身"
