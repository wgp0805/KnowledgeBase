## 定义
Lowcode（低代码）是一种以**配置和可视化代替硬编码**的软件开发范式：开发者通过声明式配置（如 JSON Schema）或图形化界面描述业务需求，由运行时或生成器自动渲染/产出应用功能，从而把重复性开发工作压缩为配置工作。与"零代码（No-code）"的边界在于：Lowcode 通常保留自定义代码扩展能力，面向专业开发者提效，而非完全取代编码。

## 关键信息

### 典型形态（以 [[DripTable]] 为例）
- **Schema 驱动**：用 JSON Schema 声明列表的列（key/title/dataIndex/component/options），运行时自动渲染成动态列表——同一份 Schema 可以在配置端可视化编辑、在应用端渲染
- **配置端 / 应用端分离**：配置端负责生成符合标准的配置数据（可视化拖拽 + low-code 微调），应用端只负责按配置渲染——两端通过 Schema 标准解耦
- **扩展点保留**：支持自定义组件开发（通过 API 生成自定义单元格组件）、自定义主题包——复杂业务不被配置能力天花板锁死

### 适用边界
- **适合**：中后台 CMS 这类模式高度重复的页面（列表页、表单页），可用配置批量生成
- **不适合**：交互复杂、性能敏感、需要精细控制的核心业务逻辑

### 与相关范式的关系
- 相比**手写组件**：牺牲部分灵活性换取交付速度，把"改一个字段"从改代码变成改配置
- 相比 **No-code**：保留代码逃生舱，面向研发团队而非纯业务人员
