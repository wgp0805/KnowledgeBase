## 定义
异构索引（Heterogeneous Index）是一种将存储层与查询层分离的架构模式。核心思路是使用 Elasticsearch、HBase 等专门处理复杂查询的中间件作为查询索引层，主库（MySQL/分库分表）只负责写入和事务，两者数据结构可以异构（不同 schema、不同存储引擎）。本质上是 CQRS（读写分离）思想的落地实践。

## 关键信息

### 典型链路
```
写入路径：业务 → MySQL 分库分表 → Canal 监听 binlog → Kafka → Elasticsearch
查询路径：分页查询 → ES（条件过滤 + 排序 + 分页）→ 拿到主键 ID → 回 MySQL 批量取详情
```

### 组件职责
- **MySQL 分库分表**：承载写入与事务，不承担复杂查询
- **Canal**：监听 binlog 变更，实时捕捉数据变化
- **Kafka**：消息缓冲，解耦生产与消费速率
- **Elasticsearch**：负责复杂的条件过滤、排序、分页、模糊搜索

### 核心优势
- 性能优秀，深翻页也能秒级返回
- 支持任意复杂查询条件（多字段组合、模糊搜索）
- 主库压力小，写性能不受查询复杂度影响
- 解耦清晰：ES 管查询，MySQL 管存储，各司其职

### 缺点与风险
- 架构复杂度急剧上升，需维护 Canal + MQ + ES 一整套链路
- **数据延迟**：从 MySQL 到 ES 通常有秒级延迟，强一致性场景要慎用
- 成本高，ES 集群本身就要不少机器资源
- 适用于复杂查询和深翻页频繁的场景

### 生产实践
- 美团、饿了么、有赞等公司都采用此方案
- C 端：游标分页（简单高效）
- B 端 / 复杂查询：ES 异构索引
