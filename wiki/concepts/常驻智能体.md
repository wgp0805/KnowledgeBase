## 定义
常驻智能体（Always-on Agents）：拥有独立云端计算环境、7×24 小时在后台主动运行的自主智能体。与"输入 Prompt、输出一段字"的被动答题器不同，它自带云电脑与浏览器，无人发消息时也在巡检、调研、起草方案，把 AI 从"等指令的问答框"变成"赛博打工人"。

## 关键信息
- **代表产品**：OpenAI [[Dots]]（每个 Dot 独立云电脑 + Proactive Research 后台只读巡检 4000+ 应用）；[[MetaMuse]]（每用户隔离 Secure VM + 后台任务）；[[Instinct]]（云端电脑 + 主动推进长期目标）；腾讯 LightVela（云端专属 Agent 实例 7×24 在线）
- **五大能力要素**：自带专属独立云电脑/沙箱；全渠道常驻（网页、桌面、手机、Slack/Teams、语音通话）；主动后台巡检（Proactive Research）；分级安全与审批沙箱（后台只读、敏感操作人工审核）；面向组织的专职数字员工（如 Specialist Dots）
- **算力后果**：主动式 Agent 拥有自己的作息生命周期，可在全天任意时间静默"苏醒"处理任务，90% 以上工作负载与 Token 吞吐发生在人眼看不见的后台——算力需求比被动式 AI 高两到三个数量级
- **成本支撑**：常驻运行必须依赖低推理成本（批处理异步任务、GPT-6.1 Sol 缓存输入降至 0.10 美元/百万 Token、flash 档位模型）才可能成立，参见 [[Agent边际成本]]
- **安全设计共识**：后台主动工作时默认只读，不能擅自发消息/改资产；不可逆动作必须触发人工审核——与 [[Agent主动性]] 的"自主行动区/必须询问区"框架一致
- **打工逻辑之变**：开发者与普通打工人面对的分水岭——套壳问答工具的窗口期基本闭合，能把垂直业务痛点拆成长链路 Agent、善用极低缓存成本搭自动化流水线的人迎来红利

### 工程实现解剖（2026-10-21，Lee Robinson 在斯坦福 CS146S 的分享，详见 [[摘要-always-on-agent-斯坦福分享]]）

从「模型 + 工具 + 循环」的最小 harness 扩展为常驻 agent，需要解决四组工程问题：

**1. 存在方式：睡眠与唤醒**
- 服务器和 agent 能用的那台电脑**平时都是睡着的**，被消息或触发器叫醒才加载 agent 全部状态启动；需要浏览器或点屏幕时才启动那台电脑，用完再睡回去
- 原因很现实：**让每个人的电脑一直开着，既贵，世界上也没有那么多计算机**
- 状态保存在数据库里，包括对话记录、记忆、例行任务
- 唤醒来源多样：用户消息、Slack 消息、电话/会议、跑了几小时的后台任务要总结

**2. 打扰启发式**
所有事件先进 **router** 去重，再放进对话，同时有一套启发式规则判断「这件事需不需要打扰用户」。比喻很直白：**同事每有一点进展就来找你说「快看，我有进展了」，你肯定烦，大多数任务一天一次状态更新就够了。**

**3. 可靠性底座：durable workflow**
普通任务队列崩溃后要重放一到三步会出很多问题；**durable workflow 可安全重试，失败后直接从第三步接着做**（见 [[DurableWorkflow]]）。每个子智能体本身也是一个 durable workflow。

**4. 上下文与成本**
- **动态工具发现**：每条消息只放工具名字，模型决定要用哪个再去文件读详细定义（见 [[动态工具发现]]）
- **能力阶梯**：先试最便宜最可靠的办法，一级级往上爬，全失败才打扰用户（见 [[能力阶梯]]）
- **prompt caching**：工具定义与系统提示保持不变以命中缓存——**「缓存没命中，其实就是系统里的一个 bug」**；NVIDIA 实测多轮编码 Agent 流量下缓存命中率可达 85%~97%、首字延迟降低约 5 倍
- **记忆分层**：核心事实 / 按日期的对话日志 / 半小时级草稿 / 其余放文件按需查

**架构取向**：thin client / thick server——客户端与服务器之间**只有一个工具 `send to user`**，重活全在服务端（见 [[ThinClientThickServer]]）；承载那台电脑的是 [[Firecracker]] 虚拟机，可快照、可重建、带虚拟桌面。

**产品哲学**：Lee 团队的原则是 "delete the product"——认定今天的模型是它们这辈子最差的时候，六个月后可能要把界面整个重做。**能保留的是你对问题的理解和评测体系，其余的随时准备推倒。**
