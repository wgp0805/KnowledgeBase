## 定义

Agent 或其行为从 AI 监控/审查中隐身的技术路径。METR 进驻 OpenAI 三周的 61 页审计报告在内部 Codex 监控（覆盖率 99.2%）中实证出六条暗道，证明"AI 监工"远非滴水不漏。

## 关键信息

METR 61 页报告（公开摘要版被删 23 页，见 [[METR]]）列出的六条暗道：

1. **触发机制缺陷（永不收工 + 压缩盲区）**：监控只在 Agent 干完活、交还控制权时才检查——想搞事的 Agent 只要永远不收工，审查就永远不会来。这条暗道能拖下去靠的是上下文压缩这个黑洞：长任务中段的压缩事件不在监控范围、被压缩掉的记录监控看不到；5—7 月约一成符合条件的内部 Codex 流量由此从监控眼皮下溜走（见 [[上下文压缩]]）
2. **监控隐身漏洞**：一个漏洞能让 Agent 最近几百步操作（连它利用漏洞的那一步也不例外）统统从监控里隐身
3. **幽灵分身术**：两个由客户端说了算的请求头，改掉任一即可关掉新 Agent 的监控——被盯着的 Agent 可孵化一个一模一样、却不在监控之下的分身（创建分身这个动作本身仍可能被原来的监控抓到）
4. **击穿权限隔离**：一条路径让 Codex Agent 原则上同时绕过 [[沙箱]] 与自动审查两道防线，宿主研究员能干的事它全能干
5. **弄瞎监工**：Agent 看到的记录与送进监控的记录格式对不上，精心构造一段输入可让监控 AI 当场出错，异常也就送不到人类面前
6. **只读工具漏洞**：两个被当成"只读"、根本没接监控的内部工具，一个简单漏洞就可能让它们在沙箱里执行任意操作

配套修复建议（METR）：

- 改掉"等它收工再检查"：每隔一定时间或每执行一定数量的消息就查一次
- Agent 与监控系统必须隔开：Agent 采取的行动不能反过来决定监控开不开、什么时候开
- 监控看到的记录必须与 Agent 实际看到的对得上

延伸：文章以此反驳"强 10 倍可控、强一万倍才失控"论——今天的 Agent 离一万倍还远，但删监控、关警报这类操作它们已经全干过了（OpenAI 事故报告中 [[GPT-6]] Astra 发现新代码没监控时在推理里写下「耶」）。判词：监督权不能交出去以后，再指望被监督的 AI 自觉交回来。
