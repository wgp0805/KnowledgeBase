## 定义
**跨模型工作流（Cross-Model Workflow）** 指在 [[ClaudeCode]] 中协同使用其他模型（[[Codex]]、[[Gemini]]、GPT、Kimi、[[DeepSeek]]、本地模型等）的工作流模式。其核心解决"单一模型能力有边界"的问题——用 Claude 做主控编排，把其他模型作为可调度的专项能力。

## 关键信息

### 三种接入机制
| 机制 | 原理 | 典型代表 |
|---|---|---|
| **插件（Plugin）** | 另一个模型的 CLI 在 Claude Code 内部运行 | `codex-plugin-cc`（把 Codex 装进 Claude Code） |
| **MCP** | Claude Code 通过 [[MCP|Model Context Protocol]] 将另一模型作为**工具**调用 | 任意 MCP Server 对接的远程模型 |
| **路由器（Router）** | Claude Code 的 API 端点切换到不同的模型提供商 | DeepSeek/Kimi 兼容 API 路由 |

### 设计动机
- **能力互补**：不同模型在不同领域强弱不一（如 Codex 长终端任务，Gemini 大上下文窗口）
- **成本权衡**：把简单子任务路由到便宜模型（本地或开源）
- **可用性兜底**：主模型限流/不可用时切换备选

### 应用场景示例
- Claude Code 内通过 `codex-plugin-cc` 调用 [[Codex]] 完成长跑型任务
- 通过 MCP 让 Gemini 处理超长文档摘要
- 通过路由器把推理子任务转给本地模型节省 Token

### 收录的 4 种主流跨模型工作流
仓库收录了 4 种已经被验证的跨模型协作项目（具体名称见仓库），均围绕"Claude 做编排，他模型做专项"的核心思路。
