# Codex 操作手册 — 从入门到精通

## 一、Codex 是什么？

[[Codex]] 是 **OpenAI 官方出品的桌面端 AI Agent**，它不是简单的"聊天窗口"，而是能理解项目、操作文件系统、运行命令行、调用浏览器、连接外部服务的"AI 干活系统"。

**核心定位**：从编程 Agent 进化为[[把Codex用到极致|电脑工作系统]]（Computer Work System），三大支柱：
- **长线程（durable threads）**：持久上下文，工作不必每次重来
- **工具接入**：浏览器/Chrome/Computer Use/MCP/Skills 扩展操作范围
- **验证器（validators）**：长任务有可度量的完成标准

## 二、安装与配置

### 前置条件
- **Node.js**（最新 LTS 版本）
- **Git**（版本管理）
- 一个 **OpenAI / ChatGPT 订阅账号**

### 下载方式
- **App 桌面版**：OpenAI 官网下载桌面客户端（推荐，GUI 友好）
- **CLI 命令行**：通过 npm 安装 `npm install -g @openai/codex`
- **Web 版**：浏览器直接访问
- **IDE 插件**：JetBrains / VS Code 插件市场搜索 Codex

**最新版本参考**：Codex App 26.415、Codex CLI 0.128.0，基于 GPT-5.5 模型

## 三、四大运行模式

| 模式 | 适合场景 | 特点 |
|------|---------|------|
| **App 桌面版** | 日常开发、GUI 操作 | 最完整的体验，支持插件、MCP、自动化面板 |
| **CLI 命令行** | 终端重度用户、自动化脚本 | 轻量、可集成到 CI/CD 管道 |
| **Web 版** | 快速实验、不在自己电脑上 | 无需安装，功能受限 |
| **IDE 插件** | 在 IDE 内直接使用 | 嵌入编辑器，适合小范围修改 |

**推荐新手从 App 桌面版开始**。

## 四、核心使用方法 — 三步入门

### 第 1 步：创建项目工作空间
把相关文件、资料、截图放同一工作空间。**项目边界越清楚，Codex 越不容易跑偏**。

```
my-project/
├── src/          # 源代码
├── docs/         # 需求文档、设计文档
├── screenshots/  # 界面截图
└── AGENTS.md     # 项目说明书（最关键！）
```

### 第 2 步：写 AGENTS.md（项目说明书）

这是 **Codex 的"宪法"**，告诉它项目的规矩。只放三类内容：

```markdown
# 项目约定

## 构建/测试命令
- 构建：mvn clean install
- 测试：mvn test
- 启动：mvn spring-boot:run

## 编码规范
- 包名使用小写，类名使用 PascalCase
- Controller 层只做参数校验，不写业务逻辑
- 所有异常使用统一的 Result 包装

## 红线规则（禁止/Never）
- 禁止修改 pom.xml 中的依赖版本
- 禁止直接操作数据库，必须通过 Service 层

## 代码定位策略
- 用户相关代码在 com.example.user 包下
- 订单相关代码在 com.example.order 包下
```

> **AGENTS.md 控制在 200 行以内**，踩坑后动态更新，不要一次性写完。

### 第 3 步：使用计划模式

任务超过两三步，**必须先开[[计划模式]]**。在对话中告诉 Codex：

```
请用计划模式分析这个需求，输出：
1. 需要理解什么
2. 影响哪些模块
3. 分几步实现
4. 每一步怎么验证
5. 哪里容易出错
```

确认计划后再执行，**审计划比推翻重来高效得多**。

## 七、高效工作流方法论

### 7 步工作流（推荐）

[[摘要-再见吧-codex]] 提出的核心方法论——**别把 Codex 当许愿池**：

```
1. 阅读理解 → 2. 写计划 → 3. 确认范围 → 4. 小步实现 → 5. 验证 → 6. 总结 → 7. 新会话
```

**细节**：
1. **阅读理解**：先让 Codex 阅读项目结构、架构、启动/测试/部署方式
2. **写计划**：复杂任务先让 Codex 输出实现计划
3. **确认范围**：确认要改哪些文件、影响范围
4. **小步实现**：只改当前步骤需要的文件，不顺手改无关代码
5. **验证**：执行测试，认真看 diff，不只是 happy path
6. **总结**：让 Codex 总结改了什么、为什么改、验证了什么、需要人工确认什么
7. **新会话**：把总结带入新对话，避免旧假设污染

### 9 条最佳实践

[[摘要-AI-agent工具应该怎么使用]] 总结：

1. ✅ **先建 AGENTS.md** — 进入项目先 /init
2. ✅ **Plan 模式先行** — 先出执行计划再写代码
3. ✅ **大需求拆小任务** — 每个原子功能独立对话
4. ✅ **测试是质量保障** — 用另一个 Agent 交叉验证
5. ❌ **不要手动改 AI 代码** — 手动改会导致 AI 覆盖你的改动
6. ✅ **多模型协作** — Codex 写代码 + Claude Code 审查
7. ✅ **Prompt 要精确** — 结构：背景+目标+约束+验收标准
8. ✅ **用官方模型** — 中转站有模型偷换、限流问题
9. ✅ **架构由你，实现交给 AI** — 你负责边界，AI 负责填充

### "收工了"总结模板

每次结束回答 5 个问题：
- 改了哪些文件？
- 每个文件为什么改？
- 改完后做了什么验证？
- 哪些验证没覆盖？
- 哪些地方需要人工确认？

结论写入 AGENTS.md。

## 八、进阶技巧

### 1. MCP — 进阶分水岭
[[MCP]] (Model Context Protocol) 让 Codex 连接外部系统：GitHub、Notion、Linear、数据库等。
**先稳定跑通一个，比堆十个半成品强**。

### 2. 自动化任务
在自动化面板设置定时任务：定时收集信息、定期检查项目、周期性生成报告。
> 注意：自动化面板不继承对话模型设置，需手动改。

### 3. 学会看 Git
至少知道 Codex 改了哪些文件、哪些是新增/删除、能否回退。**会看 diff 是区分"用 AI 工具"和"被 AI 工具用"的关键**。

### 4. Worktree 隔离
给 Codex 开[[Worktree]]隔离工作区，不污染主项目：
- 小修补 → Local（当前目录）
- 重要构建 → Worktree（隔离分支）
- 长时间自动化 → Cloud（云端）

### 5. 手机远程操控
轻量操作随时接想法、看进度，不用绑在电脑前。

### 6. Bug 修复原则
提供日志和复现步骤，让 Codex 定位。**不要预先给猜测**（如"我觉得是异步问题"），避免带偏方向。如果一顿操作没解决，开新会话重来。

## 九、Java / Spring Boot 实战指南

[[摘要-codex-从原理到-java落地]] 专门针对 Java 项目给出了实践建议：

### 适合 Codex 做的事
- 多文件联动修改
- 遗留代码重构
- 常规 Bug 排查
- 单元测试骨架生成
- 有明确规则的技术栈迁移

### 不适合 Codex 做的事
- 架构选型决策 ← 人负责
- 复杂核心业务逻辑 ← 人负责终审
- 安全敏感代码 ← 人负责终审

### 描述任务的结构
```markdown
## 目标
[一句话描述要做什么]

## 技术栈约束
- 使用 Spring Boot 3.x + MyBatis-Plus
- 包路径：com.example.xxx
- Controller 统一返回 Result<T>

## 输出位置
- Controller 在 xxx 包下
- Service 在 xxx 包下
- Mapper 在 xxx 包下

## 验证标准
- 编译通过
- 执行 UserServiceTest 测试通过
- 提供 curl 请求示例
```

### 质量保障三层
1. **自动检查**：编译、测试通过
2. **交叉 AI 审查**：用另一个 Agent（如 Claude Code）审查 Codex 的代码
3. **人工业务审查**：人负责终审

### 团队落地三阶段
1. **试点**：选一个模块，让一个人先跑通全流程
2. **推广**：制定团队规范，明确 AI 代码的审查流程
3. **持续优化**：沉淀 AGENTS.md、Skill、踩坑记录

## 十、避坑清单

| 坑 | 说明 | 对策 |
|----|------|------|
| 🕳 **丢需求等结果** | 不提背景直接让 Codex 写 | 先建 AGENTS.md，用 Plan 模式 |
| 🕳 **一步到位** | 一个对话搞定所有功能 | 拆成小任务，每个独立对话 |
| 🕳 **手动改 AI 代码** | 改完后 AI 覆盖你的改动 | 改完必须开新对话 |
| 🕳 **不看 diff** | 直接信任 AI 的修改 | 每次提交前认真看 diff |
| 🕳 **不写 AGENTS.md** | 每次都从头解释项目 | 必须有项目说明书 |
| 🕳 **Skill 全装** | 装了不用浪费上下文 | 按场景装，不用的删除 |
| 🕳 **敏感数据喂 AI** | 把密钥/密码传给 Codex | 关键交易/权限/加密代码人工审查 |

## 总结：三条黄金法则

1. **先规矩，再干活** → AGENTS.md + 计划模式
2. **小步快跑，验证为王** → 拆任务 → 实现 → 验证 → 总结
3. **架构在你，实现给 AI** → 你管边界，AI 管填充
