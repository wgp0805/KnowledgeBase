# PandaWiki

## 定义

长亭科技（chaitin）开源的 **AI 大模型驱动的知识库搭建系统**，定位是快速构建**产品文档、技术文档、FAQ、博客系统**，并在其上提供 AI 创作、AI 问答、AI 搜索三项能力。TypeScript 实现，AGPL-3.0 协议，2025-05-15 建仓，2026-11-27 查询时约 **10,579 Star / 1,048 Fork**，官方文档站 pandawiki.docs.baizhi.cloud，另有免部署的 SaaS 版（百智云 AI 知识库）。

**关键认知：它的"知识库"是"一组文档的集合"，产出物是一个对外可访问的 Wiki 网站**——与 [[LLMWiki]] 那种"供 Agent 读取的编译层"不是同一类产物，详见 [[pandawiki-vs-llmwiki-选型对比]]。

## 关键信息

### 四项功能特色（README 原文口径）
1. **AI 驱动智能化**：AI 辅助创作、AI 问答、AI 搜索
2. **富文本编辑**：兼容 Markdown 与 HTML，支持导出 Word / PDF / Markdown
3. **第三方集成**：网页挂件（挂到其他网站）、钉钉 / 飞书 / 企业微信聊天机器人
4. **多来源导入**：网页 URL 导入、Sitemap 导入、RSS 订阅、离线文件导入

### 部署与运行前提
- 需 **Linux + Docker 20.x+**，root 执行一键脚本 `bash -c "$(curl -fsSLk https://release.baizhi.cloud/panda-wiki/manager.sh)"`
- 默认访问 `http://<ip>:2443`，默认用户 `admin`，密码在安装时输出
- **必须先配置 AI 模型**（一键配置或手动配置，官方推荐百智云模型广场，注册赠 5 元额度），否则 AI 创作 / 问答 / 搜索三项能力全部不可用
- 属于典型的 [[自托管]] 部署，与 [[Docker]] 工具链配套使用

### 产品模型
控制台侧管理"知识库"（文档集合）→ 上传文档后等待"**学习成功**"（即完成切片与索引）→ 每个知识库对应一个"**Wiki 网站**" → 前台 Wiki 站点承接 AI 问答与搜索。

## 与本知识库的边界

### 它不具备的能力（对照 [[LLMWiki分层架构]]）
- **无不可变真相层**：没有 `raw/` 那种"只读、禁止修改删除、唯一事实来源"的分层，导入即入库
- **无 claims 级溯源**：不提供 [[Claims溯源]] 那种"每条事实关联来源文件与行号"的校验机制
- **无双链图谱与索引契约**：不维护"页页互联 + 禁止孤岛 + index 注册"这套约束，也就没有对应的 lint 工作流
- **无冲突双保留**：没有"新知识与旧知识冲突时不静默覆盖、新建区块并存两说"的机制
- **不产出可被 Agent 直接消费的知识层**：属于 [[编译器模式vs解释器模式]] 中的**解释器模式**——每次问答走站点内检索 + 生成，不沉淀为结构化可复用产物

### 它的正确位置
**发布与交互层**，而非沉淀层。适用场景：
- 把已沉淀的知识**对外发布**成产品文档 / FAQ / 博客站
- 给团队或外部用户一个**对外 AI 问答入口**，并接钉钉 / 飞书 / 企业微信
- 从网页 URL、Sitemap、RSS、离线文件批量**导入外部内容**再做 AI 搜索

### 与同类工具的坐标
- [[OpenWiki]]：同为开源知识工具，但 OpenWiki 是 [[LLMWiki]] 理念的工程实现（为 Agent 写文档、claims 溯源、CI 自动更新），PandaWiki 是为人看的文档站生成器——方向相反
- [[WeKnora]]：腾讯开源的**企业 AI 知识底座**（MIT），走 RAG + ReAct Agent + Wiki Mode + 知识图谱 + MCP + 企业权限，偏"组织治理型平台"；PandaWiki 更偏"文档站 + 问答"
- [[腾讯乐享]]：商业化的企业知识库产品，Agent 自主建库分类
- [[Dify]]：LLMOps 平台，可视化搭建知识库与 Agent，能力面更宽但同样不是编译式知识层
- [[CherryStudio]]：桌面端个人知识库工具，与 [[KnowledgeBase]] 里记录的"Cherry Studio + DeepSeek 搭个人知识库"同类

## 选型注意

- **协议**：AGPL-3.0 具传染性，闭源商业化需评估合规成本
- **运维成本**：Linux + Docker + 必须配模型，明显高于纯 Markdown 方案（[[Obsidian]] 本地库零运维）
- **资料局限**：官方文档站是 Next.js 单页应用、正文客户端渲染，抓取只能拿到导航外壳；本页事实来自 GitHub README 与 GitHub API 仓库元数据，权限模型、版本历史、检索实现细节等边界未实测验证
