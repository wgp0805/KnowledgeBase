## 定义
**zvec-grep**（简称 zg）是 2026 年 8 月底开源的**本地优先搜索层**，3.5K Star，仓库持续更新。GitHub: https://github.com/zvec-ai/zvec-grep。它把**语义检索、BM25 全文、rg 正则、混合检索**放到同一个接口，让 CLI 与 Agent 共用一份本地索引。底层基于阿里巴巴开源的嵌入式向量数据库 **zvec**——"向量数据库里的 SQLite"。

## 关键信息

### 核心解决的问题：检索税
Agent 面对的任务很多时候不明确——「主题偏好是怎么在应用启动时恢复的？」代码里可能没有"主题偏好"这几个字，真正负责的函数叫 hydratePreferences。单纯关键词搜索会遇到**检索税**（消耗时间、工具调用次数、上下文窗口和模型 Token），遗漏关键文件还可能得出看似合理实际错误的结论。

### 四种检索方式（同一接口）
1. **语义检索**：用自然语言描述问题，找到相关代码与文档
2. **BM25 全文检索**：结果较多时用来排序和收敛
3. **rg 精确匹配和正则搜索**：知道要找什么时的最快路径
4. **混合检索与结果融合**：多路结果去重排序，优先给出带来源位置的紧凑片段

**定位不是取代 rg，而是让本地搜索覆盖更多场景**。

### 三阶段检索流程
1. **探索**：只知道问题大致含义，适合语义搜索
2. **收敛**：结合关键词/路径/符号/文件类型缩小范围，BM25 或混合检索
3. **验证**：目标明确时用精确文本/正则/直接读取文件

三阶段非固定流程，可以跳步。

### 核心设计
- **一份本地索引，连接多条检索路径**
- 索引存储在 .zvec-grep/ 文件夹，增量更新，是持久资产（Git 仓库建议加 .gitignore）
- CLI 和 Agent 共用索引，避免重复建同一份

### 默认模型与部署
- **默认模型**：potion-code-16m-v2（16M 参数、约 32MiB 缓存、CPU 直跑、无需 GPU）
- **纯文档场景**：`zg index --embedding local/potion-multilingual-128m`
- **前置要求**：Node.js 22+

### 三步部署
```bash
npm install -g @zvec/zvec-grep
zg install  # 自动发现已装 Agent 配好 MCP
zg index    # 建索引
```

### 支持的 Agent（zg install 自动发现）
Codex、Claude Code、Cursor、OpenCode、Qoder——CLI 和 Agent **共享同一份索引**。

### 三个实测案例
1. **定位配置项位置**：知识库 API Key 存在哪里、格式长什么样
2. **追踪完整处理链路**：PDF 上传到可搜索，后台依次经过哪些处理步骤（涉及多个模块、关键词分散）
3. **梳理检索方式实现**：WeKnora 支持哪几种检索方式（关键词/语义/混合），每种在代码里怎么定义、什么时候触发

### 边界（重要）
- **本地优先 ≠ 不联网**：首次下载 npm 包、模型文件、主动选择远程 Embedding 时仍可能产生网络请求
- **不能自动理解 PDF/Office/图片**：通常需先转换为可识别的文本格式
- **语义搜索不是万能**：API Key、变量名、版本号、正则表达式、精确配置值仍应回到 BM25/rg 确认
- **索引新鲜度影响结果**：项目文件发生较大变化后应确认增量索引是否成功

### 检索对象
代码仓库、项目文档、研究资料、本地知识库——**不局限于代码仓库**。
