## 定义
Jev 是由 [[TypeSafeAI]] 于 2026-09-15 发布的 **System One Model**——一个彻底放弃文本生成、只做"判断"的模型。它接收到一段内容（任意文本或 JSON）后，不组织语言、不写答案，而是直接返回**类型化的概率决策**：选哪个、打几分、是不是。Jev 被称为 Agent 系统里缺了很久的一个零件：快判断层。它不是"更便宜、更快、更小的 GPT"，而是从一开始就把任务收窄到判断上。

## 关键信息

### 起源与采用
- 由 [[DiogoAlmeida]]（前 OpenAI 研究员、RLHF 与 ChatGPT 早期贡献者）创办的 [[TypeSafeAI]] 发布，建立在对 RLHF 路线的公开批判之上
- Vercel 官方博客称其为 AI Gateway 历史上**最快被采用的模型**：上线 24 小时内近 13% 付费团队在使用，是 GPT-5.6 系列的 2 倍、Fable 5.1 的 6 倍以上
- 完全闭源，只提供云端 API（console.typesafe.ai / docs.typesafe.ai），已免费开放；也可在 OpenRouter、Vercel 调用（需绑卡验证）
- 模型版本 1.13，上下文 32k，不能多轮对话

### 三种决策原语
| 原语 | 中文理解 | 输出形态 | 适合场景 |
| --- | --- | --- | --- |
| **Choice** | 单选题 | 选项 + 每个选项概率 + confidence（最多 255 个候选） | 工具路由、动作选择、分类 |
| **Score** | 打分题 | 连续标量 / 2~10 个有序等级 + 概率分布 + confidence | 风险评分、质量评分、相关性评分 |
| **Noul** | 判断题 | 0~1 的校准概率（自造词） | 是否保留、是否危险、是否达成目标 |

输出永远是**类型化数值**。软件直接检查、分支、执行，不需要从散文里抢救出一个决定。你让它判断 "urgent 还是 not urgent"，它不会写一段分析，只给你一个 0 到 1 之间的概率值。

### 为什么快：非自回归单次并行推理
传统大模型逐 token 自回归生成，哪怕只输出一个 "A" 也是先写"答案是"再写"A"——中间全是浪费。Jev **跳过自回归解码**，采用非自回归的单次并行推理：不写文本，直接在隐状态上打分，一次前向计算完成所有问题判断。

更关键的是**多问题并行评估**：所有问题在同一次请求中同时完成，不管多少个问题，延迟都落在 70-500 毫秒之间（中位 105 毫秒；对照 GPT-5.6 Luna 关闭推理 710ms、低推理 808ms）。传统模型每多问一个问题就多生成一段文本，4 个问题串行延迟翻 4 倍；Jev 4 个问题同一次前向计算，总延迟与 1 个问题几乎一样。这带来"输出 token 永久免费"的底气——没有可计费的解码过程。

### 训练与校准
训练方法为 [[RLCD]]，与 RLHF、RLVR 并列自成一个序列。校准误差 ECE 仅 **0.07**（基线 0.14-0.18）；保留 Jev 最自信的一半答案，平均准确率提升 **7.6 个百分点**。详见 [[置信度校准]]。独立基准（49 任务 / 8225 测试项）显示 Jev 在 42 个任务上与 LLM 基线打平或胜出，优势领域为逻辑推理、常识推理、科学问答、知识问答；弱项为计数任务、超大选项集（77 选项 0.81 vs 0.87）、问题与否定形式概率不一致（平均偏差 0.32）。

### 速度成本对比
| 维度 | 传统大模型 | Jev |
| --- | --- | --- |
| 输出方式 | 逐 token 生成文本 | 隐状态直接打分 |
| 端到端延迟 | 数千毫秒 | 70-500 毫秒 |
| 速度对比 | 基准 | 快 20-200 倍（独立工作流评测最高快 193.6 倍） |
| 成本对比 | 基准 | 便宜 40-400 倍（最高便宜 444.6 倍） |
| 输出 Token | 按量计费 | 永久免费 |
| 输入价格 | 基准 | $0.042 / 百万 Token |

### "零幻觉"的准确含义
Jev 保证的是**模式匹配**：给 A、B、C 三个选项，它不会自作主张编出 D——因为输出空间被严格限定在候选集内。但**正确答案明明是 A 时，它照样可能选成 B**。类型正确，事实不一定正确。所以"零幻觉"的准确含义是：它不会编造不存在的选项，但它可能判断错误。风险靠置信度阈值管理——置信度低就转人工。

### 适用与不适用
- **适用（强烈推荐）**：工单分类/意图识别（一次请求多问题并行，延迟低至百毫秒）、浏览器 Agent 动作选择（候选动作集合交给 Choice，消除格式幻觉）、模型/工具路由、内容审核/风险判断（校准概率设阈值自动分级）、Agent 执行轨迹监督（用 Jev 监控 LLM Agent，防越狱，成本可规模化）、批量数据分类（1000 封邮件 6 秒 9 美分 vs GPT-5.6 5 分钟 62 美分）
- **不适用**：需要生成文本的任务、需要复杂推理/长链路规划的任务、超大选项集（>255 需两阶段模式，准确率下降）
- **不适合的用法**：只判断一次然后把结果长期当成不会变化的结论（判断前提变化太快时结论会过时；但若系统能持续拿到最新数据让 Jev 重新判断，它仍可参与）

### 在 Agent 架构中的定位
Jev 是 Agent 的**反射神经**而非大脑。架构共识是"快慢分工"（见 [[Agent快慢分工]]）：昂贵大模型负责规划/推理/生成（慢思考），高频原子化的分类/选择/评分（快判断）交给 Jev，确定性逻辑交给普通代码，高风险/低置信度交人工或更强模型。TypeSafeAI 创始人的一句话点题：**"我们优化人类语言优化了四年，但对自动化来说，这没用。因为计算机说的是另一种语言。"** Jev 说的就是计算机的语言——类型、概率、确定性。

### 实际场景案例
- **银行客服**：判断问题类型（账单/售后/技术支持）、客户流失风险、是否需转人工；返回置信度（如转账单部门概率 90%），软件按阈值自动处理/转人工/升级
- **交通信号灯**：JEVCITY 演示，关闭 Jev 按固定 7 秒定时轮换；打开后约 300ms 读一次路况，判断每个路口继续放行还是切换方向，按实时车流动态调整
- **内容筛选**：每天海量帖子评论判断类别（广告/干货/推广/搞笑/闲聊/垃圾），明确自动保留隐藏、不确定转人工
- **知识图谱决策**：缺货时把状态（订单金额/用户等级/缺货占比/投诉历史）传 Jev，给三选项（取消订单/延迟发货/推荐替代品），返回取消订单 0.87 概率、置信度 0.94，自动执行退款通知，全程无人介入

### Java 生态
官方只发布 Python 和 JavaScript SDK，Java 需直接调 HTTP API。社区已补齐缺口：
- **社区 Java SDK**：纯 Java 17+，唯一依赖 Jackson，**不依赖 Spring AI 的 ChatModel 抽象**（因 ChatModel 假设自回归：消息进/生成文本出/支持流式，而 Jev 无消息、无生成、无流，强塞进去会丢掉类型化问题和概率访问）；同步+异步 API、自动重试（429/5xx 指数退避+抖动）、客户端校验、密封类型
- **Spring Boot Starter**：`io.typesafe:typesafe-ai-java-spring-boot-starter`，自动配置 TypeSafeClient
- **Kotlin 客户端 kev**：基于 Ktor + kotlinx.serialization 的 suspend 协程
- **MCP Server jev-mcp-spring**：基于 Spring AI，提供 classify/score/check/health 四种工具，支持 HTTP 与 Streamable HTTP/SSE
