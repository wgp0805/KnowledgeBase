## 定义

Kyle Kukshtel 是资深独立游戏工程师，独立策略战棋游戏 **《Cantata》** 的制作人、游戏数据编辑器 **Depot** 的作者，拥有约 15 年游戏程序员经验。他是长文《Your Game Is A Harness》的作者（博客园 leikooo 转载编译为中文），也是"**把游戏本身做成 Agent Harness**"这一方法论的提出者。

## 关键信息

- **职业背景**：近 15 年游戏程序员，自述"能在一英里外一眼嗅出糟糕的游戏代码"；同时是《Cantata》制作人与 Depot 编辑器作者，正在把 Depot 打造成面向业界的商用产品。
- **AI 编程起点**：从情绪板网站 mood.site 开始把 LLM 引入日常开发。当时行业还没有"智能体"概念，他纯粹想测试 ChatGPT 能否写出像样的代码，用下班时间约 2–3 周、累计约 20 小时完成，结论是"没有 LLM 我可能到今天还在折腾第一个版本"。
- **核心论断**：LLM 在现代 Web 技术栈上几乎无所不能，但在游戏开发场景几乎必定翻车——原因是游戏的公开高质量训练源码少几个数量级、且代码只是冰山一角（海量非代码资产对模型不透明），**这是上下文工程问题，而非模型或游戏的先天缺陷**。
- **解决方案**：八条游戏工程架构原则（固定随机性、截图与图像差分、单一 Fat Struct、命令模式、外部化数据、独立无头模拟内核、纯文本性能分析、闭环飞轮），目标是把 Agent 的迭代轮次从数十分钟压缩到数秒。
- **团队实践**：《Cantata》团队 7 位非程序员成员全部使用日常构建版 + Depot 做内容迭代，无需他频繁重新打包。
