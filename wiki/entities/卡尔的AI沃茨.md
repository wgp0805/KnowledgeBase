## 定义
卡尔的AI沃茨是 AI 模型实测方向自媒体作者（微信公众号同名），擅长用真实工作任务（不拿玩具样例）连测模型能力。代表作《实测豆包新模型 2.1-pro》五个真实任务连测 [[Doubao-Seed-2.1-Pro-0915]]，并介绍 [[QBS法]] 治 AI 说空话。2026-10 与 yc 星辰合著《开源「红绿灯」提示语》，提出给 Agent 装"红绿灯"制动装置。

## 关键信息
- **测评风格**：不拿玩具样例，整份甩入真实文件，中途不帮拆步骤不追喂提示
- **代表测评**：[[Doubao-Seed-2.1-Pro-0915]] 五案例（Three.js 体素樱花岛 / The Dumpling Club 3D 互动网页 / 五份洗衣机文档→Excel / 60 子表 Excel 含钢量计算 / 加拿大三城办公室选址调研）
- **方法论贡献**：[[QBS法]]（让 AI 不说空话：先给一本正经书 → book-to-skill 转 skill → AI 调用 skill 按书答）
- **日常模型**：[[Doubao-Seed-2.1-Pro-0915|Seed-2.1-pro]] 与 [[DeepSeek]]、[[GLM]] 排队日常批量跑
- **合著者**：yc 星辰
- **红绿灯提示语（2026-10-13，详见 [[摘要-红绿灯提示语]]）**：针对"Agent 永远不会主动说做完了"手搓不到 300 字进度提示语——🟢绿灯=原始需求有未达项（顺手改进只记搁置）、🟡黄灯=原始需求已达成且超出项能构成带证据的后续计划（落盘 plan/handoff 等人决策）、🔴红灯=原始需求已达成但超出项零散（三行存档结束）；可配 hook 每对话自动生效、不依赖 skill。核心论点：Agent 每轮推荐下一步本身就是认知陷阱，"每一种强大的能力背后都跟着一个制动装置"
- **GoodCase.ai**：作者做的 AI 提示语案例库（1700+ 案例，人工打分 + Claude/Codex/DeepSeek 三模型自动评估校准），用于 AI 视频生成质量测评档位参考（详见 [[GoodCaseAI]]）
- **四大 Personal Agent 实测（2026-10-16，与 yc 星辰合著，详见 [[摘要-四大personal-agent实测33委托率]]）**：两周 300 多刀订阅费（Muse 100/ChatGPT Pro 200/Manus 40/Grok 100）实测 Google Muse、Grok Bot、OpenAI Dots、Manus Cue 跑 12 个自媒体平台，**可委托率仅 33%**（两个月前 0%）；给出 3 个可复制提示语——[[多任务进度条]]（进度表防谎报防吞任务）、[[六道门验证]]（六道机检关卡 + 只读硬约束防编造数据）、融合日报（信息源五段结构输出飞书）；架构为"云端 Personal Agent + 本机 Codex"，判断 Personal Agent 现阶段是本地 Agent 的补充
- **提示语三件套关系**：红绿灯（收尾刹车）→ 多任务进度条（过程可见）→ 六道门（结果可信）
- **老爷爷「提示语管理.skill」（2026-10-21，与 yc 星辰合著，详见 [[摘要-提示语管理skill-老爷爷]]）**：开源提示语路由 [[Laoyeye]]，把 25 个思考类提示语熔炼进一个路由，分六个场景（问清问题/学习理解/解决问题/决策类/计划类/自我认识类），收录苏格拉底式提问、第一性原理、双向钢人论证、乔哈里视窗、逆向法等。核心洞察：**问题不在存储，而在「到了要用的那一秒想不起来自己存过什么」**——提示语库带来的认知负担对人类太难了，但对 AI 来说只是一次匹配。工程纪律：**原提示语一个字不改**（最常见的错误是把提示语拆散改写成 Agent 风格流程，导致「每次只问一个问题」被压成「请逐步提问」、模型一次倒出六个问题、整条提示语价值清零）；收录上游提示语时统一加来源前缀（matt-grilling / kaz-leader / carl-idea-king），与上游 skill 名字零重合不覆盖。灵感来自 Matt Pocock 的 ask-matt 路由形态
