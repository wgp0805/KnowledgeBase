## 定义

公众号「长弓小子」的作者，人人都是产品经理平台作者，长期分享交互设计与 AI 协作方法论。

## 关键信息

### 核心观点
- 与 AI 对话的底层逻辑**不是「求 AI 帮忙」而是「教 AI 做事」**
- **AI 输出的质量取决于你输入的信息密度**——想要精准反馈，需求就要足够具体
- 不要中途打断或临时加需求；跑偏了要及时刹车开新窗口，而不是在同一上下文里反复纠正

### 代表方法论
[[AI对话五环节]]：确定目标 → 输入指令 → 输出结果 → 校验迭代 → 沉淀复用，以及结构化 Prompt 公式「AI 角色 + 业务背景 + 核心任务 + 硬性规则 + 输出格式」。

### 实践风格
以 B 端后台交互设计为场景展开，强调把团队规范沉淀为 Skills / 知识库、用梯度提需分步落地需求，并指出**组件间距、圆角、字号这类局部参数由设计师手动调整比反复跟 AI 描述更高效**。

### Skill 撰写方法论（2026-10-22）
《如何从0-1写好一个Skill？超全教程+案例分享！》→ 见 [[摘要-如何从0-1写好一个skill]]，提炼概念 [[Skill撰写指令]]（五段式指令：AI 身份 / Skill 用途 / Skill 内容 / 交付要求 / 禁用事项）与 [[Skill]]（四部分结构与调优三维度）。
- 核心立场：**不推荐完全从 0-1 手搓 Skill**，应在 TRAE / Claude Code 中给出完整撰写指令让 AI 出初版，人力投在检验与调优
- 但明确指出后期的质量检验与人工调优**目前仍无法被 AI 完全替代**，场景定义、任务拆解、结构搭建、易错点沉淀必须由人工把控

### 内容创作 Agent 实测（2026-10-23）
《实测 Ribbi：一个 AI Agent 能不能顶掉内容团队？》→ 见 [[摘要-ribbi-内容创作agent]]，实测驻浏览器的内容创作 Agent Ribbi（"一蛙抵一队"），并提出内容创作三趋势判断：内容会变多、信息会膨胀，但真正有价值的创作不会廉价、反而更值钱。
