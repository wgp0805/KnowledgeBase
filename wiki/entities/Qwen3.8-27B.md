## 定义
Qwen3.8-27B 是阿里通义千问团队推出的 27B 稠密大语言模型，是 [[Qwen]] 系列中面向本地 Agent 部署的"甜品点"模型。以 4bit 量化后约 16.69GB 的体积，配合两张 24GB+ 显卡即可跑满 256K 上下文，被视作本地 Agent 工作站的事实标准模型之一。

## 关键信息

### 基本参数
| 属性 | 详情 |
|------|------|
| 发布方 | 阿里巴巴（通义千问团队） |
| 参数规模 | 27B（稠密模型） |
| 上下文窗口 | 262,144 tokens（256K） |
| 架构特点 | 混合注意力：64 层中 48 层为线性注意力（Gated DeltaNet），仅 16 层为全注意力——KV cache 大幅缩小 |
| 量化后权重 | Q4 GGUF 约 16.69GB（unsloth UD-Q4_K_XL 动态量化） |
| 视觉能力 | 支持多模态（附带 0.86GB 视觉投影器 mmproj-F16.gguf） |
| 许可证 | Apache 2.0 |

### 为什么是 27B
- 单张 24GB 显卡装得下 Q4 权重，但 256K 上下文的 KV cache 会撑爆显存
- 两张 24GB 卡（如 2× RTX 5090）通过 [[TensorSplit]] 平均分摊权重和 KV cache，跑满 256K 上下文毫无压力
- 27B 的能力在 Agent 编程、操作系统任务、网页操作、多模态理解方面表现极为出色

### 量化档位参考
| 量化档位 | 权重大小 | 内存门槛 | 适用显卡 |
|----------|----------|----------|----------|
| IQ2_XXS (2bit) | 9GB | 11-13GB | 12GB 卡也能跑 |
| UD-Q3_K_XL (3bit) | ~13GB | 13-16GB | 16GB 卡 |
| **UD-Q4_K_XL (4bit)** | **16.69GB** | **17-19GB** | **24GB 卡（甜品点）** |
| Q6_K (6bit) | ~23GB | 24GB | 24GB 卡卡线 |
| Q8_0 (8bit) | ~29GB | 31GB | 32GB 卡 |
| BF16 (不量化) | 54.7GB | 56GB | 多卡/大内存 |

> Agent 这种长链路任务，建议至少 4bit。2bit 虽然能跑，但精度损失在复杂任务中会放大。

### 实战表现（2026-08-18 本地双卡实测，详见 [[摘要-人类智力基线与2张显卡]]）
- 配置：2× RTX 5090 + llama.cpp + DSH
- 任务：从零写网页版 Minecraft
- 生成速度：66 tokens/sec（日志波动 44-100）
- 预填充速度：2,500-2,900 tokens/sec
- 首 Token：平均 2.9 秒
- 缓存命中率：98%
- 交付：38 步、23 分钟，753 行 game.js + 63 行 index.html + 596KB three.js，双击即玩
