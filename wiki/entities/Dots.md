## 定义
Dots 是 OpenAI 在 DevDay 2026（2026-09-29 发布会）推出的常驻自主智能体（Always-on Agents），由旗舰模型 GPT-6 Astra 驱动，能够承担持续职责：每个 Dot 拥有独立云端电脑，24/7 不眠不休主动找活干，被视为 OpenAI 终结"人工敲 Prompt 提问"旧时代的核心形态。

## 关键信息
- **独立云电脑**：每个 Dot 配云端虚拟沙箱电脑 + 专属浏览器，脱离本地设备自行开网页、操作应用、检索资料、处理数据；经授权也可连接用户笔记本跨端协同
- **全渠道常驻**：进驻 ChatGPT 网页端、桌面客户端、手机 App，并可进驻公司 Slack 与 Microsoft Teams；复杂工作可直接语音"打电话"给它
- **Proactive Research（主动后台调研）**：用户没发消息时以"只读受限模式"主动巡检连接的 4000+ 款应用，测试中曾自动起草忘开的账单发票并推送审批卡片，只等人类确认
- **分级安全**：后台主动工作时只有只读权限，不能擅自发公开消息/改关键资产/接管核心权限；付款、发合同、改密码等敏感操作必须经 Auto-Review 触发人工审核
- **企业版 Specialist Dots**：面向组织的专职数字员工，有独立数字身份、组织权限与凭据，承接采购核验、发票报销、法务合同审查、一线客服；与微软深度协同，整合进 Microsoft Agent 365 由企业既有管理后台统一管控
- **开放节奏**：面向符合条件地区的 Pro、Business Premium 用户灰度开放，首个 Dot 免费赠送、首月赠双倍深度计算额度，企业版管理员后台一键开启
- **"第二身份"路线解读（2026-10-01）**：关键词是 always-on——每个 dot 有云端电脑、插件生态连接 4000+ 应用、经 ChatGPT/Slack/Teams 协作，目标是同一 Agent 跨任务跨渠道保留你的目标、标准与反馈（逐渐知道你如何判断证据、怎样写内容）；优势是"一个主 Agent"降低多工具管理成本、信任积累后替换成本高，风险是判断出错影响范围比单次聊天大；权限设计：用户不在场时主动研究限只读，Custom Rules 可允许/要求批准/阻止动作，改密码等敏感任务必须用户自己完成；在 [[默认委托权]] 争夺中代表"第二身份"路线（详见 [[摘要-personal-agent六条海外路线]]）

### 实测：云电脑规格与通宵移植（2026-10-03，Ai学习的老章，详见 [[摘要-chatgpt-dot实测]]）
- **云电脑配置**：完整 Debian Linux，9 核 CPU、9.7GB 内存、32GB 磁盘，全功能 Bash 终端+GUI 应用，可一键"接管"（Take Control）抢回键鼠
- **重活实测**：把开源 macOS 音频工作台移植成 Windows 客户端——云端克隆仓库、装 Node/Electron 编译链、重构音频接口，通宵交付独立分支+草稿 PR：101 项单元测试、19 项界面测试、9 项 Electron 测试全过，GitHub Actions 打出约 158MB Win10/11 免安装便携包；作者评价其"蜕变为主按工业标准交付成品的初级软件工程师"
- **四个玩法**：全天候开源 Issue 猎手（自动复现→定位→Draft PR→手机审批闭环）、跨时区长程调研白皮书、多应用只读观察与主动预警（Proactive Research 起草待办等审）、本地合盖即走的云端执行
- **三个争议的回应**：①自建 24h Mac mini+内网穿透对极客可行、对 99% 用户门槛高，大厂把笨重方案封装成平民化服务；②**生态孤岛硬伤**——Dot 的主动力建立在 Google Workspace/Slack/Microsoft 365 上，触达不了微信/企微/飞书/钉钉，国内场景"巧妇难为无米之炊"，国内好用的 Personal Agent 要看本土厂商跑通本土办公生态；③安全=只读探测+Auto-review 人工确认+随时接管
- **开放节奏**：Pro、Business Premium、Enterprise 用户分批灰度；作者提醒别把它当聊天搜索引擎，而是"云端数字员工/外包工程师"，现阶段不要指望它拍板商业决策

### Tibo 访谈视角：为什么是 Dots（2026-10-07，详见 [[摘要-retention-is-distribution]]）
- **反工作流宣言**：让用户自己搭循环、画流程图、微调工作流"也许有人兴奋过"，但 Tibo 不认为这是未来——真正会赢的是 Dots 思路：一个极聪明、全天候工作的 agent，理解你的目标和偏好，从反馈里学习，用户不需关心内部怎么循环
- **产品细节补充**：无模型选择器、无一堆配置，唯一要选的是沟通渠道；每个用户一个 primary dot（最懂你的偏好），第二个起组成虚拟团队各司其职（Tibo 自己有专管 X 的 dot）；可通过 ChatGPT、Slack、Microsoft Teams 联系，短信渠道稍后；随 Pro 和 Business Premium 订阅提供、不额外收费
- **技术底料**：长时间持续运行任务研究两年多、记忆系统同量级时间、加上 Codex harness 与全天候能力；首搭 Astra 因其最安全、对齐程度最高
- **架构细节**：Dots 的 harness 不跑在用户机器上，自有电脑也可连用户笔记本（将来可同时连十台，Tibo 比作章鱼——一个中心多条触手）
- **发布前五分钟轶事**：DevDay 演示前 ChatGPT 生产故障，Tibo 的 dot 主动报告并请求修复，被以"你还没到那一步"拒绝——理解关联做对了，动手修被护栏拦住（详见 [[二级监控]]）
- **分发逻辑**：插件被推荐只看留存与使用质量，"做好插件"即分发（详见 [[留存即分发]]）
- **医疗深水区的天花板（2026-10-08，详见 [[摘要-personal-agent-技术内核与医疗落地]]）**：在医疗试金石下，Dots 是"云端全能实习生"（云沙盒、四根支柱齐活），但公有云部署、**不支持 HIPAA 等监管场景**、不能碰临床数据，可帮医生管日程/行政/搜文献，进不了医院系统深水区——垂直的 [[DAXCopilot]] 才是临床入口；其权限三档设计（只读默认允许/低风险可自动/高风险确认 + Auto-review 二次拦截）与文章"谁签字谁负责"原则互相印证

### 四款 Personal Agent 委托率实测中的 Dots 缺陷（2026-10-16，卡尔的AI沃茨，详见 [[摘要-四大personal-agent实测33委托率]]）
- 实测结论：**四款（Google Muse/Grok Bot/Dots/Manus Cue）跑 12 个自媒体平台，可委托率仅 33%**，Dots 是唯一答案但问题一堆
- **单对话框架构**：不能像 Grok Bot 那样分多 agent 分任务共享一台电脑，所有对话发生在一个对话框里；"最终活动面板"点开后**不记录每次对话的执行结果**，任务状态只能一个个点开看，没有总览
- **一次只能连一台电脑**：哪怕有 50 台电脑一个账号最多绑一台，3 台可加入但必须互相切换、没法同时连
- **登录态死结**：无法复用本机登录状态——最理想是遇到未登录直接复用本机登录态（不用担心异地掉线/登录失效），但"完完全全行不通"；要么用毕生记忆力把无 API 账号登进云端并关掉部分安全设置，要么像 Grok Bot/Dots 走 Computer Use 路线
- **对策**：作者用 [[多任务进度条]] 提示语强制每次回复附任务进度表（执行端/状态/证据/下一步），把 Dots 造成的任务不可见降到可用
- **组合定位**：Dots 做云端采集 → 存飞书文档 → 邮件通知 → 本机 [[Codex]] 读取并下发指令——Personal Agent 现阶段是**本地 Agent 的补充**，不是有云电脑就能全交出去
