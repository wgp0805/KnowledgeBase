## 定义
Manus 是定位 General Agent（通用 Agent）的 AI 产品，2025 年 3 月上线即以"一个聊天框搞定查资料、整理文件、写代码、做网页、操作浏览器"出圈。经历与 Meta 的收购/独立波折后，2026 年 9 月 1 日恢复独立运营，27 天后（9 月 28 日）发布 2.0，把"通用"从定位做成体验，并推出个人 Agent 应用 Cue 与 Meta Muse 正面竞争。

## 关键信息
- **2.0 本体**：底层换成自研 Agent 框架 Cascade，官方单测数据 Token 消耗减少 23.2%、任务耗时缩短 28.2%、运行成本降低 32%（发布会将"成本降低 32%"放在最显眼位置）
- **Manus Studio**：桌面端定位"人和 AI 共享的工作空间"，新增视频编辑（Alchemy mode 结合视频生成与代码生成组织画面）与游戏开发专属环境，网站/应用/文档/幻灯片与分散数月陆续上线的 Skills、Project Skills、Connector、Scheduled Tasks 全部整合进同一工作区；此前能力越拆越细，2.0 是"收纳袋式"重新整合
- **云电脑**：Cloud Computer（4 月发布）为项目提供持续运行环境，多人游戏等长任务天然需要；Computer Use 进一步接入本机文件、浏览器和应用，手机可远程发指令
- **Cue**（独立个人 Agent App，邀请制）：给每个 Agent 配独立邮箱、电话号码、钱包和电脑，可在用户设定预算内付款、接电话留摘要；多个 Agent 可拉进同一群聊分工（一个查场地、一个筛选、一个写方案成 Deck）
- **调度哲学**：通用更像一套调度方式——用户不必自己决定下一步打开哪个 AI 产品；新 Agent Harness 平时轻量、按需引入专业模块，由 Cascade 服务调度。垂直产品比拼单点深度，Manus 要拿的是入口和调度能力；风险是链条越长、任一环节偏差越影响最终结果
- **定位演进**：早期"能力覆盖面广的执行助手"→ 2.0 证明"任务之间的价值"，不追求每个单项都赢
- **国内动向**：面向国内市场的产品在筹备、团队正在组建，与国产模型厂商合作推进；没有自家"围城"的独立玩家反而敢做真正的"连接者"
- **腾讯入股（2026-10-04，详见 [[摘要-腾讯四款muse产品盘点]]）**：腾讯牵头国内资本以约 **20 亿美元估值**从 Meta 手中回购 Manus 相关股权，腾讯成为**最大单一外部股东**、创始团队仍掌握实际控制权——虽不控股不属腾讯系，但为多方合作创造可能；文中 Cue 对标对象实为 Meta 的 Muse（原文笔误写作"Meta 的 Manus"）

## OpenManus：GitHub 定律的极致案例（2026-10-05，详见 [[摘要-github定律-openxxx复刻]]）
- 2025 年 3 月 Manus 刷屏、邀请码被炒成稀缺品时，**OpenManus 与 Manus 发布同一天**出现在 GitHub，最早的可运行版本据称只用了约 3 个小时
- 3 小时做出的 OpenManus 只是早期版本、与 Manus 完整能力仍有距离——把已成熟的 AI、网页操作与任务执行能力组合起来先让大家看到思路
- Manus 走火还带火了 OWL 等原有项目：老项目找到新的介绍方式被更多人看到
- 复刻与被复刻的关系印证 [[GitHub定律]]：代码不再稀缺，判断力/品味/渠道才是差距

## 四款 Personal Agent 实测中的 Cue（2026-10-16，详见 [[摘要-四大personal-agent实测33委托率]]）
- 作者两周花 300 多刀（含 Manus 40 刀）实测四款，12 个平台可委托率仅 33%
- **Cue 没有控制本地的 Computer Use 能力**（与 Grok Bot 同短板）——无法用 Computer Use 抓取需要本机登录态的国内平台后台数据
- 该文对整个赛道的判断：除非 Agent 记住所有账号密码 API，否则云端 Personal Agent 会陷入不可能三角；现阶段是本地 Agent 的补充

## 执行身份视角的 Cue（2026-10-22，易安说AI，详见 [[摘要-四家ai-bot对比-权限模型]]）
- 定位：Manus 的 Cue 给每个 Agent 配电话、邮箱、钱包和电脑，为其提供**真实世界里的执行身份**——不再只做研究整理，还能持续对外联系、接收回复、在预算内付款；电话可接听留摘要，邮箱可持续询价确认，钱包按设定预算支付
- 把任务终点推到原本需用户亲自接手的动作上：现实任务最难的往往不是"找出选项"，而是联系商家、确认需求、下单付款
- 风险最高的一类 Agent，产品设计建议至少落实四层控制：①**金额分级**——低于小额阈值可自动执行，超阈值必须确认；②**收件人校验**——首次联系、外部域名、敏感地址必须显示预览并等批准；③**支付白名单**——只允许向已验证商家、已绑定服务和限定类别付款；④**行动回执**——电话/邮件/订单/支付都需可审计日志、撤销窗口与异常告警
- 关键提醒："在预算内付款"不是产品文案而是一套**资金授权模型**——预算需配合支付范围、次数上限、收款方约束和不可逆操作的二次确认
- 适用场景：对外沟通、询价、预约或有限预算内完成交易的流程；上线前先建立预算、收件人、商家、支付类别与人工确认规则
